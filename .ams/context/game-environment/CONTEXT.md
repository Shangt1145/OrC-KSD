# 游戏环境（KARDS 模仿）

Orc 触发器引擎之上的游戏逻辑域（Orc.Game）；第一批＝对局骨架（集合类/卡牌库/战场/玩家/对局 Match/回合体系）；第二批分三阶段（2A 结构层 / 2B 打出链 / 2C 指挥与词条），KARDS 规则为对齐基线。

## Language

**对局（Match）**：
带状态机的对局聚合根——创建（准备态）→ Initialize()（进行态）；承载双玩家、回合序、战场与管理器群。
_Avoid_: 战斗、战役

**管理器群**：
回合 / 玩家 / 战场 / 资源 / 卡牌库五个管理器；单领域单一真源，Match 只协调转发（转发只读、不复制状态）。
_Avoid_: 控制器、服务层

**回合五连**：
turn.end.before → turn.end → turn.start.before → turn.start → turn.start.after 五条阶段信号更新，经总线按序 Emit。
_Avoid_: 回合事件、阶段回调

**信号先行、处理随后**：
turn 系列为阶段信号；开始处理（结算→抽牌）位于 turn.start 与 turn.start.after 之间；回合结束序列无点数处理（结束方点数保留原值）。
_Avoid_: 钩子处理、回调顺序

**指挥点结算**：
槽+1（至上限，默认 12、可配置）→ 点数＝槽值（设为、不累积）；初始槽 0/点 0；回合结束不清零（点数保留、敌方回合内可读残留），下次己方回合开始被重设覆盖。
_Avoid_: 资源累积、补满机制

**起手装载**：
先手 4 / 后手 5，静默（不发任何更新）；从洗牌后的卡组抽取（2A 起加载先于起手、抽取已加载实例）。
_Avoid_: 初始手牌、开局发牌

**抽牌链路**：
卡组取首张并移除 → 加入手牌（2A 起实例在加载期生成）；回合抽牌连发 card.drawn → card.hand.add，起手静默不发。
_Avoid_: 摸牌、抓牌

**卡组（CardList）/ 手牌（CardSet）**：
卡组＝可重复、有序、可洗的卡牌集合（计数语义＝剩余可抽张数；2A 起初始化加载后承载已加载实例）；手牌＝引擎卡牌实例集（保序、拒绝同一实例重复归属）。
_Avoid_: 卡池、持牌区

**卡牌定义 / 卡牌库**：
定义＝名称＋四项基础数值（2A 起可区分三类卡）；卡牌库＝id→定义的注册表（注册/查询/实例化），实例化产出三类卡之一（CardBase 子类）＋拆分数据组件。
_Avoid_: 卡表、模板

**数据组件全集（2A）**：
指挥点花费（部署费单列）／对战（行动费/攻击力/防御力＝只读基准）／单位（位置〔Slot 引用〕/已毁/类型枚举列表/三实时值＝运行值）／指挥（可移动/可攻击）／词条（标识登记列表；数值由效果模块维护）／反制激活；原四合一「基础数据组件」退役。
_Avoid_: 基础数据组件、四合一属性表、数值面板

**卡牌加载（对局开始加载）**：
初始化固定链一环——对双方卡组（洗牌后、玩家索引升序）逐张执行卡牌基类加载模板并广播 card.load；加载实例＝后续起手/抽牌所用同一实例。
_Avoid_: 初始化装载、牌库预热

**卡牌基类（CardBase）**：
三类卡（单位卡 UnitCard / 指令卡 CommandCard / 反制卡 CounterCard）的抽象基类；承载加载模板、子类重写点与触发器声明位（单位/指令＝预打出＋打出；反制＝使用反制的触发器）。
_Avoid_: 卡牌模板、卡类

**战场三线**：
玩家A 支援线 / 前线（中立共享）/ 玩家B 支援线；各自固定归属；2A 起槽位化（Slot 序列、容量 4/5/4）；初始化后支援线含 HQ 占位（槽 0）、其余空；「敌线」＝视角称呼（不改名、不引入新对象）。
_Avoid_: 阵线、区域

**HQ**：
玩家的总部（占支援线槽 0）；G11 起＝**独立 HQ 实体**——非卡实体（Entity＋组件容器＋词条/效果装载面；不入死亡/销毁链；取代槽中 Player 引用，Player 持 HQ 引用）；"防御力"＝血量域；数值改变走通用数据改变管线；归零＝终局。
_Avoid_: 主基地、大本营

**槽位（Slot）/ 邻位动态候选**：
槽位＝线内固定位置＋占用者（单位/总部/空）；邻位动态候选＝遍历线内被占槽位（含 HQ）、取左右空邻位、去重、索引升序——部署/移动候选位。
_Avoid_: 格子、位置表

**更新常量类（16 条）**：
turn 五连＋card.played / card.drawn / card.stat.changed＋2A 六项（card.load / card.hand.add / card.died / unit.joined / unit.deployed / unit.position.changed）＋W4-1 洗切一项（deck.shuffled）＋W2-G7 弃置一项（card.discarded）；字面值为对外订阅契约（冻结）。
_Avoid_: 事件枚举、Hook 名称表

**准备 / 进行**：
对局两态；准备＝已创建未初始化（无管理器/无玩家/无更新）；进行＝初始化完成、可推进回合。
_Avoid_: 等待态、运行中

**Targeter（指示器）**：
对局内目标选择的请求对象（筛选器＋可缺省槽位）；唯一发起入口＝其 Targeting() 异步方法。
_Avoid_: 选择器、指示器组件

**Targeting（目标选择执行）**：
一次目标选择流程——入队 → 桥接收集候选 → 粗筛 → 细筛 → 桥接交互 → 终局（恰好一次）；结局三态不抛。
_Avoid_: 选择流程、目标选择

**TargeterManager**：
Targeter 的 FIFO 串行执行队列（一次一个、终局后出队下一条）；对局管理器群第六员。
_Avoid_: 调度器、目标管理器

**目标桥接（Bridge）**：
前端实现的后端↔前端通道：候选收集 ＋ 交互（Begin／Complete／Cancel，请求标识配对）。
_Avoid_: 适配器、前端代理

**粗筛 / 细筛**：
两级过滤——粗筛批量式（完整引用列表 → 允许子集）；细筛单引用谓词逐项（在粗筛结果上）。
_Avoid_: 过滤规则层、预筛

**置黑**：
前端对未返回项／被淘汰项的显示处理；后端只产出"允许什么"、不负责显示语义。
_Avoid_: 禁用、灰显、可用性标记

**触发器分层（底层/外部）与注册表**：
底层触发器＝引擎初始化注册、与 UI 沟通并触发更新；外部触发器＝业务层；对局级注册表＝只记账（登记触发器＋分层分类、按分层枚举）、与运行解耦（不做强拦截、靠自觉）。
_Avoid_: 触发器管理器、事件表

**事件装配 / 注册表登记**：
事件装配＝向触发器自身注册事件 handler；注册表登记＝游戏层分层注册表登记（对象＋分类）——2A 术语区分，避免混用。
_Avoid_: 触发器注册（歧义用法）

**打出链（Play Chain）**：
三类卡生效流程的结构总称——单位/指令＝两段式（预打出＋打出）；反制＝「使用反制的触发器」单入口状态翻转（激活↔取消）。
_Avoid_: 出牌流程、释放链

**单位化（Unitification）**：
部署/加入两条入场路径共用的后半段（挂单位数据＋指挥组件、实际入槽）；部署与加入以 unit.deployed / unit.joined 区分。
_Avoid_: 入场化、实体化

**槽位引用（Slot Reference）**：
让槽位以引用形态进入 targeter 候选/产出面的承载（2B 受控变更引入）——「选中空槽位」的断言对象。
_Avoid_: 坐标、索引

**反击豁免**：
攻击结算中判定"目标方是否反击"的规则表——目标轰炸机永不反击；攻击者炮兵不受任何反击；攻击者轰炸机不受反击（目标战斗机例外）；多类型单位逐条套用、豁免条款优先。
_Avoid_: 特例表、免伤规则

**伏击改写**：
伏击单位被攻击时以"攻击者死亡、被攻击者不受伤"替代同时互伤的机制；成立前提＝目标方具备反击资格（豁免表通过）∧其实时攻击力＞攻击者实时防御力。
_Avoid_: 伏击反击、先制反击

**终局**：
HQ 生命≤0 当刻对局置"结束"态并记录胜者；当次结算收尾照常完成，此后全部对外动作入口拒绝、更新流冻结、只读查询保持可用。
_Avoid_: 比赛结束、Game Over

**前线占据**：
"前线不存在存活敌方单位"的实时状态判定（空线或己方已占皆然；无占据标记）；作为推进的前置条件。
_Avoid_: 控线、占线

**轰炸机拦截**：
轰炸机攻击时，目标战线存在存活敌方战斗机 → 该战线非战斗机目标（含 HQ）不可选（置黑）；跨战线目标不受影响。
_Avoid_: 制空、优先打击

## Decisions

- **装配模式**（第 1/11 轮）：调用方提供数据（卡组名单×2、定义集、[种子]、[先手]）、Match 负责装配；引擎由 Match 内部新建并公开（match.Engine）；先手默认第一位玩家；空名单创建期拒绝，不足起手走运行时抛错。
- **初始化序列**（第 1/4 轮；2A 修订）：生成管理器群 → 批量注册定义 → 创建玩家 → 洗牌（传随机源）→ 卡牌加载（逐张 card.load、洗牌后序、顺序逐位稳定）→ 起手装载（静默）→ 先手回合开始序列（3 条更新入总流）→ 置进行；API 返回即全部完结；重复 Initialize / 准备态推进抛错；加载失败＝fail-fast。
- **更新序列契约**（第 4 轮；2A 修订）：初始化＝双方卡组总数＋3（标准 43：逐张 card.load＋三连；无 card.drawn）；回合循环＝抽牌位连发 card.drawn→card.hand.add（硬性位于 turn.start 与 turn.start.after 之间）；测试断言随契约迁移（总数不减）。
- **集合边界**（第 7 轮）：空集 Draw 抛错；Insert 越界抛错；CardSet 拒重复实例；Instantiate 纯转换（空→空集 / 未注册→抛错 / 重复→独立实例、保序）。
- **可复现**（第 6 轮）：同种子＋同参 → 洗牌/起手/抽牌逐位一致（纳入测试）；种子可读；上限创建期可配（默认 12、正整数）。
- **载荷**（第 2/9 轮）：card.drawn＝{玩家, 卡牌实例}；card.stat.changed 无载荷（硬约定）；card.played 载荷后置；turn 系列＝{玩家, 回合数}（自洽即可、定型汇报）。
- **结构自由**（第 3/11 轮）：命名/密封性/文件组织实现者定型并汇报；玩家＝普通数据类（不继承引擎 Entity）；对外契约（Match 便捷属性/EndTurn 无参门禁/五管理器公开 API 面）须符合需求记录。
- **Targeter 归属与接入**（Targeter 对齐）：第六员＝TargeterManager（Match 构造可选参数注桥接、Initialize 生成、公开面读取；亦可独立构造）。
- **Targeter 三态与协议**（Targeter 对齐）：统一结果对象不抛（成功／取消／失败＋类别化原因）；一次 Begin 恰好一次终局；内容不合规＝拒绝＋留痕＋继续等待；取消仅前端 Cancel（无超时/CT）。
- **写入双模式**（Targeter 对齐）：界＝产出形态——无/单槽位＝扁平（视图 [Mutate] 写入）；多槽位＝非扁平（强类型写 ctx、按槽位名取）；类型化辅助入口必须存在且显式写入。
- **Targeter 验证口径**（Targeter 对齐）：mock 两阶段入口脚本化＋Match 端到端用例；留痕可观测并纳入断言；流程隔离纳入测试。
- **2A 加载接入**（2A 对齐）：初始化时对双方卡组逐张执行加载模板并广播 card.load（洗牌后序、玩家升序）；加载实例同一性＝验收要求（起手/抽牌所得＝加载实例）；失败＝fail-fast。
- **2A 抽牌连发**（2A 对齐）：回合抽牌连发 card.drawn→card.hand.add；起手静默不发；其他来源零调用点（入口就绪）；card.died/unit.* 为零调用点。
- **2A 数据组件与槽位化**（2A 对齐）：部署费单列＋对战三值（基准只读、无双真源、原四合一退役）；三线统一槽位化（4/5/4）；HQ 占各自支援线槽 0（占容量格）；邻位候选含 HQ 被占位、去重、索引升序；槽位越界＝明确错误。
- **2A 注册机制**（2A 对齐）：对局级注册表；登记＝本体＋分层分类（必填；重复/null 拒绝；无移除；与运行解耦）；查询＝按分层枚举（底层清单供审计，本批不建审计行为）；声明位不登记（真实登记自 2C）。
- **2A 受控变更授权**（2A 对齐）：初始化/循环序列、卡组运行时表示、Battlefield、CardStatsData 拆分均可调整（旧→新对照）；既有 Orc.Game.Tests 允许最小化适配（总数不减）。
- **2B 打出链对齐**（2026-10-03）：单位/指令＝两段式（预打出＋打出）、反制＝单入口状态翻转；预打出拒绝原因可区分（点数不足/无空槽）；单位/指令打出段前复验（反制无）；成功即完整、失败即零副作用（卡留手）；离手＝收尾扣费后。
- **2B 更新发射与费用**（2026-10-03）：部署＝card.played＋unit.deployed；加入＝unit.joined；指令＝card.played（先于主动 handler 集）；反制零更新；card.played ≠ 引擎 card.placed；扣费＝该卡花费（部署/指令收尾恰一次；加入不扣）。
- **2B 反制状态**（2026-10-03）：单入口翻转（激活↔取消）；费用＝该卡花费（激活扣、取消无条件退）；仅己方回合（＝卡所有者是当前行动方）；handler 注册/注销须可断言。
- **2B 槽位引用**（2026-10-03）：槽位以引用形态进入 targeter 候选/产出面（受控变更；形态实现层定、交付回报）。
- **2B 部署词条**（2026-10-03）：独立于词条系统（2C 接入）；按登记序触发；默认检查失败仅跳过、不中止部署；异常隔离。


- **2C 行动状态生命周期**（2026-10-03，2C 第1轮）：置 true＝闪击（部署链收尾·扣费后）＋回合恢复（turn.start 处理、作用于当前行动方在场单位〔HQ 除外〕、本批包含）；常态初值 false（部署当回合不可行动）；清除＝动作成功执行（移动清可移动、攻击清可攻击；非坦克二选一另一同清、坦克独立清；奋战按词条记账判首/次）；失败/取消不消耗。
- **2C 外层更新**（2026-10-03，2C 第1轮）：两 bool 法定写入点全集＝指挥流程外层收尾／部署链收尾（闪击）／回合恢复；内层（移动/攻击触发器、词条）禁止写；硬约束以测试断言保证；两 bool 公开可读，动作合法性聚合判定须可公开调用（形式实现定）。
- **2C 闪击时序**（2026-10-03，2C 第1轮）：以「扣费后」为准（Q13-b）；注入/执行落点＝扣费完成之后、打出链返回之前；「部署触发器末尾」表述作修正。


- **2C 攻击范围矩阵**（2026-10-03，2C 第2轮）：步/坦＝支援线→敌前线｜前线→敌支援线与敌 HQ；支援线→敌支援线禁止；同线互攻不开（相邻＝跨线；无阻挡规则、后置）；炮/轰任意线（含 HQ）；HQ：不反击、伤害＝攻击者实时攻击力、血量写入口＝受控变更；胜负后置。
- **2C 守护与烟幕**（2026-10-03，2C 第2轮）：烟幕＝对一切攻击者生效（置黑）、不限制自身行动；守护＝同线槽位相邻（跨线不计）、保护计入 HQ、多守护不叠加、守护者不可被守护；被守护维护须覆盖一切影响支援线布局的变动（至少 position.changed），防陈旧。


- **2C 移动口径**（2026-10-03，2C 第3轮）：仅推进（支援线→前线）；目标＝前线任意空槽（不受邻位规则约束——邻位为支援线部署专用，避免空前线推进死锁）；仅支援线单位可动；后撤/横移后置；原槽变空并参与邻位计算；成功＝移槽＋position.changed 恰一次＋扣费＋外层清位；失败/取消零副作用。
- **2C 行动费用**（2026-10-03，2C 第3轮）：每动作各扣 1 次实时行动费、自当前行动方扣；双层验证（发起判定〔动作级拒绝〕＋执行前复验）、ValidationRejected 表意、零副作用＋留痕；时序＝执行成功→收尾扣费恰一次；与 bool/矩阵并行聚合判定；被隔离异常视为已执行。


- **2C 攻击结算**（2026-10-03，2C 第4轮）：互伤同时（互扣前实时值基准；同归于尽双方 card.died 均发、固定序〔被攻击者→攻击者〕）；死亡清理最小口径＝槽位释放／IsDestroyed／card.died 恰一次／已挂载效果注销／Position 置空·实例保留可查询；死亡不发 position.changed（被守护维护走等效内部触达）；死亡单位不参与后续指挥/筛选。
- **2C 造成攻击伤害与伏击**（2026-10-03，2C 第4轮）：对局级内置共享流程触发器（单位 vs 单位攻击必经）；默认＝基础互伤；伏击＝目标侧、加载时注册；比较＝互扣前实时值，成立→攻击者统一死亡流程＋被攻击者无伤，否则正常；HQ 攻击不走该流程（直接扣血）。

## 决策摘要（表达力补全 · W1-B1：G8 效果级随机服务，2026-10-04）

**对局随机服务面**：

_Avoid_: 伪随机库、标准随机数

_Avoid_: 随机单例、直连随机

**无旁路（随机消费纪律）**：
对局内随机消费不得绕过服务使用其他随机源；证据＝生产侧 System.Random 消费点清零或逐点列明。
_Avoid_: 双随机源、兼容旧随机

**语义级洗切兼容**：

_Avoid_: 逐位兼容、序列保持

**随机分配（循环取样组合）**：
"分配"类需求由调用方循环调用取样原语实现；服务只提供取样原语、不建分配专门机制（场 2 决议）。
_Avoid_: 分配原语、分发机制

- **拒绝语义**：归属口径＝卡当前所在手牌；前提不满足/重复弃置＝明确拒绝；拒绝形态由实现者定（须可区分）。
- **信号契约**：载荷 {Card, Player}（对齐卡的动作事件族）；不携原因/路径；烧牌（HandLimit）信号归属留待 HandLimit 轮。
- **次序与验收深度**：移除→销毁（含清理）→信号；验收三层＝①离手不可再用 ②信号恰一次＋载荷正确 ③销毁接线最小用例佐证（既有机制不含清理面须申报、不扩 Scope）；失败不留未定义半态。
- **离手路径边界**：打出离手不改造、不销毁；弃置独立动作面。



**读改写口（词条）**：
词条读取与改写的统一入口——存在性/参值读取＋授予/移除/参值改写；多来源（固有/授予；能力型/标记型）统一经它读写。
_Avoid_: 直读内部结构、多路查询

- 决策摘要（第 2 轮·A1）：三口（标识登记/逻辑装载/运行计数器）**合并替代**、不保留；静态 HasKeyword 保留为便利转发面；查询缺省＝可空（null＝无参值可读、配 HasKeyword 区分）；测试**受控随改**（断言迁移＋逐条记录、覆盖不减少）。


### Language（G7·轮 2 增补）

**烧牌**：
HandLimit 超限处置——满手时抽到的牌不经手牌、直接销毁（KARDS 烧牌语义）；复用 card.discarded 信号。
_Avoid_: 爆牌、入手再弃

### Decisions（G7 · 轮 2：HandLimit 烧牌）

- **裁决点**：装配于回合抽牌链路（进手牌前判定）；起手装载不受裁决（4/5＜9、当前不可达超限；维持静默）；生成→手牌等新路径本批不涉（边界披露）。
- **动作语义**：直烧口径——不经手牌（手牌全程 9、无瞬时第 10 张）；"移除"由抽取步骤自然完成、处置＝销毁；不经弃置动作（共享销毁原语与信号）。
- **信号流**：card.drawn 恰一次（既有载荷）→ card.discarded 恰一次（{Card, Player}）；hand.add 零次；销毁先于 discarded；不另立信号（烧牌＝弃置的自动路径；如需区分再评估）。
- **语义裁定**：算"被抽到"、不算"进过手牌"。
- **验收口径**：手牌终态/全程 9＋卡组 −1＋被烧卡不可再用＋销毁佐证＋信号分段断言（drawn→discarded）。



**词条注册面**：
标识→词条组件的解析注册机制（合法标识集来源；内建词条同经此面装配、支持扩展注册）。
_Avoid_: 硬编码清单、switch 工厂

- 决策摘要（第 3 轮·A1）：生命周期三操作——授予（存在 true／行为生效）；移除＝**完整卸载**（存在 false／参值不可读／行为注销）；**死亡注销＝仅行为撤销**（存在 true、信息保留）。重复授予幂等（参值变更走改写口）；**A1 支持动态授予**（含无词条卡）；示例词条走注册面（测试内注册、经声明全链）。


### Language（G7·轮 3 增补）

**手牌顺序原子面**：
CardSet 的纯容器操作集——移至最左/最右/指定位置（0 基结果位置）、按索引移除（返回卡引用）、Peek（按索引只读）；无副作用、单次原子。
_Avoid_: 手牌重排、队列操作

**纯容器操作**：
只发生成员/顺序变化的容器级操作——不发射信号、不销毁卡、不触发更新；要么成功、要么集合不变。
_Avoid_: 无痕操作、静默变更

### Decisions（G7 · 轮 3：手牌顺序原子面）

- **语义**：移动＝0 基且为移动完成后所在位置（0..Count−1）；不在手牌/越界＝明确拒绝；自移＝无操作成功；按索引移除＝返回被移除卡引用；Peek＝按索引只读（可复用索引器读面、不强制重复建设）。
- **性质与组合**：纯容器操作（无副作用＋原子）；「弃掉最左」＝定位（读/Peek）＋弃置动作；按索引移除不得与销毁混用/拆分串联（先移除再弃置＝预期拒绝）；按索引移除用途＝"取出（不销毁）供其他处置"、与弃置解耦。
- **范围**：限定手牌（CardSet）；CardList 无对称面要求；空/单牌边界须覆盖测试。



- 决策摘要（第 4 轮·A1）：内嵌效果＝实例持有为基准、完整链装载（托管/回滚/无残留）；授予/移除＝可等待完成、缺上下文防御跳过；声明面＝单一声明类型（参值位可空、同标识重复拒绝）；参值改写＝目标须存在（异常）、可置空、A1 纯存储。


### Language（G7·轮 4 增补）

**回迁**：
跨集合受控动作——手牌移出＋装入卡组一体完成（位置＝卡组顶/指定位置）；仅凭卡引用即可；不发信号；保证同一实例不丢失不重复。
_Avoid_: 手牌转移、入组操作

**洗入**：
组合式语义——回迁装入卡组＋既有洗切面调用；一次洗入＝洗切恰一次（一条 deck.shuffled）；不设专属封装。
_Avoid_: 洗入动作、批量洗牌

### Decisions（G7 · 轮 4：回迁与洗入）

- **回迁形态**：跨集合受控动作（＋基础件：卡组容器级"新增条目＋装配实例"原子面）；不变量由动作保证；仅凭手牌卡引用（id 自行解析）；位置＝卡组顶（索引 0）/指定位置（0 基、0＝下次抽取取件端、0..N 含尾部）。
- **拒绝语义**：不在所声明手牌/重复归属/越界＝明确拒绝；回迁整体静默（不新增信号）。
- **洗入**：组合式（回迁＋既有洗切面）；位置参数在洗入路径无关；全体＝装入完成后洗切恰一次；空集＝无操作；衔接＝零改动调用既有公开面、域外改动＝先申报。


### Decisions（G7 · 轮 5：验收场景细化）

- **场景②**：选择＋回迁（卡组顶）两步组合；不含洗切（无 deck.shuffled）；附"回迁指定位置"最小断言。
- **场景③**：＝选择＋手牌内移动（组合消费级；⑤为原语级）——手牌轴与卡组轴（②）分离。
- **场景④**：全体＝逐张回迁（缺省）→洗切恰一次；随机单张＝取样→回迁→洗切恰一次（种子可复现）；空集＝独立分支断言（无操作、无信号）。
- **交互驱动**：桥接脚本化演示（不新增生产侧入口/文件、不绕受控面）。
- **场景⑦**：两层断言——信号层（恰一次＋{Card, Player}＋恰序）＋自写监听 handler 消费层（私有状态、条件触发可观测）。
- **场景①**：含"选择终局产出＝被弃卡"衔接一致性断言。



- 决策摘要（第 5 轮·A1）：挂载序列＝存在置位→效果装载→OnGrant（链内失败逆序回滚、无半态）；移除＝OnRevoke→效果卸载→存在清除；死亡注销同 OnRevoke 序列（终态：操作面拒绝、查询面可用）；注册面＝进程级（注册先于使用、单源）；词条面寻址＝卡上可达（含无词条卡、不抛）。


### Decisions（G7 · 轮 6：约束收尾）

- **编辑域判定**：以"是否修改/新增域外文件"为准；域外只读调用不属触碰；预计零申报；须新增公开面＝先申报。
- **Player.cs 随改**：HandLimit 注释更新为已启用语义（常量值与公开读面不变；超限判定为内部行为、不新增公开状态）。
- **测试适配授权**：最小化适配（非删除、总数不减、随改后全绿）；无法机械适配＝暂停申报。
- **更新序列契约**：分支细化——普通分支不变；满手分支＝drawn＋discarded（hand.add 零次）；普通分支既有断言不变＋满手分支新断言。
- **随机弃**：确定性种子下可复现断言（对齐场景④）。


**对战词条（Combat Keyword）**：
词条的分类标记（判定依据＝B 站 Wiki 标注：闪击/守护/伏击/重甲X/奋战/烟幕/冲击）；供「随机获得对战词条／对战词条数」类效果筛选；打标清单随官方口径受控更新（池边界＝已实现且打标）。
_Avoid_: 战斗词条、对战关键词

**预报（Forecast）**：

_Avoid_: 预测、天气预报


**钳击（Pincer）**：
部署时（可选、单选）选一友方同伴形成一对一配对（已配对者不可选）；双方获得「钳击效果」、任一方离开战场即失去（不自动重建）；钳击效果＝以钳击关系为来源的成组施加/撤销（各卡 X 为内容层）。
_Avoid_: 钳制、配对

**抑制（Suppress）**：
施加时执行清空处置（清词条〔除「被抑制」自身——含被压制/防护等其他施加物、字面全量〕／清修饰器／防御复位〔若上限＞当前则复位至上限、损伤清零〕／清额外效果）；「被抑制」标记保留供条件查询；「无法被抑制」＝施加前资格判定。
_Avoid_: 沉默、禁用


**压制（Suppressed）**：
不能移动或攻击；施加后首先到来的「拥有者回合」结束时解除（剩余轮数承载，默认 1、可延长）；「被压制」标记保留、经移除路径清除；「无法被压制」＝施加前资格判定。
_Avoid_: 钉住、封锁

**动员（Mobilize）**：
友方回合开始 +1/+1 的成长机制；受到伤害（实际承伤＞0）后失去词条、**既得加成保留**；「失去动员」对外观察面留后续（自身能力可经 OnRevoke 承载）。
_Avoid_: 激励、集结


**重甲（Heavy Armor）**：
受到的对战伤害 -X（攻击+反击均含；下限 0、值封顶 3）；与免疫同属伤害结算环节介入；「无视重甲」「重甲作用于指令伤害」为预留开关（默认关闭）。
_Avoid_: 护甲、减伤层

**情报（Intelligence）**：
使对手 X 张手牌明牌（值封顶 3）；触发结构＝「被使用时」（推断口径）；明牌执行依赖 G18——本批结构就位、执行申报。
_Avoid_: 侦察、探牌


**免疫（Immune）**：
仅拦截伤害（全来源、结算 handler 前归零）；非伤害效果照常；不限制索敌；单位与 HQ 同一归零机制。
_Avoid_: 无敌、霸体

**防护（无法被压制／无法被抑制）**：
可授予标记（词条体系承载）；压制/抑制施加前按对位防护做资格判定（同一判定族）；有防护＝拒绝且无副作用。
_Avoid_: 抗性、免控


**词条标识字面（对外契约）**：
机制名＝压制/抑制（非强制注册）；状态标识＝被压制/被抑制；词条标识＝动员/钳击/预报/免疫/重甲/情报；防护标识＝无法被压制/无法被抑制；参值书写＝「标识+数字直连」（如 重甲2），数据面＝结构化字段（不引入字符串解析）。
_Avoid_: 英文名混写、分隔符

### Decisions（A4 · 轮 1：亡计结算步）

- **死亡流程次序**：槽位释放 → 置毁 → **亡计结算** → 词条注销 → 修饰清理 → 钳击通知 → 效果卸载 → 位置置空 → card.died（除新增亡计结算步外，各步位置保持现状）。

### Decisions（A4 · 轮 2：亡计授予与执行面）

- **授予形态**：亡计＝注册内建词条；"获得亡计"＝"标识＋内容载荷（内嵌效果体，以实例为基准、随词条生灭）"；参值位对亡计无语义。
- **执行面（单源·硬性）**：死亡结算与再触发共用同一执行面（驱动内部效果动作一次、不经订阅面）；统一上下文（宿主卡＋引擎引用；宿主状态随语境）；动作约定＝无交互、可同步完成。


### Decisions（A4 · 轮 3：再触发执行体与目标语义）

- **再触发执行体**：部署＝重放"部署效果段"（部署逻辑条目按登记序；不含单位化/入槽/链级信号/打出收尾）；亡计＝亡计执行面驱动（单源）。
- **目标与信号**：目标＝在场存活单位（亡计按"行为态"、死者排除）；再触发本身不发链级信号；遵循对局门禁（终局零副作用）；逐条异常隔离；统一机制（链类型参数化）。


### Decisions（A4 · 轮 4：发布面与处理边界）

- **发布语义**：发布—接收—执行同一同步链（P2，返回即完成）；单卡请求、批量＝调用方遍历；发布入口＝效果作者可达公共面；请求更新＝机制内部导航（非对外契约）。
- **处理边界**：重复请求各执行一次（非幂等）；嵌套继承既有口径（同卡同链最小自重入防护；跨卡循环＝作者责任）；非法输入分层（结构性＝防御异常，状态失效＝忽略）。


### Decisions（A4 · 轮 5：部署逻辑生成面）

- **生成面**：装配方程序化提供条目（已构造逻辑；不扩卡定义）；装配链加载期生成并挂载部署组件（原设想落实）；手动登记并存。
- **边界**：本批＝机制面（生成通道＋装配接线＋端到端验证）；内容层（逐卡部署效果编码）不在本批。


### Decisions（A4 · 轮 6：声明一致性与验收精度）

- **声明与空内容**：内容只经运行时授予通道提供（定义期声明与内容无关）；声明"亡计"合法；空内容＝合法静默（对齐"空 handler 条目"口径）；亡计不打对战词条标。
- **验收与授权**：时序＝"死亡前可观察状态"清单逐项断言；路径＝端到端必须（形态记录）；必须用例＝反例/重入/隔离/空内容/归零正例；既有测试可受控变更（记录旧→新）；FilesToModify＝预期清单。


### Decisions（A4 · 轮 7：部署侧单源与接口宽严）

- **部署侧单源（硬性）**：部署效果段重放与部署链①段共享同一执行实现（打出路径观察面保持既有）；顺序语义两处唯一（登记序）。单源＝内部实现（不改"现状模式"）。
- **接口宽严与测试**：结构性非法＝明确异常；实现以类型收窄使情形不可达＝允许申报（"不可达即更严格保证"）；失效忽略＝必测；重入"跳过"＝必测、"记录"形态自由。
