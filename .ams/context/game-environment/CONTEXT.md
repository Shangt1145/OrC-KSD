# 游戏环境（KARDS 模仿）

Orc 触发器引擎之上的游戏逻辑域（Orc.Game）；第一批＝对局骨架（集合类/卡牌库/战场/玩家/对局 Match/回合体系）；第二批分三阶段（2A 结构层 / 2B 打出链 / 2C 指挥与词条），KARDS 规则为对齐基线。

## Language

**对局（Match）**：
带状态机的对局聚合根——创建（准备态）→ Initialize()（进行态）；承载双玩家、回合序、战场与管理器群。
_Avoid_: 战斗、战役

**管理器群**：
回合 / 玩家 / 战场 / 资源 / 卡牌库五个管理器；单领域单一真源，Match 只协调转发（转发只读、不复制状态）。
_Avoid_: 控制器、服务层

**回合五连**：
turn.end.before → turn.end → turn.start.before → turn.start → turn.start.after 五条阶段信号更新，经总线按序 Emit。
_Avoid_: 回合事件、阶段回调

**信号先行、处理随后**：
turn 系列为阶段信号；开始处理（结算→抽牌）位于 turn.start 与 turn.start.after 之间；结束处理（结束方点数清零、槽保留）位于 turn.end 之后。
_Avoid_: 钩子处理、回调顺序

**指挥点结算**：
槽+1（至上限，默认 12、可配置）→ 点数＝槽值；初始槽 0/点 0；回合结束不保留（结束方点数清零、槽保留）。
_Avoid_: 资源累积、补满机制

**起手装载**：
先手 4 / 后手 5，静默（不发任何更新）；从洗牌后的卡组抽取（2A 起加载先于起手、抽取已加载实例）。
_Avoid_: 初始手牌、开局发牌

**抽牌链路**：
卡组取首张并移除 → 加入手牌（2A 起实例在加载期生成）；回合抽牌连发 card.drawn → card.hand.add，起手静默不发。
_Avoid_: 摸牌、抓牌

**卡组（CardList）/ 手牌（CardSet）**：
卡组＝可重复、有序、可洗的卡牌集合（计数语义＝剩余可抽张数；2A 起初始化加载后承载已加载实例）；手牌＝引擎卡牌实例集（保序、拒绝同一实例重复归属）。
_Avoid_: 卡池、持牌区

**卡牌定义 / 卡牌库**：
定义＝名称＋四项基础数值（2A 起可区分三类卡）；卡牌库＝id→定义的注册表（注册/查询/实例化），实例化产出三类卡之一（CardBase 子类）＋拆分数据组件。
_Avoid_: 卡表、模板

**数据组件全集（2A）**：
指挥点花费（部署费单列）／对战（行动费/攻击力/防御力＝只读基准）／单位（位置〔Slot 引用〕/已毁/类型枚举列表/三实时值＝运行值）／指挥（可移动/可攻击）／词条（标识登记列表；数值由效果模块维护）／反制激活；原四合一「基础数据组件」退役。
_Avoid_: 基础数据组件、四合一属性表、数值面板

**卡牌加载（对局开始加载）**：
初始化固定链一环——对双方卡组（洗牌后、玩家索引升序）逐张执行卡牌基类加载模板并广播 card.load；加载实例＝后续起手/抽牌所用同一实例。
_Avoid_: 初始化装载、牌库预热

**卡牌基类（CardBase）**：
三类卡（单位卡 UnitCard / 指令卡 CommandCard / 反制卡 CounterCard）的抽象基类；承载加载模板、子类重写点与触发器声明位（单位/指令＝预打出＋打出；反制＝使用反制的触发器）。
_Avoid_: 卡牌模板、卡类

**战场三线**：
玩家A 支援线 / 前线（中立共享）/ 玩家B 支援线；各自固定归属；2A 起槽位化（Slot 序列、容量 4/5/4）；初始化后支援线含 HQ 占位（槽 0）、其余空；「敌线」＝视角称呼（不改名、不引入新对象）。
_Avoid_: 阵线、区域

**HQ**：
玩家纯数据（20 血、可读、无修改入口）；2A 起占支援线槽 0（占用者＝Player 引用、占容量格、参与邻位计算）。
_Avoid_: 主基地、大本营

**槽位（Slot）/ 邻位动态候选**：
槽位＝线内固定位置＋占用者（单位/总部/空）；邻位动态候选＝遍历线内被占槽位（含 HQ）、取左右空邻位、去重、索引升序——部署/移动候选位。
_Avoid_: 格子、位置表

**更新常量类（14 条）**：
turn 五连＋card.played / card.drawn / card.stat.changed＋2A 六项（card.load / card.hand.add / card.died / unit.joined / unit.deployed / unit.position.changed）；字面值为对外订阅契约（冻结）。
_Avoid_: 事件枚举、Hook 名称表

**准备 / 进行**：
对局两态；准备＝已创建未初始化（无管理器/无玩家/无更新）；进行＝初始化完成、可推进回合。
_Avoid_: 等待态、运行中

**Targeter（指示器）**：
对局内目标选择的请求对象（筛选器＋可缺省槽位）；唯一发起入口＝其 Targeting() 异步方法。
_Avoid_: 选择器、指示器组件

**Targeting（目标选择执行）**：
一次目标选择流程——入队 → 桥接收集候选 → 粗筛 → 细筛 → 桥接交互 → 终局（恰好一次）；结局三态不抛。
_Avoid_: 选择流程、目标选择

**TargeterManager**：
Targeter 的 FIFO 串行执行队列（一次一个、终局后出队下一条）；对局管理器群第六员。
_Avoid_: 调度器、目标管理器

**目标桥接（Bridge）**：
前端实现的后端↔前端通道：候选收集 ＋ 交互（Begin／Complete／Cancel，请求标识配对）。
_Avoid_: 适配器、前端代理

**粗筛 / 细筛**：
两级过滤——粗筛批量式（完整引用列表 → 允许子集）；细筛单引用谓词逐项（在粗筛结果上）。
_Avoid_: 过滤规则层、预筛

**置黑**：
前端对未返回项／被淘汰项的显示处理；后端只产出"允许什么"、不负责显示语义。
_Avoid_: 禁用、灰显、可用性标记

**触发器分层（底层/外部）与注册表**：
底层触发器＝引擎初始化注册、与 UI 沟通并触发更新；外部触发器＝业务层；对局级注册表＝只记账（登记触发器＋分层分类、按分层枚举）、与运行解耦（不做强拦截、靠自觉）。
_Avoid_: 触发器管理器、事件表

**事件装配 / 注册表登记**：
事件装配＝向触发器自身注册事件 handler；注册表登记＝游戏层分层注册表登记（对象＋分类）——2A 术语区分，避免混用。
_Avoid_: 触发器注册（歧义用法）

**打出链（Play Chain）**：
三类卡生效流程的结构总称——单位/指令＝两段式（预打出＋打出）；反制＝「使用反制的触发器」单入口状态翻转（激活↔取消）。
_Avoid_: 出牌流程、释放链

**单位化（Unitification）**：
部署/加入两条入场路径共用的后半段（挂单位数据＋指挥组件、实际入槽）；部署与加入以 unit.deployed / unit.joined 区分。
_Avoid_: 入场化、实体化

**槽位引用（Slot Reference）**：
让槽位以引用形态进入 targeter 候选/产出面的承载（2B 受控变更引入）——「选中空槽位」的断言对象。
_Avoid_: 坐标、索引

**反击豁免**：
攻击结算中判定"目标方是否反击"的规则表——目标轰炸机永不反击；攻击者炮兵不受任何反击；攻击者轰炸机不受反击（目标战斗机例外）；多类型单位逐条套用、豁免条款优先。
_Avoid_: 特例表、免伤规则

**伏击改写**：
伏击单位被攻击时以"攻击者死亡、被攻击者不受伤"替代同时互伤的机制；成立前提＝目标方具备反击资格（豁免表通过）∧其实时攻击力＞攻击者实时防御力。
_Avoid_: 伏击反击、先制反击

**终局**：
HQ 生命≤0 当刻对局置"结束"态并记录胜者；当次结算收尾照常完成，此后全部对外动作入口拒绝、更新流冻结、只读查询保持可用。
_Avoid_: 比赛结束、Game Over

**前线占据**：
"前线不存在存活敌方单位"的实时状态判定（空线或己方已占皆然；无占据标记）；作为推进的前置条件。
_Avoid_: 控线、占线

**轰炸机拦截**：
轰炸机攻击时，目标战线存在存活敌方战斗机 → 该战线非战斗机目标（含 HQ）不可选（置黑）；跨战线目标不受影响。
_Avoid_: 制空、优先打击

## Decisions

- **装配模式**（第 1/11 轮）：调用方提供数据（卡组名单×2、定义集、[种子]、[先手]）、Match 负责装配；引擎由 Match 内部新建并公开（match.Engine）；先手默认第一位玩家；空名单创建期拒绝，不足起手走运行时抛错。
- **初始化序列**（第 1/4 轮；2A 修订）：生成管理器群 → 批量注册定义 → 创建玩家 → 洗牌（传随机源）→ 卡牌加载（逐张 card.load、洗牌后序、顺序逐位稳定）→ 起手装载（静默）→ 先手回合开始序列（3 条更新入总流）→ 置进行；API 返回即全部完结；重复 Initialize / 准备态推进抛错；加载失败＝fail-fast。
- **更新序列契约**（第 4 轮；2A 修订）：初始化＝双方卡组总数＋3（标准 43：逐张 card.load＋三连；无 card.drawn）；回合循环＝抽牌位连发 card.drawn→card.hand.add（硬性位于 turn.start 与 turn.start.after 之间）；测试断言随契约迁移（总数不减）。
- **集合边界**（第 7 轮）：空集 Draw 抛错；Insert 越界抛错；CardSet 拒重复实例；Instantiate 纯转换（空→空集 / 未注册→抛错 / 重复→独立实例、保序）。
- **可复现**（第 6 轮）：同种子＋同参 → 洗牌/起手/抽牌逐位一致（纳入测试）；种子可读；上限创建期可配（默认 12、正整数）。
- **载荷**（第 2/9 轮）：card.drawn＝{玩家, 卡牌实例}；card.stat.changed 无载荷（硬约定）；card.played 载荷后置；turn 系列＝{玩家, 回合数}（自洽即可、定型汇报）。
- **结构自由**（第 3/11 轮）：命名/密封性/文件组织实现者定型并汇报；玩家＝普通数据类（不继承引擎 Entity）；对外契约（Match 便捷属性/EndTurn 无参门禁/五管理器公开 API 面）须符合需求记录。
- **Targeter 归属与接入**（Targeter 对齐）：第六员＝TargeterManager（Match 构造可选参数注桥接、Initialize 生成、公开面读取；亦可独立构造）。
- **Targeter 三态与协议**（Targeter 对齐）：统一结果对象不抛（成功／取消／失败＋类别化原因）；一次 Begin 恰好一次终局；内容不合规＝拒绝＋留痕＋继续等待；取消仅前端 Cancel（无超时/CT）。
- **写入双模式**（Targeter 对齐）：界＝产出形态——无/单槽位＝扁平（视图 [Mutate] 写入）；多槽位＝非扁平（强类型写 ctx、按槽位名取）；类型化辅助入口必须存在且显式写入。
- **Targeter 验证口径**（Targeter 对齐）：mock 两阶段入口脚本化＋Match 端到端用例；留痕可观测并纳入断言；流程隔离纳入测试。
- **2A 加载接入**（2A 对齐）：初始化时对双方卡组逐张执行加载模板并广播 card.load（洗牌后序、玩家升序）；加载实例同一性＝验收要求（起手/抽牌所得＝加载实例）；失败＝fail-fast。
- **2A 抽牌连发**（2A 对齐）：回合抽牌连发 card.drawn→card.hand.add；起手静默不发；其他来源零调用点（入口就绪）；card.died/unit.* 为零调用点。
- **2A 数据组件与槽位化**（2A 对齐）：部署费单列＋对战三值（基准只读、无双真源、原四合一退役）；三线统一槽位化（4/5/4）；HQ 占各自支援线槽 0（占容量格）；邻位候选含 HQ 被占位、去重、索引升序；槽位越界＝明确错误。
- **2A 注册机制**（2A 对齐）：对局级注册表；登记＝本体＋分层分类（必填；重复/null 拒绝；无移除；与运行解耦）；查询＝按分层枚举（底层清单供审计，本批不建审计行为）；声明位不登记（真实登记自 2C）。
- **2A 受控变更授权**（2A 对齐）：初始化/循环序列、卡组运行时表示、Battlefield、CardStatsData 拆分均可调整（旧→新对照）；既有 Orc.Game.Tests 允许最小化适配（总数不减）。
- **2B 打出链对齐**（2026-10-03）：单位/指令＝两段式（预打出＋打出）、反制＝单入口状态翻转；预打出拒绝原因可区分（点数不足/无空槽）；单位/指令打出段前复验（反制无）；成功即完整、失败即零副作用（卡留手）；离手＝收尾扣费后。
- **2B 更新发射与费用**（2026-10-03）：部署＝card.played＋unit.deployed；加入＝unit.joined；指令＝card.played（先于主动 handler 集）；反制零更新；card.played ≠ 引擎 card.placed；扣费＝该卡花费（部署/指令收尾恰一次；加入不扣）。
- **2B 反制状态**（2026-10-03）：单入口翻转（激活↔取消）；费用＝该卡花费（激活扣、取消无条件退）；仅己方回合（＝卡所有者是当前行动方）；handler 注册/注销须可断言。
- **2B 槽位引用**（2026-10-03）：槽位以引用形态进入 targeter 候选/产出面（受控变更；形态实现层定、交付回报）。
- **2B 部署词条**（2026-10-03）：独立于词条系统（2C 接入）；按登记序触发；默认检查失败仅跳过、不中止部署；异常隔离。


- **2C 行动状态生命周期**（2026-10-03，2C 第1轮）：置 true＝闪击（部署链收尾·扣费后）＋回合恢复（turn.start 处理、作用于当前行动方在场单位〔HQ 除外〕、本批包含）；常态初值 false（部署当回合不可行动）；清除＝动作成功执行（移动清可移动、攻击清可攻击；非坦克二选一另一同清、坦克独立清；奋战按词条记账判首/次）；失败/取消不消耗。
- **2C 外层更新**（2026-10-03，2C 第1轮）：两 bool 法定写入点全集＝指挥流程外层收尾／部署链收尾（闪击）／回合恢复；内层（移动/攻击触发器、词条）禁止写；硬约束以测试断言保证；两 bool 公开可读，动作合法性聚合判定须可公开调用（形式实现定）。
- **2C 闪击时序**（2026-10-03，2C 第1轮）：以「扣费后」为准（Q13-b）；注入/执行落点＝扣费完成之后、打出链返回之前；「部署触发器末尾」表述作修正。


- **2C 攻击范围矩阵**（2026-10-03，2C 第2轮）：步/坦＝支援线→敌前线｜前线→敌支援线与敌 HQ；支援线→敌支援线禁止；同线互攻不开（相邻＝跨线；无阻挡规则、后置）；炮/轰任意线（含 HQ）；HQ：不反击、伤害＝攻击者实时攻击力、血量写入口＝受控变更；胜负后置。
- **2C 守护与烟幕**（2026-10-03，2C 第2轮）：烟幕＝对一切攻击者生效（置黑）、不限制自身行动；守护＝同线槽位相邻（跨线不计）、保护计入 HQ、多守护不叠加、守护者不可被守护；被守护维护须覆盖一切影响支援线布局的变动（至少 position.changed），防陈旧。


- **2C 移动口径**（2026-10-03，2C 第3轮）：仅推进（支援线→前线）；目标＝前线任意空槽（不受邻位规则约束——邻位为支援线部署专用，避免空前线推进死锁）；仅支援线单位可动；后撤/横移后置；原槽变空并参与邻位计算；成功＝移槽＋position.changed 恰一次＋扣费＋外层清位；失败/取消零副作用。
- **2C 行动费用**（2026-10-03，2C 第3轮）：每动作各扣 1 次实时行动费、自当前行动方扣；双层验证（发起判定〔动作级拒绝〕＋执行前复验）、ValidationRejected 表意、零副作用＋留痕；时序＝执行成功→收尾扣费恰一次；与 bool/矩阵并行聚合判定；被隔离异常视为已执行。


- **2C 攻击结算**（2026-10-03，2C 第4轮）：互伤同时（互扣前实时值基准；同归于尽双方 card.died 均发、固定序〔被攻击者→攻击者〕）；死亡清理最小口径＝槽位释放／IsDestroyed／card.died 恰一次／已挂载效果注销／Position 置空·实例保留可查询；死亡不发 position.changed（被守护维护走等效内部触达）；死亡单位不参与后续指挥/筛选。
- **2C 造成攻击伤害与伏击**（2026-10-03，2C 第4轮）：对局级内置共享流程触发器（单位 vs 单位攻击必经）；默认＝基础互伤；伏击＝目标侧、加载时注册；比较＝互扣前实时值，成立→攻击者统一死亡流程＋被攻击者无伤，否则正常；HQ 攻击不走该流程（直接扣血）。

## 决策摘要（后置项补全，2026-10-04）

- **反制位置（终态）**：不做「激活区」；激活/取消＝状态翻转＋费用（激活扣、取消无条件退；各恰一次、可反复、仅己方回合）；卡保持手牌位置不变（锁定）。
- **移动（终态）**：只做推进（支援线→前线；候选＝前线空槽）；不做后撤、不做横移；普通单位（位于己方支援线）的指挥 targeter 目标范围＝前线。
- **战斗补全（终态）**：反击豁免判定表（轰炸机防御不反击；炮兵/轰炸机攻击不受反击〔目标＝战斗机例外〕）；HQ≤0 立即终局（全动作门禁）；前线占据前置＋轰炸机拦截。


- **豁免×伏击仲裁（终态，后置项）**：**豁免约束改写**——先判目标方反击资格（无资格→改写不成立、按表单方结算）；有资格再判伏击条件（命中改写：攻击者死亡、被攻击者不受伤；不命中按表互伤）；多类型单位＝逐条套用豁免表、冲突时豁免（不反击）优先。


- **终局语义（终态，后置项）**：HQ≤0 → 判定于伤害结算点、当刻置结束＋胜者；当次结算收尾照常完成（不经门禁）；此后零新处理/零新更新、全部对外动作入口拒绝（含 Targeter 发起）、只读面可用；不发终局通知、不处理平局。


- **前线阻挡（终态，后置项）**：推进前置＝"前线不存在存活敌方单位"（候选剔除＋执行复验、实时恢复）；轰炸机拦截＝目标战线存在存活敌方战斗机时该线非战斗机目标（**含 HQ**）不可选（仅轰炸机、候选＋确认全程、多条无优先级）；部署/加入不直接受推进前置约束（边界已记录）。


- **后置项验收深度（终态，2026-10-04）**：适配授权＝仅 Orc.Game.Tests、迁移非删除、总数不减、旧→新对照；覆盖口径＝判定表每规则分支≥1 用例＋伏击三态＋多类型两例＋终局门禁六类逐一＋更新流冻结/重复查询稳定断言；防回归锁定＝负面/不变式断言（候选不含支援线内部与同线产物、卡位置不变性、费用对账）；回归＝三项目全绿；汇报含验收矩阵表（验证点→测试名→断言摘要）。
