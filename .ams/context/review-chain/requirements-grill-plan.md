## 已决问题

### Q1: 审查链的"链"语义 Completed
- 决策：**a —— 仅声明期静态图**；运行期实际调用链由 `EventStream` / `EventStreamJson` 承担。

### Q2: 序列化的往返目标与逻辑本体表示深度 Completed
- 决策：**不做完整的序列化和反序列化**；触发器/hookID 引擎提供、作引用基础；视图仅单向快照；**效果双向**（快照 + 反序列化 + 运行时加载/计划）。

### Q3: 序列化的使用场景 Completed（并入 Q2）
- 决策：运行时加载/计划（效果快照 → 反序列化 → 装载计划 → 装配）；视图侧 = 审查导出。

### Q4: 标识空间与"对局内不变"的粒度 Completed
- 决策：**a —— 定义级标识**。TriggerId 标识"触发器种类/定义"；hookID = hook 规范标识；实例以 (TriggerId, 宿主) 定位。效果快照可跨对局复用；链节点 = 触发器种类。

### Q5: 效果序列化对"主动效果"的形态 Completed
- 决策：**a —— 纯动作型声明**。主动效果快照 = 主触发器(Active) + 施放事件的 handler 预制体 + moding，**无"挂载 HookID"段**；施放入口沿用既有 `ActiveEffect.CastAsync` / `ICastAction`。
- 补充语义（用户）：**主动触发器可被其它新增的被动触发器调用** —— 即"handler 声明的下游边"允许指向主动触发器。

### Q6: "预制体"定义与 handler 逻辑来源 Completed
- 决策：**采用 CSX**（逻辑可文本化）；新增**预制体管理器**（从程序集 + 动态挂载 csx 获取委托、统一管理、支持 moding）。
- 基线：csx 属项目已规划后置项（`触发器引擎原型/需求.md:22,34,36`）；全仓无 Roslyn 依赖，需新增 satellite 工程。

### Q7: 管理器与工程承载位置 Completed
- 决策：**a —— 内核登记 + satellite 执行（接口倒置）**。编排管理器与预制体管理器落在**内核 `Orc`**；游戏层只负责注册；csx 执行另开 satellite（如 `Orc.Script`，**不引用 Orc**，脚本经 `ScriptOptions` 引用 `Orc.dll`），内核经 `IScriptEvaluator` 接口注入、保持零包依赖。

### Q8: 审查链的覆盖范围与起点 Completed
- 决策：**c —— 全域**。起点 = 引擎 hook 锚点 + 全部触发器（引擎内置 + 卡上 + 效果 + 动态）+ 全部效果（被动/主动/未装载）+ 词条内嵌效果 + 预制体/动态效果。

### Q9: 预制体的形态与作用域 Completed
- 决策：**三层都要** —— 效果预制体 → 引用 → 触发器预制体 + handler 预制体；支持定义动态效果/触发器/handler；实例化时**从文本重建"携带完整逻辑的动态效果"**。

### Q10: csx 的信任/沙箱边界与运行时约束 Completed
- 决策：**b —— csx 面向社区**，采用 **SecureCSharpEval** 方案（尽力安全）+ **要求社区明文储存 csx**（提升可审计性）。
- 核实：SecureCSharpEval = **同进程 Roslyn + 命名空间白/黑名单 + 关键字文本过滤 + 超时**的**弱沙箱**（非进程隔离、可绕过、无第三方审计、License 未标注）；明文储存只提升透明性、不提升执行期安全。
- 后置加性项：**进程级隔离**（独立进程 + OS 资源限制 + 禁网 + 最小权限），或社区退回 `Orc.Lua` 硬沙箱。

### Q11: csx 源码 / 预制体在效果快照中的承载方式 Completed
- 决策：**c —— 混合**。内置预制体（程序集来源、无文本）走**引用**；动态/社区预制体（csx）走**内联**（自包含、可离线重建、利于审查）。

### Q12: moding 与预制体的关系及可序列化性 Completed
- 决策：**a —— 纳入快照**。快照可声明 moding 项 `{目标 = 预制体内某注册项, 替换逻辑 = handler 预制体}`；实例化时重建 moding 栈（保留运行期注销、回退基础逻辑的语义）。

### Q14: 审查链的输出形态 Completed
- 决策：**c —— JSON 真源 + 派生文本视图**。编排管理器导出结构化 JSON（节点-边真源，供工具/UI/比对），再由其派生人类可读文本视图。

### Q17: 程序集来源预制体的发现方式 Completed
- 决策：**a —— 显式注册 API**（装配期逐条 `RegisterPrefab(id, 委托/工厂)`，对齐 `CardEffectRegistry.Register`）。

### Q13: 动态触发器与 hookID 的边界 Completed
- 决策：**b + c 并用** —— hook 空间开放（动态触发器可声明新 hook，首次登记即固化）+ 保留自由字符串语义 + 提供 **hook 名 ↔ hookID 互转**。
- 衍生（实现级，记入 implementation-grill）：hookID/TriggerId 的生成方式（确定性派生 vs 顺序分配）与稳定域。

### Q15: 动态效果与现有 C# 效果体系的关系 Completed
- 决策：**a —— 加性并存**。现有 C# 效果（`DeathrattleEffect` 等）与测试保留不动；动态效果为新类别（预制体 + csx 实例化为 `Effect` 包装），进既有 `Card.Effects` + 装载链；预制体管理器与 `CardEffectRegistry` 并存。
- 补充（用户）：**后续做卡一律采用预制体**；现状保留。

### Q16: 预制体的来源与分发 Completed
- 决策：**a —— 本地明文目录 + 显式注册；只做本地分发**（不做在线仓库）。内置预制体经显式 API 注册（装配期）；社区预制体 = 本地明文文件目录（效果/触发器/handler 声明 + csx），运行时扫描加载。

- 仲裁：不保留"编排层"（避免与 CONTEXT"触发器＝编排单元"两义）；"handler 预制体"改称"**事件预制体**"；"动态 handler"按**来源**消歧（csx / Lua）。
