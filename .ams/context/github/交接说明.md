## 四、本机环境事实（踩坑集中区）

1. **Git 不读取 Windows 系统代理**。本机代理为飞鸟加速器（`C:\Program Files\飞鸟加速\core.exe`）。不显式指定代理时直连 GitHub 会失败：`Recv failure: Connection was reset`。
   - **代理端口是动态的，勿硬记**：同日实测 `20955` → `21601` → `24450`（加速器重启／`core` 进程更替即换，前面的端口会直接失效）。
     **不要抄历史值，每次现场枚举**：
     1. 取候选进程号：`Get-Process | Where-Object { $_.ProcessName -match "^(core|飞鸟加速)$" }`（进程名 `core` 的那个才是代理）。
     2. 枚举其监听端口：`netstat -ano` 过滤 `127.0.0.1:<port> ... LISTENING`，且末列 PID 属于上一步。
     3. 逐个验证：`git -c http.proxy=http://127.0.0.1:<port> -c https.proxy=... ls-remote origin`，**返回哈希即可用**。
     实测判别特征（都不是断网）：`CONNECT tunnel failed, response 404/405`＝端口在监听但不是 HTTP 代理；
     `Failed to connect ... Could not connect to server`＝该端口已失效。`12345`（飞鸟加速主进程）常返回 `404`，别浪费时间。
   - 当前处置：推送时临时附加 `-c http.proxy=<port> -c https.proxy=<port>`（见 SOP）。
   - 待决：是否固化到 git 配置（见第八节 I4）。**注意**：端口动态意味着「固化」本身有失效风险。
2. **认证已就绪**：Git Credential Manager（`credential.helper=manager`），凭据已缓存，通常**不需要重新登录**；若需重新授权，`push` 会弹出浏览器登录窗口。
3. **`core.autocrlf = true`**（Git for Windows 默认）：入库为 LF、检出为 CRLF，`LF will be replaced by CRLF` 警告属正常。
4. **中文提交信息**：不要用 `git commit -m "中文"`（PowerShell 传参可能造成编码失真）。改用 UTF-8 文件承载：`git commit -F .git/COMMIT_MSG.txt`。
5. 环境为 Windows PowerShell（非 bash）；`git` 版本 2.53。

- `.ams/` 下 `context/` 以外的子目录：`skills/`、`packages/`、`versions/`
- .NET 构建产物与 IDE 本地状态：`**/bin/`、`**/obj/`、`.vs/`、`TestResults/`、`*.user`、`*.suo`

### `.gitignore` 设计说明（勿随意改动）

```gitignore
/ams/                 # 整体排除：含明文密钥与 68MB 二进制
/.ams/*               # 默认全部排除
!/.ams/context/       # 仅放行 context（agent 产出的文档成果）
/outputs/             # 过程性输出：随时可再生成
**/bin/               # .NET 构建产物
**/obj/
.vs/
TestResults/
*.user
*.suo
```

`.ams` 采用「**默认拒绝 + 白名单放行**」：将来 `.ams` 下新增任何工具目录都自动不入库，比逐个列黑名单安全。

### 判定原则

**产出入库，过程不入库。** 一个文件要入版本控制，先问：它是「成果」还是「随时可再生成的中间物」？后者一律排除（`bin/obj`、`outputs/`、抓取快照、缓存）。

## 六、标准操作流程（SOP）

```powershell
# ① 逐项审查（强制步骤，不要跳过、不要无脑 git add -A）
cd d:/OrC-KSD
git status --porcelain -uall
#    对每个条目判定归属：
#      src/  tests/  docs/  .ams/context/  .ams-docs/  根目录 md   → 允许
#      ams/  outputs/  bin/  obj/  .vs/  *.user                    → 不得入库（应由 .gitignore 挡住）
#    若出现「未预期的路径」（某个 agent 新造的目录、来源不明的文件），
#    先向用户汇报再做决定，不要自行提交。
#    若 .gitignore 挡住后仍有敏感文件出现在清单里，立即停止并汇报。

# ② 暂存（按①的判定挑路径；仅当清单全数为允许项时才用 git add -A）
#    已知需手工排除（三者都在 .ams-docs 下、.gitignore 覆盖不到，必须显式拉出）：
#      **/_tools/、**/tools/            抓取/同步脚本、构建日志、上游源码快照
#      **/isolate/                      整目录实验副本（可能含 ams/ 明文密钥与嵌套 .git）
#    更稳的做法：不用 git add -A，改为显式 git add <允许的路径>。
git add -A
git reset -q -- "**/_tools" "**/tools" "**/isolate"

# ③ 提交前安全校验 —— 必须**单独执行并亲眼看输出**，确认空之后才执行④
#    （反面教材：把③④串在同一条命令里无条件跑，曾把 _tools/isolate 一起提交进本地提交）
git diff --cached --name-only | Select-String -Pattern "/(bin|obj)/|^ams/|^outputs/|\.exe$|_tools/|/tools/|/isolate/|kards"

# ④ 提交（中文信息走 UTF-8 文件承载；该路径不会被版本控制）
git commit -F .git/COMMIT_MSG.txt

# ⑤ 推送（必须带代理参数；<port> 见第四节——端口动态，每次先现场确认）
git -c http.proxy=http://127.0.0.1:<port> -c https.proxy=http://127.0.0.1:<port> push

# ⑥ 验证本地与远程一致
git -c http.proxy=http://127.0.0.1:<port> -c https.proxy=http://127.0.0.1:<port> ls-remote origin
git status -sb    # 期望：## main...origin/main（无差异）
```

提交信息约定（沿用现有风格）：

- 初始化/环境类：`chore: ...`
- 新功能/新代码：`feat: ...`
- 文档类：`docs: ...`

## 七、排障对照表

| 现象 | 根因 | 处置 |
|---|---|---|
| `Recv failure: Connection was reset` | git 未走代理（直连被重置） | 命令加 `-c http.proxy=http://127.0.0.1:<port> -c https.proxy=...`（端口现场探测，见第四节） |
| `403 Permission to ... denied to <user>` | collaborator 邀请未接受，或加错了账号 | 被邀请人登录 GitHub 打开 `https://github.com/Shangt1145/OrC-KSD/invitations` 接受；或请所有者核对 `Settings → Collaborators` |
| `401` / 要求登录 | 凭据失效 | 按弹窗重新完成 GCM 浏览器授权 |
| 刚提交完 `git status` 又有改动 | 主力 agent 正在并发写入 | 正常现象，重新执行 SOP 即可 |
| `LF will be replaced by CRLF` | `core.autocrlf=true` | 正常，无需处理 |
| 提交信息显示乱码 | 用了 `-m` 传中文 | 改用 `-F .git/COMMIT_MSG.txt` |
| 清单里出现 `outputs/`、大体积快照 | 忽略规则失效或用了 `git add -f` | 检查 `.gitignore`；必要时 `git rm -r --cached <路径>` 停止跟踪（本地文件保留） |
| `Failed to connect to github.com port 443 via 127.0.0.1` | 代理端口已变（加速器重启换端口） | 按第四节方法重新枚举端口；**不要沿用上一次记下的端口** |
| `CONNECT tunnel failed, response 40x` | 该端口在监听但不是 HTTP 代理（API/控制端口） | 换端口重试，勿误判为断网 |
| `status` 显示 `ahead N`、`log` 里有自己没有的提交 | AMS 自行提交了 | 按第二节审计这些提交的红线，干净则直接 `push` |

