## 四、本机环境事实（踩坑集中区）

1. **推送通道：直连优先，代理兜底**（2026-10-09 修订）。本机装有飞鸟加速器 `C:\Program Files\飞鸟加速\core.exe`。
   - **代理未运行**（无 `core`/`飞鸟加速` 进程）→ **直连可用**：2026-10-08 实测 `git ls-remote` 与 `git push` 直连均成功。
   - **代理在运行** → Git **不读取 Windows 系统代理**，需显式指定端口，否则直连报 `Recv failure: Connection was reset`。
   - 结论：**先试直连，失败再探测端口**。旧版本"必须先探端口"的说法已作废（原第四-1 条）。
2. **代理端口是动态的**（仅在需要代理时探测）。实测一天内变过多次：`20955` → `21601` → `24450` → `20293` → `21589` → `19027` ……**旧端口会直接失效，不要抄历史值**。

   探测三步（每步都有实测依据）：

  ```powershell
  # 1) 取候选进程号（进程名 core 的才是代理；飞鸟加速主进程 12345 端口不是 HTTP 代理）
  Get-Process | Where-Object { $_.ProcessName -match "^(core|飞鸟加速)$" } | Select-Object ProcessName, Id
  # 2) 枚举其监听端口：netstat -ano 里 末列 PID 属于上一步、且 127.0.0.1:<port> LISTENING
  # 3) 逐个验证，返回 40 位哈希即可用：
  git -c http.proxy=http://127.0.0.1:<port> -c https.proxy=http://127.0.0.1:<port> ls-remote origin refs/heads/main
  ```

   实测判别特征（**都不是断网**）：`CONNECT tunnel failed, response 404/405`＝端口在监听但不是 HTTP 代理；
   `Failed to connect ... Could not connect to server`＝该端口已失效；偶发 `schannel: failed to receive handshake`（TLS 抖动）→ 重试一次或换端口即可。
3. **认证已就绪**：Git Credential Manager（`credential.helper=manager`），凭据已缓存，通常**不需要重新登录**；若需重新授权，`push` 会弹出浏览器登录窗口。
4. **`core.autocrlf = true`**：入库为 LF、检出为 CRLF，`LF will be replaced by CRLF` 警告属正常。
5. **中文提交信息**：不要用 `git commit -m "中文"`（PowerShell 传参可能编码失真）。用 UTF-8 文件承载：信息写进 `.git/COMMIT_MSG.txt`（该路径不在版本控制内），再 `git commit -F .git/COMMIT_MSG.txt`。
6. **中文路径**：`git status`／`git diff` 默认会把非 ASCII 路径转成八进制转义（`\346\226...`）。
   **加 `-c core.quotepath=false` 才可读**；`git diff --name-only` 里含中文的路径会带双引号，做匹配前先 `Trim('"')`。
7. **文本文件编码**：`.gitignore` 与多数文档为 **UTF-8 无 BOM**。用 `Get-Content` 直接读会显示乱码（PS 5.1 按 ANSI 解析），**读中文文件加 `-Encoding UTF8`**；写文件用 `[System.IO.File]::AppendAllText($p,$s,(New-Object System.Text.UTF8Encoding($false)))` 以避免加 BOM。
8. 环境为 Windows PowerShell（非 bash）；`git` 版本 2.53。**不要用 `cmd /c` 包裹命令**（在本环境的命令包装下会污染后续语句的解析）。
9. **`.git/worktrees/verify-worktree` 残留**（2026-10-05）：`.git/worktrees/` 下留有一个**访问被拒**的空登记（疑似被进程句柄占用）。
   影响：**无**（不进版本控制、不影响提交/推送/克隆）。处置：占用释放后 `git worktree prune`；不必为它折腾。

## 六、标准操作流程（SOP）

```powershell
cd d:/OrC-KSD

# ① 审查（强制，逐项判定归属；不要无脑 git add -A）
git status -sb
git --no-pager log --oneline -5
git -c core.quotepath=false status --porcelain -uall    # 必须 quotepath=false，否则中文路径不可读
#    允许：src/ tests/ samples/ docs/ .ams/context/ .ams-docs/（仅 md） 根目录文档
#    不得入库：ams/ outputs/ bin/ obj/ .vs/ *.user、.ams/sealed/ 及第五节的扣下项
#    出现「未预期的路径」（新造的顶层目录、来源不明文件）→ 先汇报再做决定

# ①b ⚠ 探测远程（必做，防 remote-tracking 过期；见第三、七节）
git ls-remote origin refs/heads/main        # 与本地 HEAD 比较；不一致则先 git fetch 再看
git fetch origin main                        # 若远程超前：可 ff 就 ff，不可 ff 见第七节

# ② 暂存：优先显式路径（最稳），只在必要时才 git add -A
git add src tests samples OrcEngine.sln                 # 代码
git add docs .ams-docs .ams/context CONTEXT.md .gitignore  # 文档 / 忽略规则
#    过程物现已由 .gitignore 自动排除，无需再手工 reset

# ③ 提交前校验 —— **必须单独执行并亲眼看输出**，两段都空才可提交（纵深防御，规则之外的兜底）
#    a) 白名单（主）：凡不落在允许前缀内的一律列出，宁多报不漏报
$allow = @('^src/','^tests/','^samples/','^docs/','^\.ams/context/','^\.ams-docs/','^(OrcEngine\.slnx?|CONTEXT\.md|USER\.md|PROJECT\.md|COMMUNICATION\.md|RULE\.md|\.gitignore)$')
git diff --cached --name-only | Where-Object { $p = $_.Trim('"'); -not ($allow | Where-Object { $p -match $_ }) } | ForEach-Object { "越界待确认: $_" }
#    b) 黑名单（辅，注意误报）：用「官方卡牌」而不是「kards」——后者会误伤 kards-game-layer、kards-diy-*
git diff --cached --name-only | Select-String -Pattern "/(bin|obj)/|^ams/|^outputs/|\.exe$|_tools/|/tools/|/isolate/|verify_|_work/|_tmp/|_probe/|tmp-probe|官方卡牌|^scripts/"
#    b2) .ams-docs 只应有 md（规则已保证，此处复核）
git -c core.quotepath=false diff --cached --name-only | Select-String -Pattern "^\.ams-docs/" | Where-Object { $_ -notmatch "\.md" }
#    c) 目录级核对：逐任务目录看文件数，数量异常（几十上百）即疑似副本
git -c core.quotepath=false diff --cached --name-only | ForEach-Object { $p = $_.Trim('"'); ($p -split '/')[0..2] -join '/' } | Group-Object | Select-Object Count, Name

# ④ 提交（信息先写入 .git/COMMIT_MSG.txt，UTF-8；该路径不受版本控制）
git commit -F .git/COMMIT_MSG.txt

# ⑤ 推送：先试直连，失败再探测代理端口（<port> 不是固定值）
git push
#  若报 Recv failure: Connection was reset → 按第四节探测端口后：
git -c http.proxy=http://127.0.0.1:<port> -c https.proxy=http://127.0.0.1:<port> push

# ⑥ 核验（三条都要过）
git ls-remote origin refs/heads/main    # 远程哈希
git rev-parse HEAD                      # 与本机 HEAD 一致
git status -sb                          # 期望 "## main...origin/main"（无差异、无 ahead）
```

**误提交的补救**（仅在**未推送**时）：`git reset --mixed HEAD~1` 撤销本地提交、工作区内容保留，修正后重新走②③④。
（已推送的提交**不要**改写历史：公开仓库不可逆，宁可补一次更正提交。）

**别人先推了（远程超前）**：
1. `git fetch origin main` → `git merge-base origin/main HEAD` 判断关系；
2. 若能快进（远程是本地祖先）→ `git merge --ff-only origin/main`；
3. 若已分叉（本地有未推送提交）→ **先 `git merge-tree --write-tree origin/main HEAD` 做非破坏冲突探测**，无冲突再 `git rebase origin/main`；有冲突则停下汇报，**绝不 force push**。

**提交粒度与信息风格**：

| 类型 | 前缀 | 内容 |
|---|---|---|
| 初始化/环境 | `chore:` | 忽略规则、工程范围、环境处置 |
| 新代码 | `feat:` | 新增工程/机制/测试 |
| 文档 | `docs:` | 需求/实现文档、上下文、registry、交接说明 |

主体用「`- 要点`」列表描述，`-` 后可换行续写；一次同步通常产出 2~3 个提交（代码、文档，必要时加一个交接文档更新）。

## 七、排障对照表

| 现象 | 根因 | 处置 |
|---|---|---|
| `Recv failure: Connection was reset` | 代理在运行但 git 未走代理 | 先试直连；不行则按第四节探测端口后带 `-c http.proxy=... -c https.proxy=...` |
| `Failed to connect to github.com port 443 via 127.0.0.1` | 代理端口已变 | 重新枚举端口，**不要沿用上次的值** |
| `CONNECT tunnel failed, response 40x` | 端口在监听但不是 HTTP 代理 | 换端口，勿误判为断网 |
| 偶发 `schannel: failed to receive handshake` | 代理侧 TLS 抖动 | 重试一次；`push` 已成功时以 push 输出 + `status -sb` 为准 |
| `403 Permission ... denied to <user>` | collaborator 邀请未接受或加错账号 | 本人登录 `https://github.com/Shangt1145/OrC-KSD/invitations` 接受；或请所有者核对 `Settings → Collaborators` |
| `401` / 要求登录 | 凭据失效 | 按弹窗重新完成 GCM 浏览器授权 |
| **`status -sb` 显示无 ahead，但 `push` 被拒（non-fast-forward）** | **第二写手直推了远程，本地 remote-tracking 过期** | **SOP ①b 未做**：先 `git ls-remote`/`fetch`；按第六节「别人先推了」处理 |
| `status` 显示 `ahead N`、`log` 里有自己没有的提交 | 他人自行提交 | 按第二节审计其文件范围，干净则直接 push |
| 刚提交完 `git status` 又有改动 | 多人并发写入 | 正常，下一轮同步即可 |
| 清单里出现 `_work/`、`_tools/`、`_tmp/`、`_probe/` 等 | 过程物目录（现已由 `.gitignore` 覆盖） | 规则应已忽略；若仍出现在清单，说明是**已跟踪**文件 → `git rm -r --cached <路径>` |
| 清单里出现 `.ams-docs` 下的 `*.py`/`*.log`/`*.txt` | 同上（`/.ams-docs/**` 已覆盖） | 同上；并检查是否有人用了 `git add -f` |
| 清单里出现 `outputs/`、大体积快照 | 忽略规则失效或用了 `git add -f` | 检查 `.gitignore`；必要时 `git rm -r --cached <路径>`（本地文件保留） |
| 校验通过但事后发现有漏，或提交里混入过程物 | **校验与提交串在一条命令里无条件执行** | 立即 `git reset --mixed HEAD~1`（未推送时）；此后③必须单独执行 |
| 提交里出现 `R100 a → b` | 文件被移动（git 自动识别为重命名，内容未变） | 正常，必要时在提交信息里说明归档/移动 |
| 提交信息显示乱码 | 用了 `-m` 传中文 | 改用 `-F .git/COMMIT_MSG.txt` |
| 读中文文件乱码 | PS 5.1 按 ANSI 解析 UTF-8 无 BOM 文件 | `Get-Content -Encoding UTF8` |
| `LF will be replaced by CRLF` | `core.autocrlf=true` | 正常 |
| `git worktree list` 只显示主工作树，但 `.git/worktrees/` 有残留 | 目录被删、登记被占用 | 无害，等占用释放后 `git worktree prune` |
