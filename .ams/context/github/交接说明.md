## 四、本机环境事实（踩坑集中区）

1. **代理端口是动态的，每次现场探测**（本机为飞鸟加速器 `C:\Program Files\飞鸟加速\core.exe`）。
   Git **不读取 Windows 系统代理**，不显式指定就直连 GitHub 并失败：`Recv failure: Connection was reset`。
   实测端口一天内变过多次：`20955` → `21601` → `24450` → `20293` → `21589` ……**旧端口会直接失效，不要抄历史值**。

   探测三步（每步都有实测依据）：

   ```powershell
   # 1) 取候选进程号（进程名 core 的才是代理；飞鸟加速主进程 12345 端口不是 HTTP 代理）
   Get-Process | Where-Object { $_.ProcessName -match "^(core|飞鸟加速)$" } | Select-Object ProcessName, Id
   # 2) 枚举其监听端口：netstat -ano 里 末列 PID 属于上一步、且 127.0.0.1:<port> LISTENING
   # 3) 逐个验证，返回 40 位哈希即可用：
   git -c http.proxy=http://127.0.0.1:<port> -c https.proxy=http://127.0.0.1:<port> ls-remote origin refs/heads/main
   ```

   实测判别特征（**都不是断网**）：`CONNECT tunnel failed, response 404/405`＝端口在监听但不是 HTTP 代理；
   `Failed to connect ... Could not connect to server`＝该端口已失效。偶发 `schannel: failed to receive handshake`
   （TLS 抖动）→ 重试一次或换端口即可。

2. **认证已就绪**：Git Credential Manager（`credential.helper=manager`），凭据已缓存，通常**不需要重新登录**；若需重新授权，`push` 会弹出浏览器登录窗口。
3. **`core.autocrlf = true`**：入库为 LF、检出为 CRLF，`LF will be replaced by CRLF` 警告属正常。
4. **中文提交信息**：不要用 `git commit -m "中文"`（PowerShell 传参可能编码失真）。用 UTF-8 文件承载：信息写进 `.git/COMMIT_MSG.txt`（该路径不在版本控制内），再 `git commit -F .git/COMMIT_MSG.txt`。
5. **中文路径**：`git status`／`git diff` 默认会把非 ASCII 路径转成八进制转义（`\346\226...`）。
   **加 `-c core.quotepath=false` 才可读**；`git diff --name-only` 里含中文的路径会带双引号，做匹配前先 `Trim('"')`。
6. **`.git/worktrees/verify-worktree` 残留**（2026-10-05）：曾有一个 `git worktree` 检出用作验证副本，目录已删除、`git worktree list` 已只剩主工作树，但 `.git/worktrees/` 下留了一个**访问被拒**的空登记（疑似被进程句柄占用）。
   影响：**无**（不进版本控制、不影响提交/推送/克隆）。处置：占用释放后 `git worktree prune`；不必为它折腾。
7. 环境为 Windows PowerShell（非 bash）；`git` 版本 2.53。**不要用 `cmd /c` 包裹命令**（在本环境的命令包装下会污染后续语句的解析）。

## 六、标准操作流程（SOP）

```powershell
cd d:/OrC-KSD

# ① 审查（强制，逐项判定归属；不要无脑 git add -A）
git status -sb                                          # [ahead N] => AMS 自行提交了，见②后半
git --no-pager log --oneline -5
git -c core.quotepath=false status --porcelain -uall    # 必须 quotepath=false，否则中文路径不可读
#    允许：src/ tests/ samples/ docs/ .ams/context/ .ams-docs/ 根目录文档
#    不得入库：ams/ outputs/ bin/ obj/ .vs/ *.user 及第五节的「过程物目录」
#    出现「未预期的路径」（新造的顶层目录、来源不明文件）→ 先汇报再做决定

# ①b 若 ahead N：审计 AMS 的提交（不改写、不回退）
git -c core.quotepath=false --no-pager diff --name-status <远程点>..HEAD

# ② 暂存：优先显式路径（最稳），只在必要时才 git add -A
git add src tests samples OrcEngine.sln                 # 代码
git add docs .ams-docs .ams/context CONTEXT.md          # 文档
#    然后按第五节清单把过程物拉出暂存区（务必用**显式完整路径**）
git reset -q -- "<第五节列出的每个路径>"
#    ⚠ 硬教训：不要用 "**/_tools" 这类递归通配——实测**不匹配**
#      （gitlink 条目路径是 ".../isolate/exp1"，不以 "/isolate" 结尾）

# ③ 提交前校验 —— **必须单独执行并亲眼看输出**，两段都空才可提交
#    a) 白名单（主）：凡不落在允许前缀内的一律列出，宁多报不漏报
$allow = @('^src/','^tests/','^samples/','^docs/','^\.ams/context/','^\.ams-docs/','^(OrcEngine\.slnx?|CONTEXT\.md|USER\.md|PROJECT\.md|COMMUNICATION\.md|RULE\.md)$')
git diff --cached --name-only | Where-Object { $p = $_.Trim('"'); -not ($allow | Where-Object { $p -match $_ }) } | ForEach-Object { "越界待确认: $_" }
#    b) 黑名单（辅，注意误报）：用「官方卡牌」而不是「kards」——后者会误伤 kards-game-layer、kards-diy-*
git diff --cached --name-only | Select-String -Pattern "/(bin|obj)/|^ams/|^outputs/|\.exe$|_tools/|/tools/|/isolate/|verify_|_work/|官方卡牌|^scripts/"
#    c) 目录级核对：逐任务目录看文件数，数量异常（几十上百）即疑似副本
git -c core.quotepath=false diff --cached --name-only | ForEach-Object { ($_ -split '/')[0..2] -join '/' } | Group-Object | Select-Object Count, Name

# ④ 提交（信息先写入 .git/COMMIT_MSG.txt，UTF-8；该路径不受版本控制）
git commit -F .git/COMMIT_MSG.txt

# ⑤ 推送（端口按第四节现场探测；<port> 不是固定值）
git -c http.proxy=http://127.0.0.1:<port> -c https.proxy=http://127.0.0.1:<port> push

# ⑥ 核验（两条都要过）
git -c http.proxy=http://127.0.0.1:<port> -c https.proxy=http://127.0.0.1:<port> ls-remote origin refs/heads/main
git status -sb        # 期望 "## main...origin/main"（无差异、无 ahead）
git rev-parse HEAD    # 期望与上面 ls-remote 的哈希一致
```

**误提交的补救**（仅在**未推送**时）：`git reset --mixed HEAD~1` 撤销本地提交、工作区内容保留，修正后重新走②③④。
（已推送的提交**不要**改写历史：公开仓库不可逆，宁可补一次更正提交。）

**提交粒度与信息风格**：

| 类型 | 前缀 | 内容 |
|---|---|---|
| 初始化/环境 | `chore:` | 忽略规则、环境处置 |
| 新代码 | `feat:` | 新增工程/机制/测试 |
| 文档 | `docs:` | 需求/实现文档、上下文、registry |

## 七、排障对照表

| 现象 | 根因 | 处置 |
|---|---|---|
| `Recv failure: Connection was reset` | git 未走代理（直连被重置） | 按第四节探测端口后带 `-c http.proxy=... -c https.proxy=...` |
| `Failed to connect to github.com port 443 via 127.0.0.1` | 代理端口已变 | 重新枚举端口，**不要沿用上次的值** |
| `CONNECT tunnel failed, response 40x` | 端口在监听但不是 HTTP 代理 | 换端口，勿误判为断网 |
| 偶发 `schannel: failed to receive handshake` | 代理侧 TLS 抖动 | 重试一次；`push` 已成功时以 push 输出 + `status -sb` 为准 |
| `403 Permission ... denied to <user>` | collaborator 邀请未接受或加错账号 | 本人登录 `https://github.com/Shangt1145/OrC-KSD/invitations` 接受；或请所有者核对 `Settings → Collaborators` |
| `401` / 要求登录 | 凭据失效 | 按弹窗重新完成 GCM 浏览器授权 |
| `status` 显示 `ahead N`、`log` 里有自己没有的提交 | AMS 自行提交 | 按第二节审计其文件范围，干净则直接 push |
| 刚提交完 `git status` 又有改动 | AMS 并发写入 | 正常，下一轮同步即可 |
| 清单里出现 `_work/`、`_tools/`、`isolate/`、`verify-*` | 过程物目录（`.gitignore` 覆盖不到） | 用显式路径 `git reset` 拉出暂存区（第五、六节） |
| 清单里出现 `outputs/`、大体积快照 | 忽略规则失效或用了 `git add -f` | 检查 `.gitignore`；必要时 `git rm -r --cached <路径>`（本地文件保留） |
| 校验通过但事后发现有漏，或提交里混入过程物 | **校验与提交串在一条命令里无条件执行** | 立即 `git reset --mixed HEAD~1`（未推送时）；此后③必须单独执行 |
| 提交里出现 `R100 a → b` | 文件被移动（git 自动识别为重命名，内容未变） | 正常，必要时在提交信息里说明归档/移动 |
| 提交信息显示乱码 | 用了 `-m` 传中文 | 改用 `-F .git/COMMIT_MSG.txt` |
| `LF will be replaced by CRLF` | `core.autocrlf=true` | 正常 |
| `git worktree list` 只显示主工作树，但 `.git/worktrees/` 有残留 | 目录被删、登记被占用 | 无害，等占用释放后 `git worktree prune` |
