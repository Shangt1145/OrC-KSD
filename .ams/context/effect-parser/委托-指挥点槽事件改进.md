## 1. 用户口径（原文，不得改写）

> 首先，定义两个 hook：额外获得 n 个指挥点槽 和 失去 n 个指挥点槽，两者内部再经过一个指挥点槽改变的 hook，
> 回合开始的指挥点槽递增走这条路（不走额外和失去 hook），卡牌效果可以走额外获得和失去，也可以修改回合开始的递增 hook。

要点提炼：
1. **两条对外信号**：额外获得 n 槽、失去 n 槽。
2. 这两条**内部汇聚**到第三条：指挥点槽改变。
3. **回合开始的递增直走「槽改变」**（**不**发 额外/失去）。
4. 卡牌效果可发 额外获得/失去；**也可改写「回合开始的递增」**。

## 3. 设计要求（定稿）

### 3.1 三条信号（命名沿用现有风格：小写点分）

| 常量（`GameUpdates`） | 字符串 | 语义 | 载荷键 |
|---|---|---|---|
| `SlotGained` | `slot.gained` | **额外获得** n 个指挥点槽 | `Player`、`Amount` |
| `SlotLost` | `slot.lost` | **失去** n 个指挥点槽 | `Player`、`Amount` |
| `SlotChanged` | `slot.changed` | 指挥点槽**改变**（唯一汇聚点） | `Player`、`OldSlots`、`NewSlots` |

- `slot.changed` 是**唯一**"槽值真的变了"的信号；`slot.gained`/`slot.lost` 是**语义前置**信号。
- **回合开始递增**：只发 `slot.changed`（**不发** gained/lost）。
- 数值未变化（已在上限/下限）＝**不发任何信号**（对齐 P1「改变才传播」）。

### 3.2 「回合开始的递增」可改写

- 新增判定器名 `JudicatorNames.PointSlotIncrement = "resource.slot.increment"`，签名 `(Player) → int`（默认返回 `1`）。
- `Settle` 的增量**经该判定器取值**（默认 1 ⇒ 行为与现状完全一致）；`Match.Initialize` 的**内置固定注册段**注册默认实现。
- 卡牌效果经既有 `JudicatorRegistry.RegisterModing` 改写该递增（全局生效、注销回退）——即"修改回合开始的递增 hook"。

### 3.3 `ResourceManager` 受控面（上限可变、下限 0）

- 构造改为 `ResourceManager(LogicEngine engine, int maxPointSlots = DefaultMaxPointSlots)`（需引擎发信号）。
- `MaxPointSlots` 由只读改为 `public int MaxPointSlots { get; private set; }`（本轮允许改上限，但**不新增**外部写入方法，除非 §3.5 需要）。
- 新增（`async Task<bool>`，返回是否实际变化）：
  - `GainSlotsAsync(Player player, int amount, CancellationToken ct = default)`：`amount ≤ 0` 拒绝；Δ = `min(amount, Max - current)`；Δ > 0 时发 `slot.gained` → 改值 → 发 `slot.changed`。
  - `LoseSlotsAsync(Player player, int amount, CancellationToken ct = default)`：Δ = `min(amount, current)`；Δ > 0 时发 `slot.lost` → 改值 → 发 `slot.changed`。
  - 内部私有 `SetSlotsAsync(player, newValue, emitChanged: bool)` 收敛改值＋发信号。
- **`Settle` 行为保持不变**：增量＝判定器值（默认 1），`min(+1, Max)` 封顶 → 改值 → 发 `slot.changed` → `Points = PointSlots`。**不**发 gained/lost。

### 3.4 信号发射帮助（必须）

`GameHooksTests.Every_Signal_Has_A_Static_Emit_Callpoint` 要求**每条信号都有静态 Emit 入口**：
在 `GameUpdates` 增 `public static Task EmitSlotGained/EmitSlotLost/EmitSlotChanged(LogicEngine engine, ..., CancellationToken ct = default)`（载荷同 §3.1）。

### 3.5 效果侧接入

- `EffectRuntime` 增 `Func<ResourceManager?>` 延迟读取器（`Match.Initialize` 注入 `() => _resourceManager`），并新增
  `GainPointSlotsAsync(Card viewer, int amount, ct)` / `LosePointSlotsAsync(Card viewer, int amount, ct)`
  （卡 → 玩家 → `Match` 级资源管理器；不可达＝false）。
  > 注：`ResourceManager` 现由 `Match` 持有；若从 `card` 不可达，按既有风格给 `Player` 注入（`ConfigureResourceManager`）并 `ResourceManager.ResolveFor(card)`。
- 词表/DSL/模板（**本仓 `Orc.Game/EffectParsing`**）：
  - `filters.json` 已有 `指挥点槽 → {dimension:"object", value:"pointSlot"}`；新增动作词 `失去 → key "loseSlot"`；
    `获得` 保持 `gain`。
  - `SemanticMapper`：`gain` 分支里 `objectNoun == "pointSlot"` 由**"显式失败"改为产出 `op gainSlot`**（`amount = payload`）；
    新增 `loseSlot` 分支（要求 `objectNoun == "pointSlot"`，否则失败）。
  - `DslOpRegistry` 增 `gainSlot` / `loseSlot`（`Required: ["amount"]`）；新增 `Templates/ops/gainSlot.csx.tpl`、`loseSlot.csx.tpl`
    （经 `Orc.Game.Effects.EffectRuntime.*` 调用；占位符 `{{amount}}`）。
