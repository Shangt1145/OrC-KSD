## 1. 任务是什么

给 OrC 引擎做**效果解析器**：把**中文卡面文本**变成**能真正运行的效果**。

三层流水线：

```
卡面文本
  →（tokenizer → 切分/归属 → AST）      ← 解析段
  →（DSL：模板效果 + 官方原语 + csx 逃生舱） ← 中间层（可独立序列化）
  →（模板渲染 → 带 csx 的 EffectSnapshot） ← 转换段
  →（csx 编译执行 → EffectRuntime 调游戏层） ← 运行期
```

设计要点（均为用户裁决）：
- 效果解析表达力**是引擎表达力的子集**（参照 kards-diy 水平），不追求等价。
- **模板效果**是**专用格式**（`*.tpl.json`，与 `EffectSnapshot` 同构子集 + `slots` 槽位声明）；不含"主触发器"的部分由 DSL 填写。
- 官方原语＝带参 op；**无法表达者只能走 `csx` 逃生舱**；**op 层无法解析**（非句式失败）⇒ 原文保留进 DSL 并标记 `needsCsx`。
- 句式**内建**、词表**外置**；超子集文本 ⇒ **显式失败 + 诊断**（不产占位效果、**不静默丢弃**）。

## 4. 剩余问题

### 4.1 `attack_basic`（inject 型监听）——**已闭环**（E1-37）

**根因**（决定性探针：dump `RootStream.Entries`）：处理器**确实被调用了**，是在**调用内抛异常**——
```
[Error] 单位攻击触发器/e1 | Exception has been thrown by the target of an invocation. | kw=exception:TargetInvocationException
```
`Trigger<TView>.RunEventsAsync` 对"事件内业务异常"是**隔离记录并继续** ⇒ 命令仍 `Success`、外部表现**等同"没被调用"**。
异常来源＝宿主包装 `WrapWithHostCore` 走 `PropertyInfo.SetValue(view, host)`，而 `view` 的真实类型是
`ViewProxyFactory` 生成的**代理**、其 setter 被烘焙成权限闸门（`[Read]` 属性禁止写入）⇒ 必抛。

**修法**：宿主注入改走**数据面**（`ctx.Data["Host"] = effect.HostOrNull`，与内核 hook 路径同手法）。
**验收**：`Generated_Attack_Listener_Runs_After_Attack` 取消 `Skip` 后通过 ⇒ **0 跳过**。

> **教训（接手必读）**：本项曾被连续 5 轮"实例/区段/优先级/包装/解析"实验误判为"处理器未被调用"——
> 真实形态是**异常被隔离**。**凡"注册成功但无效果"**，第一步就该拉 `RootStream` 的 `exception:` / Error 记录，
> 而不是继续加探针猜通道。

### 4.2 两处**已登记、未做**的解析层缺口

1. **「本单位…时」不校验事件主体是否为宿主卡**（grill plan **I35**）：监听分支只做归属过滤，
   词面 `本单位X时` 与 `友方单位X时` 走同一条路 ⇒ `本单位受到伤害时` / `本单位交战并存活后` 会在**任意**单位/卡事件上触发
   （`death_basic` 因"死亡链先卸载效果"而自愈，其余不会）。
   修法候选：`DslCondition` 增"自指"kind（`self.same` ⇒ `object.ReferenceEquals(self, view.Unit ?? view.Card)`）。
   **本轮刻意用 `友方单位交战并存活后` 做端到端用例**，避免把该缺口伪装成"已正确"。
2. **`使用X牌`／兵种过滤族**（≈22 条，grill plan **I32/I36**）：信号（`card.played`/`unit.deployed`）**都已存在**，
   缺的是**对"事件卡属性"的过滤**（卡类型/词条/子类别 tag/阵营/花费/兵种）——这是**新能力**（DSL 条件层扩展），
   不能靠"宽松映射"糊（否则 `友方使用情报牌时` 会变成"友方打出任意牌都触发"，属**语义错误**）。

### 4.3 无发射点的监听族（**不建议补信号**，前置是实现机制）

- **不错误执行**：宁可"空转/报错"，也不产"看起来对、其实打错人"的效果。
  （历史踩过的两例已修：`获得闪击` 会打到"场上第一个单位"；`相邻陆军具有 +2 攻击力` 会加成到**宿主自己**。）

### 6.4 缺口归因：为什么停在 52.2%

**未解析记录 587 条的原因分布**：

| 次数 | 原因 | 实质 |
|---|---|---|
| 375 | 未识别动作词 | 多为**机制描述**：`无法…`／`升为老兵`／`反制其部署`／`与其战斗`——中文读得出，**动作词没有对应机制** |

| 80 | 监听型触发不在子集 | 老兵/指向/反制/条件态触发（见 A/B 表） |
| 43 | 事件不在子集 | `抉择`、专属事件 |

> **结论**：继续堆词表只能把 ① 推高，**推不动 ②（语义完整）**——这正是"暂停解析、先补游戏层"的依据。

### 6.5 恢复条件：游戏层要补什么（按性价比排序）

1. **"等同于…"类动态数值 ＋ 事件数值透传**（≈42，最容易）：`造成等同于其花费的伤害`／`获得等量的防御力`——
   已有先例（`unit.damage.dealt`／`card.died.Killer`／`counter.triggered` 的四处同步模式）。
2. **"总部（HQ）作为效果对象"**：`使友方总部获得…防御力／具有烟幕`——需 HQ 属性修饰面
   （E1-57 已在**条件**里用 `Hq.Health` 表达"总部防御力"，但 op 侧尚无 HQ 属性面）。
3. **选靶面扩容**（≈12）：`相邻`／`本单位左侧`／`陆军（地面组）`／`手牌中的`／`某卡类型`——
   `GameEnvironment` 已有 `AreAdjacent`/`GetLineOf`/`GetPositionOf`，可复用。
4. **钳制语义**：`花费至少为 1`（对修正后的取值设下限）——不是条件，需 op 级语义。
5. **机制实现批次**（工程量最大，建议逐个立项）：门禁（`无法…`）、洗入卡组、复制、双倍/溢出伤害、开发/抽取选择、
   冲击、收缴/协力/流亡、老兵、预报/天气、山地、钳击、转换、隐蔽揭示、撤退/返回手中。
6. **条件面续补**：对手对象取面（`大于敌方总部`）／状态与历史条件（`上回合没有被攻击`、`动员`）。
7. **modal（抉择）**：二选一机制。

## 7. 踩过的坑与**新增硬约束**（接手必读）

1. **csx 默认导入不预置 `Orc.Game.*`**（否则未加载游戏层的宿主会编译失败），但**程序集白名单**已含 `"Orc.Game"`。因此：
   - 模板里游戏层类型一律**全限定**（如 `Orc.Game.Effects.EffectRuntime`）；
   - 视图类型若跨程序集，必须用**程序集限定名**（`, Orc.Game`）——内核 `DynamicEffectBuilder.ResolveViewType` 用 `Type.GetType`，
     **非限定名只搜"调用程序集+核心库"**；编译器侧会剥掉 `, Assembly` 再写 csx。
2. **inject 型效果的主触发器必须是 `passive`**（哪怕是 `active` 语义）——否则 `ApplyFrameworkInjects` 按"非动态被动形态"**直接隔离跳过注入**。
   `passive` **允许无 hooks**（只有 `active + hooks` 被拒）。
3. **纯注入型效果（主触发器无 hooks）不挂总线**——已修 `DynamicPassiveEffect.MountMainTrigger`；这是 inject 型模板能存在的前提。
4. **注入的处理器的视图类型必须与目标触发器一致**（不一致 ⇒ `RegisterBand` 强制转换失败 ⇒ `注入失败（隔离）`）。
5. **视图是"权限闸门代理"，不能用属性 setter 写入**（E1-37 根因）：视图实例由 `ViewProxyFactory` 生成，
   `[Read]` 属性（含 `Host`/`Unit`/`Player`）的 setter 一律 `throw PermissionDeniedException`。
   **框架侧要注入数据只能写 `ctx.Data["<键>"]`**（getter 直读该字典，键＝属性名）。
6. **注入优先级不能为负**——`Trigger.AddEvent` 对 `priority < 0` 直接 `throw`，被 `ApplyFrameworkInjects` 捕获后记为
   `注入失败（隔离）`、**注入数=0**（无异常外泄）。故"负优先级"不是可用的提前执行手段。
7. **归属过滤有"取值面"之分**：载荷是卡/单位（`card.*`/`unit.*`）用 `owner.same`/`owner.different`
   （守卫读 `(view.Card ?? view.Unit)`）；载荷**只有玩家**（`slot.gained`/`slot.lost`）用
   `owner.same.player`/`owner.different.player`（守卫读 `view.Player`）。
   且**只有载荷确实带该面**的模板才可加守卫（白名单 `OwnerFilterableTemplates` / `PlayerFilterableTemplates`）——否则守卫恒假或编译不过。
8. **`unit.acted` 不为已阵亡单位发射**；**`card.damaged` 按"改变才传播"**（已经被打到 0 再受伤＝零变化，不发）；
   **`unit.combat.survived` 在死亡判定之后发射**（已阵亡者不发射）；
   **`unit.damage.dealt` 按"实际变化量 > 0"**（反击 6 点但防御仅 5 ⇒ 记 5）。
9. **死亡归属的"抢占"陷阱**（E1-47）：战斗路径里那句 `ProcessDeathAsync(target, killer: attacker)` 的**结算内兜底通常不执行**——
   `ApplyDefenseDamageAsync` 内的跑链 → `card.stat.changed` → 总线 → `HandleDefenseDepletionAsync` → `ProcessDeathAsync(无归属)`
   **先行**完成死亡。故本轮引入**伤害来源游标**（`CommandManager._damageSourceCursor` ＋ `WithDamageSourceAsync`，
   try/finally **恢复式**，同一同步调用链内有效）：**改伤害/死亡归属时先确认自己没被这条链抢占**。
10. **`RunEventsAsync` 会隔离事件内业务异常并继续**（结局仍 `Normal`）⇒ 生成物"跑不起来"时，
   **先查 `exception:` 关键字记录**，不要凭外部表现判断"没被调用"。
11. **内核两个潜伏缺陷**（已修，但同族问题可能还有）：`TriggerReflection.Unregister` 曾从**开放式泛型**取 `MethodInfo`（`Invoke` 必抛）；
    `bus.Mount` 对**零 hooks 触发器**会抛。
12. **选靶缺省＝`self`**（E1-41）：中文卡面省略主语时主语即"本单位"。**缺省曾是 `one`** ⇒ 无目标 op（`获得闪击`／`获得 +1+1`）
    会打到"**A 支援线第一个单位**"（跨阵营！）。**新写 op 若需自指，勿再传 `one`**。
13. **过滤短语有"限定词 vs 宾语"之分**（E1-41）：`TargetPhrase.Filters` 混装两类——**动词之前**的才是目标限定词
    （`其他友方坦克具有…` 的 `坦克`）；**动词之后**的是动作宾语（`…具有 +1 攻击力` 的 `攻击力`）。
    用 `QualifierFilters`/`ObjectFilters` 分离；否则 `获得闪击` 会被当成"选一个带闪击的单位"。
14. **期限必须落地，不许忽略**（E1-41）：`Modifier` 已支持 `ModifierExpiry`（相位＋过滤器，挂载即自订阅）；
    `grant` **无期限面** ⇒ 带 `直到…` 的授予必须落 `needsCsx`（否则静默变成**永久**词条）。
15. **阿拉伯数字 vs 中文数字**（E1-41）：`两`/`一个` 是 `Quant`，而 `2`/`1 个` 会成 `Num` ⇒
    `使 1 个友方步兵具有 +2 攻击力` 的载荷曾被读成 `1`。现规则：`[数字][量词(measure)]` 且**本子句尚无动作词** ⇒
    判为**数量短语**（例外：紧跟**引号卡名**，如 `将 3 张“X”加入手中`）；`+`/`-` 符号并入紧随的阿拉伯数字（**一个** Num）。
