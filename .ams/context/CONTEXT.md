# 卡牌引擎（触发器系统）

卡牌游戏的后端逻辑引擎（供 Godot C# 客户端消费）的触发器系统术语表。2026-10-03 起随需求 grill 逐步建立；未定稿条目已标注"对齐中"。

## Language

**卡牌（Card）**:
薄容器：数据放数据组件、逻辑放逻辑组件。（2026-10-03 确认）

**触发器（Trigger）**:
逻辑的起点与编排单元。主动触发器由其他逻辑调用激活（触发函数可重载、可传入额外参数）；被动触发器挂载在总线上。内部维护 band 列表（默认含 default 区段），事件在其中按优先级顺序触发。一个触发器只有一个 ContextView。
_避免_: 用它称呼单个 handler（那是"事件"）。

**Band（区段）**:
触发器内部的有序语义分区，以 **C# 枚举**定义（枚举成员可指定值）；默认枚举仅含 default（值 0）。**二选一保护**：要么用默认枚举（无 band 注入＝落 default，只给优先级即可），要么声明专门枚举（必须显式指定 band；无 band 注入方法报错、拒绝 default，防止技术债）；专门枚举允许使用 0 值成员。排序键＝band 值×1000＋band 内优先级（0≤内<1000）＋注册序。（2026-10-03 定）

**事件（Event）**:
触发器内部的原子逻辑，即 handler；按 band/优先级顺序执行，可改写 ctx 数据，可在其内触发其他触发器。
_避免_: 用它称呼"时机点"（时机点的名称是 Hook）。

**Hook**:
时机点。触发器内部维护 hook 列表，登记其关心的时机；被动触发器借此挂载在总线上、对更新作出反应（如 hook"card.deployed"）。
_备注_: 原设计文档中"事件"一词指时机点；2026-10-03 经用户仲裁，时机点更名为 Hook（用户选择方案 1.a）。

**ContextView**:
触发器唯一的数据契约声明；接收引擎引用与额外参数并**转接**（Translate，手写硬编码；引用按可变 Ref、值按不可变快照处理，可透传进 ctx 字典），产出 ctx，用于解决引用隐式依赖。
_又称_: 转接器（用户口语，与 ContextView 等价；代码/文档统一用 ContextView）。

**ctx（上下文）**:
由触发器 ContextView 产出的一次性执行上下文，被该触发器全部事件共用。

**总线（Bus）**:
只负责广播更新（如"放置单位"等操作类更新、card.data 等）的中间层，不做逻辑编排；被动触发器挂载于此——触发器直接声明其要挂载的更新字符串。同一更新的多个触发器按「优先级（框架提供一套参考常量集）+ 注册序」执行。（2026-10-03 定）

**更新（Update）**:
总线广播的消息，如"放置单位""card.destroyed""card.data""effect.removed"；被动触发器通过 hook 对更新作出反应；更新同时写入事件流。

**事件流（EventStream）**:
显式对象，专门收集事件日志；带唯一 ID。作为触发器被触发的返回值（`Task<EventStream>`）；级联触发时自动挂载到触发者的事件流中，挂载动作本身写入一条日志（含父/子事件流 ID）；日志写入时自动向父流逐级冒泡；日志条目带扁平结构的关键词。逻辑引擎持有总事件流；配套脚本阅读工具（追踪、过滤），供 agent 高效分析。（2026-10-03 用户澄清）
_条目结构（拟）_: kind（log/attach/update）、时间戳、级别、来源、消息、关键词（扁平）、数据。

**效果（Effect）**:
＝逻辑组件（术语合并）。挂在卡牌上的逻辑封装；组装方式：默认**实例化**，**继承**＝额外注入 handler 的途径。主触发器为主动 → 主动效果（法术/一次性效果等），为被动 → 被动效果（可能与场上单位绑定）。
_挂载_: 总线提供"放置单位"等更新，**在放置时挂载效果**（把其被动触发器挂载到总线等）；挂载逻辑同时 hook"效果移除"并注册专属移除逻辑（如清除引用等）；注册/注销属模板代码，待（最小）工具化。

**注入（Inject）**:
将 handler 注册到通用流程触发器的**具名 band**（"对应位置"），使效果参与该流程。
