# 宿主集成面（agent 需要知道的最小集）

本服务层通常运行在两种形态之一：

- **无头/MCP 形态**：只有 agent 连着你（`samples/Orc.Mcp.Stdio`）。此时你是唯一操作者。
- **UI 宿主形态**：一个真实 UI 宿主在**同一进程**共享同一个对局（人机同局）。此时还有一个人在操作。

## 你需要知道的差异

| 方面 | 含义 | 对你的影响 |
|---|---|---|
| **唯一活跃对局** | 服务层持有一个对局；UI 只是它的视图 | 你建局/销毁对局时，UI 会收到创建/销毁事件（无需你通知） |
| **唯一桥 + 待决请求订阅** | 选靶由服务层统一派发；UI 也会看到同一个待决请求 | 你的 `target.submit` **可能失败**——若人先认领了该请求（先到先服务） |
| **接管** | `target.claim` 可把请求的应答权收到自己这边 | 人在场但迟迟不点，可用 `target.claim` 接管后自行应答 |
| **超时** | 待决请求超时（默认 10 分钟）按取消处理 | 无人应答不会卡死；你的动作会以 `cancelled` 结束 |
| **段消费** | 宿主可声明自己取段（UI 形态） | 此时 `observe.segments` 只读**宿主喂入的缓存**，`takenNow` 恒为 0——不是错误 |
| **门禁共享** | UI 的动作与你的工具走同一把锁 | 你会拿到 `pending-targeting`/`busy`，而不是并发进入引擎 |

## 操作要点

1. 动作工具返回 `code: "targeting"` 时：**先看 `details.pending`**——若你打算应答，可先 `target.claim`（若人可能抢答）。
2. `target.submit` 失败时读 `message`：区分"会话不存在/已取消"（超时或被应答）与"已被另一方认领"。
3. 人在场时，避免用 `sandbox.*` 把对局改得面目全非（会影响人正在看的局面）；调试动作优先在"无人操作"的窗口做。
4. UI 形态下 `observe.segments` 可能暂时为空——宿主帧循环没跑就不会有新段；此时可用 `observe.view`/`observe.snapshot` 获取当前状态。

## 沙盒 vs 玩家模式

- 沙盒模式（`--mode authoring`）：你全知、可用调试工具；`observe.view` 返回含对手手牌明细的全知摘要。
- 玩家模式（`--mode player`）：你占一个座位、操作能力与真人玩家完全等同；调试工具**不存在**（调用会得到 `unknown-tool`）；`observe.view` 返回按座位过滤的视图（对手手牌只有数量）。
