## 第 1 轮（2026-10-12）

### Q1 静态资产的「真源与扩展机制」【待答】
"把静态资源（阵营/单位枚举等）做成从可 moding 的判定器中获取"——需要钉死静态资产的**定义源**与**扩展路径**。三选一（详见对话）：

- a) **判定器即查询服务**：保留 C# 枚举作契约，新增"资产服务判定器"（如 `faction.list` / `faction.valid`）供插件改写值域与校验；枚举字面仍编译期冻结。
- b) **静态资产完全数据化**：废除 `Faction`/`UnitType` 等枚举，改字符串标识＋注册表；判定器只承载"默认规则/校验"，值域由插件数据声明。
- c) **混合**：枚举仅作"内置词条"的便利别名，真源＝运行期注册表（内置项由内核预置，插件可增删），判定器承载裁决。

### Q2 插件的技术承载形态【待答】
插件里要提供"判定器／核心 API／底层触发器 moding"——但 csx 产不出这些强类型注册项。需定型：
- a) 插件＝**C# 程序集**（编译产物，冷加载）；
- b) 插件＝**csx 脚本集**（须先扩 csx 宿主契约，令 csx 可产出判定器/组件等）；
- c) **混合包**（manifest ＋ csx 效果 ＋ 可选程序集）。

### Q3 「启动」的定义与作用域【待答】
"引擎启动时静态加载"——是进程启动 / 宿主启动 / 每对局（`Match.Initialize`）？插件注册落到进程级静态面还是对局级注册表？多对局并发时插件的注册是一次还是每局一次？

### Q4 卡包热加载的边界【待答】
"热加载"发生在：建局前 / 对局进行中（新卡只对新对局生效）/ 对局中即时生效（经 `EffectRuntime` 动态装载）？已加载卡包的效果能否在局中**替换**？

### Q5 效果双来源与依赖解析【待答】
效果既可插件定义又可卡包定义；"卡牌加载要求其效果必须先存在"。需定义：依赖声明格式（"依赖插件的资产名"具体键）、解析/校验时点（建局前 dry-run / 加载期 fail-fast）、插件效果与卡包效果同名冲突裁决。

### Q6 包管理器的职责边界【待答】
发现/清单/版本约束/依赖拓扑排序/加载顺序/失败隔离/卸载——哪些纳入？"插件包即版本"＝包整体带版本？卡包是否也版本化？

### Q7 moding 的开放范围【待答】
"核心 API 及底层触发器也 moding"——开放哪些（内核 `LogicEngine`/`Bus`/`Trigger`？游戏层 `CommandManager`/`PlayManager`？）？moding 形态＝判定器替换（既有 `RegisterModing`）还是通用 delegate 注入？

### Q8 兼容与回归约束【待答】
是否可改内核 `src/Orc`？既有冻结契约（信号名 `GameUpdates`、判定器名 `JudicatorNames`、`KeywordIds`）是否解除？测试全绿/0 警告是否沿用？

## 第 2 轮（2026-10-12）

### 基线补充（判定器机制，代码侧核对）
- `Judicator` 为 abstract 基类＋**统一无类型主方法** `object[]? Invoke(object[]? args)`（`src/Orc/Core/Judicator.cs:11-53`）——返回值任意 `object[]`，**机制上已支持"取数"**（非仅 bool）。

- `JudicatorBinding` 双路径：对局路径（注册表条目句柄）／独立构造路径（内置默认实例）（`JudicatorBinding.cs`）。
- CONTEXT 现定义判定器＝"独立**无状态**服务；**对局加载时**加载；判定/取数/bool 判断"（`CONTEXT.md:71-72`）。

### Q1 静态资产的「真源与扩展机制」【已答：b】
裁定（2026-10-12）：**选 b——静态资产完全数据化**。废除 `Faction`/`UnitType` 等 C# 枚举作为真源，改**字符串标识＋运行期注册表**；**判定器升格为外部的数据/逻辑储存服务**，由它提供枚举（值域）与裁决。

### Q1-a 术语仲裁：判定器语义扩展【已答：b】
裁定（2026-10-12）：**选 b——新设术语「资产服务」（AssetService）**，与「判定器」并列：判定=算、资产服务=存/查；两者共用 `JudicatorRegistry` 机制（条目+moding 栈+句柄），语义分立。需在 CONTEXT 登记：资产服务、插件、卡包、包管理器、冷加载、热加载、资产名。

### Q1-b 静态资产的数据模型【待答】
"资产服务提供枚举"不只是返回字符串列表：现有 `Faction` 带关系（`FactionRules.MajorFactions` / `IsValidAlly`），`UnitType` 带类型组（`CombatTypeGroups.AnyLineRangeTypes` / `GuardEligibilityTypes`）。需定：资产条目的字段模型（id/名称/属性/关系）与其 JSON schema。

### Q2 插件的技术承载形态【已答：c】
裁定（2026-10-12）：**选 c——混合包**。分工边界：①**数据（枚举/资产值域）＝JSON**；②**逻辑（判定器/效果/核心 API 与触发器 moding）＝csx**（与既有 csx 效果通道统一）；③**可选程序集**仅作 csx 表达不了/性能敏感的逃生舱。

### Q2-a csx 宿主契约扩展形态【待答】
现状 `IScriptEvaluator` 只回吐 `Func<TView,Context,CancellationToken,Task>`；要令 csx 产判定器/资产服务/注册动作，须新增"注册期入口"契约。请求/结果类型如何扩展？（实现层，详列于实现-grill）

## 第 3 轮（2026-10-12）

### Q3 插件作用域与「启动」的定义【已答：a】
裁定（2026-10-12）：**选 a——引入进程级包运行时/宿主**（暂名 `EngineHost`/`PackageRuntime`）。职责：插件冷加载 ＋ 资产目录（AssetCatalog）；`Match` 从目录**快照**出对局级注册表；"启动"＝宿主启动。

## 第 4 轮（2026-10-12）

### Q4 卡包热加载的生效范围与时点【已答：c】
裁定（2026-10-12）：**选 c——两级**。卡包注册默认**仅对新对局生效**；另提供**显式受控动作**把某效果/卡定义注入当前对局（复用既有 `EffectRuntime` 动态装载链）。

### Q4-a 替换/卸载语义【默认采纳推荐·可否决】
默认：以**追加**为主；同 id 卡/效果冲突＝**拒绝并隔离报告**（对齐现状"注册即配置、重复拒绝"）；替换/卸载仅经**显式受控动作**。

### Q4-b 「效果必须先存在」的校验时点【默认采纳推荐·可否决】
默认**三层**：①卡包分发**预检 dry-run**（沿用既有预检器先例；Error>0 整包不放行）；②建局装配期 **fail-fast**（引用效果/资产缺失＝初始化失败）；③卡实例装载期**单卡隔离兜底**。

## 第 5 轮（2026-10-12）

### Q5 效果双来源与依赖声明的载体/粒度【已答：c】
裁定（2026-10-12）：**选 c——两级混合**。manifest 级声明"包依赖包"；效果/卡条目级声明"效果依赖资产名"；两级拓扑校验。

### Q5-a 依赖对象粒度与命名空间【已答：类型 + 包GUID前8位】
裁定（2026-10-12）：**资产名 ＝ 类型（确定加载方）＋ 包 GUID 前 8 位**；要求**全局唯一**；**若不唯一，后者无法加载**。
（待 Q5-c 确认：GUID 是否跨版本稳定、拼接格式、类型取值集合。）

### Q5-b 同名/冲突裁决【已答：唯一性要求】
裁定（2026-10-12）：**要求唯一**；不唯一＝**后者无法加载**（拒绝，不覆盖）。
需求原文："效果既可在插件里定义也可在卡包里定义，支持热加载；卡牌的加载要求其效果必须先存在""效果声明其依赖的插件的资产名"。
基线：效果来源三形态——①C# 类型（`CardEffectRegistry.Register` + `PrefabManager.RegisterHandler`）；②预制体 JSON（`*.prefab.json`）；③DSL→编译产物（csx）。卡数据经 `effects` 组件引用（`{prefabs:[id], inline:[...]}`）。判定器/效果引用一律**按名解析**（`JudicatorRegistry.Resolve`、`PrefabManager.ResolveHandler`）。
- a) **显式字段**：效果预制体/卡包条目内加 `requires: [assetName]`，包管理器据边做加载前拓扑校验。
- b) **隐式解析**：不声明；依赖＝"按名引用"自然形成，加载时按名解析、缺失即 fail-fast。
- c) **两级混合**：manifest 级声明"包依赖包"，效果/卡条目级声明"效果依赖资产名"，两级拓扑。

### Q5-a 依赖对象粒度与命名空间【待答】
"资产名"指的是一枚**插件内命名资产**（判定器名/资产服务 id/词条/效果 id/单位类型组…）？还是**插件包名**？跨插件的全局资产命名空间如何定义、唯一性如何保证（防重名）？

### Q5-b 同名/冲突裁决【待答】
插件效果与卡包效果同名、或两插件声明同名资产时：拒绝 / 覆盖 / 命名空间前缀隔离？

## 第 6 轮（2026-10-12）

### Q5-c 包 GUID 的稳定性与资产名格式【已答：a】
裁定（2026-10-12）：**GUID ＝ 稳定身份**（跨版本不变）。
**资产名文法（定稿）**：`{类型名}：{资产名}@{资产GUID8}#{版本号}`
— 示例：`csx：faction.service@ab12cd34#1`。
"类型名"＝**加载方/来源**（甲口径：数据JSON / csx / 可选程序集）。

## 第 7 轮（2026-10-12）

### Q5-d 版本号是否进入「依赖引用」【已答：a + 通配】
裁定（2026-10-12）：**依赖写全名**（含 `#版本`）；版本＝**`x.y.z` 语义化版本**；**第一序列号（主版）锁定**，**第二、第三序列号允许通配（`*` 或 `^`）**。
（`*`/`^` 精确语义 ＋ "多版本能否并存"见 Q5-e。）

## 第 8 轮（2026-10-12）

### Q5-e 版本约束语法与多版本并存【已答：②甲；①默认(i)】
裁定（2026-10-12）：**②＝甲：允许同一资产多版本并存**；对局初始化时把依赖**解析到具体版本并锁定**（升级不影响正在跑的对局）。
①`*`/`^` 语义未选，默认**(i)：`^` ＝ "≥下界、向上取新"**——可否决。
