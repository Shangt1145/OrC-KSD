# Requirements — 插件与卡包双层资产模型（游戏层全面资产化）

把游戏层的静态/结构资产从"编译期硬编码"改造为**双层模型**：进程级**插件**（冷加载、提供局内不可变的静态资产，含可 moding 的判定器与资产服务）＋ 运行期**卡包**（热加载、纯卡牌数据）；效果可在任一层定义并支持热加载，且卡牌加载前其依赖的效果/资产必须先存在。终局目标＝引擎核心零业务资产（内置资产全部迁为内置插件）。

本文件为**需求 grill 定稿**（2026-10-12）。

## Scope

- Includes：
  - **R1** 静态资产完全数据化；判定器升格为「资产服务」（提供枚举值域与裁决）。
  - **R2** 双层模型：插件（进程级冷加载）＋ 卡包（热加载）。
  - **R3** 进程级包运行时/宿主（`EngineHost`）与作用域分层。
  - **R4** 资产命名文法与语义化版本/约束。
  - **R5** 插件承载形态（混合包）与 csx 宿主契约扩展。
  - **R6** 两级依赖声明与三层校验。
  - **R7** 包管理器（发现/清单/版本选择/拓扑/顺序/隔离）。
  - **R8** 卡包（第二层）形态、热加载生效范围与装配优先级。
  - **R9** moding 开放范围（两级形态＋黑名单）。
  - **R10** 全面资产化的分批迁移。
  - **R11** 新术语登记入 CONTEXT。
- Excludes：
  - 包管理器高级能力：卸载 / 重载 / 回滚 / 依赖图持久化（后续可选）。
  - 内核 `src/Orc` 的**新 moding 改写口**（仅沿用既有 `JudicatorRegistry.RegisterModing` / `Trigger.RegisterModing`）。
  - 强隔离沙箱（沿用既有"弱沙箱、非安全边界"定位）。
  - UI / 网络 / AI。

## Constraints

- **允许改内核** `src/Orc`，但限**最小必要改动**（新增 csx 宿主契约；不开放内核 moding 口）。
- **冻结契约保持冻结**：信号名字面 `GameUpdates`、判定器名 `JudicatorNames`、`KeywordIds`。
- 构建 **0 错误 / 0 警告**；既有测试**全绿**。
- 沿用 P1/P2 不变量（禁无条件数据更新；更新不允许异步）。
- csx 定位＝**弱沙箱（同进程、非安全边界）**。

## Requirement Items

### R1: 静态资产数据化 ＋ 资产服务
- Status: Confirmed
- Scenario/Trigger: 任何读取阵营/单位类型等静态资源之处。
- Behavior: 废除 `Faction`/`UnitType` 等 C# 枚举作为真源，改**字符串标识 ＋ 运行期注册表**；判定器**升格为「资产服务」**（与「判定器」并列，共用 `JudicatorRegistry` 机制：条目＋moding 栈＋句柄），提供枚举值域与裁决。
- Acceptance:
  - [ ] 静态资产无编译期枚举真源；读取统一走资产服务。
  - [ ] 资产条目模型＝`{ id, 名称, 类型, 属性{...}, 关系{...} }`（阵营：是否主国/可盟列表；单位类型：类型组[]）。
  - [ ] 插件可在不改内核的前提下新增/改写资产值域（经 moding）。
- Terminology: [资产服务]、[判定器]

### R2: 双层模型（插件 / 卡包）
- Status: Confirmed
- Scenario/Trigger: 引擎/宿主加载资产时。
- Behavior: **插件**＝进程级、启动时**冷加载**、提供局内**不可变**静态资产（含资产服务/判定器/效果/核心 API 相关触发器）；**卡包**＝运行期**热加载**、内容限卡牌数据（含效果引用与内联效果）。
- Acceptance:
  - [ ] 插件仅冷加载（不支持运行期重载）。
  - [ ] 卡包可热加载（默认仅对新对局生效，见 R8）。
  - [ ] 插件资产在对局生命周期内不可变。
- Terminology: [插件]、[卡包]、[冷加载]、[热加载]

### R3: 进程级包运行时/宿主与作用域
- Status: Confirmed
- Scenario/Trigger: 进程启动、创建对局时。
- Behavior: 引入进程级 **`EngineHost`/`PackageRuntime`**：承担插件冷加载与**资产目录（AssetCatalog）**；`Match` 从目录**快照**出对局级注册表（`JudicatorRegistry`/资产服务/效果）。
- Acceptance:
  - [ ] 资产目录**共享一次加载**；每局注册表**独立一份**。
  - [ ] moding **不跨对局泄漏**。
  - [ ] 多版本资产可并存；对局初始化时**解析到具体版本并锁定**。
- Terminology: [插件]、[资产服务]

### R4: 资产命名文法与版本
- Status: Confirmed
- Scenario/Trigger: 声明/引用资产、解析依赖时。
- Behavior: 资产全名 ＝ `{类型名}：{资产名}@{资产GUID8}#{版本约束}`；`类型名`＝**加载方/来源**（数据JSON / csx / 可选程序集，甲口径）；`GUID8`＝资产**稳定身份**前 8 位（跨版本不变）；版本＝**`x.y.z` 语义化**。
- Acceptance:
  - [ ] 全名**全局唯一**；不唯一＝**后者不予加载**（拒绝、不覆盖）。
  - [ ] 依赖引用写**全名**（含 `#版本`）；**主版锁定**，第二/三段允许通配 `*` / `^`。
  - [ ] `*`＝任意；`^`＝"≥ 下界、向上取新"。
  - [ ] 同一资产多版本可并存（不同全名）。
- Terminology: [资产名]

### R5: 插件承载形态（混合包）
- Status: Confirmed
- Scenario/Trigger: 插件包被加载时。
- Behavior: 插件＝**混合包**：①**数据（枚举/资产值域）＝JSON**；②**逻辑（资产服务/判定器/效果/核心 API 与触发器 moding）＝csx**；③**可选程序集**＝csx 表达不了/性能敏感的逃生舱。
- Acceptance:
  - [ ] 扩 **csx 宿主契约**，使 csx 可产出资产服务/判定器等注册项（现契约仅回吐触发器 handler 委托）。
  - [ ] CSX 扩展仅新增机制，不改既有 `IScriptEvaluator.Evaluate` 语义。
- Terminology: [插件]、[csx 动态效果]

### R6: 两级依赖声明与三层校验
- Status: Confirmed
- Scenario/Trigger: 加载插件/卡包、建局、卡实例装载时。
- Behavior: **manifest 级**声明"包依赖包"；**条目级**声明"效果依赖资产名"。校验分三层：①分发**预检 dry-run**（Error>0 整包不放行）；②建局装配期 **fail-fast**；③卡实例装载期**单卡隔离兜底**。
- Acceptance:
  - [ ] 依赖缺失可在加载前被拓扑检出。
  - [ ] 校验报告沿用预定器 Errors/Warnings 分列口径。
- Terminology: [资产名]、[分发预检器]

### R7: 包管理器
- Status: Confirmed
- Scenario/Trigger: 插件/卡包装载时。
- Behavior: 核心六件——**发现、清单解析、约束校验与版本选择（取满足约束的最高版）、依赖拓扑排序、加载顺序（拓扑序＋声明序）、失败隔离**。卸载/重载/回滚列为后续。
- Acceptance:
  - [ ] 单包失败＝**隔离整包**，不阻断其余。
  - [ ] 包发现支持**约定目录扫描**与**显式清单**两种。
  - [ ] 同层无依赖包按声明序稳定加载。
- Terminology: [包管理器]

### R8: 卡包（第二层）
- Status: Confirmed
- Scenario/Trigger: 热加载卡包、对局取用卡包时。
- Behavior: 卡包与插件**同构**（manifest/版本/依赖/命名文法），内容限**卡牌数据**（允许引用效果与内联效果）。热加载**默认仅对新对局生效**；另提供**显式受控动作**把某效果/卡定义注入当前对局（复用 `EffectRuntime` 动态装载链）。
- Acceptance:
  - [ ] 热加载不影响进行中的对局（除经显式注入动作）。
  - [ ] 装配优先级：**插件效果先注册 → 卡包效果后注册**（保障"卡牌加载时效果先存在"）。
  - [ ] 以**追加**为主；同 id 冲突＝拒绝并隔离；替换/卸载仅经显式动作。
- Terminology: [卡包]、[热加载]

### R9: moding 开放范围
- Status: Confirmed
- Scenario/Trigger: 插件需要改写行为时。
- Behavior: 两级形态——**语义规则类 → 判定器 moding**（沿用 K1–K5 收编路线）；**流程/时机类 → 触发器 band/hook 注入**。插件声明 moding，`EngineHost` 加载后由**每对局** `Match.Initialize` 应用；冲突沿用**栈语义、后者胜**。
- Acceptance:
  - [ ] moding **只开放游戏层 `src/Orc.Game`**；内核不新增改写口。
  - [ ] **黑名单不可 moding**：`GameUpdates`、`JudicatorNames`、`KeywordIds`、P1/P2 不变量。
- Terminology: [接入点]、[判定器]

### R10: 全面资产化的分批迁移
- Status: Confirmed
- Scenario/Trigger: 分批交付时。
- Behavior: 终局目标＝现有内置资产（19 词条 / 20 判定器 / 6 数据组件 / 效果类 / 选择器 / 规则表）全部迁为**内置插件**（随引擎发布、与三方插件同构）；**分批**推进，首批＝判定器/资产服务。
- Acceptance:
  - [ ] 首批后，判定器/资产服务可完全由插件提供（含内置项）。
  - [ ] 后续批次按清单逐步迁移，引擎核心业务资产递减。
- Terminology: [插件]

### R11: 术语登记
- Status: Confirmed
- Scenario/Trigger: 定稿后。
- Behavior: 新术语登记入 `CONTEXT.md`：**插件、卡包、包管理器、资产服务、资产名、冷加载、热加载**；并**修订「判定器」定义**（去"无状态"；作用域改启动/装配期；说明其升格为数据/逻辑储存服务）。
- Acceptance:
  - [ ] 上述术语入表且与代码/文档称谓一致。
  - [ ] 「判定器」定义修订后不再与"资产服务"冲突。
- Terminology: —
