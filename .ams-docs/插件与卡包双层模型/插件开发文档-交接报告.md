## 3. 插件契约速查（写文档的核心）

### 3.1 目录与清单

```
<pluginsRoot>/<任意目录名>/manifest.json      # kind = "plugin"
<pluginsRoot>/<任意目录名>/data/*.json        # 数据资产（约定）
<pluginsRoot>/<任意目录名>/csx/*.csx          # 逻辑资产（约定）
<pluginsRoot>/<任意目录名>/asm/*.dll          # 可选程序集（逃生舱）
<packsRoot>/<任意目录名>/manifest.json        # kind = "cardpack"
<packsRoot>/<任意目录名>/cards/*.card.json    # 卡牌数据（约定）
```
- 默认根：约定扫描 `<base>/plugins` 与 `<base>/packs`；亦可给"显式清单"（一行一个包根目录，`#` 注释）——见 `PackageDiscovery`。
- 权威 schema：`PackageManifest.cs`（字段：`kind`/`id`/`guid`/`version`/`dependsOn[]`/`assets[]`；资产：`type`/`name`/`path`/`scope`/`phase`）。

### 3.2 资产名（全局唯一）

文法：**`{类型名}：{资产名}@{包GUID8}#{版本}`**，例如 `csx：faction.service@ab12cd34#1.0.0`。
- `类型名` ＝ 加载方/来源：`json` | `csx` | `asm`
- `包GUID8` ＝ 包 `guid` 前 8 位（**包内资产全部继承包的 GUID 与版本**）
- 版本 ＝ `x.y.z`（随包版本）；**不唯一＝后者不予加载**
- 解析/格式化：`AssetName.TryParse`／`ToString()`（读宽写窄：接受全角/半角冒号与大小写）

### 3.3 作用域与相（`scope`/`phase`）

| 值 | 何时执行 | 能注册什么 |
|---|---|---|
| `scope: match`（默认）＋ `phase: preCommand`（默认） | 建局、CommandManager **之前** | 判定器／资产服务／效果 handler／moding |
| `scope: match` ＋ `phase: postCommand` | 建局、CommandManager **之后** | 经 `IMatchBindingServices`：流程触发器登记、词条效果库装配 |
| `scope: process` | **宿主冷加载期**（早于一切对局） | 经 `IGlobalRegistrationServices`：词条、数据组件 |

⚠️ 失败语义分相：`preCommand` ＝ **单包失败隔离**；`postCommand` ＝ **异常上抛（建局 fail-fast）**；`process` ＝ 单包隔离。

### 3.4 csx 写法（唯一权威：`CSharpPluginScriptEvaluator.cs` ＋ `PluginScripting.cs`）

```csharp
// csx 内：以【具名变量】Register 暴露入口，类型必须是 Action<IPluginRegistrationContext>
Action<IPluginRegistrationContext> Register = ctx =>
{
    ctx.RegisterJudicator("my.judicator", new MyJudicator());   // 返回句柄，可组合
    ctx.DeclareDependency("json:my.table@deadbeef#1.0.0");       // 条目级依赖声明
    var text = ctx.ReadAsset("my.table");                        // 读本包数据资产（沙箱禁文件 IO）
};
```
- 入口名固定 **`Register`**（`PluginScriptRequest.EntryName`，默认即 `Register`）。
- 进程级脚本用 **`IGlobalPluginContext.Global`**；后置相用 **`IMatchPluginContext.Binding`**；对局协作者用 **`IMatchPluginContext.Match`**（`IMatchServices`）。
- 受控面全部成员见 `IPluginRegistrationContext`（`RegisterJudicator`／`RegisterAssetService`／`RegisterHandler`／`DeclareDependency`／`ReadAsset`／`DeclareModing`）。

### 3.5 moding（逻辑替换）

`ctx.DeclareModing(ModingTarget.Judicator | AssetService, "目标名", args => 结果)`；
声明即登记，宿主在**该包注册完成后**应用（`ApplyModings`）；**栈语义、后声明者胜**；目标须已注册（未注册＝fail-fast）。
范围：**只开放游戏层**；黑名单＝信号名 `GameUpdates`／判定器名 `JudicatorNames`／`KeywordIds`／P1-P2 不变量（其中信号名与 `KeywordIds` 非注册表条目 ⇒ **结构性不可 moding**）。

### 3.6 版本与依赖

- `dependsOn: [{ "id": "其它包id", "version": "1.*.*" }]`；约束：第一段（主版）**精确**，第二/三段可 `*`（任意）／`^`（无下界）／`^N`（该段 ≥ N）。
- 目录**允许同一资产多版本并存**；建局时解析到具体版本并**锁定**（`AssetCatalogSnapshot.VersionLocks`）。

## 4. 卡包契约速查

- `kind: "cardpack"`；内容＝**卡牌数据**（`*.card.json`），可引用效果，也可**内联效果**（现状 `effects` 组件支持 `inline`）。
- **卡数据 schema 真源**：`src/Orc.Game/Cards/Data/Components/BuiltInCardComponents.cs`（6 个组件的字段与读/写）＋ `Orc.Game/Cards/Data/CardComponentRegistry.cs`。
- 已知取值映射：类型词 `order`→指令、`countermeasure`→反制；阵营/类型/稀有度**读侧大小写归一**（官方语料 PascalCase ↔ 规范小写 id）。
- 装配优先级：**插件效果先注册 → 卡包效果后注册**（保障"卡牌加载时其效果已存在"）。
- 热加载**默认只对新建对局生效**；把效果注入**当前**对局＝显式受控动作（`CardPackInjection.InjectEffectsAsync` ＋ 游戏层 `ICurrentMatchInjector`）。
- 追加为主；同 id 冲突＝拒绝隔离；替换/卸载/重载/回滚见 §6。

## 5. 沙箱约束（**写文档必须专章**；这些都是实测踩过的坑）

权威：`src/Orc.Script/CSharpScriptSecurityOptions.cs`；插件求值器默认在此基础上追加 `Orc.Packages`、`Orc.Plugins.BuiltIn`（见 `CSharpPluginScriptEvaluator.DefaultPluginOptions`）。

- **允许引用的程序集**：`System.Private.CoreLib`、`System.Runtime`、`System.Collections`、`System.Linq`、`System.Text`、`System.Threading.Tasks`、`Orc`、`Orc.Game`（＋插件求值器追加 `Orc.Packages`、`Orc.Plugins.BuiltIn`）。
- **允许导入的命名空间**：`System`、`System.Collections.Generic`、`System.Linq`、`System.Text`、`System.Threading`、`System.Threading.Tasks`、`Orc.Core`、`Orc.Cards`。
  → **不预置 `Orc.Game.*`**：引用游戏层类型请用**全限定名**（如 `Orc.Game.Judicators.JudicatorNames`）。
- **文本级屏蔽词**（命中即拒）：`unsafe`、`fixed`、`stackalloc`、**`Process`**、**`File`**、**`Directory`**、`Registry`、`Socket`、`WebClient`、`HttpClient`、`System.IO`、`System.Net`、`System.Reflection`、`System.Diagnostics`、`Assembly`、`Activator`、`DllImport`、`Environment`、`#load`、`#r `。
  → ⚠️ **命名禁忌**：任何**成员名/类型名**若含上述子串（如 `…Process…`）都会让脚本被拒。实例：进程级上下文成员原拟名 `Process`，因撞屏蔽词而改名 `Global`。
  → ⚠️ 需要文件内容？**必须**走 `ctx.ReadAsset("短名")`（禁直接文件 IO）。
- **超时**：默认 5000 ms（可经 `PluginScriptRequest.TimeoutMs` 覆盖）；同进程内超时＝尽力中断。
- **失败分类**（结构化返回，不抛）：`sandbox`／`compile`／`runtime`／`entry-missing`／`signature`／`timeout`。
- 定位：**弱沙箱**（同进程、非安全边界）——文档须如实写明"非安全边界"。

## 8. 已知限制与约定（写文档需如实说明）

1. **`Selectors` 不迁移**（判定结论）：`src/Orc.Game/Targeting/Selectors.cs` 是**前端/UI 契约的类型形态**（前端据 `Kind`/`SelectorNames` 选视觉实现），非业务资产 → **不在插件化范围**；`SelectorNames` 为冻结常量契约。
   > ⚠️ **2026-10-13 修订（前端资产迁移任务）**：本条**部分推翻**——「**卡/盘面投影**」（`UiCardView`/`UiMatchView`）本次被纳入插件化范围：新增 `Orc.UI.Contracts`（纯 DTO）+ `Orc.UI`（内置插件，投影提供者 + 卡包词条加载）。**`Selectors` 本身仍不迁移**（理由不变）。依据：`.ams-docs/前端资产迁移/requirements.md`。
2. **插件只能冷加载**（不可卸载／不可重载）；只有**卡包**支持热加载/卸载/重载/回滚。
3. **三方插件不享有内部访问**：`InternalsVisibleTo` 只给了内置插件；三方插件只能用 public 面 ＋ `IMatchServices`。
4. **`AssetScope.Process` 的执行时机**：内置插件走"消费方启动触发（幂等）"；外部插件走 `EngineHost` 冷加载相。
5. `^` 无数字时＝下界 0（等价 `*`）；要真下界须写 `^N`。
6. 沙箱为**弱沙箱**、非安全边界（见 §5）。
7. 未做：UI／网络／AI；强隔离沙箱；`Rarity`/`CardCategory` 之外的枚举（已全部数据化，`TriggerLayer`/`CardComponentPhase`/`MatchPhase` 等仍为枚举，属机制枚举）。
