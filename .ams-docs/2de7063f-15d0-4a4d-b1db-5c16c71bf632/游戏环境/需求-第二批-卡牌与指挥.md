# 需求 — 游戏环境第二批（卡牌与指挥）

「继续制作游戏骨架」——三大类卡牌体系、打出链、战线槽位、指挥系统、对战词条、hook 扩展、单位化。
**状态：需求 grill 已完成（2026-10-03）；进入实现 grill。**

## Scope
- Includes（本批＝功能结构全量）:
  1. **三大类卡牌基类**（单位/指令/反制；预打出＋打出〔反制仅「使用反制的触发器」〕）；基类＝**加载逻辑模板**，子类重写＋装配（持久化重建后置）；
  2. **打出链**：单位（预打出＝指挥点验证＋拖拽 targeter 空槽位；打出＝外层验证＋内层部署链＋收尾扣费）；指令（预打出可加 handler 捕获引用；打出 `object?` 参数承载**单引用/列表/targeter**）；反制（验证→扣/退点→反转激活状态＋handler 注册/注销）；
  3. **数据组件**：花费（单列）；对战（行动费/攻/防初始值）；单位（位置/已毁/类型枚举列表/三实时值）；指挥（可移动/可攻击）；词条；激活状态；
  4. **战线槽位模型**（被占/空槽位；总部占位；邻位生成、重叠去重；部署仅空槽）；**单位化**（部署触发器/加入触发器→共用单位化触发器；仅部署扣费、加入不走部署词条+扣费）；
  5. **指挥系统**：内置**指挥触发器**（拖拽＋targeter：空槽/敌单位/总部；其他禁入）＋单位移动/攻击触发器；两 bool **只在外层更新**；KARDS 规则（坦克双动/其他二选一/奋战双攻/空军炮兵任意/步兵坦克相邻/烟幕不可攻/守护）；
  6. **对战词条**（＝逻辑组件；加载时统一挂更新 hook；被动＝仅登记、主动＝除登记外作为逻辑组件；**数值由效果模块维护**）；首批 4 词条（闪击／奋战／烟幕／伏击）；
  7. **hooks 6 项**（见下）＋**触发器分层**（底层/外部；有且仅有底层触发器触发更新）。
- Excludes: 持久化与重建（卡牌总装阶段）；真实 Godot 前端；超时/取消扩展；词条扩展集；战斗数值域校验。

## 原文要点与决策记录（A~I）

**A. 三大类卡牌基类**：为单位/指令/反制各定义预打出触发器与打出触发器（反制只有一个「使用触发器」）。
- 轮1：基类的初始化逻辑（对局开始加载）定义**模板**；子类加载时从持久化文件重建 handler/效果/组件、重写相关方法、然后在触发器里挂载。
- 轮2：**持久化与重建 → 后置到「卡牌总装阶段」**（本批只做功能结构）。

**B. 单位**：预打出合法性＝检查指挥点；预打出＝拖拽离开手牌一点距离→targeter 获取空槽位→选中触发打出、拖回取消。
- 轮1：**仅部署扣费**；新增**部署词条效果**（主动触发器：被部署时检查「部署逻辑组件」、按序触发）；加入（其他途径）不走部署词条+扣费。
- 轮2：部署触发器默认检查（部署逻辑组件存在性＋handler 非空）；部署效果＝组件生成逻辑＋被动主效果（加载时生成部署组件）。

**C. 指令**：预打出默认无效果、可增 handler 捕获多个引用；打出触发器 `object?` 参数（targeter 结果由预打出传入）；主体＝空的主动 handler 集；加载时挂载、打出时触发。
- 轮3：`object?` 承载＝单引用/列表/targeter 皆可。

**D. 反制**：额外数据组件存启用状态；激活时先验证（未激活时检查指挥点）；合法→反转状态→扣/退点。
- 轮3：反制＝自己提供 handler 注册到激活触发器、取消时取消注册；无其他专门设计。
- 轮4：触发器定名＝「**使用反制的触发器**」。

**E. 数据组件**：指挥点花费单独组件；指令无其他组件。单位＝对战数据组件（行动花费/攻/防）＋单位化时挂 单位数据组件（位置/已毁/类型枚举列表/三实时值）＋指挥组件。反制＝激活状态组件。

**F. 指挥系统**：引擎内置指挥触发器（拖拽）→targeter（空槽/敌单位/总部）→移动/攻击触发器；两 bool 先读判定→执行→最后更新（只在外层）；KARDS 规则：坦克双动、其他二选一；奋战双攻；空军炮兵任意阵线；步兵坦克相邻；烟幕不可被攻击；**守护（轮2）**：相邻单位获「被守护」仅能被炮/轰攻击；守护者不可被守护；由「卡牌位置更新」hook 更新。

**G. 对战词条**：＝逻辑组件；效果加载时统一挂更新 hook。被动（仅登记）/主动（有主动逻辑，除**登记**外本身作为逻辑组件〔轮4 纠错：原「等级」为「登记」笔误〕；**数值（如重甲 2）由效果模块维护**）。四词条：
1. **闪击**：部署触发器**末尾（扣费后，轮5 定）**追加逻辑——允许单位可移动和攻击；
2. **奋战**：被动——攻击后据是否奋战/本轮是否攻击过决定还可否攻击；
3. **烟幕**：被动——决定单位能否在攻击 targeting 中被筛选调用；
4. **伏击**：主动——在「造成攻击伤害」触发器里，若被攻击单位攻击力＞攻击者防御力，则改为攻击者死亡、被攻击者不受伤。

**H. hooks**（轮4 定，6 项）：`card.load`（{Card,Player}）／`card.hand.add`（{Card,Player}）／`card.died`（{Card}；与 `card.destroyed` 并存）／`unit.joined`（{Unit,Position}）／`unit.deployed`（{Unit,Position}）／`unit.position.changed`（{Unit,OldPosition,NewPosition}）。
- **触发器分层**：底层触发器（引擎初始化注册；与 UI 沟通＋触发更新）/ 外部触发器（业务层）；**有且仅有底层触发器在合适时机触发更新**。
- **落实（轮5）**：形态 a（底层/外部标注等轻量机制）＋**主要靠自觉**（不做强拦截）；约束重心＝**底层触发器不得漏发更新**（重复更新＝性能损耗可接受；漏发＝严重）；既有管理器 Emit 视为底层体系（保持）。

**I. 单位化**：加入战场与部署都是单位化的（加单位组件＋指挥组件）；后半段共用**单位化触发器**；前段注入不同（部署触发器 vs 加入触发器）。

**J. 补充对齐（GQ2 决议，2026-10-03）**：
- **E1＝a**：移动/攻击执行时各扣**行动花费**（指挥点）；
- **E2＝a**：基础交战完整版——互相伤害 → HP≤0 死亡（`card.died`＋清理）＋攻击 HQ 掉血（胜负后置）；反击豁免体系最小化；
- **E3＝b**：**移动＝仅推进（支援线→前线）**；后撤/双向后置；
- **E4＝a**：奋战两攻由**词条自行记账**（bool 由外层更新——首次攻击后仍可攻、二次后不可）；
- **E5＝a**：分层标注＝**游戏层注册表**（机制建于 2A；指挥触发器于 2C 注册）；
