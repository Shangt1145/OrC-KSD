# 需求 — 触发器验证与 Targeter（架构改进）

架构改进需求：①为触发器引入**合法性验证**（暴露式检查 ＋ 触发前默认校验 ＋ "合法后错误兜底"契约）；②引入 **Targeter 指示器**（前端桥接的目标选择：筛选器 / 槽位 / 队列管理）。
**状态：需求 grill 已完成（2026-10-03）；进入实现 grill。**

## Scope
- Includes:
  1. **触发器合法性验证**（归属：Orc 引擎级；受控变更）：virtual 验证方法（基类默认恒合法、可选覆写）；暴露面＝接收**原始引用** → bool；每次触发由框架**固定先调用**；不合法＝**仅本次取消**（不绑视图、不跑事件、留痕）；**契约：判定合法 ⇒ 后续错误（含绑定失败）捕获处理、安全结束（返回流＋失败标记）**。
  2. **Targeter 指示器**（归属：Orc.Game；对局管理器群的一员）：Targeter（请求对象：筛选器＋槽位）＋ Targeting（执行、前端桥接等待）＋ TargeterManager（FIFO 串行队列、防冲突、取消返回失败且队列继续）；前端桥接接口（Godot 前端实现，本批 mock）。
     - 筛选器：粗筛（规则；候选＋可用性标记，**不可用置黑保留/不可选**；细筛淘汰项＝置黑保留）＋ 细筛（回调 `Func<候选, bool>` 逐项、可查游戏状态）；
     - 槽位：SingleSelect / MultiSelect(min,max)（最小集）；
     - 用法：独立 / 作为参数传递（**均允许**）；
     - 位置：尽量只在 ctxv 里 targeting；**允许 handler 内调用并写入触发器上下文**；
     - 写入双模式：扁平列表→视图 [Mutate] 属性；有槽位声明/非扁平→强类型结果直接写 ctx、按槽位强类型获取引用；
     - 产出：引用。
- Excludes: 真实 Godot UI；具体游戏规则的筛选器实现（后续按需）。

## Constraints
- 验证：Orc 引擎（现状：绑定失败原样传播 → 改为捕获，属受控变更，需迁移相关测试并标注）；
- Targeter：Orc.Game（引用 Orc；桥接接口在此定义）；
- 基于现有触发器/ContextView/对局管理器体系；委托不主动 git 提交。
