# Orc.Lua 动态 handler —— 需求阐明记录

> 委托：Orc.Lua 动态 handler 本体（e8802a93）· Grill 层级：类/功能流程级 · 本记录随 grill 逐轮增长。

## 一、需求概述（范围）

**目标**：社区 DIY 能力第一步——**动态 handler 本体**（独立组件 Orc.Lua）：基于 MoonSharp，从 Lua 脚本源定义动态 handler、C# 侧调用执行、通用动态编组（参数表进、结果值/表出）、硬沙箱＋动词白名单、结构化错误模型。

**明确范围外（后置）**：脚本加载逻辑（文件/目录/热重载）；Orc 引擎集成（适配器）；Filament.Core 直接集成（已否，规避许可风险）。

**交付形态**：`src/Orc.Lua/`（独立程序集，不引用 Orc 核心）＋ `tests/Orc.Lua.Tests/`；加入 OrcEngine.sln（仅追加）。

## 二、已阐明的需求条目

### R1. 状态模型与隔离语义（2026-10-03 · 第 1 轮确认）

- **环境单位＝脚本源**：每个脚本源初始化一次，得到独立的 Lua 环境。
- **同源共享**：同一源产出的多个 handler（按名获取的多个函数）共享该源环境及其内部状态（同源全局/模块级数据互通）——这是设计特性，不是缺陷。
- **跨源隔离**：不同源之间的 Lua 全局/模块状态、脚本定义物（函数/表等）互不可见、互不干扰。
- **调用间状态延续**：同一 handler 的连续调用可观察前次调用留下的状态（如累加计数器第二次返回累计值）；"可复用 handler 对象"的价值＝①免去重复解析/初始化；②状态延续。
- **按名获取不重执行源**：同一源被获取 N 次（含同名重复获取）＝指向同一环境/函数的等价引用；不产生 N 份独立环境。若需要独立实例，以两份源满足；显式多实例 API 为后置项。
- **白名单可见性＝宿主级共享**：同一批已注册动词对所有源一致可见；按源/按 handler 的差异化授权为后置项。
- 隔离覆盖范围：脚本侧一切（全局/模块状态、定义物）；宿主注册 API 的可用性不按源区分（本版）。

### R2. 边界项（对抗性审视补充）

- **错误隔离性**：任一 handler 的失败（编译/运行时/白名单拒绝等）不影响其他源与其他 handler 的环境与可用性。
- **并发模型**：单线程（与引擎一致）；并发调用安全、跨线程使用为后置项。
- **资源限制**：脚本执行时长/内存限制本版不做（后置——沙箱的后续维度）。

### R3. 定义与获取（支持矩阵与失败时点）（2026-10-03 · 第 2 轮确认）

- **支持矩阵（第一版）**：两种定义形态均入版——①【按名获取】按单层名字取函数；②【取执行结果】源执行结果本身是函数即得 handler。
- **按名解析空间（单层）**：先查**源执行结果**（若结果为表，取其成员）；未命中再查**源环境全局**；命中值须为函数。多级路径（如 a.b.foo）为后置增强。
- **失败时点（三层）**：
  - 初始化源：语法/编译错误、源顶层运行时错误 → **结构化失败**（源单元不可用）；不得延迟、不得抛出。
  - 获取：名字不存在 → 结构化"缺失函数"失败（**即验即败**，不允许"先拿引用、调用才失败"）；命中非函数、或"取执行结果"而结果非函数 → 结构化失败。
  - 调用：运行时/编组/白名单类错误的暴露点（获取阶段已通过的验证不重复承担）。
- 工程口径：参数误用（null 等）可抛参数异常（编程性错误），与脚本错误的结构化返回区分。

### R4. 宿主流程与产出物形态（2026-10-03 · 第 2 轮确认）

- **流程语义**：初始化（以源建立可复用单元）→ 获取（取函数得 handler）→ 调用（handler 可反复调用）；三步语义可分解（错误时点按阶段定义，见 R3）。
- **入口步骤数不锁**："源＋函数名一步直达"等便利形态**不强制要求**（实现自由，不作硬验收）；验收＝功能语义正确（得到符合 R1 状态/隔离语义的可调用 handler）。
- **"可调用"边界（第一版）**：仅 C# 方法调用形态（参数包进、结果出）；转换为 C# 委托/回调形态＝**后置项**。

### R5. 白名单与沙箱行为规格（2026-10-03 · 第 3 轮确认）

- **注册（宿主侧）**：白名单注册为**组件实例级**（同进程多实例各自独立、无全局单例）；注册项为**可调用值（动词）**；注册名支持**点分层级**（如 `orc.combat.play` → Lua 侧对应嵌套可调用值）；根命名空间可配置（默认 `orc`）；**同名重复注册＝拒绝**（宿主配置错误，显式失败）；**约定在源初始化之前完成注册**（运行期增删注册的语义为后置项）。
- **访问控制（统一气质：越界即显式失败）**：
  - 白名单域（`orc.*`）中**未注册名字**：读取（索引）或调用**均须失败**，分类＝**白名单拒绝**（不得静默返回 nil 任脚本误用）。
  - **禁用面**（io、os、package、debug、require、loadstring、loadfile、dofile、print、collectgarbage 等）：访问（读取或调用）**均须失败**，分类＝**沙箱限制**。
  - **保留面**（string、math、table 与基础函数 pairs/ipairs/type/tostring/tonumber/pcall/error/assert 等）：保证可用，**须有测试验证**（沙箱不误伤对照组）。
  - 不得经由 `_G`、元表等间接途径访问未注册/禁用主体（一致性为硬要求）。
- **失败语义**：白名单拒绝与沙箱限制均以结构化错误**使该次调用整体失败**（未捕获路径必然暴露给宿主、分类正确）；**允许脚本以 pcall 捕获**（Lua 机制使然，组件不对抗脚本捕获）；关键不变量——**无论如何，未授权主体永远不会被实际调用成功**（能力永不授予）。
- **宿主回调**：注册项可指向宿主回调（可调用值）；验收观察＝Lua 侧调用成功并拿到回调结果 ＋ 宿主侧可观察被调用；**回调签名/形态属实现自由**，语义要求（可调用、结果可回传、错误不炸穿并纳入结构化错误模型）为约束。

### R6. 调用输入输出与编组语义（2026-10-03 · 第 4 轮确认）

- **调用契约（参数表）**：Lua handler 总是收到**恰好一个表参数**（所有 C# 侧参数合并为单表）；无参数调用时传入**空表**（非 nil）。参数表为**字符串键（命名参数）**；位置式（1-based 数组）为后置项。
- **输入编组覆盖（第一版）**：标量（数值/字符串/布尔）、null、字符串键字典（表）、序列列表（数组，1-based 表）、以及它们的**嵌套组合**；输入面**不支持类型**（宿主自定义对象、委托等）＝结构化**"参数编组错误"**（调用失败、不抛）。
- **返回值形态**：结果＝**第一个返回值**（多返回时其余忽略）；**nil 返回＝成功＋空结果**（非失败）。
- **输出编组覆盖（第一版）**：标量、nil→空、表→**自适应**：纯序列（1..n 连续数字键、无字符串键）→列表；其余（含混合、空）→字典（字符串键保真；数字键落座由实现选择并在汇报说明）；嵌套递归同规则。**特殊类型（函数/线程/用户数据）→ 结构化编组错误**（调用失败、不抛）。
- **值语义（快照式）**：参数与返回值均为**值拷贝式编组**——Lua 侧修改收到的参数表不影响宿主原对象；宿主修改返回结果不影响 Lua 侧内部状态。与 R1 的关系：**跨边界传递＝数据快照**；R1"状态延续"作用于**源环境内部**状态，两者互补不冲突。（"活引用/代理穿透"明确不做；如有需要为后置项。）
- **边界补充**：循环引用/超深嵌套结构不在支持面（实现应防御、不无限递归；处理方式由实现选择并在汇报说明）；数值遵循 Lua double 语义（大整数精度损失由实现说明）；编组为值拷贝（快照语义的固有成本，无专门性能指标）。
- **错误归属口径**：编组失败属结构化错误（不抛）；API 层误用（方法参数为 null、名字为空等）仍可抛参数异常（编程性错误）——与 R3 口径一致。

### R7. 结构化错误模型（2026-10-03 · 第 5 轮确认）

- **公共承载**：第一版公共契约＝**统一结果对象**——成败判别 ＋ 载荷（成功＝编组后的结果值；失败＝结构化错误信息）；验收以该统一形态断言；实现内部类型组织属实现自由。
- **错误信息最低集**：**分类**（结构化、可按类型/枚举断言） ＋ **人类可读消息**为必选断言面；**来源/位置**（行号、堆栈、阶段等）为"应尽力提供"项、**非第一版硬断言面**（可含于消息；避免测试耦合具体格式）。
- **分类清单（第一版冻结，六类）**：脚本编译/语法错误、运行时错误、缺失函数、**编组错误**（含入/出双向——入＝"参数编组错误"、出＝"返回值编组失败"）、白名单拒绝、沙箱限制。
- **多项错误重叠口径**：以"使该次调用失败的最终未捕获错误"为准（被捕获且脚本正常完成的错误不构成失败——例：越界被 pcall 捕获后正常返回＝调用成功）。
- **异常边界**：**必不抛**＝六类失败全部场景（初始化/获取/调用三阶段的脚本与数据错误，含编组失败）——一律以结果对象返回；**可抛**＝API 层宿主编程性误用（现有示例：null/空参数、空名字、重复注册；原则＝"违反调用契约"；完整清单由实现者按原则细化并在汇报说明）。
- **失败后可用性**：①初始化失败的源单元＝**不可用**（后续获取/调用一律立即结构化失败、不得部分工作）；宿主可丢弃并以（同一或修正后的）源重新初始化（重试无限制、产生全新单元、无状态残留）。②同一 handler 一次调用失败后**仍须可用**（与 R2 错误隔离性一致）；**不要求状态回滚**（失败前已执行部分对环境的修改保留——Lua 语义、与"状态延续"一致）。
- **附加数据**：错误信息中的附加数据（涉及的名字/类型等）为可选增强（实现自由）。

### R8. 白名单写保护与沙箱面收口（2026-10-03 · 第 6 轮确认）

- **白名单域写保护（能力不可篡改）**：脚本对白名单域（`orc.*` 命名空间）的**任何写入**——新增未注册成员、覆盖已注册成员、覆盖子层级、覆盖根命名空间本身（如 `orc = {}` / `orc = nil`；含经 `_G` 等间接途径）——一律**失败**，分类＝**白名单拒绝**；失败暴露语义与 R5 一致（未捕获必然失败返回；pcall 可捕获）。
- **局部遮蔽不受约束**：`local orc = ...` 等局部变量遮蔽为合法 Lua 语义，不受写保护约束（读写自由）。
- **写保护列入第一版验收**（白名单/沙箱测试组：写拒绝用例 ＋ 局部遮蔽正例）。
- **沙箱面清单收口**：
  - 禁用面：R5 所列＝**最低要求清单**（实现**可增不可减**）。
  - 保留面：R5 所列（string/math/table＋基础函数）＝**必须可用**的最低集；**未列出的标准库/函数默认按最小暴露处理（不提供）**，实现如需保留须在汇报中说明（且不得违反沙箱底线）。
  - "保留面须测试可用"的最低覆盖＝R5 所列；其余保留项不强制测试（实现汇报说明）。
- **源单元初始化语义（可验收表述，细化 R1"两份源满足"）**：**每次初始化动作＝全新独立环境**（与源文本内容相同与否无关）；"需要独立实例"＝对（同一或不同）源文本**执行两次初始化**（产生两个互不可见的环境）。

### R9. 执行模型收口（并发与重入）（2026-10-03 · 第 7 轮确认）

- **线程模型（可验收表述）**：组件**不承诺线程安全**；使用假设＝同一组件实例的一切操作（初始化/获取/调用）由调用方保证在**同一线程串行**执行；"并发调用安全"的准确含义＝**同一线程内的重入/嵌套调用行为定义良好**（见下），**非**多线程安全。
- **跨线程＝全部不承诺（后置）**：不同组件实例跨线程、不同源跨线程、同一环境跨线程均不承诺、不测试；违反单线程假设的并发使用＝不受支持（未定义）；实现侧以单线程假设处理（无同步、无锁），假设与限制在汇报中说明。
- **无并发测试**：第一版不以并发/线程用例验收（以单线程使用假设为准）。
- **重入（同一线程）**：**允许**脚本→宿主回调→再调用 handler（同源/异源均可）的嵌套重入；**无特别禁止清单**（如"回调内重新初始化源""回调内获取 handler"均合法）；重入时环境状态延续照旧（同一环境、串行嵌套）。
- **回调失败落点**：宿主回调**抛异常** → 该次调用以**运行时错误**失败（消息应尽力表明回调来源）；回调**返回不可编组值** → **编组错误**；两者均**不炸穿宿主**、且**允许脚本 pcall 捕获**（与 R5 一致，未捕获则调用失败返回）。
- **验收面**：重入基本情形（回调内再调用 handler）与回调失败两分类（异常→运行时错误、不可编组值→编组错误）**列入验收**；跨线程/深层嵌套/其余细节＝实现侧处理并汇报。

### R11. 错误分类映射矩阵补全与交互留白（2026-10-03 · 第 9 轮确认）

- **初始化阶段失败矩阵（按实质分类）**：
  - 语法/编译错误 → **编译/语法错误**；
  - 源顶层运行时错误 → **运行时错误**；
  - 源顶层越界（访问未注册名 / 禁用面）→ 对应分类（**白名单拒绝 / 沙箱限制**）；
  - 顶层越界经 pcall 捕获且源正常完成＝初始化成功（沿 R7 重叠口径）。
- **获取阶段失败矩阵**：名字不存在、命中非函数、取执行结果而结果非函数（含 nil）→ **统一归"缺失函数"类**（语义＝获取失败：未获得可用函数）。
- **不可用单元的后续操作**：以**复现初始化失败的原分类**为失败结果（不再执行任何操作）；测试按原分类断言。
- **调用参数包 null 边界**：不提供参数 / 空字典 → 空表（正常，沿 R6）；**显式 null → 可抛参数异常**（API 层误用，沿 R7 示例清单）。
- **禁用面写保护（对照组）**：脚本对禁用面**名字**的写（如 `io = {}`）＝**失败（沙箱限制）**——与读/调用口径一致（名字整体封锁）；`local` 遮蔽＝自由（对称 R8）。
- **参数表键合规性**：**顶层参数包键须为字符串**；非字符串键（数字键等）→ 结构化**"编组错误"**（调用失败、不抛）；嵌套容器内序列（列表）不受此限（R6 已允许）；**列入验收覆盖**。

### R12. 验收覆盖矩阵收口（2026-10-03 · 第 10 轮确认）

- **最低覆盖（下限，必测）**：
  - 六类错误每类 ≥1 例；**初始化/获取/调用三阶段全覆盖**（允许同例叠加维度）；
  - 委托 AcceptanceCriteria 与 Requirements 测试 6 项**逐条可指认**（名称级证据映射）；
  - 所有"已注明列入验收"的既有条目（R8 写保护＋局部遮蔽；R9 重入＋回调失败两分类；R11 参数键合规）。
- **本轮新增列入验收**：
  - **失败后可用性**：同一 handler 一次失败后可再次调用（成功）＋ 不回滚（失败前已执行的状态修改保留可观察）；
  - **不可用单元**：初始化失败后的获取/调用复现原分类；
  - **快照语义正/反例**：宿主修改返回对象不影响脚本内部状态；Lua 修改参数表不影响宿主原对象；
  - **多组件实例独立**：两实例的白名单互不干扰；
  - **契约细节组**：无参调用＝空表（列入）；从执行结果取函数（列入）；**显式 null ＝断言抛参数异常**（"可抛"收口为"以参数异常暴露"）；**禁用面写失败**（并入白名单/沙箱测试组）；
  - 保留面可用与局部遮蔽正例：并入相应测试组（R5/R8）。
- **不要求测试（实现侧处理＋汇报）**：跨线程/并发、深层嵌套重入细节、循环引用与超深嵌套防御、位置/来源信息、性能指标。
- **测试组织**：文件划分/用例命名/数量＝实现自由（建议与现有测试项目风格一致）；对外以"名称级证据映射"验收。

### R13. 访问控制外延与边角核查（2026-10-03 · 第 11 轮确认）

- **保留面外延（必须可用）**：R5 原列之外，**补入 `next、select、unpack`**（纯读/纯计算、无越界能力）。
- **禁用面扩展（必须不提供、访问即失败·沙箱限制）**：**raw 系**（`rawget/rawset/rawlen/rawequal`——与"索引即拒/写即拒"的拦截式访问控制根本冲突，必然不提供以免绕过）、**元表操作对**（`setmetatable/getmetatable`——可改造/窥探表与环境行为，保护环境完整性；受控开放为后置）。
- **间接途径口径**："不得经 `_G`、元表等间接途径"中的"**等**"**明确覆盖 raw 系、元表路径及任何其它绕过路径**；统一原则＝**任何路径访问未注册/禁用主体、或修改封锁域，均失败**；分类按被触达边界（禁用面/绕过原语→**沙箱限制**；封锁域→**白名单拒绝**）。经 `next`/`pairs`/`_G` 的**枚举面**不得用于获取未授权能力；被封锁内容不得经枚举被读取/修改（实现按最小暴露处理、汇报）。
- **raw 写路径**：含 `rawset` 在内的一切写路径对封锁名的写入均被禁止（名字整体封锁/能力不可篡改含 raw 路径）；由于 raw 系不提供，该路径实际不可达。**列入验收**（沙箱组：raw/元表系访问＝沙箱限制用例）。
- **空源字符串**：`""`＝**合法**（空 chunk、初始化成功、结果 nil；后续获取→缺失函数）；与"显式 null 源→可抛"的边界区分（空内容≠null）。
- **宿主回调返回 C# null**：→ Lua 侧 **nil**（正常回传，非"不可编组值"）；回调的参数/返回值编组**复用 R6 双向类型面**（无额外规则）。
- **域存在性**：白名单域**始终存在**（与注册数无关）；**读域本身合法**（根名是域引用，非"未注册成员"）；域下任何未注册成员（0 注册时即全部）→ **白名单拒绝**；写域本身仍失败（沿 R8）。

## 三、逐轮 Q&A 与决策记录

### 第 1 轮：状态模型与隔离语义（2026-10-03）

**子的问题（要点引录）**：

- 主问题一："调用间状态隔离"的准确落点——（1）约束"不同 handler 之间"，还是同时约束"同一 handler 的多次调用之间"？（2）"重复调用"的期望：同一 handler 连续两次调用，第二次能否观察到第一次在 Lua 侧留下的状态（如闭包变量累加计数器）？"有状态可复用"与"每次调用全新状态"期望哪一种？（3）若期望"每次调用全新状态"，"可复用的可调用 handler 对象"的复用价值是否仅为"免去重复解析脚本源"？
- 主问题二：（1）"多个 handler 可并存"的来源——每源产出可调用 handler（多源并存），还是也允许"同一源中按名获取多个函数、各自成为并存 handler"？（2）若允许同源多 handler：共享同一 Lua 环境，还是各自独立环境？"同一源被获取 N 次"是否意味着"独立执行 N 次、各自得到独立环境"？（3）"隔离"还约束哪些东西必须互不可见（宿主注册的 API、脚本定义的其他函数）？还是仅针对"Lua 侧数据/状态"？

**回复（裁决）**：

- 主问题一：（1）约束的是**不同 handler 之间**（隔离边界＝源）；**不**约束同一 handler 的多次调用——后者**状态延续**。（2）"重复调用"期望＝**有状态可复用**：第二次调用可以观察到第一次留下的状态（计数器返回累计值）。（3）"复用对象"价值确认＝免去重复解析/初始化 **且** 状态延续（不止"免解析"）。
- 主问题二：（1）允许同源按名产出多个 handler（与"一源一 handler"并存）。（2）同源 handler **共享源环境**；"同一源被获取 N 次"＝同一环境中的等价引用，**不**独立执行、**不**产生独立环境（需要独立实例时以两份源满足）。（3）隔离约束"脚本侧一切"跨源互不可见；宿主注册 API＝宿主级共享（非按源隔离项）；差异化授权为后置项。

**备选方案与拒绝原因**：

- 备选 A「每次调用全新状态（纯函数式）」：**拒绝**——每次调用重建环境/重载源成本高；违背 Lua 闭包语义与 mod 作者直觉；确定性/回放诉求由未来引擎集成层的显式状态通道解决（后置）。
- 备选 B「handler 级隔离（同源各函数独立环境）」：**拒绝**——与"源＝一个作者的模块"直觉冲突（同一文件内函数互不可见）；需重执行源 N 次；隔离的本来的目的＝防跨源干扰。
- 备选 C「单一全局共享环境（不隔离）」：**拒绝**——社区脚本互扰、命名冲突，违背安全目标。
- 备选 D「按源差异化白名单授权」：**后置**（本版宿主级共享）。

### 第 2 轮：定义与获取支持矩阵（2026-10-03）

**子的问题（要点引录）**：

- 主问题一：支持矩阵、解析空间与失败时点——（1）"按名获取 Lua 函数"与"从执行结果取函数"两种形态：第一版是否要求两者都支持，还是至少其一、另一个可选/后置？（2）"按名"在哪个空间解析（源执行后返回值/模块表字段、环境全局、还是两者，优先级？）；名字是否要求多级路径（a.b.foo），还是只要求单层？（3）失败时点：源语法/编译错误在"定义/初始化"阶段还是调用阶段暴露？"按名获取"不存在的名字：获取阶段立即失败，还是先拿引用、调用才失败？"结果非函数（数字/表）"期望什么行为？
- 主问题二：宿主流程与产出形态——（1）流程是否为"先建可复用加载单元（环境）→按名取函数得 handler→可反复调用"？是否也要求"源＋函数名一步直达 handler"？验收是否只关心功能语义、不锁入口步骤数？（2）"从执行结果取函数"是否仅指"结果本身是函数"？结果是表、从表按名取是否归入"按名获取"（本质区分＝直接取结果值 vs 按名字取成员）？（3）"可调用"边界：仅 C# 方法调用？还是也要求转换为 C# 委托/回调（是否后置）？

**回复（裁决）**：

- 主问题一：（1）**两者都支持、均入第一版验收**。（2）按名＝**单层解析**，顺序为「源执行结果（若为表）成员 → 环境全局」；多级路径后置。（3）失败时点分三层——初始化（语法/编译、顶层运行时错误）→ 结构化失败；获取（名字缺失、命中非函数、结果非函数）→ 即验即败、结构化；调用 → 仅运行时/编组/白名单类。
- 主问题二：（1）流程理解**准确**（初始化→获取→调用三步语义）；"一步直达"不强制要求、不作硬验收，验收只关心功能语义。（2）"从执行结果取函数"＝**直接取结果值且本身是函数**；从结果表按名单层成员**归入"按名获取"**（本质区分＝直接取结果值 vs 按名查找）。（3）第一版仅 C# 方法调用形态；委托/回调转换为**后置项**。

**备选方案与拒绝原因**：

- 备选 A「支持矩阵只保其一（仅按名 或 仅结果函数）」：**拒绝**——"源返回函数"与"全局命名函数"均为主流写法，缺一即限制脚本风格；两形态实现同源、成本低。
- 备选 B「多级路径（a.b.foo）入第一版」：**后置**——单层（结果表成员＋全局）已覆盖主流写法；多级为增强，且与"结果表按名取"边界易混淆，统一后置。
- 备选 C「名字缺失允许延迟到调用时失败」：**拒绝**——延迟失败难定位；未验证引用无价值；获取即验。
- 备选 D「委托/回调转换入第一版」：**后置**——属引擎/宿主集成维度（与 Orc 事件签名对接相关），超出"动态 handler 本体"最小范围。

### 第 3 轮：动词白名单与硬沙箱的行为规格（2026-10-03）

**子的问题（要点引录）**：

- 主问题一：白名单注册与访问的宿主/Lua 双侧形态——（1）注册动作的形态与归属：何时注册（建立组件/宿主对象时，还是任意时刻均可）？注册表是"组件实例级"还是"进程/全局级"（多实例是否彼此独立）？同名重复注册的期望行为（覆盖/拒绝/未定义）？（2）Lua 侧访问形态与命名："命名空间风格如 orc.*"的可调范围（仅根名前缀可换，还是层级结构也包含）？默认根名是否即为 orc？注册项在 Lua 侧是否就是对应命名空间下的可调用值、没有其他包装？（3）"未注册访问必须失败"的准确边界：脚本"读取"未注册名字（只索引不调用）与"调用"未注册名字的期望行为？"必须失败"至少覆盖哪一种，还是两者都要？
- 主问题二：失败行为与错误分类边界——（1）"白名单拒绝"发生后的执行语义：该次调用是否整体以结构化错误返回宿主？脚本可否以 pcall 捕获并继续/静默吞掉？期望"可捕获"还是"必须暴露给宿主不可静默"？验收口径？（2）两个错误分类的边界：访问未注册 orc.* 名＝白名单拒绝；脚本访问/调用被禁库（io/os/package/debug/require 等）＝沙箱限制触发，还是表现为普通运行时错误（归"运行时错误"）？"等"的外延清单（require/loadstring/loadfile/dofile/print 是否在禁用面）？保留面（string/math/table 等）是否要求测试验证仍可用？（3）"宿主回调可达/可被 Lua 调用"的验收口径：注册宿主回调后，验收期望观察到什么？宿主回调的签名（参数、返回）属需求约束还是实现自由？

**回复（裁决）**：

- 主问题一：（1）注册＝宿主侧、**组件实例级**（多实例彼此独立、无全局单例）；注册项＝**可调用值（动词）**；**约定在源初始化之前完成注册**（运行期增删注册的语义为后置项）；**同名重复注册＝拒绝**（宿主配置错误，显式失败）。（2）根命名空间**可配置**（默认 `orc`）；**支持点分层级**（层级注册名 → Lua 侧嵌套可调用值）；注册项就是对应命名空间下的可调用值、**无其他包装**。（3）**两者都要覆盖**：读取（索引）与调用未注册名均须失败——统一"越界即显式失败"，不得静默返回 nil 任脚本误用。
- 主问题二：（1）**未捕获路径**：该次调用以结构化"白名单拒绝"整体失败返回宿主（必然暴露、分类正确）；**允许脚本以 pcall 捕获**（Lua 机制使然，组件不对抗脚本捕获、不承诺不可捕获）；关键不变量＝**无论如何，未授权主体永远不会被实际调用成功**（能力永不授予）。验收＝未捕获路径的结构化失败与分类正确 ＋ 不变量检查。（2）分类边界：白名单拒绝＝`orc.*` 域未注册名访问；**沙箱限制**＝禁用面（io/os/package/debug/require/loadstring/loadfile/dofile/print/collectgarbage 等）访问——**均以结构化"沙箱限制"失败（不归笼统"运行时错误"）**；保留面（string/math/table 与基础函数）**须测试验证可用**。（3）宿主回调验收＝Lua 侧调用成功并拿到回调结果 ＋ 宿主侧可观察被调用（测试标记）；**回调签名/形态属实现自由**（语义约束：可调用、结果可回传、错误不炸穿并纳入结构化模型）。

**备选方案与拒绝原因**：

- 备选 A「注册表进程/全局级单例」：**拒绝**——违背多实例隔离哲学（与 LogicEngine 多实例、组件独立性一致）。
- 备选 B「注册名仅单层」：**拒绝**——宿主 API 组织需要层级（如 orc.state.get），点分注册成本低、表达力必要。
- 备选 C「未注册读取返回 nil（宽松）」：**拒绝**——静默通过、拼写错误延迟暴露、分类不可控（与"不得静默"冲突）。
- 备选 D「白名单拒绝做 pcall 免疫（对抗脚本捕获）」：**拒绝**——军备化超出范围且与 Lua 机制常识相悖；组件义务＝未捕获路径必暴露 ＋ 能力永不授予。
- 备选 E「禁用面以自然 nil 移除（不报错）」：**拒绝**——"沙箱限制"分类将失去触发场景、与"越界即显式失败"不统一。
- 备选 F「宿主回调签名定为需求约束」：**拒绝**——形态属实现自由；需求只锁语义（可调用、可回传、错误安全）。

### 第 4 轮：调用的输入输出形态与编组语义（2026-10-03）

**子的问题（要点引录）**：

- 主问题一：参数包的形态与编组覆盖范围——（1）"参数以『参数表』传入"的准确落点：Lua handler 是否总是收到"恰好一个表参数"（所有 C# 侧参数合并为单表）？无参数调用时是"传空表"还是"不传参数（函数收到 nil）"？（2）参数表的键空间：仅字符串键（命名参数）？还是也要求位置序列（1-based 数组）？还是第一版只需支持其一？（3）编组类型覆盖：标量（数字/字符串/布尔）、嵌套表、数组式表是否都须支持？C# 侧输入值的类型集合？不支持的类型（宿主自定义对象、委托等）作为参数时，期望＝结构化"参数编组错误"（调用失败、不抛）还是可抛 Argument 异常（宿主误用）？
- 主问题二：返回值形态与值语义——（1）返回值编组：只须处理单返回值，还是多返回值也要有明确行为（取第一个？结构化失败？后置）？Lua 返回 nil 时的期望（成功＋空结果？）？（2）"表 → C#"映射到什么（字典、列表、还是混合自适应）？嵌套表与空表如何处理？"函数引用等特殊类型（函数/线程/用户数据）"的处理：实现者选定并汇报即可，还是需求期望某一类行为（如统一结构化失败）？（3）值语义（快照 vs 活引用）：参数与返回值是否都是快照式编组——Lua 侧修改收到的参数表不影响宿主侧原对象；宿主侧修改返回结果不影响 Lua 侧内部状态？还是要求某种"双向可见/活引用"？

**回复（裁决）**：

- 主问题一：（1）**总是恰好一个表参数**；无参数调用传**空表**（非 nil）。（2）**字符串键（命名参数）**为第一版契约；位置式（1-based 数组）后置。（3）第一版输入面＝标量＋null＋字典表＋序列表＋嵌套组合；不支持类型＝**结构化"参数编组错误"**（调用失败、不抛）。
- 主问题二：（1）结果＝**第一个返回值**（多返回其余忽略）；nil＝**成功＋空结果**。（2）表→**自适应**（纯序列→列表；其余含空→字典；嵌套递归；数字键落座实现选择+汇报）；特殊类型（函数/线程/用户数据）→**结构化编组错误**。（3）**快照式**：参数与返回值均为值拷贝编组——跨边界互不穿透；与 R1"状态延续"互补（延续的是源环境内部状态，跨边界只传数据快照）；"活引用/代理穿透"明确不做（后置）。

- 主问题一：（1）**按实质分类**：编译/语法→编译/语法错误；顶层运行时→运行时错误；顶层越界→对应分类（白名单拒绝/沙箱限制）。（2）三情形（不存在/非函数/结果非函数含 nil）→ **统一"缺失函数"**（语义＝获取失败：未获得可用函数）。（3）**复现初始化失败的原分类**（不再执行、直接以原失败结果为答）。
- 主问题二：（1）不提供/空字典→空表（正常）；**显式 null→可抛参数异常**。（2）**写禁用面名＝失败（沙箱限制）**（与读/调一致、名字整体封锁）；local 遮蔽自由。（3）**非字符串键→结构化"编组错误"**（不抛）；列入验收；嵌套序列不受限。

**备选方案与拒绝原因**：

- 备选 A「初始化阶段一切失败统一归'编译/语法错误'」：**拒绝**——误导定位（顶层运行时/越界有更准确类别）；分类矩阵价值在按实质归置。
- 备选 B「命中非函数归'编组错误'」：**拒绝**——编组＝值跨边界转换失败；"未获得可用函数"是获取失败，语义不同。
- 备选 C「不可用单元后续操作用固定分类」：**拒绝**——丢失根因信息（初始化因沙箱失败会被误报为固定类）；复现原分类信息量最大、断言最稳。
- 备选 D「显式 null 宽容为空表」：**拒绝**——与 R7"null/空参数可抛"示例清单冲突；显式传 null 属调用契约违反。
- 备选 E「禁用面写允许（只拦读/调）」：**拒绝**——名字封锁应整体（写而不可读自相矛盾；统一"越界即显式失败"）。
- 备选 F「非字符串键静默忽略」：**拒绝**——"不得静默"；宿主参数被丢弃难察觉。
- 备选 G「非字符串键透传（事实支持位置式）」：**拒绝**——与 R6"位置式后置"矛盾；先例语义混乱。

### 第 10 轮：验收覆盖矩阵的最终收口（2026-10-03）

**子的问题（要点引录）**：

- 主问题一：已确认的边界需求哪些列入第一版测试验收、哪些仅"实现侧处理＋汇报"——（1）失败后可用性（失败后可再次调用、不回滚）与不可用单元后续操作（复现原分类）？（2）快照语义（互不穿透）是否要求正/反例测试？（3）多组件实例注册表独立是否要求测试？（4）契约细节组：无参＝空表（成功路径，其理解必验）、显式 null＝异常、从结果取函数（成功路径，其理解必验）、禁用面写失败——null 参数与禁用面写是否列入验收？（5）保留面可用与局部遮蔽正例是否直接并入相应测试组？
- 主问题二：覆盖最低要求与组织原则——（1）最低覆盖＝"六类错误每类至少一例、验收标准与测试 6 项逐条可指认"为下限；R1–R11 其余条目按"已注明列入验收者必测、未注明者尽力覆盖"？（2）测试组织（文件/命名/数量）＝实现自由、仅以名称级证据映射对外验收？

**回复（裁决）**：

- 主问题一：（1）**均列入验收**（失败后再次调用成功＋不回滚；不可用单元复现原分类）。（2）**列入**（正/反例各一）。（3）**列入**（两实例白名单互不干扰）。（4）无参＝空表、从结果取函数：**列入**（其理解正确）；**显式 null：列入（断言抛参数异常——"可抛"收口为"以参数异常暴露"）**；**禁用面写失败：列入**（并入白名单/沙箱组）。（5）**确认**（并入相应测试组）。
- 主问题二：（1）**采纳并补**：下限＝六类各≥1＋**三阶段全覆盖**（可叠加）＋委托 6 项逐条可指认；其余条目分三层——"已注明列入验收者必测"；可测行为契约"应有覆盖（省略须汇报）"；非行为性/实现侧＝不要求。（2）**确认**（组织自由；名称级映射对外）。

**备选方案与拒绝原因**：

- 备选 A「快照语义不测（自明）」：**拒绝**——"互不穿透"是易错点（实现常犯拷贝遗漏），正/反例便宜且高价值。
- 备选 B「显式 null 允许两可（抛或结构化）不测」：**拒绝**——两可无法断言；收口为"参数异常"使边界可测（与 C# 惯例一致）。
- 备选 C「多实例独立不测」：**拒绝**——"无全局单例"是 R5 关键不变量，双实例用例是唯一直接证据。
- 备选 D「失败后可用性只测'可再次调用'、不回滚不测」：**拒绝**——"不回滚"是易误判行为（实现者可能擅自回滚），需正面断言。
- 备选 E「覆盖要求减到'只保委托 6 项'」：**拒绝**——逐轮新增的行级契约（写保护/重入/键合规等）若无覆盖会系统性退化为"口头约定"。
- 备选 F「锁定测试文件划分与命名」：**拒绝**——组织属实现自由；名称级映射已足以验收。

### 第 11 轮：访问控制外延与边角核查（2026-10-03）

**子的问题（要点引录）**：

- 主问题一：保留面外延与间接绕过口径——（1）"基础函数……等"的外延：raw 系（rawget/rawset/rawlen）、setmetatable/getmetatable、其他常用（next/select/unpack 等）各为"必须可用/必须不提供/实现选定并汇报"？（2）rawget(_G,"io") 等间接路径的期望结果与分类？"等"是否明确覆盖 raw 系与元表路径？（3）rawset 写路径是否必须失败？列入验收还是实现防御＋汇报？
- 主问题二：两个边角与一个一致性确认——（1）空源字符串 ""：合法（空 chunk、结果 nil、后续缺失函数）还是空参数误用（可抛）？（2）宿主回调返回 C# null：Lua 侧得 nil 还是"不可编组值"→编组错误？回调参数/返回值编组是否复用 R6 双向类型面？（3）无任何注册时：白名单域是否仍存在（可读域本身；域下未注册→白名单拒绝）？

**回复（裁决）**：

- 主问题一：（1）**三档**：必须可用＝R5 原列＋`next/select/unpack`；**必须不提供＝raw 系＋元表操作对**（并入禁用面）；其余未列＝实现选定（默认最小暴露，沿 R8）。（2）**raw 系必然不提供**（访问即沙箱限制），该路径不可达；"等"**明确覆盖** raw/元表/任何绕过路径；统一原则＝任何路径访问未授权主体或修改封锁域均失败，分类按被触达边界。另补枚举面条款。（3）**写保护含 raw 写路径**（原则层面）；raw 系不可用使路径不可达；**列入验收**（raw/元表系访问＝沙箱限制用例）。
- 主问题二：（1）**空源合法**（空 chunk；非误用；与 null 边界区分）。（2）**返回 null→nil**（正常回传）；编组**复用 R6 双向面、无额外规则**。（3）**域始终存在**；读域本身合法；域下未注册（含 0 注册）→白名单拒绝；写域仍失败。

**备选方案与拒绝原因**：

- 备选 A「raw 系保留（要求封锁为物理移除）」：**拒绝**——白名单"索引即拒"语义依赖拦截层，raw 读会拿到 nil 而非拒绝（语义破坏）；不提供才与既有语义自洽。
- 备选 B「元表操作受控开放（保护敏感目标、其余允许）」：**拒绝**——第一版复杂度不划算（黑名单目标机制）；OOP 有闭包替代；受控开放记后置。
- 备选 C「raw/元表系访问返回 nil（静默）」：**拒绝**——"不得静默"气质；沙箱限制（显式失败）一致。
- 备选 D「空源＝可抛误用」：**拒绝**——空内容≠null；空 chunk 是合法 Lua 语义；宽容处理零成本。
- 备选 E「回调返回 null＝编组错误」：**拒绝**——null→nil 是自然映射（与输入面"null"覆盖一致）；"不可编组"仅指类型不可映射。
- 备选 F「0 注册时域不存在」：**拒绝**——域存在性与注册数无关（拦截层/域引用恒定）；否则访问行为随注册数变化、语义不稳。
