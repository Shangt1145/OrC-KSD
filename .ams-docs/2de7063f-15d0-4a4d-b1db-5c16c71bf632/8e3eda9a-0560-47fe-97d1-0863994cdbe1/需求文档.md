# S3 总线与更新 — 需求阐明记录

> 委托：S3『总线与更新』（Orc 库）· 对齐级别：类/功能流程级（GranularityLevel=class）。
> 用途：沉淀需求阐明——功能职责、约束、验收标准、已解决歧义；技术实现由实现者自主。

## 一、功能职责（本阶段）

1. **总线（Bus）**：按更新字符串分槽的订阅容器；负责被动触发器的挂载（Mount）、按所有者卸载（UnmountOwner）、更新广播（Emit）。只做广播，不做逻辑编排。
2. **更新类型**：字符串常量集（内置便利常量 + 允许任意自定义非空白字符串）+ 载荷字典；总线**不做更新类型注册/白名单**（开放集合）。
3. **更新入流**：Emit 时把更新作为条目（kind=update）写入事件流（发射者流/总流）。
4. **被动触发器挂载**：触发器在构造期声明 hook；Mount 时总线读 hook 列表注册订阅；同更新的多触发器按「挂载优先级 + 注册序」执行。
5. **引擎壳扩展**：LogicEngine 持总线 + 总事件流；多实例语义保持。

## 二、核心契约（本阶段已阐明）

### 2.1 触发器侧：hook / Kind / Owner（第 1 轮阐明）

- **hook 声明时机：仅构造期**（不提供运行期注册 hook 的 API；S4 不需要——效果装载＝对已构造触发器做 Mount、注入＝事件注册；未来如需再议）。
- **构造期一致性校验**：
  - `Kind=Active` 且 hooks 非空 → **拒绝**（矛盾声明：主动触发器不挂载；且会干扰"效果→主动/被动"分类）。
  - hooks 每项：空串 / 纯空白 → **拒绝**；同列表中重复项 → **拒绝**。
  - `Kind=Passive` 且 hooks 为空 → **允许构造**（可存在、不可挂载；保持 S2 中 Kind=Passive 可独立存在的语义）。
  - （错误类型实现者定，须在汇报中标注。）
- **Kind 语义**：保持 S2 不变（默认 Active、运行期可读）；S3 仅新增上述校验与"挂载条件"关联。
- **Owner**：触发器级声明、构造期给定、可选（object），默认 null；null=无所有者，**合法**。

### 2.2 总线侧：Mount / UnmountOwner / Emit

- **Mount(trigger) 拒绝集**（完整）：
  1. trigger 为 null → `ArgumentNullException`；
  2. Kind=Active → 拒绝；
  3. hooks 为空 → 拒绝；
  4. 该触发器已处于挂载状态 → 拒绝（防重复挂载导致双执行；卸载后状态复位、可再次挂载）。
- **挂载优先级**：触发器级声明（int；框架提供参考常量集，拟案 High=100 / Normal=0 / Low=-100，可调）；同一更新下排序＝挂载优先级 + 注册序兜底。
- **UnmountOwner(owner)**：
  - owner 为 null → 拒绝（`ArgumentNullException`；不把 null 特判为"无主"）。
  - 移除该 owner 跨**所有**更新字符串的全部挂载；卸载不打断在途 Emit 轮次（快照语义）。
  - 本阶段**仅此一种卸载途径**（无单触发器 Unmount）；owner=null 的被动触发器不可卸载＝**已知边界**（后续如需，另议）。
- **Emit(updateType, payload?, ct)**（完整契约见 2.6）：
  - updateType 为 null → 拒绝；空串/纯空白 → 拒绝；payload 为 null 视为空载荷。
  - 顺序 await 各订阅者（单线程）；执行期间注册/卸载变化不影响本轮（快照）。
  - **更新入流**：写入"发射时的当前执行者流"（在触发器执行中发射）；无执行帧（引擎边界）→ 写入引擎总流。
- **被动触发器的事件流挂载点**：被更新激活的执行流挂载到"发射时的当前执行者流"（无则总流）——沿用 S2 执行帧机制。

### 2.3 受控变更边界

- Trigger 构造签名：在现有 4 个可选参数（name / kind / bandType / events）**之后追加**可选参数（hooks / priority / owner）；**旧调用形态（省略或具名）保持完全可用**；不得改动既有参数的顺序、名称、类型。
- 旧行为保持：Kind 默认 Active、运行期可读（S2 语义）。若个别既有用例需调整，属受控变更并须在汇报中列出。

### 2.4 明确不做（防误扩展）

- 总线不做更新类型注册/白名单、不做订阅者并行、不打断在途轮次。
- 不禁止被动触发器被 `InvokeAsync` 直接调用（保持 S2 自由；语义上预期经总线激活）。

### 2.5 总线归属与引擎绑定（第 2 轮阐明）

- **一对一绑定**：每个 LogicEngine 实例恰持有一个总线（`engine.Bus` 只读、不可替换）；总线**不可脱离引擎**独立存在（测试场景＝创建引擎实例后经其获得总线）。总线经所属引擎触达总事件流（用于边界入流与顶层挂载）——该可达性是绑定关系的需求来源。
- **多实例互不相通**：多引擎实例之间总线完全独立（订阅表、广播、总流均不共享）；引擎 A 的广播与失败不影响引擎 B。
- **「已挂载」状态＝触发器实例级**：同一触发器实例同一时间只能挂在一个总线上（跨总线重复挂载拒绝；卸载后复位，可再挂）。
- **engine.Emit 便捷转发**：同时提供（与 Bus.Emit 完全一致、纯转发，含入流目标流判定）。
- **引擎壳形态**：保持 sealed / 多实例 / 无单例；RootStream 命名保持；Bus 为公开只读属性。
- **公开读面（最小）**：提供"查询某更新字符串的订阅者有序快照"（与执行序一致；未知更新返回空；用于调试与测试断言）；其余检视能力不做。

### 2.6 Emit 行为契约与更新条目观测面（第 3 轮阐明）

- **签名与返回**：`Task Emit(string updateType, IReadOnlyDictionary<string, object?>? payload = null, CancellationToken ct = default)`——顺序 await 全部订阅者后完成；**返回 Task，不返回流聚合**（被动执行的流信息经事件流树观察：发射者流/总流的子流与条目）。
- **取消**：ct 传入并传递给订阅者的执行；Emit 入口先检查——已取消＝直接抛（不写条目、不广播）；任一订阅者传出取消类异常（含 ct 触发）→ **停止后续订阅者、原样向上穿透**。
- **更新条目构成**（kind=update）：source＝`"bus"`（固定）；message＝更新类型文本；keywords＝[更新类型字符串]（扁平）；data＝载荷字典（原样键值）；level＝Info。
- **时序与流捕获**：更新条目在广播前**先写**（同流内先于各订阅者的挂载/执行条目）；"发射时的当前执行者流"在 Emit 被调用一刻**捕获一次、整轮固定**；嵌套 Emit 各自按各自发射点捕获；引擎边界时：总流上先 update 条目、再各订阅者流 attach。
- **订阅者激活**：以 payload 为执行数据调用该触发器的统一入口（`InvokeAsync(engine, payload)`）；payload 键值原样成为本次执行 ctx 数据；**框架不注入保留键、不占键名**（是否需要"更新类型"等上下文由载荷自行携带）。
- **失败记录流向**：订阅者执行传播出的非取消异常（含绑定失败/载荷缺必填键）→ 记录进**发射者流**（与 update 条目同处；source 标识该订阅者），并继续后续订阅者；条目形态沿用 S2 隔离记录同构（kind=log、level=Error、keywords 含异常类型名——与 S2 现状一致）。

### 2.7 排序契约与订阅读面形态（第 4 轮阐明）

- **排序规则**：同一更新的多订阅者执行顺序＝「挂载优先级**降序（数值大者先）**」→「注册序**升序（先挂先执行）**」。（注意：与 S2 触发器内部事件排序的升序方向相反——band 是"阶段序号"、挂载优先级是"介入优先级"，两者语义不同，勿混淆。）
- **注册序**：＝触发器被 Mount 的时点序号；同一更新的订阅序在 Mount 时确定。触发器构造时 hooks 的声明顺序仅决定"注册到哪些更新的订阅表"，与同一更新内排序无关；一个触发器挂多个更新时，其注册序在各订阅表内一致。
- **重挂**：卸载后状态完全复位（含注册序）——重新挂载视为新的 Mount 时点，排到当时挂载序列的最后（同优先级内）；不保留旧序。
- **优先级声明**：触发器构造参数（随"末尾追加可选参数"），默认 Normal=0；**任意 int（含负值）合法，不设界、不拒绝**；优先级声明后不可变（运行期不可改；需变更＝卸载后以新优先级重挂）。
- **参考常量集**：固定常量类名 `UpdatePriorities`，成员 `High`/`Normal`/`Low`（拟值 100 / 0 / -100；属"可修订的常量"，非运行期可配置）；不做更多档位；**纯参考——不作为取值校验依据**。
- **订阅读面**：给定更新字符串 → 返回其订阅者**有序只读快照**（顺序与执行序一致；元素＝触发器标识（展示名；未命名时以视图类型名退化））；"快照"＝调用时点的一致副本（其后挂载变化不影响已返回快照）。**不提供**"触发器→更新"的反向查询（后续如需可加性扩展）。

### 2.8 更新常量集 / owner 匹配 / 留痕范围 / 验收⑥口径（第 5 轮阐明）

- **更新常量集 `Updates`（固定形态）**：类名 `Updates`（Updates.cs），成员与值固定——`CardPlaced = "card.placed"`、`CardDestroyed = "card.destroyed"`、`CardData = "card.data"`、`EffectRemoved = "effect.removed"`；如实现中发现需要调整（值/成员名），按受控变更在汇报中提出。使用者自定义字符串与常量**平等**（总线不做注册/白名单）。
- **载荷模型**：载荷＝`IReadOnlyDictionary<string, object?>` 字典（既有形态的说明，**不新增类型**、无包装/构建辅助）。类型化载荷属后续演进（加性）。
- **载荷键**：框架**不提供**内置载荷键常量；键名由使用者自定义并与视图声明对齐（后续阶段如确立标准载荷约定，可再增设——加性）。
- **UnmountOwner 匹配语义**：**引用相等（ReferenceEquals）**——owner 语义＝"所有者对象身份"（卡牌/效果等实例的唯一归属）；避免 Equals 重写/字符串等值导致的误匹配。值语义归属应使用专职 owner 对象。
- **留痕范围（S3 增量）**：除 ① Emit 的 update 条目、② 订阅者失败错误条目外，**Mount / UnmountOwner 动作本身也自动写 kind=log 条目**（source=`"bus"`；message 含动作与目标标识；keywords 含动作标识如 `"mount"`/`"unmount"` 及目标标识）；写入"当前执行者流（无则总流）"（与 Emit 同规则）。留痕不影响快照语义；噪音可用关键词过滤（阅读工具）。
- **验收⑥断言口径**（"引擎壳（总线暴露、总流联动）"）：
  1. `engine.Bus` 可达（非空、只读、实例稳定——同一引擎两次访问同实例）；`engine.Emit` 与 `bus.Emit` 行为等价（含入流目标流判定）；
  2. 引擎边界 Emit（无执行帧）→ update 条目落**总流**、被动执行流挂**总流**；
  3. 触发器执行中 Emit（有帧）→ update 条目落**发射者流**、被动执行流挂**发射者流**（入流目标判定的帧内情形，与 2 配对覆盖）；
  4. 多引擎独立：A 的挂载/广播不影响 B；多实例无单例；
  5. 总流可达性：任意订阅者执行的条目/挂载经冒泡均可达总流（RootStream 可完整枚举"条目+子流"）。

### 2.9 公共面增量边界 / 留痕边界 / 标识语义（第 6 轮阐明 · 方法级）

- **公共面增量完整清单**（S3 全部，此外不擅自扩展）：
  1. `Trigger`：构造参数追加 hooks / priority / owner（**不新增公共只读属性**——这些声明值仅内部使用）；
  2. `Bus`：类型 + `Mount` / `UnmountOwner` / `Emit` / 订阅查询读面（契约见下）+ 留痕语义；
  3. `LogicEngine`：`Bus` 属性 + `Emit` 便捷转发（**仅此两项**；不新增订阅查询转发、不新增 RootStream 之外的暴露）；
  4. `Updates` / `UpdatePriorities` 常量类。
- **订阅查询读面（方法契约）**：形态由实现者择定（示例：`IReadOnlyList<string> GetSubscribers(string updateType)`）；语义固定——有序只读快照（与执行序一致）、元素＝触发器**标识（展示名）**；空订阅/未知更新返回空列表。
- **触发器标识（展示名）语义**：`Name` 非空白时用 `Name`，否则以视图类型名退化标识；读面与留痕共用此语义；同名不做消歧（原型）。
- **留痕边界**：
  - `UnmountOwner` **未命中（无任何挂载）不写留痕**（无实际变更；幂等路径）；Mount 成功时写、卸载命中时写；异常路径不写。
  - 留痕目标流规则与 Emit **完全一致**：写"当前执行者流（无则总流）"（触发器事件内动态 Mount 时＝该执行者流）。
  - **卸载留痕粒度：每个受影响触发器一条**（与 Mount 对称）；同一 owner 重复卸载（第二次起未命中）不写。
- **留痕条目 keywords**：Mount＝[`"mount"`, 触发器标识, 各挂载更新字符串…]；Unmount＝[`"unmount"`, 触发器标识, 各涉及更新字符串…]（扁平字符串列表）。
- **update 条目断言形态（测试③切切断言）**：message＝更新类型字面值（如 `"card.placed"`）；keywords＝**恰为单元素** `[updateType]`（无附加词）；data＝载荷键值（内容一致）；**payload 为 null 时 data 为空字典**。

### 2.10 更新字符串同一性 / 留痕细节 / 错误条目 source（第 7 轮阐明 · 方法级）

- **更新字符串同一性**：订阅匹配为 **ordinal 序数、大小写敏感、逐字符原样比较**（不做文化敏感比较、不做大小写折叠）；**不做任何归一化**（不 Trim、不去空白）——"card.placed "（尾空格）与 "card.placed" 是不同更新、互不匹配（但两者都通过非空白校验、都可使用）。（实践提示：使用 `Updates` 常量可规避拼写/大小写问题。）
- **留痕条目（Mount / Unmount）**：level＝**Info**；message 最低要求＝含动作词与目标标识的可读文本（**具体措辞不作硬性规定**；机器断言以 keywords 为准）。
- **订阅者失败错误条目**：source＝该订阅者的**展示名（纯）**——与读面/留痕一致；**不含事件名等附加信息**（失败发生在执行入口/绑定阶段，无事件上下文）。
- **不双重记录**：订阅者事件内的非取消异常由 S2 内部隔离记录（入订阅者自己的流，经冒泡可达总流）；总线层**只记录"传播出来的"失败**（绑定失败、Translate/契约异常、其它入口阶段异常）——同一失败不会在总线层产生第二条记录。
- **级别汇总**：update 条目＝Info；Mount/Unmount 留痕＝Info；订阅者失败＝Error。

### 2.11 动作 API 返回值 / 留痕顺序 / keywords 次序（第 8 轮阐明 · 方法级）

- **Mount 返回 void**：成功即完成（注册已生效）；失败抛异常。无返回信息（调用方持有所声明信息，无需回传）。
- **UnmountOwner 返回 void**：**API 不承诺区分"命中/未命中"**（有意设计：幂等清理语义；两者均无异常）。观测路径：命中时有留痕条目（经事件流查看）、读面/行为可反查；未命中无留痕。**（本条取代第 6 轮备选理由中"经返回值/无异常即可感知"的表述。）**
- **卸载留痕多触发器相对顺序**：不作硬性要求（测试以集合式断言："存在这些条目"）；实现宜保持确定性（同状态同顺序）。
- **Mount 留痕 keywords 的更新字符串次序**＝触发器 hooks 的**声明顺序**；构成完全确定（动作词、标识、声明序更新字符串），**可按等值断言**（沿用"keywords 无隐藏附加词"原则）。
- **公共面增量清单（收口）**：Mount / UnmountOwner 返回 void，属 2.9 清单第 ② 项既有构成，**不新增公共面**；其余不变。

## 三、逐轮 Q&A 记录

### 第 1 轮 · 类/功能流程级 · 触发器侧契约（hook/Kind/Owner/受控变更）· 2026-10-03

**子的问题（原文）**：

> ■ 主问题（hook 声明形态与 Kind 一致性）：Requirements 第 2 条说"触发器直接声明其要挂载的更新字符串（构造参数或注册 API，取更简形态）；hook 列表非空即被动语义（与 TriggerKind 一致）"。请阐明这句话的准确语义与校验方向：
> (1) "hook 列表非空即被动语义"——当构造时 hook 非空但 Kind=Active 时，期望行为是哪一个：a) 构造期直接拒绝（参数非法，因为二者矛盾）？b) 允许构造但 Mount 时拒绝？c) hook 非空时框架自动认定/视作 Passive（即 Kind 由 hook 推断，与显式声明的 Kind 无强制一致关系）？
> (2) 反向：Kind=Passive 但 hook 为空是否允许"存在"（可构造、不可挂载，或等待运行期注册 hook）？还是也要求构造期拒绝？
> (3) Kind 仍保持"默认 Active、运行期可读"的 S2 语义不变，对吗？（即 S3 只增加"Passive+hook 才能挂载"的关联，不改变 Kind 自身含义。）
>

**阐明（决定）**（汇总见"2.11"节）：
