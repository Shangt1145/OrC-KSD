> 委托：游戏环境第二批『后置项补全』（A 反击豁免 / B 胜负判定 / C 前线阻挡 / E 注释同步 ＋ D/F 核对锁定）。

## 一、委托范围要点（定稿基线）

- **A 反击豁免**：判定表〔目标＝轰炸机→永不反击；攻击者＝炮兵→不受任何反击；攻击者＝轰炸机→不受反击、例外：目标＝战斗机可反击；其余正常反击〕；同时互伤框架；与伏击改写组合：改写优先、未改写按表；攻击 HQ 不属交战。
- **B 胜负判定**：HQ≤0 → 立即终局（状态＋胜者＋全部动作入口拒绝；其后效果不再处理）；超杀暂不记录。
- **C 前线阻挡**：推进前置＝前线无敌方单位；轰炸机拦截＝目标战线有敌战斗机则该战线非战斗机目标置黑。
- **D 移动（决策：不做扩展）**：**不做后撤、不做横移**；普通单位（位于己方支援线）的指挥 targeter 目标范围＝前线（推进→前线空槽；攻击→前线敌方单位按矩阵）。
- **E 注释同步**：移动候选＝前线空槽、无后撤/横移候选；同类"位置语义后置"注释同步为终态口径。
- **F 反制位置（决策：不做激活区）**：激活/取消＝纯状态翻转＋费用；**卡保持手牌位置不变**；**可重复激活**。
- 核对锁定：D/F 相关"不做"需核对＋防回归锁定。

### Round 2（2026-10-04）

#### 【主问题】反击豁免×伏击改写的仲裁原则

**子问题原文（摘要）**：已交付的伏击改写判定＝"被攻击单位（目标侧）含伏击 ∧ 目标实时攻击力＞攻击者实时防御力 → 攻击者死亡、被攻击者不受伤；条件不成立＝按默认结算"。本批把默认互伤从"零特例"改为"按豁免表结算"。请阐明仲裁原则：**豁免是否约束改写成立**（改写命中时是否还需检查"按豁免表该目标原本可否反击"）？还是改写完全独立（命中即替代互伤、豁免表仅在未改写时参与）？典型冲突场景：①攻击者＝炮兵/轰炸机（不受反击）攻击带伏击目标——改写能否照常命中？②目标＝轰炸机（永不反击）带伏击被攻击——改写能否命中？

**父方裁定**：
- **仲裁原则＝豁免约束改写（先资格、后条件）**：伏击改写属"防御方回击"类机制（KARDS 基线中伏击系"先对攻击者结算反击"的强化形态，受反击豁免与压制体系约束）——改写"成立"的完整前提＝**（目标方按豁免表具有反击资格）∧（伏击条件命中）**。
- 判定次序：①按豁免表判定目标方反击资格；②**无资格** → 不发生反击、**改写不成立**、按表结算（单方伤害）；③**有资格** → 检查伏击条件：命中＝改写（攻击者死亡、被攻击者不受伤）；不命中＝按表正常同时互伤。
- 对委托文本的澄清："改写优先级 0 成立则替代默认互伤"中『**成立**』含『豁免资格通过』前提（优先级 0 描述触发链内事件顺序）；"未改写按豁免表结算"覆盖『无资格』与『条件不命中』两种情形。
- 备选：改写独立于豁免（命中即替代）——**拒绝**（依据：KARDS 基线中伏击∈反击体系且受豁免/压制约束〔冲击克制伏击〕；若伏击穿透豁免，豁免表语义被击穿、克制循环失真——与"整体模仿 KARDS"总纲冲突）。

#### 【子问题 1】场景一细化（攻击者＝炮兵 / 轰炸机）

**父方裁定**：
- 攻击者＝**炮兵**攻击带伏击目标：**改写不成立**（目标无反击资格）→ 按表结算：攻击者不受任何反击、目标正常受伤；攻击者不会死亡。
- 攻击者＝**轰炸机**攻击带伏击的**战斗机**：战斗机具反击资格（表内例外）→ 检查伏击条件：**命中 → 改写**（轰炸机死亡、战斗机不受伤）；不命中 → 按表正常互伤（战斗机反击轰炸机）。
- 攻击者＝**轰炸机**攻击带伏击的**非战斗机**：无资格 → 改写不成立 → 按表：目标单方受伤、轰炸机不受反击。

#### 【子问题 2】场景二细化（目标＝轰炸机带伏击）

**父方裁定**：
- 目标＝轰炸机（永不反击）带伏击、被步兵/坦克攻击：**改写不成立**（无反击资格）→ 按表结算：轰炸机不反击、正常受伤；攻击者不受伤。

#### 【子问题 3】多类型单位判定口径

**父方裁定**：
- 判定＝**按 UnitTypes 列表逐条套用豁免表；任一相关条款适用即适用；条款冲突时以『豁免（不发生反击）』优先**（仅当全部相关条款均允许反击时，才有反击机会并进入伏击资格判定）。
- 示例：攻击者含炮兵＋轰炸机攻击战斗机 → 不受反击（炮兵条款的绝对豁免优先于轰炸机条款的例外）；目标含轰炸机＋炮兵被步/坦攻击 → 不反击（轰炸机"永不反击"优先于炮兵"被步/坦会被反击"）。
- 依据：豁免语义＝"攻击方式的保护／防御方的弱点"；多类型叠加时保护取更强、不作中和。

### Round 3（2026-10-04）

#### 【主问题】"立即终局"的检查时机与"当次结算收尾"边界

**子问题原文（摘要）**：攻击 HQ 致 HQ≤0 的当次攻击，其收尾步骤（扣费、攻击者行动状态更新、奋战记账、本次结算链内的死亡清理等既定步骤）是否照常完成？"其后所有效果不再处理"的可观测验收口径（此后不再处理什么）？

**父方裁定**：
- **检查时机**：HQ 生命≤0 的判定发生在该次 HQ 伤害结算点；**当刻置对局为结束态＋记录胜者**（"立即"的可观测点）。
- **当次结算收尾＝照常完成**：该次攻击的既定收尾步骤（扣费、攻击者行动状态更新与奋战记账、本次结算链内的死亡清理等）属"当次结算"的组成部分——**不因终局被拒**（内部步骤不经对外门禁）——完成后整链返回。
- **"其后不再处理"边界**：收尾完成后——不再发起/执行任何新处理：不执行后续效果、**不再产生任何新更新（更新流不再增长）**、不再接受任何对外动作入口调用（见子问题 1）。
- **可观测验收口径**："不再处理"以**状态冻结**断言——①此后动作入口全部被拒（零副作用、状态不推进）；②无新更新、无状态/组件变动；③查询面保持可读且稳定。
- 备选：HQ 归零瞬间连收尾也中止——**拒绝**（与委托文本"当次结算收尾后不再进行后续处理"相悖；收尾属当次结算；中止收尾会留下扣费/状态不一致的中间态）。

#### 【子问题 1】门禁清单与拒绝形式

**父方裁定**：
- **A. 拒绝清单（终局后）**：①回合推进（EndTurn）；②指挥入口（拖拽指挥开始）；③打出链各入口——单位预打出（开始/取消/确认）、单位打出/加入入口、指令预打出/打出、反制激活/取消；④移动/攻击流程（含其触发器级对外入口；验收以"对外面拒绝"为准）；⑤对局初始化/卡牌加载链（"卡牌加载"＝对局初始化加载链；**不得再 Initialize/加载**）；⑥**Targeter 发起（新入队）**——即时失败、零副作用（"等"含 Targeter）。

- **C. 拒绝形式**：沿用各入口既有失败模式（抛错或失败结果均可）——**统一验收口径＝"拒绝且零副作用、状态不推进"**（不要求统一异常类型）。
- 备选：统一异常类型/统一结果码——**拒绝**（无需求依据；增加无谓改造面）。

#### 【子问题 2】胜者记录语义与可读面

**父方裁定**：

### Round 4（2026-10-04）

#### 【主问题 ①】推进前置的表现面（敌占线时）

**子问题原文（摘要）**：敌方占线（前线存在敌方单位）时，己方单位推进的"动作可用性/候选面"如何表现（推进不可用、移动候选为空；敌方清空前线上全部单位后自动恢复）？执行兜底（分派后复验）是否同样拒绝（防御性双保险）？

**父方裁定**：
- **前置条件精炼表述**＝"前线不存在存活敌方单位"（空前线或己方已占均可）。
- **表现＝候选面剔除**：不满足时，"推进到前线"路径**不进入 targeter 候选面**（移动候选为空；前线物理空槽不作为移动候选）；攻击候选（前线敌单位等）不受影响。
- **恢复＝实时计算**：敌方清空前线全部存活单位后，**下一次候选查询即恢复**（无需额外动作或事件）。
- **执行兜底＝是（防御性双保险）**：分派后、执行移动前复验前置条件；不满足 → 拒绝（零副作用、不消耗行动状态）。与既有复验基调一致。
- 备选：仅候选层约束、不设执行复验——**拒绝**（与批次内既有"候选＋确认全程受约束"基调不一致）。

#### 【主问题 ②】轰炸机拦截的筛选面

**子问题原文（摘要）**："该战线的非战斗机目标不可选（置黑）"是否包括该战线的敌方 HQ（敌方支援线存在存活敌方战斗机时，轰炸机能否选择敌方 HQ）？"存在敌方战斗机"是否以存活为限？多条战斗机共存时是否不引入额外优先级？

**父方裁定**：
- **包括 HQ**：拦截以"目标所在战线"为判定域——HQ 位于敌方支援线、属该战线目标；敌方支援线存在**存活**敌方战斗机时，轰炸机**不可选该战线 HQ**（须先攻击战斗机）。依据：基线"目标战线"涵盖 HQ 所在支援线。
- **以存活为限**：死亡/不在场不计。
- **多条共存＝无额外优先级**：该战线战斗机均可选、其余目标全部不可选（不区分"必须打哪一条"）。
- 表现口径：后端＝候选面不产出/不可确认（与粗筛"置黑"机制语义一致）；前端置黑显示。

#### 【子问题 1】适用主体与流程面

**父方裁定**：
- **仅轰炸机攻击者**：炮兵/战斗机/步兵/坦克的攻击筛选不受拦截约束。
- **候选面＋确认面全程**：交互中的确认同样受同一筛选约束（确认前复验；非仅候选展示层）。

#### 【子问题 2】清空判定与恢复时机

**父方裁定**：
- "清空"＝**前线无任何存活敌方单位**（纯实时判定；不引入"曾占据"标记等额外状态）。
- 判定为**实时计算**：清空后下一次候选查询即恢复（无需额外动作）。

#### 【子问题 3】范围边界（"进入前线"的路径面）

**父方裁定**：
- 前置约束**仅作用于"支援线→前线"的推进**。
- **部署**（必然入支援线）与**加入**（调用方驱动的特殊通道）**不直接受该约束**。
- **边界记录**：本批"进入前线"的常规路径＝推进（唯一需检查者）；若未来加入路径被用于"直接进入前线"的场景，需另行对齐是否施加同一前置（**本批不施加、不视为缺陷**）。

**【父方补注】**：拦截与"守护保护 HQ"为并行多层保护（互不冲突）；终局门禁（Round 3）生效后，前线相关判定不再被调用（全部入口拒绝覆盖）。

#### 【子问题 2】覆盖深度

**子问题原文（摘要）**：①豁免表"全组合"深度＝四类关键场景＋常规组合即可，还是两两全排列矩阵级？②伏击×豁免三态（改写命中／有资格条件不命中／无资格）是否须覆盖？③多类型冲突判定用例是否纳入？④终局门禁六类入口逐一拒绝用例还是代表性覆盖；"更新流冻结"与"重复查询稳定性"断言是否纳入？

**父方裁定**：
- **① 覆盖口径＝"判定表每条规则分支≥1 用例"**（语义等价类覆盖）：四类关键场景（目标＝轰炸机〈永不反击〉／攻击者＝炮兵〈不受反击〉／攻击者＝轰炸机×目标战斗机〈例外〉／常规步·坦·机互攻）＋常规组合代表性交叉（含"被步/坦/机攻击时炮兵反击"）；**不要求机械两两全排列**（同语义组合冗余，拒绝理由：维护负担＞信息增量）。
- **② 伏击×豁免三态＝是**：改写命中／有资格但条件不命中（→正常互伤）／无资格（→改写不成立、按表单方结算）三态均须用例。
- **③ 多类型冲突＝是**：至少覆盖 Round 2 所举两例——攻击者含炮兵＋轰炸机攻击战斗机 → 不受反击；目标含轰炸机＋炮兵被步/坦攻击 → 不反击。
- **④ 终局门禁＝六类入口逐一拒绝用例**（每类至少一条；可指认性优先）；**"更新流冻结"与"重复查询稳定性"＝纳入**（终局验收断言）。

#### 【子问题 3】防回归锁定形态与回归方式

**子问题原文（摘要）**：三条锁定是否要求负面断言形式——候选永不含支援线内部槽位/前线内槽位；激活/取消前后卡保持手牌同一位置（含"卡位置不变性"）；反复翻转费用对账（激活扣一次、取消退一次、不重复）？回归执行＝完整运行三项目测试全绿？

**父方裁定**：
- **三类锁定均以负面/不变式断言形式落地**：
  - 无后撤/无横移——候选与入口层负面断言：移动候选中**不含任何"支援线内部槽位"与"同线移动"产物**（支援线单位移动候选仅含前线空槽；前线单位无移动候选）；
  - 不做激活区——**卡位置不变性**：激活/取消前后，反制卡在手牌中的位置（保序集合内位置）不变；
  - 可重复激活——**费用对账**：连续多轮激活↔取消，每轮"激活扣一次、取消退一次"、无重复扣退，点数对账一致。
- **回归执行＝完整运行三项目**（Orc.Tests、Orc.Lua.Tests、Orc.Game.Tests）全绿。
- **补充口径**：验收证据＝每验证点至少一条**可指认测试**（测试名可定位）；汇报含"验收矩阵表"（验证点→测试名→断言摘要）。
