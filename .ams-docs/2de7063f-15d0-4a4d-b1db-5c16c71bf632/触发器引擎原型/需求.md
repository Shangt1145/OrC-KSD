# 需求 — 触发器引擎原型

为 Godot C# 游戏提供后端逻辑引擎（组件式风格）的"原型"：按设计文档规定的简化级别落地核心框架，作为后续迭代地基。本需求定义其定位、范围与完成标准，作为原型开发与验收的依据。
**状态：需求 grill 全程完成（2026-10-03）；原型 S1~S5 已交付并验收通过（详见 实现.md / 原型完成总结报告.md）。对话记录删除后，本文件为需求基线。**

## Scope
- Includes:
  - 触发器引擎核心机制（设计文档全量核心）：生命周期引用（Ref/Lifetime）、上下文（Context）、声明式视图（ContextView）、触发器（Trigger）、总线（TriggerBus）、优先级、异步/中断、日志。
  - 用户骨架（2026-10-03 第 1~13 轮澄清，终态）：
    - **卡牌**：薄容器（数据放数据组件、逻辑放逻辑组件）。
    - **数据组件**：游戏内强类型类 + 类主导的外部 JSON 序列化/反序列化，可产出序列化快照。
    - **逻辑组件＝效果**（术语合并）：挂在卡牌上的逻辑封装；组成＝主触发器＋附带的逻辑引用。主触发器为主动 → **主动效果**（法术/一次性效果等）；为被动 → **被动效果**（可能与场上单位绑定）。
      - 挂载：把其被动触发器挂载到总线；挂载逻辑同时 hook"效果移除"并注册专属移除逻辑；注册/注销属模板代码，需（最小）工具化。
      - 示例"攻击时回血"（被动效果）：主触发器 hook 放置类更新 → 单位初始化后注入回血 handler 到攻击流程对应位置；hook"效果移除"→ 取消注册、清理。
    - **逻辑引擎**：①维护总线驱动逻辑；②产出事件流并从引用提供快照，供 UI 端消费。
    - **总线**：只负责广播更新（如"放置单位"等），是中间层，不做逻辑编排。
    - **触发器**：逻辑的起点（主动/被动）；内部注册多个事件、按优先级（band 体系）顺序触发；一个触发器只有一个 ContextView，产出的 ctx 被全部事件共用（解决"引用隐式依赖"，用户称"关键设计"）。
    - **事件**：原子逻辑 = handler；可改写 ctx 数据；事件内可触发其他触发器。
    - **ContextView（=转接器）**：触发器唯一数据契约；接收引擎引用与额外参数，产出 ctx。主动触发器触发函数可重载（支持传入额外参数），其 ContextView 负责转接（手写 Translate；引用可变/值不可变；可透传）。
    - **Hook**：时机点；触发器内部维护 hook 列表；被动触发器借此挂载在总线上。
    - **更新**：总线广播消息，如"放置单位""card.destroyed""card.data""effect.removed"。
    - **编排演进**：原型阶段硬编码编排（C#）；后续开发 csx/gds 脚本接口 + 继承模式；社区 DIY 走 Lua 动态 handler（见 Lua-DIY/）。
  - S4/S5 澄清补充（第 9~13 轮，终态）：
    - **流程结构＝乙**：攻击流程（**发起方**：反制检查→调用伤害结算→收尾）与伤害结算流程（**承受方**：护盾检查结算→伤害生效）分离；施放流程＝法术（主动效果）经发起链调用伤害结算。
    - **band**：C# 枚举（成员可指定值）；二选一保护（默认枚举 or 专门枚举；显式 band 拒 default；允许覆盖零）；排序键＝band 值×1000＋内优先级＋注册序。
    - **扩展点＝具名 band**；注入＝把 handler 注册到流程触发器的具名 band（+装载登记自动撤销）。
    - **装载链路**：`card.placed` →（单位初始化先）→ 效果装载；`effect.removed`/`card.destroyed` → 清理。
    - **容器 API**：`AddData/GetData<T>`、`AddEffect/Effects`；**最小封装＝Effect 基类**（OnMount/OnUnmount）。
  - 执行结构示例（用户给出）："造成伤害"主动触发器被激活 → 内部事件 [护盾检查和结算（优先级高）→ 伤害生效] 按序执行 → ctx 被改写 → 触发更新。
  - 输出/交互契约（第 7~13 轮，终态）：
    - 程序只产出事件流 + 数据快照，供外界消费。
    - 四形式：①C# 桥接主动调用外部 API；②暴露 API；③回调模式；④JSON 产物。**原型仅完善 JSON，其余为骨架。**
    - JSON 模式＝a 事件流输出（树形）+ b 数据快照输出（单实体从引用导出 + 全量）。
    - 后续演进记录：回放支持（事件/帧/回合驱动的时间段快照）；阅读工具两版（.csx / py，前置＝格式定稿）。
  - 原型验证载体：**测试集承载全部演示场景**——场景 1（火球/护盾/反制/中断）、场景 2（攻击时回血）、场景 3（部署/移除链路）。
- Excludes: 游戏规则本身/网络同步/UI；脚本化编排（csx/gds）与完整工具化；数据组件 JSON 载入；完整日志系统；回放（后续）。

## Constraints
- 语言/平台：C# (.NET 8+)；Godot C# 游戏（引擎为后端类库）。
- 架构风格：组件式（卡牌=薄容器；"Unity ECS"所指＝组件式组织，非 DOTS）。
- 原型简化级别：反射视图 / 单线程 / Task。
- 输出纯净性：只产出事件流与数据快照，无 UI/渲染耦合。
- 实施方式：逐阶段委托（CodeImplementation + grill），串行推进；委托不主动 git 提交。
