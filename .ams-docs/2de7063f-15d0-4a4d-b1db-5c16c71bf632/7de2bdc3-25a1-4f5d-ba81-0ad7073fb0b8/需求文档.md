# Targeter 指示器 — 需求阐明记录（类/功能流程级）

> 本文档记录 Targeter 委托（Orc.Game）grill 阶段的需求阐明：功能职责、流程与数据流契约、边界与失败模式、验收要点。技术实现细节由实现阶段自主，不在本文档。
> 对齐方式：子 agent 逐轮提问 → 裁定 → 逐轮累积；本文档为需求一致性基准。

## 1. 目标与范围

在 Orc.Game 实现对局内目标选择框架（Targeter 指示器）：

- 业务方（ctxv / handler）以 Targeter 请求对象发起 targeting；
- 经 TargeterManager 排队、经前端桥接等待玩家完成选择（拖拽 / 复选 / 取消）；
- 经两级筛选（粗筛 / 细筛）确定允许集，按槽位结构产出引用；
- 结局三态（成功 / 取消 / 失败），不抛异常；本批以 mock 桥接测试（不含真实 Godot UI）。

## 2. 核心组件与职责（类/流程级）

### 2.1 Targeter（请求对象）
- 职责：承载一次目标选择的参数（筛选器、槽位〔**可缺省**——缺省＝单一选择；见 §3〕）；**唯一发起入口＝其 Targeting（异步）方法**（内部自动经 Manager 排队与桥接等待）。
- 复用：允许串行多次使用（每次独立执行、独立结果）。

### 2.2 Targeting（执行流程）
- 流程：入队 → 出队执行 → **经桥接「候选收集」入口获取前端提交的完整引用列表（执行时收集）** → 粗筛 → 细筛 → 经桥接「交互」入口交前端交互（Begin → 操作 → Complete/Cancel）→ 终局（恰好一次）→ 结果对象返回。
- 收集与筛选在交互开始前完成（同步计算）；等待须异步、不得阻塞；终局恰好一次（Complete 或 Cancel 其一）。

### 2.3 TargeterManager（队列）
- 全局 FIFO 串行：一次只执行一个 targeting；终局后出队下一条；**所有请求（含跨实例）统一排队、防冲突**。
- 获取：经 Match 公开面读取（管理器群"第六员"，与既有模式一致）；**支持独立构造**（注入桥接）供测试与脱离对局场景。
- "第六员"＝TargeterManager 本身（非额外封装层）。
- **对局接入（变更面锁定）**：Match 构造新增**可选**桥接参数（旧调用不破坏）；第六员随管理器群在 Initialize 内**加性生成**（既有生成序列与 3 条更新契约不变；既有五管理器公开面不动）；经 Match 公开属性读取（准备态沿用既有门禁）；**桥接缺失时 Targeting＝失败结局（不抛＋留痕）**（允许无桥接装配，调用时以失败结局暴露）；多 Manager 实例互不干扰（各自队列、各自桥接）。

### 2.4 前端桥接接口
- 职责：后端↔前端交互通道，含**两个阶段入口**：
  - ① **候选收集**：执行时向流程提供"前端当前可交互的完整引用列表"；
  - ② **交互**：Begin（请求描述）→ 玩家操作 → Complete(refs) / Cancel()。
- 绑定：Manager 与桥接**一对一**（构造/装配注入；生产＝对局装配、测试＝mock）。
- 请求描述至少包含：候选数据（允许子集）、槽位描述、请求标识（用于终局配对）。

## 3. 数据流与责任划分（核心契约）

- 候选数据流（含时序）：**出队执行时**，后端经桥接「候选收集」入口取得前端提交的**完整引用列表**（语义＝"前端当前可交互的全部引用"，含不满足规则者）→ 粗筛（**批量式**：列表 → 允许子集 A）→ 细筛（**逐项谓词**：单引用回调，在 A 上逐项）→ 最终允许集 B → 经交互入口交前端展示与选择。
  - 列表在**执行时**收集（不在构造期/入队前）——保证候选新鲜度（队列可能等待较久）。
  - 脏数据：约定前端提交干净列表（不得含 null）；后端做最小防御（null 剔除、保证不崩溃）；重复引用不做强制去重（保持提交原样）；细节实现定型并汇报。
- **后端产出"允许什么"；前端显示"不允许什么"（置黑）**：未返回项与细筛淘汰项由前端置黑；后端不产出置黑标记、不负责显示语义。
  - 注：此模型为用户最终修正（"UI 端给引用列表→粗筛返回允许的引用；细筛只有一个引用参数；无标签结构"）；父方早期文档中"候选＋可用性标记"的表述以此为准。
- **产出形态与"扁平/非扁平"界**（对应写入双模式）：**无槽位/单槽位＝扁平产出**（SingleSelect→单个引用；MultiSelect→引用列表；顺序＝前端提交原样、无额外排序承诺）——适用视图 [Mutate] 属性写入；**多槽位声明＝非扁平产出**（按槽位命名的结构化结果）——适用 ctx 强类型写入。多槽位本批口径＝**统一候选池**（同一列表经两级筛选；槽位仅约束选择数量/结构）；每槽位独立筛选属演进项。**多槽位交互语义**：一次 Begin 完成全部槽位选择；Complete 按槽位组织提交（每槽位一组引用）；后端按每槽位独立约束（各自 min/max）＋成员（⊆B）校验；槽位名由业务方构造时声明（名＋类型＋约束）；产出可**按槽位名取出**（键/访问形态实现定型并汇报）；**默认允许同一引用被多槽位同时选中**（互斥选择属演进）；各槽位空选语义一致（min=0 可空）。
- **写入与读取（业务方范式）**：targeting 结果为**显式写入**（业务方自行把产出写入目标；框架不自动写）；生产代码**提供类型化辅助入口**（扁平＝写入/读取 [Mutate] 属性的便捷；非扁平＝按槽位读取强类型的便捷；形态与命名实现定型并汇报）；**键名/结构业务方自由**（辅助不规定固定键名；范式用例键名可作参考）；写入语义＝普通数据写入（重复即覆盖）。
- **元素类型口径**：前端提交截面**允许弱类型**（object? 等，实现定型）；**流程产出必须为引擎引用类型**（"强类型获取引用"的前提）；弱类型输入的规范化（转换规则、无法规范化元素的处理）＝实现定型并汇报。
- **调用位置（需求锁定，两个不同场景）**：①**主路径＝ctxv 内 targeting**（触发器视图/转接环节）；②**允许 handler 内调用 targeter 并写入触发器上下文**（执行期间动态获取；写入后本触发器后续事件可读取，ctx 共享范围内可见）。两位置均为需求覆盖范围；Targeter/Manager 获取路径**不固定单一样式**（范式至少演示一种可行路径；实现定型并汇报）。

## 4. 边界与失败模式（含审视补充）

- **空可用集**：判定点在**筛选完成后的最终允许集 B 为空**（粗筛为空必然导致 B 为空、不单独判定；无细筛时即 A 空）→ 以"失败（系统原因：无可用候选）"立即结束、不进入前端交互（区别于前端取消）。
- **空选完成**（min=0 且用户未选）：**成功、空产出**；与"空可用集失败"相区分（前者有可用项而用户不选、后者无可用项）。
- **取消**：来源仅前端 Cancel()（本批）；取消＝失败返回不抛、队列继续。
- **统一失败模式（桥接交互异常 / 候选收集失败 / 筛选回调异常）**：失败结局、不抛；不得使 Manager/队列崩溃；队列继续。
- **违规调用**：协议上"一次 Begin 恰好一次终局"。
  - **内容不合规**（Complete 数量不合规〔少于 min、超过 max、单槽位多引用〕、引用不在允许集）：**显式拒绝（不构成终局）＋留痕**；请求**继续等待**有效终局（前端可纠正重试或 Cancel）。
  - **时序违规**（重复 Complete、Cancel 后再 Complete、无请求时调用）：实现定型并在汇报说明（显式拒绝或幂等忽略）。
  - 底线＝不得破坏队列与后续请求状态。
- **并发**：同实例或不同实例并发发起＝排队（不拒绝）。
- **超时 / 外部 CancellationToken**：不在本批范围（不作为验收要求）。

## 5. 验收要点（本批）

- 排队：并发请求串行化（含跨实例）；
- 两级筛选：粗筛批量允许子集、细筛单引用回调逐项（含缺省＝全通过）；
- 槽位：SingleSelect / MultiSelect(min,max)（含边界：min=0 空选成功、max 上界、**违规 Complete 的后端真实校验与拒绝**）；产出形态（单引用/列表/多槽位结构）；**多槽位**：一次交互完成全部槽位、按槽位组织提交、每槽位独立约束＋成员校验、跨槽位重复默认允许；
- 取消：失败返回不抛、队列继续；失败（含无可用候选、收集/回调异常）同理；
- 双写入模式与两种用法：**用法 a（产出作参数，链路证明）与用法 b（请求对象传参＋结果传参）分别有测试证明**（允许与位置范式合并覆盖）；**显式写入＋类型化辅助存在且可用**；扁平/非扁平产出写入与读取连贯（测试证明）；
- 调用位置：**ctxv 内（主路径）与 handler 内（写入 ctx、后续事件可读取）两位置均行为断言**；
- mock 桥接完整流程（含候选收集截面）：**两个阶段入口均须 mock 覆盖**（脚本化收集/交互应答，含收集失败与交互异常路径）；
- 测试组织：允许对既有测试基础设施**加性修改**（不动既有测试断言与语义）；测试规模**以覆盖验收要点为准**；
- 结局三态可判（成功/取消/失败）＋结果对象携带产出引用与失败原因（类别化）；
- **Match 接入（端到端）**：构造（注入 mock 桥接）→ Initialize → 第六员经公开面可读 → 完整 targeting 成功流程；
- **桥接缺失（Match 装配）**：无桥接装配 → Targeting＝失败结局（原因类别＋留痕）纳入测试。

## 6. 对齐记录（逐轮）

### 第 1 轮（主层＝类/功能流程级）

**Q1① 调用面与结果形态**（子问要点：入口在 Targeter 方法还是 Manager 方法？成功/取消/失败三种结局的返回形态？结果是否携带成功标记与失败原因？）
- 解答：入口＝**Targeter 的 Targeting 方法**（业务方唯一发起面；Manager 非发起入口）。结果＝**统一结果对象、不抛**；必须携带成功标记＋失败原因，**能区分三态**：成功（携带产出引用）/ 取消（前端主动）/ 失败（系统原因）。
- 备选与拒绝：Manager 入口（拒：调用面分裂、管理面应最小化）；异常表达失败（拒：与"失败返回不抛"冲突）；不区分取消/失败（拒：调用方对两者策略不同）。

**Q1② 复用语义**：允许串行复用；并发/未完成时再发＝**排队**（不拒绝），结局与产出互不干扰。
- 备选与拒绝：并发即拒绝（拒：与队列"防冲突"定位重复、迫使业务方自建排队）。请求对象复用时内部状态重置细则＝实现定型并汇报。

**Q1③ Manager 获取与构造**：经 **Match 公开面**读取（第六员、同既有模式）；**支持独立构造**（注入桥接，供测试）；第六员＝Manager 本身。

**Q2① 桥接进入方式**：构造/装配注入（生产＝对局装配；测试＝注入 mock）；**Manager↔桥接一对一**。
- 备选与拒绝：全局/静态桥接（拒：与多实例隔离冲突）。

**Q2② 请求描述与候选数据流**：至少含候选数据、槽位描述、请求标识；后端产出＝**允许子集**（粗筛＋细筛后）；置黑责任在前端；无置黑标记、无标签结构。
- 备选与拒绝：后端产出"全量＋允许/置黑标记"（拒：与用户最终修正矛盾、数据重复）。

**Q2③ 完成语义与取消来源**：一次 Begin 恰好一次终局；违规＝实现定型并汇报（底线：不破坏队列与后续请求）；取消来源仅前端 Cancel()；超时/CT 不纳入本批。
- 备选与拒绝：纳入超时/CT（拒：超范围、引入新验收面）。

### 第 2 轮（主层＝类/功能流程级 · 候选数据流入口与两级筛选契约）

**Q1① 列表进入机制**（子问要点：出队后经桥接收集（a）／筛选器自带候选来源（b）／其他？mock 按此截面脚本化应答。）
- 解答：**机制＝a 的定型**——Targeting **出队执行时**，后端经桥接「候选收集」入口取得前端提交的完整引用列表；随后执行粗筛/细筛；再经「交互」入口 Begin 交互。桥接接口由此含**两个阶段入口**（收集／交互）。
- 备选与拒绝：筛选器自带候选来源（拒：与"UI 端给列表"的用户修正不符、把前端职责搬进业务方）；构造期就绪（拒：队列可能等待较久、列表会陈旧——新鲜度要求执行时收集）。

**Q1② 列表语义与脏数据**：语义＝"前端当前可交互的全部引用"（含不满足规则者，由粗筛剔除）。脏数据：约定前端提交干净列表（无 null）；后端最小防御（null 剔除、保证不崩溃）；重复引用不做强制去重（保持提交原样）；细节实现定型并汇报。

**Q1③ 时序与失败**：收集在**出队执行时**（非入队前/构造期）；候选收集失败或"组装候选数据"失败＝按**统一失败模式**处理（失败不抛、队列继续）。

**Q2① 粗筛形态**：**批量式**（输入完整列表 → 输出允许子集）；"规则式"＝由业务方预定义、与单次交互解耦的**可复用过滤规则**（与细筛的逐项谓词形态形成对照）。细筛保持单引用逐项。
- 备选与拒绝：粗筛也做逐项谓词（拒：浪费批量表达力、与用户"返回列表里允许的引用"的批量表述不符）。

**Q2② 挂载与缺省**：筛选器＝**一个对象含两级**（粗筛批量委托＋细筛谓词）；两级**均可缺省**（缺省＝该级全通过）；构造 Targeter 时提供（可只给其一）。

**Q2③ 游戏状态访问**：确认——回调由业务方编写，可自由捕获/访问游戏状态（对局、管理器群等）；后端不做访问限制；**粗筛与细筛均适用**。补充裁定：筛选回调异常＝失败不抛（统一失败模式）。

**Q3 空可用集判定点**：判定于**筛选完成后最终允许集 B 为空**（粗筛空必然 B 空、不单独判定；无细筛时即 A 空）；失败类别＝**系统失败**（与前端取消相区别）。

### 第 3 轮（主层＝类/功能流程级 · 选择槽位与结果对象）

**Q1① 槽位形态与 min/max 语义**（子问要点：是否固定类型表达？min 语义？min=0？max≥1？关系约束方式？）
- 解答：**固定两个槽位类型**（SingleSelect／MultiSelect(min,max)；SingleSelect＝"选 1 个"的语义特化）。min 语义＝**完成/确认时必须至少选到 min 个**；**min=0 合法**（允许空选完成＝成功、空产出）；**max ≥ 1**；**min ≤ max 等关系＝构造期校验**（拒绝非法配置，不假设业务方正确）。
- 备选与拒绝：min=0 非法（拒：可选目标场景合理存在）；关系依赖假设（拒：应在构造期早暴露）。

**Q1② 校验责任与违规 Complete**：确认"前端自行维护策略"＝**交互层策略，不解除后端校验职责**。后端在 Complete(refs) 时**必须校验**：①数量（少于 min、超过 max、SingleSelect 多引用）②成员（**每个引用须属于最终允许集 B**）。不合规：**显式拒绝（不构成终局）＋留痕**、请求**继续等待**（前端可纠正重试或 Cancel）；不得破坏队列。验收的"min/max 校验"＝**后端真实校验**（测试覆盖违规路径；前端策略模拟不属后端验收项）。
- 备选与拒绝：信任前端不校验（拒：契约防腐、mock/篡改防护）；违规 Complete＝失败结局（拒：错误可修复、不应惩罚用户流程）。
- 收紧说明：内容不合规固定为"拒绝＋继续等待"；时序违规维持第 1 轮"实现定型并汇报"。

**Q1③ 产出形态与顺序**：SingleSelect → **单个引用**；MultiSelect → **引用列表**（min=0 空选成功时为空列表）。列表顺序＝**保持前端提交顺序（原样）、无额外排序承诺**。
- 备选与拒绝：统一列表形态（拒：单引用场景编码别扭）；承诺选择顺序（拒：无需求依据、徒增约束）。

**Q2① 结果对象三态表达与失败原因**：以**状态枚举**表达（至少成功/取消/失败成员；成功→携带产出〔只读〕；取消/失败→无产出、携带原因）。**失败原因要求类别化**（至少覆盖：无可用候选、候选收集失败、桥接交互异常、筛选回调异常；含"其他/未知"兜底）；类别命名实现定型并汇报。
- 备选与拒绝：自由文本原因（拒：调用方需要程序化判断与提示分流）。

**Q2② "结果作为参数传递"与不可变性**：用法 b＝**结果对象（或其产出）交其他调用方使用**（如写入触发器 ctx 供后续事件读取、传给其他触发器/流程）。成功后产出＝**只读快照**（消费方读取/拷贝使用，不提供反向修改语义）。
- 备选与拒绝：产出可变（拒：结果对象不是游戏状态修改通道，破坏职责边界）。

**Q3 槽位缺省与扁平/非扁平界**：**允许缺省槽位声明**；缺省＝单一选择（SingleSelect 语义，单引用）。**判定界＝产出形态**：无槽位/单槽位＝**扁平产出**（单引用或引用列表；适用视图属性写入）；**多槽位声明＝非扁平产出**（按槽位命名的结构化结果；适用 ctx 强类型写入）。补充口径：多槽位本批＝统一候选池（槽位仅约束数量/结构）；每槽位独立筛选属演进项；槽位类型扩展应保持既有调用不破坏。
- 备选与拒绝：以"是否声明槽位"为界（拒：单 MultiSelect 列表场景应归扁平；界应看产出形态）；强制槽位声明（拒：简单场景应便捷可用）。

### 第 4 轮（主层＝类/功能流程级 · 写入双模式与调用位置支持）

**Q1① 写入机制（显式/自动）与"强类型"含义**（子问要点：targeting 结果由业务方显式写入还是框架自动写？"强类型"＝产出结构整体被 ctx 承载、读取按槽位取强类型引用？）
- 解答：**显式写入**——targeting 返回结果，业务方自行写入（视图 [Mutate] 属性／ctx 强类型写入）；框架提供类型化便捷但**不自动写**。"强类型"确认＝**产出结构（多槽位结构类型）作为整体被 ctx 承载、读取时按槽位取强类型引用**；元素类型口径见 Q3。
- 备选与拒绝：框架自动写入（拒：需指定写入目标、耦合流程语义；显式＋辅助更灵活清晰）。

**Q1② 辅助/范式交付形态**：**要求存在可复用的类型化辅助入口（生产代码）**（扁平＝属性写入/读取便捷；非扁平＝按槽位读取便捷；形态命名实现定型并汇报）；**验收以行为为准**（测试证明两种模式可行且辅助被范式用例使用）；"范式"＝测试中演示完整用法。

**Q1③ 键名与读取方式**：**业务方自由**选择键名/结构；辅助仅做类型化封装、不规定固定键名（范式键名可作参考）；读取方经同一辅助或直接访问 ctx 数据；写入＝普通数据写入（重复即覆盖）。

**Q2① 两位置关系与范式交付**：**两个不同场景**（非同一称法）：①ctxv 内 targeting（**主路径**，触发器视图/转接环节）；②handler 内调用 targeter 并写入触发器上下文（**执行期间动态获取**）。范式交付＝测试文件中的范式用例（两位置各一，行为断言）＋辅助入口；范式落位与形态实现定型并汇报。

**Q2② "ctxv 内"的准确含义与获取路径**：确认——业务方在触发器视图/事件逻辑内 `await Targeting()`，把结果写入该触发器的 ctx 数据（经视图 [Mutate] 属性；非扁平经强类型写入）。Targeter/Manager 获取路径：**本批不固定单一样式**（ctx 数据注入／闭包捕获／管理器读取等均可）；范式用例**至少演示一种实际可行路径**。

**Q2③ 测试覆盖**：**两位置均须覆盖**（ctxv 内主路径＋handler 内"写入后后续事件可读取"）；"测试证明"＝**行为断言为准**（写入可读、目标正确、与流程衔接正确）。

**Q3 元素类型与强类型兼容**：前端提交截面**允许弱类型**（object? 等，实现定型）；**流程产出必须为引擎引用类型**（"强类型获取引用"的前提）；弱类型→引用的规范化（转换规则；无法规范化元素的处理〔剔除或失败〕）＝实现定型并汇报。
- 备选与拒绝：产出元素保持弱类型（拒：与"强类型获取引用"矛盾）；强类型仅结构层、元素完全自由（拒：同前）。

### 第 5 轮（主层＝类/功能流程级 · 多槽位交互语义与两种用法验收）

**Q1① 多槽位交互模型与校验**（子问要点：多槽位是否一次 Begin 完成全部槽位？提交形态（按槽位组织 vs 整体序列）？后端按每槽位独立约束＋成员校验？）
- 解答：**一次 Begin 完成全部槽位选择**（一次 targeting＝一次完整交互；前端按其策略管理各槽位状态）。Complete 提交＝**按槽位组织**（每槽位一组引用）。后端校验＝**每槽位独立数量约束（各自 min/max）＋成员（⊆允许集 B）**；违规（含槽位类型不匹配，如 Single 槽位收多引用）＝按"内容不合规"处理（拒绝＋留痕＋继续等待）。
- 备选与拒绝：整体序列提交（拒：无法归属槽位、无法分槽校验）；拆多次交互（拒：破坏"一次终局"原子性）。

**Q1② 槽位命名与产出结构**：**槽位名由业务方构造 Targeter 时声明**（名＋类型＋约束）；产出按槽位名组织、**能按名取出对应产出（单引用/列表）**（能力为需求级）；键/访问形态（字典/属性/强类型结构）**实现定型并汇报**。

**Q1③ 共享候选池边界**：**默认允许同一引用被多个槽位同时选中**（不校验跨槽重复；互斥选择属演进项）；各槽位空选语义一致（min=0 的槽位可空，Single=1..1 必选）；统一池模型下各槽位候选一致（池空＝整体失败、池非空＝各槽位均有候选）。

**Q2① 用法 a（独立）验收落点**：**链路证明即可**——测试完成"targeting 成功 → 产出作为参数 → 被另一调用方实际使用"的完整链路（消费方类型不限）；断言"被使用"环节发生且参数正确。

**Q2② 用法 b 含义与验收**：请求对象传参＝**Targeter 实例作为参数被传递（接收方持有并使用该请求对象发起 targeting）**；结果传参＝结果对象/产出交其他方使用（第 4 轮已定）。**两者分别须有测试证明**。

**Q2③ 覆盖关系**：**不强制独立成组**——两种用法均被测试证明即可；**允许与位置范式（ctxv/handler）合并覆盖**（用例可组合）。
- 备选与拒绝：强制独立成组（拒：测试冗余；验收以能力均被证明为准）。

### 第 6 轮（主层＝类/功能流程级 · Match 接入变更面与测试组织）

**Q1① 桥接注入路径与变更面边界**（子问要点：构造参数／Initialize 参数／属性？受控加性变更的边界锁定？）
- 解答：**桥接经 Match 构造新增可选参数注入**（缺省＝null）。**变更面边界**：✅ 允许——新增可选构造参数（旧调用不破坏）、新增公开属性、Initialize 内附加生成；❌ 不得改变——既有五管理器公开面、Initialize 既有生成序列与 3 条更新契约、既有构造调用。
- 备选与拒绝：Initialize 参数（拒：桥接属装配输入、非初始化步骤；与两步式构造校验哲学不符）；可设置属性（拒：隐式可变、易错、校验时机晚）。

**Q1② 第六员生成与公开面**：确认——**Initialize 内随管理器群生成**；**经 Match 公开属性读取**（准备态访问沿用既有门禁模式）；属性名/命名实现定型并汇报；独立构造路径（Manager 直建）不受影响、行为一致。

**Q1③ 桥接缺失场景**：**运行时＝失败结局（不抛）＋留痕**（失败原因归"未装配/其他配置"类）；允许"无桥接装配"（可选参数缺省），Targeting 被调用时才以失败结局暴露；不新增异常路径。另：未 Initialize 时经 Match 访问第六员＝沿用既有门禁模式（表现实现定型并汇报）。
- 备选与拒绝：构造期拒绝（拒：可选装配的灵活性需要）；抛异常（拒：与统一失败模式不一致）。

**Q2① mock 落位与能力面**：落位＝tests/Orc.Game.Tests 项目内（实现定型）；能力面＝测试可观测"收到 Begin/请求描述"、脚本化触发 Complete（每槽位 refs）/Cancel、读取观测点——**足够**；**两个阶段入口（候选收集＋交互）均须 mock 覆盖**（含收集失败、交互异常等脚本化路径）。

**Q2② 测试组织**：**允许对既有测试基础设施（TestInfrastructure 等）加性修改**（新增辅助；不改既有测试断言与语义；既有测试保持绿色）；测试数量**以覆盖验收要点为准**（不设数字下限）。

**Q2③ 队列细节**：确认——FIFO＝Targeting 调用发起顺序；跨实例排队＝同一 Manager 下多 Targeter 统一排队；**多 Manager 实例互不干扰**（各自队列、各自桥接）；**排队中（未 Begin）不可取消**（取消仅交互期前端 Cancel；排队期放弃属演进项）。

### 第 7 轮（主层＝方法级 · 引用类型与规范化口径、桥接方法级契约）

**Q1① "引擎引用类型"范围与提交元素期待**（子问要点：＝Orc.Core Ref/Entity 体系还是宽泛"引擎可识别对象"？提交元素期待？）
- 解答：**产出＝Orc 引擎引用体系**（库内构造、支持失效/有效性校验的引用：如 Ref<T>／IRefInfo 实现——具体类型面实现定型并汇报）；**不接受**宽泛"任意业务对象"。前端提交元素＝**应承载引用实例**（object? 仅为容器型别）——元素内容须为引擎可识别引用。
- 备选与拒绝：宽泛"引擎可识别对象"（拒：与"强类型获取引用"及引擎失效防线体系冲突）。

**Q1② 规范化时点与回调可见类型**：**规范化在候选收集之后、粗筛之前完成**；**粗筛/细筛回调只见规范化后引用**（业务方无需面对弱类型）；**无法规范化元素＝剔除单项继续**（最终集合空→无可用候选失败）——**锁定**（非"整批失败"选项）。
- 备选与拒绝：整批失败（拒：与 null 剔除同属宽容策略；坏元素不应拖垮整批）。

**Q1③ 产出的类型面**：业务方读取产出**可以具体类型使用**（引擎引用类型面；向下转型/查验支持＝实现定型并汇报）；**SingleSelect 单引用与 MultiSelect 列表的元素类型要求一致**（同一 targeting 内元素类型统一）。

**Q2① 候选收集入口契约**：**每次 targeting 恰调用一次**（失败＝统一失败模式）；提交语义＝"完整列表"（第 2 轮已定）；返回形态（同步/异步，推荐异步）与是否随调用携带请求上下文＝**实现定型并汇报**（语义要求：收集先于 Begin、不依赖交互期状态）。

**Q2② 请求标识与配对职责**：**标识由后端生成**并随请求描述（Begin）提供；**前端在 Complete/Cancel 时回传标识**；**后端据此校验终局归属**——不匹配＝违规处理（拒绝＋留痕＋继续等待）；mock 按此契约实现。
- 备选与拒绝：不回传（仅靠"当前活跃请求"隐式配对）（拒：跨请求/陈旧调用防错弱；与"请求标识（用于终局配对）"既定表述不符）。

**Q2③ Complete 提交面统一与留痕**：**提交面统一为"按槽位组织"**（每槽位一组引用；**扁平＝缺省槽位承载**）——不保留两套形态；**Cancel 携带标识、无其他参数**；**留痕可观测**（写入引擎既有日志/事件流渠道；渠道实现定型并汇报）且**测试纳入断言**（至少覆盖"内容不合规拒绝"路径）。
- 备选与拒绝：两套提交形态（拒：契约分叉、校验重复）；留痕不纳入断言（拒：无法验证防错路径可观测性）。

### 第 8 轮（方法级/验收面 · 失效引用口径、留痕渠道适用性、Match 接入验收形态）

**Q1① 失效引用@规范化**（子问要点：失效引用＝"无法规范化→剔除"，还是规范化只判"是否引用实例"、有效性下沉筛选？）
- 解答：**规范化只判定"是否引擎可识别引用实例"**；**失效引用＝可规范化、保留**（不剔除）；有效性判定**下沉**给筛选（粗筛/细筛回调可自行用 IsAlive 判定——业务规则职责）。
- 备选与拒绝：规范化阶段检查 IsAlive 并剔除（拒：职责越权——规范化管形态、有效性属业务/筛选语义；且"选失效目标"存在特殊语义空间）。

**Q1② 终局校验与失效**：**附加"引用须仍有效"校验**——Complete 时校验引用有效性（IsAlive）；**失效提交＝内容不合规**（拒绝＋留痕＋继续等待）。理由：交互期间目标可能失效；产出可用性承诺；与可失效校验引用体系一致。
- 备选与拒绝：不附加（失效完全交消费方防线处理）（拒：消费时爆炸晚、体验差；终局防线与成员校验并列更一致）。

**Q1③ 产出写 ctx 后失效防护**：确认——**不要求 Targeter 层额外防护**；沿用引擎引用既有失效防线（Value 访问校验）。不引入新机制。

**Q2① 留痕渠道@独立构造**：**可观测性为硬要求**；渠道：对局场景＝引擎既有渠道；**独立构造＝注入优先（可选注入留痕目标）、未注入时降级为可观测记录**（如内存留痕/可查询面——实现定型并汇报）。

**Q2② 留痕覆盖范围**：**留痕覆盖所有失败与违规路径**（收集失败、桥接交互异常、内容不合规、标识不匹配、时序违规、未装配）；**测试断言范围**：收集失败、桥接交互异常、内容不合规、标识不匹配、未装配＝必须；时序违规（策略"实现定型"）以"状态不破坏"断言为主，留痕如实现有则测。

**Q3① Match 接入验收形态**：**要求端到端用例**——经 Match 装配路径：构造（注入 mock 桥接）→ Initialize → 第六员经公开面可读 → 完整 targeting 成功流程；**外加**独立构造路径的完整流程测试（既有要求）。
- 备选与拒绝：仅"生成＋可读"断言（拒：未证明装配后可用性；端到端能暴露装配/门禁/接线问题）。

**Q3② 桥接缺失测试覆盖**：**要求**——Match 无桥接装配 → Targeting＝失败结局（原因类别＋留痕）纳入测试。

### 第 9 轮（收尾校对 · 槽位声明的收尾规则与流程隔离/前端通知）

**Q1① 槽位声明合法性校验**：**槽位名要求非空、互不重复**——**构造期拒绝**非法声明（与 min/max 关系校验同级）；**本批不设槽位数量上限**。

**Q1② 单槽位/无槽位的名与提交键**：单槽位声明的名**可省略**（省略即归"缺省槽位"）；"缺省槽位"的承载（键/形态）＝**稳定可引用**（字面/形态实现定型并汇报，但须对业务方可见、mock 与前端可依据）；**辅助 API 须覆盖缺省槽位场景**（消费端"按名取出"在缺省下稳定可用）。
- 备选与拒绝：缺省承载完全实现私有随意（拒：前端/mock 无法对齐、不满足可测试性）。

**Q1③ 槽位声明不变性**：确认——**声明随请求对象、构造期固定，无中途修改语义**；传参与复用不改变声明。

**Q2① 未进入交互即失败的前端通知**：**本批不要求**显式"结束/清理"通知（未 Begin 即失败＝无交互态、无通知义务）；该失败对业务方可见（结果对象＋留痕）；前端若在收集阶段自行布置状态、其清理由前端/业务方自理；"预交互清理通知"属演进项。
- 备选与拒绝：要求显式结束回调（拒：与"一次 Begin 对应一次终局"契约不对齐——未 Begin 无终局；徒增前端契约面）。

**Q2② 流程隔离要求**：**成立**——每请求状态独立（收集/筛选/交互中间状态不跨请求泄漏）；复用 Targeter 与排队后续请求**不受前一次失败/取消/违规影响**；实现层保证方式自定（需求级只约定隔离性）；**隔离性纳入测试**（复用与失败/取消/违规后场景断言）。

## 7. 方法级需求（引用与桥接契约）

> 本层为方法级锁定（输入输出契约/边界/错误处理），不改写上级（类/流程级）需求；上级详见 §1~§5。

- **引用与规范化**：产出元素＝引擎引用类型（库内构造、可失效校验；类型面实现定型并汇报）；提交元素须承载引用实例（object? 仅容器型别）；规范化在收集后、粗筛前完成；粗筛/细筛回调只见规范化后引用；无法规范化元素＝剔除单项（最终空→无可用候选失败）；**失效引用＝可规范化保留**（有效性判定归筛选）；**终局校验附加"仍有效"**（失效提交＝内容不合规：拒绝＋留痕＋继续等待）；产出后续防护＝沿用引擎既有失效防线（无额外防护）。
- **候选收集**：每次 targeting 恰一次调用；失败＝统一失败模式；形态与上下文携带实现定型并汇报（收集先于 Begin）。
- **标识配对**：后端生成、随 Begin 提供；终局（Complete/Cancel）回传校验归属；不匹配＝违规（拒绝＋留痕＋继续等待）。
- **提交面统一**：按槽位组织（每槽位一组引用；扁平＝缺省槽位承载）；Cancel 带标识、无其他参数。
- **留痕**：可观测（对局＝引擎既有渠道；独立构造＝注入优先/降级可观测记录；实现定型并汇报）；**覆盖所有失败与违规路径**；测试断言（收集失败、桥接交互异常、内容不合规、标识不匹配、未装配；时序违规以状态不破坏为主）。
- **槽位声明（收尾规则）**：名非空、互不重复（构造期拒绝）；无数量上限（本批）；单槽位名可省略（归缺省）；缺省承载稳定可引用（实现定型并汇报）；声明构造期固定、无中途修改；辅助 API 覆盖缺省槽位场景。
- **流程隔离**：每请求状态独立（中间状态不跨请求泄漏）；复用与后续请求不受前一次失败/取消/违规影响；实现方式自定；隔离性纳入测试。
