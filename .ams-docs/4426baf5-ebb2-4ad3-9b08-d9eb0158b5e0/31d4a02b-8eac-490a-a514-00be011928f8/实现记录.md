## 三、实现决策与说明（如实登记）

1. **读面调用形态**：预检器自行 `Directory.EnumerateFiles`＋`OrderBy(StringComparer.Ordinal)` 后调 `CardDataLoader.LoadFiles`（而非 `LoadDirectory`）——为获得**跨运行确定的文件处理序**（`LoadDirectory` 内部不排序；文件序影响 Failures/Warnings 序与同批隔离"谁被裁剪"）。读面行为零修改、复用同一 Failures/Warnings 通道。
2. **库侧静态装载**：`PrefabJson.TryDeserialize`（结构化失败不抛）＋IO 异常捕获（IOException/UnauthorizedAccessException，对齐卡侧口径）；文件序显式排序；重复判定为预检新增（不复用注册面——无用例）；"同库内两条"即同目录两文件同 root.id。
3. **读面警告来源锚点**：因"不重新解析读面文本（不做脆弱分类）"与"尽可能以结构化字段附上来源"并存，采用**保守提取**：首个全角冒号前段作候选前缀（`{前缀}：{消息}` 系读面生成格式）；`.card.json` 结尾判文件名、命中成功卡 id 集合判卡 id、否则不附——仅提取来源锚点、不做细维度分类，原文（Message）逐字保留。
4. **"内联缺 id"形态**：读面对其表现为**组件级反序列化失败隔离**（`PrefabJson.Deserialize` 对空/缺失 root.id 抛 `ArgumentException`——`CardDataLoader.cs` 中"内联预制体缺少 root.id"分支经实测对 JSON 路径不可达；探针实测确认）。测试以组件失败警告形态锁定（"内联完整性复用读面已有判定并汇入"的读面事实）。该分支差异如实登记（未改读面）。
5. **统计口径**：成功卡定义数＝各目录 Definitions 合计（跨目录重复的两份定义各自成功——重复属注册面问题，Error 另报）；成功快照数＝库成功反序列化＋卡成功内联（被读面隔离者不计）；输入面统计＝去重后传入目录数（含缺失目录——防"覆盖面误读"）。
6. **报告顺序（确定性）**：①目录缺失（卡→库）②卡侧汇入（目录序、读面序）③库侧汇入（目录序、文件序）④库内重复 ⑤卡 id 重复 ⑥内联×内联跨目录 ⑦库×内联 ⑧引用未解析（目录序、声明序、引用序）。同输入同输出已由测试锁定。
7. **探针**：`_work/`（本目录内）＝实现期 Python 数据探针＋独立 C# 控制台（读面边界行为实测＋全量冒烟运行证据），非交付物、未进入源码面。
8. 未决项：无阻塞项。全量测试依赖 `outputs/kards-cards`（现网 1646 文件、已全量断言；缺失时冒烟可辨识跳过）。
