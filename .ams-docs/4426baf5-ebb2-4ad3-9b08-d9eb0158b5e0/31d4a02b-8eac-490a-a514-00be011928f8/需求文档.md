## 一、功能职责

1. **分发预检器（dry-run 校验器）**：对分发数据（卡目录＋效果库目录）做**纯只读静态校验**，在"注册/装载进对局"之前尽早暴露配置错误；输出结构化报告（Errors/Warnings 分列＋汇总统计），供创作工具/CI 做 gate（Error>0＝不放行）。
2. 校验维度：a) 读取/结构汇总（复用 `CardDataLoader` 读面结果）；b) id 重复与冲突（跨文件卡 id、卡内联 prefab id、库内 prefab id、跨目录/跨来源重复）；c) 引用完整性（卡声明的 prefab id ∈〔效果库 ∪ 卡内联〕）；d) 内联完整性（id 非空/冲突）。
3. 非目标（硬约束）：不启动对局、不注册进引擎实例——**库侧读取经 `PrefabJson` 静态反序列化（不经 `PrefabManager` 实例）**；不修改任何数据；不改既有读面行为、新增仅加性。

## 二、需求阐明（逐轮 Q&A）

### 第 1 轮（2026-10-08）：校验器输入形态与多目录语义

**子的问题（原文）**

- 主 1：请展开"一个或多个可选"的准确语义——(a) 卡目录：只支持传一个，还是可以传多个（多来源合并分发）？(b) 效果库目录：可传多个吗？(c) "可选"是指卡目录、效果库目录各自可缺省（只传一边也合法）？(d) 两边都不传时：抛参数异常，还是返回空报告？请明确允许的最小输入集合。
- 主 2（多目录时重复/冲突判定范围）：(a) 两个效果库目录里出现同一个 prefab id——算不算"库内 prefab id 重复"（子倾向应算：运行期注册面只有一个，同名注册必然失败）？(b) 两个卡目录之间同一个卡 id——算不算"跨文件卡 id 重复"？(c) 同一目录被重复传入两次——要求调用方去重，还是校验器自行去重、避免产生假重复？测试点名的"多库目录"构造应覆盖哪些场景（尤其是否含跨库重复）？
- 主 3（目录边界行为）：(a) 显式传入的目录在磁盘上不存在：沿用读面口径（空结果、零错误），还是按预检语义报 Error（或抛）？(b) 空目录（存在但无文件）：＝空报告零 Error，请确认。(c) 只给效果库目录、不给卡目录：引用完整性维度没有输入——照常返回报告（该维度为空）、其余维度正常？

**答复与决策**

**1. 输入形态与最小集合**

- (a) 卡目录：**支持多个**（多来源合并分发——分发单位＝目录；合并后按统一集合校验）。
- (b) 效果库目录：**支持多个**（多库合并为一个逻辑库——运行期注册面只有单一名空间，合并后统一判定）。
- (c) "可选"＝两边各自可缺省；允许**单边**输入（只卡／只库），两种单边均有意义（见 §3c）。
- (d) 全空输入＝**参数异常（抛）**；最小输入集合＝**至少一个目录参数**。依据：无输入的"校验"属调用方错误（参数层 fail-fast 惯例）；**不返回空报告**——空报告会被误读为"校验通过"（假阴性恰是预检器最不可接受的失败模式）。
- 备选与拒绝：全空返回空报告——拒绝（假阴性风险）；卡目录必填、库可选——拒绝（丧失"只校验库"单边模式）。

**2. 多目录的重复/冲突判定范围**

- (a) 跨效果库目录同一 prefab id＝**重复（Error）**（子倾向正确）：运行期 `PrefabManager.RegisterPrefab` 以 id 为键、重复=拒绝（fail-fast）——预检职责即提前发现"装载进对局必然失败"的问题。判定基于**成功装载集合**（装载失败条目另行报读面错误）。
- (b) 跨卡目录同一卡 id＝**重复（Error）**：卡库键唯一（重复注册被拒）；单批内重复由读面 Failures 承载、跨目录重复由预检器新增承载。
- (c) 同一目录重复传入＝**校验器自行去重**（同一路径值只处理一次，不产生假重复）；调用方无去重义务。
- "多库目录"构造测试覆盖（至少）：两库合并（无重复＝零 Error）／跨库重复 id＝Error／跨卡目录重复＝Error／同一目录重复传入＝不假重复。

**3. 目录边界行为**

- (a) 显式传入目录不存在＝**报告 Error（不抛、不静默）**：读面"宽容装载"与预检"严格校验"语义不同——预检器把"路径写错"暴露为错误而非伪装成"校验通过"。多目录部分不存在：各自 Error、存在者照常（报告式全收集）。
- (b) 空目录（存在、无文件）＝**空报告、零 Error**：确认。
- (c) 只给库／只给卡＝**照常返回报告**：只给库＝引用完整性维度无输入（空）、其余维度正常；只给卡＝解析集合退化为〔全部卡成功内联并集〕——命中＝通过、不报；仅内联面亦未命中＝按未解析（Warning，附"未提供效果库输入，无法静态判定"说明）处理〔第 2 轮 1(b) 修正；原"全部按未解析"表述取消〕。

**4. 引用完整性的级别规则（连带裁定，覆盖委托 Requirements 2c）**

- 解析集合＝〔效果库（合并）∪ 卡内联〕（第 2 轮精确化：全部卡成功内联并集）。
- **未解析（未命中）＝Warning**（文案说明：可能由宿主代码注册〔`RegisterPrefab`〕提供；纯数据分发请补齐效果库）。**不升级为 Error**——宿主代码注册为合法通道（含生产内置效果），静态面无法排除，升级将产生假阳性。
- **Error 仅用于可确证问题**：目录不存在；跨目录/**跨来源** id 重复；读面 Failures 的映射。
- **读面结果映射**：`CardDataLoadResult.Failures`→报告 Error；`CardDataLoadResult.Warnings`→报告 Warning（含未知组件、组件反序列化失败、内联 id 缺失等）；库侧装载失败条目→Error；**内联完整性复用读面既有判定并汇入**（不重复造判定）。

**5. 报告与确定性（架构审视补充）**

- **报告确定性**：同输入两次调用＝相同报告（条目顺序稳定、跨运行一致）——对齐批 1/批 2 确定性原则，纳入验收。
- 报告逐项含来源（文件/卡 id/prefab id）＋说明、可定位；Errors/Warnings 分列＋汇总统计。

**架构审视补充（对抗性发现，纳入需求）**

- **跨来源冲突**（子问题未覆盖，补入）：同一 prefab id 同时出现在〔库 ∪ 内联〕的**两个不同来源**（库×库、库×内联、内联×内联跨目录）＝**Error**（运行期注册面单一名空间下必然冲突）。
- 失败模式：部分目录坏/缺→其余照常（报告式全收集、不早退）。
- 非功能性：纯只读（性能友好）；报告确定性（§5）；可测试性（好/坏数据各形态、临时目录）。
- 元审视：子问题 2c（去重归属）——裁定工具侧去重（假重复属工具面问题，不外溢给调用方）。

### 第 2 轮（2026-10-08）：引用完整性判定基准与冲突矩阵的边界确认

**子的问题（原文）**

- 主 1（引用完整性的判定基准细化）：(a)"卡内联"的范围＝全部卡（含他卡）成功内联的并集，还是仅"声明该引用的卡自身"的内联？（子倾向"∪ 全部卡内联"——依据：运行期宿主将全部内联快照注册进全局注册面、卡加载时按 id 全局解析，"卡 A 引用卡 B 的内联 id"在数据面可解析。请裁定；若定为"仅本卡内联"，则跨卡引用他卡内联＝未解析 Warning。）(b) 第一轮 §3c 的"只给卡＝引用'引用形态'条目全部按未解析处理"表述存疑——当引用目标在（本卡或他卡）内联中可解析时，也应报"未解析"吗？（子理解＝无库输入时解析集合退化为〔卡内联〕，命中即通过、不报；仅内联面也不命中才报未解析 Warning，文案相应调整。）
- 主 2（冲突矩阵的完整清单与不对称确认）：(a) 子理解的判定基准＝"合并后仍会双双到达注册面的快照集合"：库×库（同库内两条／跨库两条）、库×内联、内联×内联（跨卡目录）＝Error；"内联×内联（同一卡目录内）"已被读面软隔离（第二条不进注册面、仅读面 Warning）→保持 Warning 汇入、不升级。请修正或确认"Error 判定基准＝未被读面隔离的双快照同 id 情形"。(b)"引用"不产生快照、不计入"来源冲突"：多卡引用同一 id（引用×引用／引用×内联／引用×库同 id）均不报 Error——其中同卡目录内的"引用×引用／引用×内联"会由读面产生 Warning 并软隔离其一（照汇入、Warning）；而跨卡目录的"引用×引用"预检器不报任何条目（无快照冲突）。请确认该不对称是有意边界，或修正。

**答复与决策**

**1. 引用完整性的判定基准（细化＋修正）**

- (a) "卡内联"范围＝**全部卡（含他卡）成功内联的并集**（子倾向正确）。依据：运行期注册面＝**全局名空间**（宿主把全部内联快照注册进 `PrefabManager`；卡加载按 id 全局解析）——"卡 A 引用卡 B 的内联 id"在数据面可解析。精确化：**"成功内联"＝进入读面产出 `CardDataLoadResult.Prefabs` 的集合**；被读面隔离的内联条目**不参与解析集合**（对其 id 的引用将按未解析处理）。
- (b) **修正第一轮 §3c**："只给卡＝引用全部未解析"表述不精确、**取消**；正解＝无库输入时**解析集合退化为〔全部卡成功内联并集〕**——命中＝通过（不报）；仅内联面亦未命中＝未解析 Warning（文案："未提供效果库输入，无法静态判定"）。§3c 原句已就地修正标注。
- 最终解析集合（全式）：〔效果库（全部库目录合并）∪ 全部卡成功内联并集〕；缺省面自然退化（未输入库→仅内联；未输入卡→空）。

**2. 冲突矩阵的完整清单与基准**

- **Error 判定基准＝"合并后仍会双双到达注册面的快照同 id 情形（未被读面隔离的双快照）"**——子理解正确，确认。
- 完整矩阵（快照面）：库内重复（**同库内两条**／跨库两条）＝Error（库侧无读面隔离机制——静态读取下两个快照文件都会到达注册面）；内联×内联（**跨卡目录**）＝Error；库×内联＝Error；内联×内联（**同卡目录内**）＝读面已软隔离（第二条不进注册面）→**照实汇入 Warning、不升级**。
- **引用不产生快照、不计入来源冲突**（确认）：引用×引用／引用×内联／引用×库——**不报冲突条目**；引用的解析判定照常独立执行（命中解析集合＝通过；未命中＝未解析 Warning）。同卡目录内"引用×引用／引用×内联"的读面 Warning（软隔离其一）**照实汇入**（Warning）；跨卡目录"引用×引用"**不报冲突条目**——该不对称＝**有意边界**。
- **统一原则（本轮固化）**：预检器＝**"照实汇入读面事实"＋"新增跨目录/跨来源判定"** 两个职责面；同目录内差异＝读面事实（含裁剪/隔离，照实汇入）；跨目录/跨来源＝预检新增（按注册面冲突基准判定）。读面既有行为（同批重复引用被裁剪等）**不在本批改造范围**（预检器不改造读面）。
- 备选与拒绝：将"同目录内已读面隔离者"升级 Error——拒绝（读面软隔离=设计使然、双源将不一致）；为"跨目录引用×引用"补报条目——拒绝（无快照冲突、属合法场景）。

**架构审视补充（第二轮）**

- 失败模式/边界：被读面隔离的内联条目不参与解析集合（连带效应已明示：其 id 的引用＝未解析 Warning）；"同库内两条同 id"由预检器**静态判定**（不经装载失败捕获——库侧为静态读取面）。
- 非功能性：报告确定性＝**同输入（含相同输入顺序）同输出**；不同输入顺序不承诺逐项同序（不扩大要求）。
- 元审视：子问题合理、无错误假设；对第一轮 §3c 表述的质疑成立、已被修正。

### 第 3 轮（2026-10-08）：报告输出契约（消费面）

**子的问题（原文）**

- 主 1（汇总统计与 gate 判定面）：(a)"汇总统计"的必须内容：是否要求至少包含某类计数（例如：扫描目录数、卡文件数、成功卡数、库文件数、成功快照数、成功内联数、Errors 数、Warnings 数；未解析引用数等）？请给出必须项清单（若有）；若无必须项，请确认由实现者自行选取。(b) 消费语义"Error>0＝不放行"：报告是否需要提供可直接判定的判定面（如"是否无 Error"的布尔/谓词），还是消费方自行查看 Errors 计数即可、不额外要求？
- 主 2（条目呈现契约）：(a) 条目是否需要稳定的"维度/类别"标识（如：读取失败、卡 id 重复、库内重复、跨来源冲突、内联缺 id、引用未解析……），以支持验收 1"报告维度全覆盖"的对应测试与消费端分类统计？还是自由文本说明即可、不要求类别字段？(b)"可定位"的最低要求：逐条目至少应含下列哪些——来源文件（完整路径或文件名）、卡 id、prefab id（按可用性提供）？对读面 Failures/Warnings 的汇入条目：要求保持原文可追溯，还是允许/要求重新结构化抽取上述字段？（子倾向"保留读面原文信息＋尽可能以结构化字段附上来源"。）(c)"未解析引用"条目的粒度：逐（卡 id，引用 id）一条（便于逐条定位与测试），还是按引用 id 聚合（一条列多个卡）？（子倾向逐条。）
- 主 3（子问题）：报告是否需要"可序列化/可打印"能力（如内容可直接输出为 JSON/文本供 CI 消费），还是"结构化内存记录"即可、序列化形态由后续消费方决定？

**答复与决策**

**1. 汇总统计与 gate 判定面**

- (a) **必须项清单（最小充分集；实现者可自行扩充）**——三段组织：
  - 输入面统计：**卡目录数、效果库目录数**（分列；建议附目录路径清单）；
  - 通过面统计：**成功卡定义数、成功快照数**（库成功装载＋卡成功内联合计；建议分列可辨）；
  - 问题面统计：**Errors 数、Warnings 数**。
  - 可选扩充（建议）：未解析引用数、扫描文件数等。
  - 依据：报告自含性——预检器的典型失败模式是"看起来通过、其实什么都没查"，统计面是防"覆盖面误读"的最低保证。
- (b) **要求提供"无 Error"直接判定面**（布尔/谓词；语义＝Errors 集合为空；**必须与 Errors 计数一致**）——服务主用途（CI gate）、防消费方误读计数；消费方仍可自行使用计数。
- 备选与拒绝：不提供判定面（消费方自行查看计数）——拒绝（gate 为主用途、低成本高价值）；统计项全自由——拒绝（自含性无最低保证）。

**2. 条目呈现契约**

- (a) **要求稳定"类别"标识**（枚举化、测试锁定；类别为"维度面"级，至少覆盖下列七类——细维度由原文承载）：
  - 目录缺失（input）；卡侧汇入（失败/警告）；库侧汇入；
  - 卡 id 重复（跨目录）；库内重复（同库/跨库）；跨来源冲突（内联×内联跨目录、库×内联）；
  - 引用未解析。
  - 说明文案自由；**类别字面值由实现者固定并被测试锁定**（后续不轻易变更）。
  - 细维度（如"读取失败／JSON 非法／内联缺 id"等读面子类）＝**由原文承载**＋测试用稳定关键词断言（仓库先例）；预检器**不重新解析读面文本**（不做脆弱分类）。
- (b) **可定位最低要求**：每条目含①类别②说明（人类可读、含必要细节）③来源锚点（按可用性）：来源文件（**完整路径优先**、不可得时退化为文件名）、卡 id、prefab id——**至少一个来源锚点**。读面汇入条目：**保留原文可追溯（必须）＋尽可能以结构化字段附上来源**（子倾向正确）。
- (c) **未解析引用＝逐（卡 id，引用 id）一条**（子倾向正确；便于逐条定位与测试）；不做聚合。

**3. 序列化/打印能力**

- **不要求**（不占本批验收）：报告＝结构化内存记录；序列化/展示形态由后续消费方决定（可选建议项、实现者可评估）。依据：委托与验收未含此面；外挂序列化不改变报告类型。

**架构审视补充（第三轮）**

- 失败模式：**全输入面均不可用（如所有目录不存在）时仍产出报告**（除参数层异常）；报告不因局部失败中止（延续报告式全收集）。
- 非功能性：统计数字与条目序在"同输入同输出"确定性范围内（承接第 2 轮）；报告规模随输入线性（无特殊性能要求）。
- 多视角：CI（gate 判定面＋计数）／创作工具（可定位条目＋统计）两视角均覆盖。
- 元审视：子问题合理——消费面确为前两轮未覆盖维度（好补充）。

**验收标准增补（并入 §三）**：见 §三 第 10、11 条。

### 第 4 轮（2026-10-08）：测试构造清单与验收口径具体化

**子的问题（原文）**

- 主 1（测试构造清单的澄清与核对）：(a)"缺引用"与"悬空引用"两个词在 Requirements 4 中并列出现——是否指同一场景（卡声明的引用 id 不在〔效果库 ∪ 卡内联〕＝未解析）？若不是，分别指什么？需要为两者分别构造测试吗？(b)"全好＝零 Error"口径：好数据构造是否也要求零 Warning（整报告 Errors/Warnings 均空），还是仅零 Error（Warning 允许）？好数据建议覆盖哪些形态组合（初步：多卡目录＋多库目录合并、含内联、含跨卡共享引用、含被引用库快照与内联全部可解析）？(c) 必须测试构造清单核对＋是否有遗漏（对照 11 条验收）？是否要求对仓库真实数据（outputs/kards-cards＋KeywordPrefabs 库）做全量预检冒烟（批 1/批 2 先例），还是全部测试用临时目录自含、不依赖 outputs？
- 主 2（验收 2"纯静态有测试证明"的形式）：①测试全程不构造 Match/LogicEngine/PrefabManager/CardEffectRegistry 等对象，仅调用校验器 API＋临时目录数据；②"库侧不经管理器件"由设计保证、无需额外断言？还是要求更强证明（无副作用断言／专门"无-引擎依赖"测试）？

**答复与决策**

**1. 测试构造清单的澄清与核对**

- (a) **"缺引用"与"悬空引用"＝同一场景**（引用 id 不在〔库∪内联〕）——委托中两词系措辞冗余、**统一为"未解析引用（Warning）"**；不分别构造（一个代表性用例＋文案断言）。**并明确**：本裁定体系下**不存在"可确证的悬空引用（Error）"类别**——未解析一律 Warning（不可确证性理由不变）；目标数据自身坏（坏文件/坏库）由各自条目承载。
- (b) 好数据口径：**Errors 与 Warnings 双零（硬断言）**——构造须完全无警告源。**构造注意**：避开"同卡目录内跨卡共享引用"面（该形态会触发读面裁剪 Warning——属"照实汇入"用例、不入好数据）；"跨卡共享引用"的好数据形态采**跨目录**布置（或各卡独立引用）。好数据形态组合（采纳子建议＋修正）：多卡目录＋多库目录合并、含内联、含库引用、含跨目录共享引用、全部可解析——双零。
- (c) 子列必须构造清单**总体确认**；**增补十项**（对照验收 8/9/10/11 与第 2 轮裁定的直证点）：
  1. **同库内两条同 id＝Error**（第 2 轮"同库内两条"裁定的直证——子清单只列了跨库）；
  2. **跨卡引用他卡内联＝通过（不报）**（解析集合＝"全部卡成功内联并集"的直证）；
  3. 无库输入时**内联命中＝通过（不报）**；未命中＝Warning（含"未提供效果库输入"文案）（只卡用例的具体断言）；
  4. **被读面隔离的内联不参与解析集合**（对其引用＝未解析 Warning）；
  5. **混合场景**：部分坏（坏文件/坏卡）→其余照常＋报告全收集（不早退）；
  6. **全输入面不可用**（如所有目录不存在）仍产出报告（各 Error 条目、非异常/非空）；
  7. **必须项统计数值断言**（好数据：卡目录数/库目录数/成功卡数/成功快照数/Errors=0/Warnings=0）；
  8. **条目契约断言**：类别标识取值（各构造对应维度）、未解析引用**逐（卡 id，引用 id）一条**（多条时条数＝引用条数）；
  9. （建议）null/空白参数＝抛（参数层）；
  10. **outputs 全量预检冒烟（要求）**：`outputs/kards-cards`（若存在）全量＝零 Error；`KeywordPrefabs` 库（若存在）＝零 Error；缺失时**可辨识跳过**（批 1/批 2 先例口径）；其余测试全部临时目录自含。
- 备选与拒绝：不要求 outputs 冒烟（全临时目录）——拒绝（真实规模冒烟＝分发工具的最强证据；先例一致）；把"跨卡共享引用"留在好数据同目录——拒绝（现有读面裁剪行为下必然 Warning、破坏双零）。

**2. 验收 2"纯静态"的证明形式**

- 期望证明内容＝①**测试仅经校验器 API＋临时目录数据**（测试不构造 `Match`/`LogicEngine`/`PrefabManager`/`CardEffectRegistry` 等引擎对象）；②**"不修改数据"副作用断言**（调用前后输入目录快照〔文件清单＋内容〕不变——"纯只读"的可观察证据、纳入测试）；③"库侧不经管理器件"＝**由 API 设计保证**（校验器不接收引擎、测试不构造）——无需额外专用断言。
- 备选与拒绝：专门"无-引擎依赖"反射/静态分析断言——拒绝（无实质增益、脆弱）；不要求副作用断言——拒绝（"纯只读"是硬约束、应可观察证明）。

## 三、验收标准（四轮增补后）

1. 报告维度全覆盖且可定位（对应测试）；
2. 纯静态有测试证明（不建对局/不注册；库侧不经管理器件）；
3. 输入形态：多卡目录/多库目录/单边/全空（异常）/不存在目录（Error）/空目录（零错误）——各测试；
4. 重复判定：跨目录卡 id、跨库 prefab id、跨来源冲突＝Error；同目录重复传入＝去重不假重复；
5. 引用完整性：未解析＝Warning（含说明）；读面 Failures→Error、Warnings→Warning 映射；
6. 报告确定性：同输入同输出（含顺序）；
7. 构建 0 警告 0 错误；全测试套件 ≥1291＋新增、零回归；
8. 引用解析集合＝〔效果库（合并）∪ 全部卡成功内联并集〕；无库输入时退化为〔内联并集〕、命中即通过；被读面隔离的内联条目不参与（对其引用按未解析处理）；
9. 冲突矩阵全项：库内重复（同库/跨库）、跨卡目录内联×内联、库×内联＝Error；同卡目录内已读面隔离者＝照实汇入 Warning（不升级）；引用不产生快照冲突条目（同目录读面 Warning 照汇入；跨目录引用×引用不报冲突）。
10. 报告必须项：输入面统计（卡目录数/库目录数）＋通过面统计（成功卡定义数、成功快照数）＋问题面统计（Errors/Warnings 数）；提供"无 Error"直接判定面（必须与 Errors 计数一致）；
11. 条目契约：稳定类别标识（至少覆盖七类维度面：目录缺失/卡侧汇入/库侧汇入/卡 id 重复/库内重复/跨来源冲突/引用未解析；细维度由原文承载）；来源锚点（文件路径优先/卡 id/prefab id，按可用性、至少一个）；读面汇入保留原文可追溯；未解析引用逐（卡 id，引用 id）一条；序列化不要求（可选）。
12. 测试与证明口径：未解析引用＝统一语义（"缺引用"/"悬空引用"同场景、无 Error 分级）；好数据＝Errors/Warnings 双零（构造避开同目录共享引用面）；必须构造清单＝第 4 轮（含增补十项）；outputs 全量预检冒烟（卡＋库，缺失可辨识跳过）；纯静态证明＝测试不构造引擎对象＋输入目录零改动断言。
