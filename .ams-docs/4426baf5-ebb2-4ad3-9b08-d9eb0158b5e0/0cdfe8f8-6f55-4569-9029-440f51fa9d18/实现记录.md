## 三、偏差、未决项与对抗性说明

1. **effects 字符串态输出开关＝未实现**（需求定为"可选〔若实现则须测试〕"，非硬要求）：本批完整落实默认策略（prefabs 按序＋inline 对象态＋分组保序＋字符串态读入→对象态写出）；未引入策略参数以保持 writer 契约与 API 面最小（可后续加性扩展）。
2. **writer 抛错隔离（iii）＝已实现并测试**（第 2 轮为"鼓励覆盖"——已超低限完成）。
3. **Windows 平台换行实证**：实测 net8.0 `System.Text.Json` 写出器在 Windows 输出 CRLF——已按硬性文本契约在 `Serialize` 出口统一规范化至 LF（测试锁定无 `\r`；跨平台输出一致）。该规范化对 JSON 字符串内容安全（控制字符必为转义形式，原始 CR 仅出现于格式换行）。
4. **防御细节（超需求最小面）**：组件写出结构平衡校验（防扩展 writer 破坏 JSON 结构）＋组件级 `ArrayBufferWriter` 缓冲（写入异常不污染主输出）——均兜底路径、不影响正常面。
5. 未决项：无阻塞项。全量测试依赖 `outputs/kards-cards`（现网存在 1646 文件、已全量执行；缺失时为可辨识跳过）。
6. 测试内部构造干预（判据 d、Attributes 不一致态、重复单位类型等）经**反射调用 internal 构造器**实现——不扩张公开 API 面（沿 B1/B2 裁定）。
