## 一、功能职责（本批）

为卡牌数据栈补齐 **CardDefinition → `*.card.json` 写出能力**，使创作数据成环（读→写→读）：
反向映射（CardAttributeMap）／六组件 Write（含类别/单位类型反向词）／注册面 Writer 槽位（CardComponentRegistry）／`CardDataJson.Serialize`／effects 写出（prefabs 引用＋inline 全对象态）／目录级 `SaveDirectory`；覆盖逐组件 → 整卡 → 目录 → 全量（1646 张）round-trip 测试与零回归。

## 二、需求阐明（逐轮 Q&A）

### 第 1 轮（2026-10-08）：Serialize 入口与警告契约；反向映射 API 消费面

**子的问题（要点）**

- A1：必须入口集合——①`Serialize(CardDataBody)`／②`Serialize(CardDefinitionEntry)`／③`Serialize(string id, CardDefinition)` 是三者都要还是允许取舍（"并/或"的准确含义）？测试将锁定哪些入口？
- A2：警告集产出形态——out 参数（对称 `Deserialize(string, out warnings)`）还是结果对象（`SerializeResult{Json, Warnings}`）？测试如何断言"警告集为空"？
- A3：失败语义——整体性非法输入（null、id 空白）fail-fast 抛出、组件级不可还原只走警告集？
- B1：反向映射 API 消费方——仅内置六组件 Write 内部（可保持类当前可见性）还是对宿主/社区工具公开？
- B2：round-trip 测试是否允许只经 `CardDataJson` 公开全路径间接覆盖，不要求单元级直调？
- B3：是否要求"正向映射的每一项都可反向生成"作为对称性硬保证（16 项 Exact＋2 项参值型＋老兵两前缀逐项往返断言）？

**答复与决策**

**A1（入口集合）**
- **必须**：① `Serialize(CardDataBody)`（最完整数据镜像形态：id/name/components）；② `Serialize(CardDefinitionEntry)`（设计定稿钦定的写出入口：id＋CardDefinition）。
- **可选**：③ `Serialize(string id, CardDefinition)`（能力与①②重叠——entry 即 id＋definition 的天然分解，允许实现者按最小接口原则省略；如实现须同样补测试）。
- 允许以"单一核心实现＋重载转换"方式落地。**测试锁定**：①②各 ≥1 例；③如实现则 ≥1 例。
- 备选与拒绝：仅取其一——拒绝（①承载读入/导出形态、②承载装载产出形态，两个既有数据形态都要，免调用方自行拼装）；仅②——同上拒绝。

**A2（警告契约）**
- **硬要求**：警告必须**可达、不得静默丢失**；公开面不得存在会吞掉警告的重载。
- 推荐形态：与 `Deserialize(string, out warnings)` 对称的 **out 参数**；`SerializeResult{Json, Warnings}` 结果对象为**可接受备选**（实现者择一；允许再加便捷重载，但便捷重载不得违反"可达"）。
- **测试断言**：全量 1646 张往返**警告集为空**（硬验收指标）；另构造不可还原例，断言警告非空且来源指向正确。
- 备选与拒绝：仅"无警告通道"的 string 返回——拒绝（违反"不静默"原则）；结果对象——不拒绝（允许）。
- 附注：若全量实现中发现"必然产生警告"的子集，须在验收汇报中专项说明并由委托方裁定，不得自行降低指标。

**A3（失败语义，两层）**
- 整体性非法（null、id 空白、组件重复等）＝ **fail-fast 抛出**（异常类型循 .NET 惯例；与读侧 fail-fast 口径一致）。
- 组件级/项级不可还原（关键词无反向、组件无 writer/未注册等）＝ **警告集记录＋组件级跳过/项级降级**，其余照常，不中断。
- **测试**：非法输入抛出断言＋不可还原警告断言，双覆盖。
- 备选与拒绝：全警告化（不抛）——拒绝（配置性错误违背既有"fail-fast/隔离分层"口径）。

**B1（消费面）**
- 反向映射 API 消费方＝内置六组件 Write（同程序集）＋测试；**维持现状可见性（internal），本批不公开扩张**。
- 依据：宿主/工具的"生成数据体"需求经公开面 `CardDataJson.Serialize` 即可满足，无需直触映射表；扩大公共 API 面需单独论证。
- 备选与拒绝：公开化——暂缓（无已证实消费场景；兼容性成本）。

**B2（测试覆盖形式）**
- **允许**经公开全路径间接覆盖（不强制单元直调）；**但反向映射每一单项都必须有逐项断言**（可独立失败、可定位）。
- 实现者可择：单元直调（若测试可访问）或黑盒逐项（单卡构造 → 导出 → 断言含预期标识 → 再读等值）。
- 备选与拒绝：仅抽样＋全量往返——拒绝（无法定位单项映射缺陷；"硬保证"需要逐项证据）。

**B3（对称硬保证）**
- **是，逐项硬保证**：Exact 16 项、参值型 2 项（`heavyArmorN`/`intelN`，N>0）、老兵双前缀（`BecomesVeteran:<id>`/`VeteranOf:<id>`）——正向每项均可反向生成并往返等值（断言"正向映射集合 ⊆ 反向可生成集合"的逐项实例化）。
- **已知边界登记**：裸『老兵』标记（`KeywordIds.Veteran`，无端口承载）无独立英文标识、不可还原——出现于声明而无 `VeteranOf:` 端口时须落入警告（不静默）；不要求为其发明新标识。
- 备选与拒绝：只保证官方 9 词条双向——拒绝（Orc 自有 7 项标识亦为数据体既定词汇，社区创作依赖其往返；实现成本相同）。

### 第 2 轮（2026-10-08）：CardComponentRegistry 的 Writer 槽位契约与验收形态

**子的问题（要点）**

- A1：writer 的输入/输出契约——输入＝组件定义实例；输出＝"可直接嵌入 components 数组的 JSON 对象"（writer 决定全部字段、含或不含 component 名），还是 writer 只产出字段、由序列化器统一补齐 component 名与包裹？
- A2：组件级警告如何回流——不可还原项的警告由谁产出（writer 内部含警告通道 vs 序列化器层统一判定）？扩展 writer 是否有"产出警告"的义务/通道？
- A3："未注册/无 writer 组件＝隔离警告"的语义确认（i 从未注册、ii 已注册未提供 writer——均警告＋跳过＋其余照写＋不抛）？是否要求专项测试锁定？
- B1：内置六项 writer 验收——显式断言（六组件均在场零警告）还是允许仅经 round-trip 间接保证？
- B2：向后兼容范围——既有 Register 调用点零修改；注册项（公开记录）尾部新增可选槽位方式演进，允许构造签名变化（尾部新增）吗？
- B3："已注册但无 writer"是否合法状态（注册期允许、仅写出时警告）？还是注册期拒绝？

**答复与决策**

**A1（Writer 输出契约）**
- **writer 只产出该组件的"字段内容"；`component` 类型名由序列化器按注册名单点注入**（单一真源，防双写漂移）。
- 依据：读侧组件名用于分派、组件自解析字段；写侧对称——序列化器分派后调用 writer、名由分派方统一写。若由 writer 自写名，扩展作者写错名会产生"读回时未知组件隔离"的隐蔽不一致。
- 实现形态（流式 writer／片段／对象）由实现者择，但"component 名单点注入"为硬契约。
- 备选与拒绝：writer 产出完整对象（含名）——拒绝（名双写漂移风险；作者负担与一致性差）。

**A2（组件级警告回流）**
- **writer 契约含警告通道**（义务：发现不可还原项必须上报，不得静默）。
- 双层警告合并进 Serialize 警告集（条目须含组件名/来源，可定位）：a) 组件级＝writer 内部发现（经其警告通道）；b) 分派级＝序列化器层（未注册／无 writer／写入异常）。
- 扩展组件 writer 采用同一契约（同样有警告通道与义务）。
- 备选与拒绝：仅序列化器层统一判定——拒绝（序列化器不可能知道组件语义的"可还原性"）；writer 无警告义务——拒绝（静默违反"不静默"、抛错违反"组件级不中断"）。

**A3（隔离语义确认＋补充）**
- 确认：(i) 组件类型从未注册、(ii) 已注册但注册项无 writer——**均进警告集＋跳过该组件＋其余照写＋整体不抛**；两类诊断信息须可区分。
- **补充（对抗性审视）**：(iii) **writer 执行抛错**（整体性非法除外）同样归隔离警告（跳过组件、不阻断）——与读侧"组件反序列化失败＝警告＋跳过"对称。
- **专项测试必须**：至少锁定 (i)、(ii) 两类；(iii) 鼓励一并覆盖。
- 附注：空组件卡（无组件声明）＝正常写出空 components（非警告）。

**B1（内置六项 writer 验收）**
- 要求**显式覆盖**：至少一处断言"六组件齐全的样本卡经 Serialize 输出＝六组件在场＋零警告"（载体：卡写出测试或 round-trip 中的显式断言；推荐行为级）。
- 不接受仅弱间接保证（宽松断言无法区分"组件被隔离跳过"与"组件在场"）。
- 备选与拒绝：仅 round-trip 间接——拒绝（弱断言不满足显式性）。

**B2（向后兼容范围）**
- 准则：**既有 Register 调用点（含测试内扩展示例）零修改编译通过**。
- 注册项（公开位置记录）演进方式：**尾部新增带默认值的可选参数**（既有构造调用兼容）。
- 如遇语言级不可抗的极小适配需求，须在汇报中列出说明；目标仍为零修改。
- 备选与拒绝：不改注册项类型、另行侧挂 writer 表——不拒绝但次优（双表同步风险；推荐注册项内演进）。

**B3（"无 writer"的合法性）**
- **合法状态**：注册期允许 writer 缺省；仅写出时隔离警告（不拒绝注册）。
- 依据：向后兼容（既有注册点不受影响）；"只读/只装载"的扩展组件为合理存在；隔离＋警告已满足"不静默"。
- 备选与拒绝：注册期拒绝无 writer——拒绝（破坏兼容与读用场景；写方向为可选能力）。

### 第 3 轮（2026-10-08）：keywords 组件的写出判据与边界（保真路径／反向合成）

**子的问题（要点）**

- A1：Attributes 非空时，写出一律"全量按序原样写回"（含未映射留痕项、畸形/多重老兵声明原文）——该路径**不产生警告**（保真即无损失）？还是畸形/多重老兵声明也须警告？
- A2：Attributes 非空时若组件内 Keywords/端口与之不一致（构造干预），写出以 Attributes 为唯一真源、不比对、不警告？
- A3：反向合成路径空产出（无 Keywords、无端口、Attributes 空）时：keywords 组件省略不写，还是写出空 attributes 数组？
- B1：不可还原情形清单确认：(a) 无反向映射（含裸老兵标记无端口）；(b) 参值型值 ≤0；(c) Exact 表词条带非默认值；(d) 老兵端口 id 空白——是否还有遗漏？参值型上界是否与读侧一致？
- B2：反向合成输出顺序（老兵链标识与 Keywords 合成结果的相对次序）要求——"稳定、读回语义等值即可"还是更强？"语义等值/往返等值"是否对 attributes 数组元素顺序敏感？
- B3：VeteranOf 端口与「老兵」标记的协调：端口非空时是否只生成 `VeteranOf:<id>` 一条（标记被吸收、不警告）？读回后如何断言与构造源等值（标记＋端口双恢复）？

**答复与决策**

**A1（保真路径警告边界）**
- 实读确认：`Attributes` 即"数据体原始标识（保真保留）"全量字段——含未映射项、含畸形/多重老兵声明原文（BuiltInCardComponents.cs:204）。
- 裁定：**Attributes 非空＝全量按序原样写回，该路径不产生警告**——保真即无损失：畸形/多重项作为原文随 Attributes 往返，读回后仍按既有口径归留痕，语义等值。
- 警告只属**反向合成路径**的"不可还原"判据（见 B1）。
- 测试锁定：含畸形/多重老兵声明的卡（如两条 `VeteranOf:`）→ 写出零警告＋全量原样＋读回留痕等值。

**A2（Attributes 与派生面不一致）**
- 裁定：**以 Attributes 为唯一真源，不比对、不警告**。`Keywords`/端口为派生面（读时由 Attributes 生成）；构造干预者若欲改变输出应同步更新 Attributes，或清空 Attributes 走合成路径。
- 理由：官方全量无损往返依赖"原文优先"；比对会引入双真源冲突与假阳性。
- 测试锁定：构造"Attributes=X 且 Keywords=Y（不一致）"态 → 写出按 X。

**A3（空产出形态）**
- 裁定：**写出空 `attributes` 数组**（组件在场 → 保写出在场；读回＝组件在场空态，保结构等值）。
- 备选与拒绝：省略组件——拒绝（丢"组件在场"结构信息）；规范形态固定为显式 `[]`（不做"缺字段"变体）。

**B1（不可还原判据）**
- 确认 (a)-(d) 全部成立（均落警告、逐项可独立断言）：
  (a) 词条/端口无反向映射（含裸「老兵」标记，无 VeteranOf 端口）；
  (b) 参值型无合法参值（Value 为 null 或 ≤0——`heavyArmor0` 类不合法）；
  (c) Exact 表词条携带任意非空值（Value≠null——标识无值位，不可表达）；
  (d) 老兵端口 id 空白（防御性）。
- **补充澄清**：
  (e) 参值上界**与读侧一致**：int 范围内任意正整数均可生成 `heavyArmorN`/`intelN`（无附加上界）；
  (f) 双端口并存（BecomesVeteran＋VeteranOf）＝可表达（各生成一条、不警告）；
  (g) `UnmappedAttributes`＝**可还原原文**（原样补入合成输出、不落警告——非静默丢失留痕项）。
- 穷举检查（Keywords 项／两端口／留痕面四类输入逐一映射）后，无其他遗漏情形。

**B2（输出顺序与等值口径）**
- 顺序要求＝**确定性**（同输入→同输出；便于测试与 diff）；不绑定参考顺序、不要求与源文件同序。
- **保真路径**＝全量按序原样（更强：保序；官方全量往返测试按**元素级同序**断言）。
- **合成路径**：等值断言＝**集合成员等值（顺序不敏感）**；推荐默认风格＝端口在前、留痕在后（非强制）。
- 依据：读侧逐项独立映射（预扫描＋逐项处理），成员真值与数组顺序无关。

**B3（VeteranOf 与「老兵」标记协调）**
- 裁定：**VeteranOf 端口非空＝只生成 `VeteranOf:<id>` 一条**；`Keywords` 中的「老兵」标记被端口吸收（不再单独处理、不警告）——读侧语义即"端口正式承载、标记随内容产出"（单一真源的对偶）。
- 对偶边界：Veteran 标记存在而 VeteranOf 端口为空＝裸标记 → 警告（(a) 内，第 1 轮已定）。
- BecomesVeteran 端口：生成 `BecomesVeteran:<id>`；**不产出标记**（升级链信息，非标记承载）。
- 读回等值断言（与构造源）：①`VeteranOf` 端口值==源；②标记读面恢复在场（由端口恢复）；③再写出幂等（==同 `VeteranOf:<id>`）。

### 第 4 轮（2026-10-08）：effects 写出策略与空形态；其余四组件写出边界

**子的问题（要点）**

- A1："可提供策略参数"的语义边界：默认＝prefabs 引用＋inline 对象态；策略参数要切换什么语义？本批是否要求实现至少一个非默认策略并配测试，还是仅预留签名？
- A2：effects 组件在场但两区皆空时：两字段省略还是写 `[]`？请给"组件在场时各可选字段的空值规范"统一口径（对照：tagData.tags 空省；keywords.attributes 空写 `[]`；effects.prefabs／inline 空＝？）。
- A3：inline 对象态确认：每项＝完整自包含对象（root.id 非空）；写出→读回分组/元素/顺序保持；字符串态读入后写出必为对象态——确认？
- B1：typeCategory 的"读不回"非法组合（Unit 且单位类型为空→读侧拒绝；类别＋单位混用→读侧拒绝）：写方向警告／抛出／照写？"保持组合与顺序合法"是否要求写方向主动保证合法（降级）？
- B2：非单位卡带 battleStats 定义——照写保真、警告、还是省略？
- B3：确认三处口径：factionCost＝枚举名＋kredits 必写；tagData＝rarity 必写、tags 空省（非空按序）；组件不在场不写组件；单位类型词＝官方小写、类别词＝order/countermeasure？

**答复与决策**

**A1（策略参数边界）**
- **必须（默认策略）**：prefabs 引用原样按序＋inline 对象态按序＋两区分组保序。

### 第 5 轮（2026-10-08）：SaveDirectory／SaveFile 的落盘契约

**子的问题（要点）**

- A1：目标目录不存在时的行为："对齐 LoadDirectory 口径"的准确含义——（i）创建目录后写；（ii）不创建、按失败/空操作；（iii）其它？"对齐"指命名/扫描口径还是行为口径？
- A2：单卡写出失败（IO/权限）＝隔离还是抛出？若隔离——返回结构（失败条目＝文件/卡 id＋原因？失败与警告是否分列）；测试锁定要求？
- A3：成功判定与返回：返回值能否让测试断言"全部写成功、零失败/零警告"；是否要求与 LoadDirectory 产物形态对称（便于目录 round-trip 断言）？
- B1：id 含非法文件名字符/路径分隔符时（读侧不校验）——拒绝（抛/失败）／清理转义／警告照写？"读回必然断裂＝警告"判据是否覆盖"文件名不可写"？
- B2：覆盖语义：目标文件已存在＝覆盖/拒绝/警告后覆盖？同批输入内含重复 id＝如何（读侧对重复 id 隔离后者——写方向是否对称）？
- B3：SaveFile 单文件入口：显式目标路径（目录+文件名）还是目录+id 组合？与 SaveDirectory 关系；两者是否都需测试覆盖？

**答复与决策**

**A1（目录不存在）**
- 裁定：**（i）自动创建目录后写**（含多级创建）。
- "对齐 LoadDirectory 口径"的准确含义＝**命名/结构口径一致**（单卡一文件、`<id>.card.json`、顶层、`*.card.json`）；**行为口径不做逐条镜像**——读宽容（不存在＝空结果）与写创建（不存在＝创建）为两个方向各自的合理行为。
- 备选与拒绝：（ii）不创建＋失败/空操作——拒绝（调用方负担、导出惯例不符）；(iii) 不存在。

**A2（单卡写出失败）**
- 裁定：**单卡级失败＝隔离**（记失败条目、跳过该卡、其余继续）——对称 LoadDirectory 的单文件隔离口径；**目录准备失败（无法创建/准备目标目录）＝整体性失败（抛出）**——不依赖单卡内容、无法开始写入（与"整体性非法＝抛"分层一致）。
- 返回结构：**成功条目／失败条目／警告条目分列**且可定位——失败条目＝卡 id＋目标文件＋原因；警告条目＝卡 id＋来源（序列化语义面）。
- 测试锁定：①全成功＝失败空、警告空；②单卡 IO 失败＝失败恰 1 条、其余卡仍成功写出（构造方式由实现者定）；③目录准备失败＝抛出断言；④空输入列表＝空成功（零文件）。
- 备选与拒绝：全抛出——拒绝（与读侧隔离先例相悖、导出场景需尽力产出＋报告）。

**A3（返回形态与断言）**
- 成功判定：返回值**必须**支持"全部写成功、零失败/零警告"断言（结构化计数/清单）。
- 与 LoadDirectory 形态关系＝**结构风格对称**（失败/警告分列、条目可定位），**非字段镜像**；目录 round-trip 断言方式＝写出后经 `LoadDirectory` 再读做语义比较（不依赖 Save/Load 返回值直接比对）。

**B1（非法 id 的文件名）**
- 裁定：**单卡失败（拒绝）**——id 含文件系统非法字符、路径分隔符、或可构成路径穿越的序列（如 `..`）时，该卡进失败集、跳过、其余继续；**不转义、不清理、不照写**。
- 理由：转义/清理破坏 id 与文件名的往返一致（读回 id 失真）；照写存在**路径穿越安全风险**（写出目录外）与平台非法字符失败；故以"拒绝＋报告"为最稳。该问题属"文件系统层不可表达"，由单卡失败契约覆盖（非序列化警告面）。
- 附注（边界提示）：文件系统大小写不敏感平台上的形异实同 id（如 `Card`/`card`）属平台边界；本批按读侧同口径（序数判重），平台冲突行为由实现说明、不作硬性要求。

**B2（覆盖与批内重复）**
- 跨运行同 id 重复保存（目标文件已存在）＝**覆盖**（导出语义，静默、不警告）。
- **同批输入内含重复 id＝首见写出、重复者进失败集**（原因＝卡 id 重复）——对称读侧"后者隔离"口径。
- 测试锁定：覆盖（先写后重写、内容更新）；批内重复（1 成功＋1 失败、失败原因正确）。
- 备选与拒绝：重复＝"警告＋覆盖"——拒绝（静默丢失"两份都想保留"的信息、与读侧口径不对称）；重复＝全失败——拒绝（首见者本是合法单卡）。

**B3（SaveFile 与 SaveDirectory 关系）**
- SaveFile 形态＝**目录＋卡条目（id＋定义）**——复用命名规则（`<id>.card.json`）与安全校验；**不提供任意目标路径形态**（如有未来需要另加底层 API）。
- 关系：**SaveDirectory＝逐卡归约到单文件写**（SaveFile 为原语）；两入口**均公开、均须测试覆盖**；返回**同一结构形态**（单卡时成功/失败条目各 ≤1）——"隔离＋报告"契约在两入口一致。
- 测试覆盖：SaveFile（成功/失败/命名/安全校验）；SaveDirectory（多卡/目录创建/批内重复/单卡 IO 隔离/空列表）。

### 方法层第 1 轮（2026-10-08）：写出文本契约与诊断条目最低要求

**A3（幂等·硬性）**
- **升级为硬性断言**：全量测试与目录 round-trip 测试中，`J1==J2` 字节级相等为硬性验收。
- 依据：文本契约（A1/A2）已全固定，幂等字节级相等成为规范收敛的直接证据。
- 适用边界：单元/组件级测试不强制（不必然走完整"读→写→读→写"链）。

**B1（警告最低字段集·硬性）**
- 每条警告至少含：①**卡 id**；②**组件名**；③**项/字段原文**（如不可还原标识原文；无法定位到项时＝组件级）；④**原因类别**（稳定关键词）。
- 语言＝**中文**（仓库惯例）。
- "来源指向正确"的验收方式＝测试能经"卡 id＋项原文（或组件名）"唯一检索到目标警告。
- 补充：多条警告逐条可分（一条一项，不合并为多义单条）。

**B2（三类隔离可区分）**
- 最低手段＝**文案中稳定、可辨识的关键词**（如"未注册"／"无 writer（无写出器）"／"写入异常"／"无反向映射"／"值不可表达"）；**结构化类别字段＝可选升级**（若提供须向后兼容）。
- 依据：与读侧警告先例（字符串列表）对称、最小 API 面；关键词即契约（实现与测试共同使用）。
- 序列化侧警告**须携带目标卡 id**（Serialize 为单卡上下文；目录级汇总同样保持）——与 Save 侧失败条目（卡 id＋目标文件＋原因）风格对齐。
- 备选与拒绝：强制结构化枚举——拒绝（扩 API 面、与读侧字符串先例不对称；选择提供＝允许但非最低）。

### 方法层第 2 轮（2026-10-08）：写方向"无载体面"边界与字段集冻结

**子的问题（要点）**

- A1：isGuard=true（代码注册路径可构造）的卡写出→读回 IsGuard=false：忽略（设计边界）还是落警告（读回不等值、不静默）？必须择一。
- A2：第 6 轮语义比较清单未含 IsGuard——刻意排除还是补入？如排除，是否要求专项测试锁定 isGuard=true 用例，或允许不测？
- A3：复核"忽略面"是否仅 IsGuard 一项？还有其它加性面/读面需"忽略或警告"裁定？
- B1：本批是否不新增任何数据体字段（字段集完全冻结=读侧镜像）？"写方向新增字段必须同步往返测试"约束是否因此无适用对象（闭合）？
- B2：IsGuard"忽略/警告"是否同时意味着不为其发明数据体载体（不做 v1 变更）？
- B3：空组件卡写出形态：`"components": []` 显式空数组——确认？

**答复与决策**

**A1（IsGuard 裁定）**
- 实读确认：`CardDefinition.IsGuard` 为公开读面（代码注册路径加性面；数据体路径恒 false；无 v1 载体）。
- 裁定：**警告＋照写**——不落盘 IsGuard（不阻断）；仅 isGuard=true 时产生警告；文案含卡 id＋原因类别（如"非数据体字段（IsGuard 无 v1 载体）"）。
- 理由：属"写方向旅程损失"（定义字段无载体丢失、读回必然不等值）——命中不静默原则；具可行动性（改用 `guard` 词条承载）；官方全量零警告不受影响（恒 false）。
- 备选与拒绝：忽略（不提警告）——拒绝（静默丢失定义字段、读回不等值不作声、无可行动指引）。

**A2（语义比较清单）**
- 裁定：**刻意排除**（第 6 轮 14 项清单维持、不含 IsGuard）——排除理由＝数据体 v1 无载体、读回必然 false（纳入则产生"已知必然失败"的比较项）。
- 但**必须**专项用例锁定：isGuard=true 代码构造卡 → 写出 → 读回：断言①警告（A1 口径、含卡 id）；②读回 IsGuard=false（不承载事实）。**不允许不测**。
- isGuard=false 常态卡：等值自动成立（隐含覆盖，不单列）。

**A3（忽略面复核）**
- 复核结论：**仅 IsGuard 一项**（已逐项过 CardDefinition 全部公开读面与构造面：Name、六组件全部派生面、双端口、UnmappedAttributes 均有载体；卡 id 外部携带已裁定）。
- 另点明一类"**不检面**"（非忽略/警告裁定）：**卡级完整性**（跨组件规则，如"缺 factionCost/tagData"）——写方向不复刻卡级校验、不警告（读回 Failures 自会揭示；见 B3）。
- 装配面数据（代码效果注册声明等）不在 CardDefinition/数据体字段集内——不属写方向承诺面（无警告）。

**B1（字段集冻结）**
- 确认：**不新增任何数据体字段**（六组件字段集＝读侧字段镜像、完全冻结）；亦不新增组件类型。
- "写方向新增字段必须同步往返测试"约束**无新增适用对象**——闭合成立；其意图保留：实施中若发现"必须新增字段/组件类型"的场景，**停下并汇报**，不得自行扩字段集。

**B2（IsGuard 载体不发明）**
- 确认：**不发明载体、不做 v1 变更**（schemaVersion 维持 1、严格相等口径不变）；**也不得借用其它既有字段旁路承载**。
- 未来如需载体：归后续批/迁移器语境（本批不涉及）。

**B3（空组件卡）**
- 形态确认：显式 `"components": []`（对齐集合空值规范）。
- 可达性说明：①经 CardDefinition 入口**不可达**（主构造强制 factionCost+tagData）；②经 CardDataBody 直接入口技术可达（body 允许空组件）——该形态属**调用者输入不完整**（读回因缺必填槽位进 Failures）；**写方向照写、不警告**（卡级完整性＝跨组件规则、不复刻；写方向警告面限定＝"写方向旅程损失＋组件级自含可判定问题"）。
- 备选与拒绝：为空组件复刻"缺必填槽位"校验并警告——拒绝（跨层复刻卡级规则、维护耦合；读回 fail-fast 已揭示）。
