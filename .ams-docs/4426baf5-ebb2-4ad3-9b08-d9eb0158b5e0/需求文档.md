# Requirements — 端到端创作卡牌工具链

把 DIY 创作数据（卡牌 `*.card.json` 与效果 `*.prefab.json`／卡内联）到游戏内卡牌的**全链路**打通：标准分发格式/方法、效果加载方式与流程（加载时机声明）、卡牌组装、卡牌整体序列化/反序列化、端到端验证。

> 状态：**草案（回溯整理版，2026-10-08）**——由功能面主 Agent 按 double-grill 流程补建；批 1/2/3 已实现并验收（1316/1316 全绿），**待用户逐项确认**（见《需求-grill计划》Q1-Q4）。
> 术语：见 `CONTEXT.md`（术语提案见需求-grill计划 Q5）。

## Scope

- Includes（已实现/已交付）：
  - **R1 标准分发格式/方法**：`*.card.json` v1 ＋ `*.prefab.json` v2 ＋ 卡内联（对象/字符串两态，读宽写窄）；分发单位＝目录；三段管道＝装载（`CardDataLoader`/`PrefabManager`）→ 校验（分发预检器）→ 注册（宿主接线 `RegisterPrefab`/`DeclarePrefab`）。
  - **R2 效果加载方式与流程（加载时机声明）**：三时点（装配/装载/授予）＋运行期注入模型；装载与否＝`kind`；激活订阅＝`hooks`；"通道即声明"。〔Q1 待用户裁定〕
  - **R3 卡牌组装**：构造期＋加载期两段式规范（现状固化）。
  - **R4 卡牌整体序列化/反序列化**：定义级双向（写方向补全：反向映射／组件 Write／注册面 Writer／`CardDataJson.Serialize`／`SaveDirectory`；效果侧 `PrefabWriter`）。
  - **R5 端到端全链路**：读→写→再读成环；分发→装载→注册→对局→打出→行为断言三链；全量 1646 卡＋6 库冒烟。
- Excludes：
  - 卡面文本→json 上游（效果编译管线生产驱动）〔Q2a 待确认〕
  - 实例级运行时状态的"读回"（导出维持现状）
  - manifest/卡包清单、自动注册封装

## Constraints

- 既有测试零回归（1260→1291→1316）；不破坏既有公开 API；内核（`src/Orc`）变更逐条登记。
- 预检器纯静态只读；落盘 UTF-8 无 BOM；文本契约（LF／2 空格缩进／尾随换行）；读宽写窄。
