## 二、需求阐明（逐轮 Q&A）

### 第 1 轮（2026-10-08）：效果落盘·写方向的数据源与 API 归属

**子的问题（要点）**

- 主问题：既有两侧不对称（`LoadDirectory` 是实例方法→注册进实例字典；批 1 `CardDataWriter.SaveDirectory/SaveFile` 是静态 API、外部传入集合）——写方向数据源按 (A) 管理面镜像（实例状态导出）还是 (B) 数据管道（静态入口、外部集合），还是两者都要？判定依据？
- 附 1：入口集与命名——卡侧命名是 `SaveDirectory/SaveFile`（委托原文写「SaveDirectory/WriteFile」）；单文件入口是否照卡侧＝"目录＋单个快照"（不接受任意目标路径）？命名/入口数量属"实现者择"还是锁定为验收面？
- 附 2：写对象范围——是否要求任意来源完整三层快照（csx／assemblyKey／含 injects/modings）均可往返？`RegisterHandler` 的 handler 面确认不落盘（只落快照）？
- 附 3：「不破坏既有公开 API」边界——在 `src/Orc/Cards/` 下新增公开类型/成员（落盘入口、报告类型）属允许的加性变更吗？

**答复与决策**

**主问题（数据源与 API 归属）：裁定 (B) 数据管道为主；不提供 (A) 实例导出便捷面。**

- 判定依据：
  1. **与卡侧一致性**：批 1 已验收的写侧风格＝静态入口＋外部载荷集合＋目录口径（`CardDataWriter.SaveDirectory/SaveFile`）；效果侧"对称"应统一到同一风格。
  2. **消费场景**：写盘发生于创作/编译产物导出（数据在管理器**外部**诞生——`EffectCompiler` → 快照 → 落盘）；"把管理器已注册状态再导出"无已证实消费场景。
  3. **组合性**：实例导出可由公开读面（`PrefabIds` ＋ `TryGetPrefab`）＋ 静态入口自行组合，无需内置（YAGNI，避免双形态 API 面）。
  4. **"对称 LoadDirectory"的正解**：＝目录口径（`*.prefab.json`、单文件隔离、报告式返回）与失败语义的对称，**非**"实例状态对偶/回收闭环"。
- 备选与拒绝：
  - 仅 (A) 管理面镜像——拒绝（无消费场景；与卡侧风格不一致；导出语义含混〔全量 vs 增量、已注册 vs 待注册〕）。
  - (A)＋(B) 两者都要——拒绝（无已证实场景；加性面维护成本；A 可组合达成）。

**附 1（入口与命名）：照卡侧口径锁定；命名/入口数＝验收面。**

- 入口＝`SaveDirectory`（目录级批量）＋ `SaveFile`（单文件）；**命名照卡侧**（委托原文中「WriteFile」为笔误，以 `SaveFile` 为准）。
- 单文件入口形态＝"目录＋单个快照"（不接受任意目标路径；文件名由实现按命名规范生成）。
- 锁定为验收面（防止命名碎片化）；除两入口外不加性扩展命名变体。
- 备选与拒绝：「WriteFile」命名——拒绝（与卡侧不一致、命名碎片化）；入口数量自由化——拒绝（对称性是本批验收主题）。

**附 2（写对象范围）：是；handler 面确认不落盘。**

- 要求：任意来源的完整三层快照（csx 形态、assemblyKey 形态、含 `injects`/`modings` 的形态）**均等价往返**（经 `PrefabJson` v2 序列化——写落盘层不得有形态过滤/降级）。
- `RegisterHandler` 程序集注册表＝**不落盘**（进程内注册、不可序列化；分发数据面只有快照——csx 内联或 assemblyKey 引用）。
- 备选与拒绝：导出 handler 注册表——拒绝（不可序列化、无分发语义）。

**附 3（公开 API 边界）：允许加性扩展；禁止破坏性变更。**

- 在 `src/Orc/Cards/` 下新增公开类型/成员（落盘入口、报告类型等）＝**允许的加性变更**（"不破坏既有公开 API"＝既有成员签名/语义不变；新增面合法）。
- 备选与拒绝：要求全部 internal/private——拒绝（分发工具链需公开可消费面）。

**委托方补充（对抗性审视增补，纳入验收面）**

- **文件命名**：`<root.id>.prefab.json`（对齐卡侧 `<id>.card.json`；保证"写→读"闭环不歧义、批内不冲突）；非法 id（路径分隔符／`.`／`..`／空白）**拒绝**（对齐卡侧防路径穿越）。
- **批内重复 id**：首见写＋重复失败（对齐卡侧口径）。
- **空输入**：空成功（零文件；对齐卡侧）。
- **输出确定性**：同输入同输出（稳定序）；跨运行覆盖（同 id 重存覆盖，对齐卡侧）。
- **报告语义**：结果＝成功/失败明细分列、报告式返回（对齐批 1 写侧结构；字段级裁定见第 2 轮）；目录准备失败＝整体抛出、单文件失败＝隔离（对齐卡侧落盘契约）。
- **闭环不变量（测试要求）**：写出的目录可被 `LoadDirectory` 读回（装载/注册不冲突）；文件扩展名与既有扫描模式（`*.prefab.json`）一致。

### 第 2 轮（2026-10-08）：效果落盘·报告与失败契约的精确形态

**子的问题（要点）**

- 主 Q1–3（报告字段级）：`PrefabLoadReport`＝`(int Loaded, IReadOnlyList<string> Failures)`（计数＋字符串）与批 1 `CardDataSaveResult`（三分列结构化：Succeeded〔id＋文件〕/Failures〔id＋文件＋原因〕/Warnings）参照系冲突——① `Written`＝成功条数还是成功明细列表？② `Failures`＝字符串列表（"文件名: 原因"）还是结构化条目？③ 是否有 `Warnings` 分列？效果侧经 `PrefabJson` v2 是否存在"警告面"？若无，明示依据。
- 附 1：`SaveFile`（单文件入口）失败语义——非法 id／序列化失败／IO 失败＝报告式返回（不抛）？目录准备失败＝抛出？即"报告式"还是"抛式"？
- 附 2：确定性的"序"＝输入集合序（首见写）还是按 id 排序？
- 附 3：非法 id 判定是否完整沿用卡侧规则（空白/`/`/`\`/平台非法文件名字符/`.`/`..`）？

**答复与决策**

**主 Q1–3（报告字段级）**：**裁定＝"写方向统一"结构（对齐批 1 `CardDataSaveResult` 的分列与明细精神）；并对参照系冲突给出效力排序**：委托中"报告形态**建议**（…）"＝建议级；"失败契约对齐批 1 写侧风格"＝硬约束；两参照系冲突时，以"写方向跨批统一（批 1）＋ 本域可对称处（报告式返回／隔离语义——非逐字段同构）"为准。

1. **`Written` → 成功明细列表（`Succeeded`；条目＝快照 id＋目标文件）——非计数**。
   - 理由：①写方向跨批统一（批 1 卡侧 `Succeeded` 为明细）；②导出清单可断言、可展示；③读侧 `int Loaded` 有查询面（`PrefabIds`）托底，写侧无等价查询面——报告直给更自然。
   - 备选与拒绝：仅计数（对齐 `PrefabLoadReport` 的 `int`）——拒绝（跨批不一致；弱断言；无查询面托底）。
2. **`Failures` → 结构化条目（快照 id＋目标文件＋原因）**。
   - 理由：对齐批 1；可定位、可编程（报告为公开 API 与测试断言对象）。
   - 备选与拒绝：字符串列表（"文件名: 原因"，对齐 `PrefabLoadReport`）——拒绝（跨批不一致；定位信息弱）。
3. **`Warnings` → 无此字段；明示"效果侧写方向警告面不存在"**。
   - 依据：①效果快照＝**完备数据模型**（csx/assemblyKey、hooks、events、modings、injects 全字段直出；无"派生面／无载体／保真路径 vs 合成路径"概念）；②`PrefabJson` v2 序列化无告警通道；③对称读侧 `PrefabLoadReport` 亦无警告面；④"预留永空字段"与批 1 grill 已立先例（拒绝占位接口）相悖。
   - 备选与拒绝：保留恒空 `Warnings` 字段（跨批字形统一）——拒绝（无可达警告源＝死字段；YAGNI 先例）。

**报告类型锁定（公开 API 面）**：`PrefabSaveResult(Succeeded: IReadOnlyList<PrefabSaveSuccess>, Failures: IReadOnlyList<PrefabSaveFailure>)`；条目＝`PrefabSaveSuccess(string PrefabId, string File)`、`PrefabSaveFailure(string PrefabId, string File, string Error)`；落点＝`src/Orc/Cards/` 与 `PrefabManager` 同域（具体文件由实现者定）。

**附 1（`SaveFile` 失败语义）**：**报告式**（不抛），与卡侧完全一致——

- 非法 id／序列化失败／IO 失败 → 进 `Failures` 条目（单卡时 `Succeeded`/`Failures` 各 ≤1）、不抛；
- 目录准备失败 → 抛出（整体性）；参数 null → 抛出（`ArgumentNullException`）；
- 返回类型与目录入口相同。
- 基准证据：卡侧 `CardDataWriter.SaveFile(directory, entry) → CardDataSaveResult`——实现须与此语义对齐。
- 备选与拒绝：抛式单文件入口——拒绝（跨批不一致；"报告式＋隔离"为本批主题）。

**附 2（确定性"序"）**：**输入集合序**（调用方声明序）——

- 处理序＝输入序；批内重复＝输入序"首见"写出、重复者进 `Failures`；**不按 id 排序**；
- 报告条目顺序与处理序一致（同输入同输出；测试锁定）。
- 备选与拒绝：按 id 排序——拒绝（丢失声明序语义〔效果快照声明序＝装载序〕；无需求）。

**附 3（非法 id 判定）**：**完整沿用卡侧规则（双防线）**——

- 单点校验＝空白／含 `/`、`\`／`Path.GetInvalidFileNameChars()`／`.`、`..`；
- 二道防线＝全路径归化前缀校验（写盘前确认落点在目标目录内）；
- 校核对象＝`<root.id>.prefab.json` 拼装落点（后缀为常量、不参与 id 校验）；
- 若发现卡侧未覆盖的平台风险，可**加性补充、不得放松**（补充项须在实现文档登记）。
- 备选与拒绝：自定义简化集——拒绝（跨批不一致、安全口径漂移）。

**修订登记**：第 1 轮"委托方补充"第三条"报告语义"表述已按本轮细化修正（成功＝明细列表；对齐对象＝批 1 写侧结构；字段级见本轮）。

### 第 3 轮（2026-10-08）：效果写出·文本契约与幂等口径（含源码触达边界）

**子的问题（要点）**

- Q1：效果 `*.prefab.json` 写出文本形态——缩进多行（宽度？与卡侧 2 空格一致？）还是紧凑单行？LF？尾随换行？UTF-8 无 BOM？与卡侧硬契约完全对齐还是"语义可读即可"？判定依据？
- Q2：幂等口径——"写→读→写"字节级幂等（J1==J2）是否本批硬指标（卡侧同级）？"同输入两次写出＝字节一致"？对"外部既有样本读入→写出"是否允许文本规范化（语义等值即可、文本不保真）？
- Q3：源码触达边界——本批对 `src/Orc` 的允许改动面：仅 `PrefabManager.cs`＋同目录新增，还是 `src/Orc/Cards/` 内既有文件（如 `PrefabJson.cs`）小改亦允许？"不动 src/Orc 其它域"的判据？

**答复与决策**

**Q1（写出文本形态）：完全对齐卡侧硬契约（多行缩进 2 空格／LF／尾随换行／UTF-8 无 BOM／确定性键序）；实现于落盘出口；`PrefabJson` 既有行为不变。**

- 契约细则：2 空格缩进多行；换行一律 LF（落盘出口统一规范化——Windows 实测 `System.Text.Json` 缩进输出为 CRLF，同卡侧处置）；尾随换行有；UTF-8 无 BOM；键序确定（由 DTO 声明序保证——同输入同输出）；null 值字段忽略（沿用既有序列化选项，作为效果侧既有形态保留）。
- 判定依据：①工具链统一（卡/效果同套文本契约，diff／版本控制／社区体验一致）；②明文分发面向人读/手改（review-chain：本地明文目录＝分发唯一形态）——多行可读性必需；③跨平台一致（LF）；④既有样本实态已是"2 空格多行"形态（`KeywordPrefabs/*.prefab.json` 实测）——对齐成本低、差异仅在 LF/尾随换行规范化。
- 实现位置口径：文本契约在**落盘出口**生效；`PrefabJson` 既有 API（默认紧凑／`indented` 参数）**行为不得改变**——卡内联 effects 嵌入面（批 1 已验收）依赖其稳定；如需加性辅助（新方法/新参数默认关闭）在 Q3 边界内允许。
- 备选与拒绝：维持默认紧凑单行——拒绝（可读性差、与卡侧不一致、社区手改不友好）；"语义可读即可、不做文本硬契约"——拒绝（工具链一致性缺失、无幂等基座）。

**Q2（幂等口径）：J1==J2 字节级＝硬指标；外部样本允许文本规范化。**

- "写→读→写"字节级幂等（J1==J2）＝**硬指标**（与卡侧同级）；"同输入两次写出＝文件字节一致"同样锁定（确定性）。
- 外部既有样本读入→写出：**允许文本规范化**（语义等值即可；不承诺文本级保真；规范化在首次写出发生、此后收敛稳定——读宽写窄原则的文本面）。
- 测试要求：落盘文件"无 `\r`＋尾随 `\n`＋无 BOM＋缩进 2 空格"字节级断言；J1==J2 断言；既有样本读入→写出→读回链的等值＋幂等断言。
- 备选与拒绝：仅语义等值、不做字节级幂等——拒绝（与卡侧不一致；版本控制伪 diff 风险）；要求文本保真（复刻外部样本形态）——拒绝（不可行且无意义）。

**Q3（源码触达边界）：允许面＝`PrefabManager.cs` ＋同目录新增文件 ＋ `src/Orc/Cards/` 内加性兼容小改；禁止面＝行为变更与其它域。**

- 允许面：①`src/Orc/Cards/PrefabManager.cs`（落盘能力自然归属）；②`src/Orc/Cards/` 同目录**新增文件**（报告类型、落盘器等）；③`src/Orc/Cards/` 内既有文件的**加性兼容小改**（如 `PrefabJson` 新增可选辅助——默认行为不变）。
- 禁止面：①对既有成员**行为/签名/默认值的变更**（如需行为变更须在实现文档列明并由委托方审定）；②`src/Orc/` 下 `Cards/` 之外的一切域；③`src/Orc.Game/**`、`src/Orc.Script/**`（只读引用）。
- 判据：改动"为本批交付物（效果落盘／往返／全链测试）直接必需，且无法在允许面内完成"方可动；每处 `src/Orc/Cards/` 既有文件改动须在实现文档**逐条登记**。
- 备选与拒绝：触达面全域放开——拒绝（批次纪律；批 1 定稿面保护）；仅 PrefabManager 单文件——拒绝（过度限制：报告类型/辅助的加性落点需同目录自由度）。

**修订登记**：（本轮无修订——第 1、2 轮表述不受影响。）

### 第 4 轮（2026-10-08）：效果快照文件级往返·等值口径与装载证据

**子的问题（要点）**

- Q1：等值比较对象与粒度——"写盘前原快照 vs 经文件系统读回（LoadDirectory 注册后 TryGetPrefab）的快照"逐层逐字段等值（覆盖 id/version/mainTrigger/otherTriggers/modings/injects 与触发器/事件全字段），还是"装载产物的等价"（Instantiate 结果一致）？两者都要吗？
- Q2："装载"的最低证据——必须真实执行 `DynamicEffectFactory.Instantiate`（csx 真编译、assemblyKey 预注册 handler；发生在"经文件往返后的注册面"上）吗？还是允许降级为结构级（BuildLoadPlan/结构断言/TryGetPrefab）？两形态各自的最低证据？
- Q3：样本来源与 outputs 依赖——csx/assemblyKey 样本＝内嵌常量还是 outputs 真实文件（缺失＝可辨识跳过）？两者都要？⑮的"既有样本读入→写出→读回链"样本是 outputs 实体文件吗？缺失时如何处置？

**答复与决策**

**Q1（等值口径）：两者都要，但职责分离——①数据等值（主、全字段）＋②装载活性（主、链路走通）；"装载产物深度等值"不要求。**
