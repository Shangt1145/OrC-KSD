## 三、偏差、未决项与对抗性说明

1. **"序列化失败"分支＝防御性、当前不可达（如实登记）**：效果快照＝完备数据模型（全字段直出、无警告通道），`SerializeForDisk` 对任意合法快照不失败；实现保留与卡侧同口径的 catch 通道（`FormatException/ArgumentException/ArgumentOutOfRangeException/InvalidOperationException`→条目化），但本批无法构造可复现输入（卡侧对应分支亦为管道隔离面）。此外：`snapshot` 为 null 属参数层（抛出），`id` 非法先于序列化被拦（报告式）——分层与卡侧一致。
2. **文本规范化实际差异登记（超"LF/尾随换行"的实况）**：实测"既有样本读入→写出"的规范化差异还包括：①数组展开多行（`System.Text.Json` 缩进固有形态——样本为行内数组 `["x"]`）；②空 `downstream` 补写为 `[]`（DTO 全字段渲染——样本省略该键）。依据需求"外部既有样本读入→写出：**允许文本规范化**（语义等值即可；不承诺文本级保真；规范化在首次写出发生、此后收敛稳定）"——测试锁定为语义等值与 **J1==J2 收敛**（均实测通过）；"差异仅在 LF/尾随换行"的设计表述与实测不完全一致，如实登记（若验收方要求与样本行内数组字面形态完全一致，需另行裁定——属超出本批文本契约细则的增强面）。
3. **非 ASCII/HTML 不转义的口径**：落盘出口采用宽松编码器（对齐既有样本实态与卡侧"不转义非 ASCII"口径）；该选择使"样本读入→写出"差异不额外引入 `\uXXXX` 转义（样本为中文/csx 原样形态）。既有 `Serialize` 默认输出（转义形态）不受影响。
4. **非法 id 二道防线**：为防御性冗余（单点校验先行拦截全部已知样本——穿越样本经单点或二道拦截均判"拒绝＋报告"）；测试覆盖"拒绝"结果本身，二道防线无法单独触达（实现保留、注释说明）。
5. **Windows 大小写不敏感同名现象**＝已知边界声明（沿用卡侧 `Ordinal` 口径；不纳入本批测试面）——与需求 Q5 裁定一致。
6. 未决项：无阻塞项。
