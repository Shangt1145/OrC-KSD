## 二、数据设计

### 2.1 结构（2 卡目录＋1 效果库目录）

```
samples/card-pack-demo/
├── README.md
├── cards/                 （卡目录 A）
│   ├── demo.rifleman.card.json
│   ├── demo.grenadier.card.json
│   └── demo.quartermaster.card.json
├── cards-support/         （卡目录 B）
│   ├── demo.vanguard.card.json
│   └── demo.scout.card.json

    └── demo.rally.prefab.json
```

### 2.2 五卡与三效果（对应关系）

| 卡（id／名） | 费用 | 数值 | 效果 | 形态 |
|---|---|---|---|---|
| `demo.rifleman`／步枪兵 | 0 | 1/2 | 无 | — |
| `demo.grenadier`／掷弹兵 | 1 | 2/3 | `demo.grenade`（部署时对敌方单位 1 伤） | 内联·对象态 |
| `demo.quartermaster`／军需官 | 0 | 1/4 | `demo.rally`（部署时抽 1 张牌） | 库引用 |
| `demo.vanguard`／先锋 | 1 | 3/3 | `demo.rally`（同一库效果） | 库引用（跨目录共享） |
| `demo.scout`／侦察兵 | 1 | 1/2 | `demo.enlist`（加入时从卡组抽取自己） | 内联·字符串态 |

### 2.3 关键设计决策

1. **跨目录共享维持预检双零**（grill 硬性）：`demo.rally` 由 `cards/` 与 `cards-support/` **各一张**引用——规避「同一卡目录内重复声明同一效果 id＝读面软隔离（警告）」，README 已注明该边界。
2. **全程 csx 形态、零 C# handler 注册**：三条效果均为 csx（csx 源码形态对齐批 2／批 6 已验收先例与官方 `KeywordPrefabs` 样本）；测试不注册任何 C# handler——纯数据分发可跑。
3. **确定性可断言行为**：掷弹兵＝部署伤害（世界状态：敌方防御 2→1）；集结号＝部署抽牌（卡组 -1＋drawn/hand.add 信号）；应征＝定向取卡（卡组 -1／手牌 +1＋信号载荷）——不依赖随机/时间；固定种子 42。
4. **文本契约**：UTF-8 无 BOM、LF、2 空格缩进、尾随换行（程序化校验通过）；示范样本与工具落盘产物同风格。
5. **命名**：统一 `demo.` 前缀（卡 id／效果 id 一致族）；文件名遵循分发契约 `<id>.card.json` / `<root.id>.prefab.json`；不与官方/既有 id 冲突。
