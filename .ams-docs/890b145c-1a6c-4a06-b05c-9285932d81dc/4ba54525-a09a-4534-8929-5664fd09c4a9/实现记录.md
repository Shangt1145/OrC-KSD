## 一、模式设计点清单（先行落稿——动员打样后、推广前）

### 1. 效果制品形态（构造/装配方式）

- **制品形态**：C# 类型的效果（`PassiveEffect` 子类）——效果体系正式对象（进入既有效果装载/生命周期链）；
  非数据形态（预制体/快照同族数据形态非硬性——Q&A-4.1a 裁定口径）。
- **装配方式**：词条组件**构造期**经 `EmbedEffect`（内嵌效果通道）注入——由 `KeywordManager` 装载链
  在授予时自动装载（`AddEffect` → 挂主触发器 → `OnMount`）、移除/死亡注销/回滚时自动卸载；
  不另起私有挂载体、不短路装配。
- **制品集**（新增文件 `src/Orc.Game/Cards/KeywordEffects.cs`）：
  - `KeywordSignalEffect`（基类——「解析对局上下文 → 装载钩子 → 订阅信号」/「卸载退订」统一承载）；
  - `MobilizeAccrualEffect`（动员·回合累积）、`MobilizeLossEffect`（动员·受伤失去）；
  - `SuppressionLifecycleEffect`（被压制·生命周期）、`IntelligenceTriggerEffect`（情报·被使用时触发）。

### 2. 生灭五路径表达

| 路径 | 承载 | 说明 |
|---|---|---|
| 装载 | 词条授予链（`GrantCore`）→ 组件 `EmbeddedEffects` 逐一 `AddEffect` | 效果随词条授予自动装载 |
| 卸载 | 词条移除链（`RevokeCore`）→ 内嵌效果逆序 `RemoveEffect` | 效果随词条移除自动卸载（含退订） |
| 死亡注销 | `RevokeOnDeath` → OnRevoke 序列＋运行逻辑注销＋内嵌效果卸载 | 行为撤销；登记/参值保留 |
| 回滚 | `RollbackGrant` → `RemoveEffectSilently` | 通道级复用（批 0 已验「装载失败→整体回滚零残留」）＝**申报引用**，不逐效果重做失败注入（无定制装载步骤） |
| 复装 | 移除后再次授予（组件重建→新效果实例）→ 标准装载链 | 复装后二轮卸载仍自动撤销（专项测试覆盖） |

### 3. 信号订阅挂点（订阅建立/撤销）

- **建立**＝效果 `OnMount`（装载链「挂主触发器 → OnMount」的 OnMount 步）；
- **撤销**＝效果 `OnUnmount`（卸载链「OnUnmount → 撤销登记 → 总线卸载」的 OnUnmount 步）；
- **上下文解析路径**＝宿主卡 → 词条管理面（`KeywordRules.TryGetKeywordManager`）→ 词条装载上下文提供器
  （`KeywordManager.LoadContextProvider`——与词条组件运行逻辑同一上下文来源）→ 对局引擎订阅口
  （`LogicEngine.Subscribe`）。
  独立构造（脱离对局）＝上下文不可达＝不订阅（功能不可用、加载不失败——沿既有语境判定口径）。
- 合规判定：沿 Q&A-5.1a 候选一（「订阅的建立与撤销随效果的装载/卸载（生命周期）自动发生」）——
  效果内部按生命周期挂订阅、不违规；不依赖「声明机制」。

### 4. 门户处置（退役/收编）

- **退役**：`UnitCard.ApplyDefenseDamageAsync` 中 `if (amount > 0) await MobilizeRules.OnUnitDamagedAsync(this);`
  直调删除（门户不再感知动员）；`MobilizeRules.OnUnitDamagedAsync` 成员删除（内部专用面；调用点清查＝
  门户唯一调用点、无其它引用；`MobilizeRules` 类保留为 public 面无成员壳）。
- **收编**：受伤失去改由 `MobilizeLossEffect` 监听 **`card.damaged`** 信号（E1-33「监听类补信号」——
  伤害结算后、实际扣减＞0 恰一次、先落定后发射）→ `RevokeAsync` 自我撤销——路径泛化并入通用信号机制。

### 5. 壳化边界与壳内残留清单

- 被压制／动员／情报三枚组件收薄为壳（标识／参值／授予-移除／读取面）：不再覆写 Mount/Unmount 生命周期回调、
  不再订阅事件、不做时序决策。
- **壳内残留清单**：无行为性残留；仅保留非行为面——①构造期 `EmbedEffect` 装配（模式的装配点）；
  ②参值面（情报的 [0,3] 钳制覆写——参值域语义，沿用不动）。
- 不动面确认：全系统读点（判定器/合法性）、清空处置/施加口（Pin/Silence 及下游服务）、被压制读点
  （`CommandBlockReason.Suppressed`）零改动。

## 三、差异申报（待裁/注明项）

1. **致死伤害边界（#⑬核对项）**：现状「失去先行（存在性清除）→ Has＝false」；迁移后「死亡注销先行
   （行为撤销、登记保留）→ card.damaged 发射时效果已卸载 → Has＝true（登记保留）」。差异场景＝致死伤害；
   迁移选择＝`card.damaged` 信号承载（现状无早于死亡的伤害信号可承载『失去』）；建议＝接受（与死亡注销
   「登记保留」既定语义一致）或后续批次引入伤害前信号后对齐。**待裁**（专项测试
   `Mobilize_Death_Registration_Kept_And_Behavior_Revoked` 固化迁移形态、注释提示申报）。
2. **非致死时序微差**：失去时点由「跑链前」变为「card.damaged 发射时（跑链后）」——既有测试断言与
   信号语义下不可观测（最终状态等价）；**申报**。
3. **动员无参值**：#⑭注明项——「参值改写随动」不适用（动员无参值位）。
4. **老兵测试适配（2a 通道·逐条）**：
   - ① `Clear_Special_Purges_Damage_Modifiers_Keywords_With_Signals_And_Reentry_Loop`：
     * 改动内容＝信号清单断言「共 2 条」→「共 4 条：`effect.removed` 恰 2 条（新增计数与顺序锁定）＋
       `card.stat.changed` 恰 1 条＋`unit.upgraded` 恰 1 条」；新增「effect.removed 先于 stat.changed」顺序断言。
     * 原因＝装配方式变化（动员词条携带内嵌效果）——词条全清时内嵌效果随卸载按通道既有语义发
       `effect.removed`（动员两类效果各 1 条、共 2 条）；原断言基于「词条无内嵌效果」旧形态。
     * 等效性论证＝原语义「升级过程信号清单精确受控＋先数值后机制＋重入零信号」全部保持；新形态下
       断言更精确（对 effect.removed 的计数与顺序显式锁定）；stat.changed/upgraded 计数与顺序断言不变；
       重入/重复发动零信号断言不变。
   - ② `Failure_Execution_Rolls_Back_To_PreState_And_Allows_Retry`：
     * 改动内容＝「`Assert.Empty(recorder.Updates)`（零信号）」→「`effect.removed` 恰 2 条（执行段
       『词条集全清』步骤的正当卸载信号）＋无其它类型信号」。
     * 原因＝同上（全清步骤的动员内嵌效果卸载信号）；回滚段自身仍零发射（该性质保持并显式化）。
     * 等效性论证＝原语义「升级失败回滚零『污染/结果类』信号＋恢复完整原状」保持——两条 effect.removed
       发生于执行段（非回滚段）、为效果体系标准卸载声明；「无 stat.changed/upgraded 等结果类信号」由
       「无其它类型」断言显式化（较原 Empty 更可读、覆盖不减）。
   - 处置结论：两处均属 2a①「内部形态适配（装配方式变化的必要适配）」；**未改任何老兵产品代码**
     （升级执行段/信号面/读取面零触碰）；由委托方验收裁定。
5. **升级/清空场景信号面（连带申报）**：词条全清（升级执行段、抑制清空处置）时携带内嵌效果的词条
   卸载按通道既有语义发 `effect.removed`。升级场景对外信号清单由「2 条」变为「4 条（含 effect.removed×2）」、
   失败回滚场景由「零信号」变为「effect.removed×2」。属「装配方式变化（词条携带内嵌效果）的连带可观察面」；
   选择＝适配测试＋申报（机制与老兵产品代码零改动）；建议＝接受（与内嵌效果通道「与外部效果同待遇」
   既定口径一致）；如需「升级零 effect.removed」语义＝需机制层另行裁定（超本批授权）。
6. **压制重施加（#⑬核对项）**：现状语义＝幂等（对已压制者再施加＝无操作、参值保持、不重置/不叠加）；
   迁移保持——**核对注明**（专项测试断言）。
