# 词条效果化·序列⑤补：测试隔离修复（情报静态竞态）——实现与验证记录

## 一、勘验结论（定位）

### 1.1 共享静态面定义与全部使用者

**产品侧定义**（`src/Orc.Game/Cards/KeywordServices.cs`）：
- `IntelligenceRules.PendingRevealHandler`：进程级 `public static` 属性（默认实现＝写引擎日志 `WritePendingRevealLog`——「明牌 X 张」执行面待 G18 接线）。
- `IntelligenceRules.InvokePendingRevealAsync`（internal）：触发点调用口，按"当前静态值"转发。
- 触发链上游（`src/Orc.Game/Cards/KeywordEffects.cs`）：`IntelligenceTriggerEffect`（「情报·被使用时触发」）订阅 `card.played`，命中本卡时调用 `InvokePendingRevealAsync`；由 `IntelligenceKeywordComponent`（`KeywordComponents2.cs`）内嵌装配（词条工厂 `KeywordRegistry.cs` 映射）——即**任何带「情报」词条的卡被使用都会命中该静态面**。

| `KeywordBatch2Tests` | 写者（替换+恢复） | `Intelligence_Trigger_Structure_Invokes_Pending_Reveal_With_Value`（替换为捕获桩、PlayUnitAsync 触发、`Assert.Single`） |

排除项（经穷尽核对不触达静态面）：`KeywordEffectChannelTests`（仅授予情报 2 读回、不播放）、`BattleKeywordTests`/`CardDataBodyTests`（数据/注册面）、解析类测试（`EffectParserTests`/`KeywordLineDeclarationTests` 等仅解析不执行）。核对手段：对 `PendingRevealHandler`、`IntelligenceRules`、`IntelligenceTriggerEffect`、`KeywordIds.Intelligence`、`情报`、`EmitCardPlayed`、`PlayUnitAsync`、`intel` 全测试目录反向搜索并逐一确认。

### 1.2 并行拓扑触发条件

- xUnit v2 默认按 collection 并行；上述 3 个类此前均**无** `[Collection]` 标注（各自独立 collection）→ 可与任意测试类并行调度。
- 写者窗口＝「替换静态 → try/finally 恢复」的整个测试体（跨 await）；触发者在此窗口内触发时，调用的是**写者的桩**（而非默认实现）→ 捕获列表被污染（写者断言 `Assert.Single`/计数/`Assert.Empty` 失败）；写者之间也可互相劫持。
- 该机制与序列⑤首轮"2 例情报测试偶发失败、复跑全绿"的现象一致（时序相关、非确定性）。

### 1.3 与 KeywordEffectBatch4 先例的关系

`KeywordEffectBatch4Tests` 已有先例：`[CollectionDefinition("KeywordEffectBatch4Serial", DisableParallelization = true)]`——"进程级注册面在测试窗口内被临时改变 ⇒ 声明为不与其它 collection 并行执行"。本竞态性质同构（进程级静态面在测试窗口内被替换），沿同一先例修复。
