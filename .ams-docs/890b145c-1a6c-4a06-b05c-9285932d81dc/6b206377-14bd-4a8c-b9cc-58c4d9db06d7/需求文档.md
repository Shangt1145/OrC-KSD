# 词条效果化·批 0（前置机制）— 需求阐明记录

> 委托：词条效果化·批 0（CodeImplementation；grill 层级＝类/功能流程级）。
> 职责范围＝①参值→模板/效果参数化通道；②运行时口（Revoke／SetKeywordValue／GrantWithContent）。
> 关联：《词条效果化规划（v3）》。

## 一、功能职责与流程约束（本委托需求基线）

- **参值通道（本批闭合面）＝效果表达侧的"静态携带"**：效果形态能够携带词条参值——DSL 值字段（可空整数，与既有词条参值面一致）→ 模板值占位符渲染 → csx 产出（授予调用携带参值）→ 运行时承接（带参值授予）。
- **参值可选性**：授予参值"未提供（不传参值）"与"显式提供（含 0）"为两种不同形态，渲染与承接均不得混淆（0 为合法参值、不等于缺省）。
- **值域校验归词条组件**：通道层不做值域校验（非负/上限等语义域）；词条域约束由词条组件既有机制承载（如重甲/情报组件侧钳制 [0,3]）；经新通道的参值行为＝与既有直接路径一致（不新增拒绝层级、不改动钳制语义）。
- **运行时口（暴露面）**：把既有词条管理能力（授予〔含参值〕/撤销/参值改写/内容型授予）经效果运行时（csx 受控入口）暴露；行为语义完全沿用既有（幂等、终态拒绝、参值改写前提＝词条存在、撤销不存在＝无操作等），不新造语义；可达域＝具备词条面者（CardBase＋Hq 同族统一；含既有无参值授予口的同步统一——Q&A-6）。
- **语言面增量（Q&A-2 冻结）**：官方 op 增量仅『授予 op 参值形态』（扩展或新增，实现者裁量申报）；『撤销/参值改写/内容型授予』只做运行时口、不做官方 op——其中撤销/参值改写的实编译覆盖经 csx 逃生舱。
- **内容型授予的验收口径（Q&A-3 冻结）**：沿用既有内容类型（映射既有签名）；csx 脚本可达性不属本批硬要求（缺口申报）；验收＝运行时口存在＋C# 行为级（授予→内容可消费／移除→卸载／重复授予幂等）。
- **验收③代表场景（Q&A-4 冻结）**：重甲N 必需（经 DSL/编译管道＋行为链实证）；情报N 可选（仅授予/读回/钳制，执行面待办）；撤销/改写核心断言经 csx 逃生舱路径完成。
- **冻结与编辑范围（Q&A-5 冻结）**：『冻结』＝行为与契约冻结（老兵/隐蔽机制的行为、公共签名、语义与既有断言不得变更；纯新增〔方法/文件/测试〕不受限）；申报分界＝『是否改变既有行为/契约』（不改＝先做后报〔汇报记载〕；改＝先问再做）。
- **非功能**：构建 0 警告（＝`OrcEngine.sln` 全部项目警告数为 0）；全量测试绿（＝四套件 Orc.Tests／Orc.Game.Tests／Orc.Lua.Tests／Orc.Script.Tests 全跑且全绿）；P1（禁止无条件数据更新）/P2（同步语义）；不删除文件。

## 二、已解决的歧义（Q&A 逐轮记录）

### Q&A-1（2026-10-06）：参值通道的语义边界（主问题）与三个子问题

**子的问题原文（摘要）**：

1. 主问题：「参值→模板/效果参数化通道」的落点范围。子方理解倾向：本批＝"效果表达侧能写死/携带参值"（DSL 值字段→渲染→csx 里携带参值的授予调用）；"词条壳自身参值在装载内嵌效果时自动填进效果实例"（运行时填槽）属批 1/2。请确认或修正。
2. 子问 1："参值→DSL 填写"转换通道边界：是否包含解析器侧（卡面文本如"重甲3"→DSL 值字段）？还是仅 DSL 模型/序列化/编译/渲染层？
3. 子问 2：运行时「词条参值→效果填槽」是否明确排除在本批之外（留批 1/2，本批只保证通道机制就位）？若本批提供"填槽"API，请给出可判定口径。
4. 子问 3：参值取值约束与校验层级：value 是否要求非负？超出词条域上限（重甲封顶 3）时，由 DSL/校验层拒绝，还是放行、由组件钳制兜底？验收断言以何为准（如授予重甲5→拒绝 or 读回3）？

**解答**：

- **主问题＝子方理解正确，确认**：本批＝"效果表达侧静态携带参值"（DSL 值字段 → 模板渲染 → csx 产出携带参值的授予调用 → 运行时承接）。"运行时词条壳参值→效果实例填槽"（动态、由词条壳驱动）**不在本批**——留批 1/2（词条壳迁移），与"词条声明→效果引用→参值传递"链条一并设计。
- **子问 1＝仅 DSL 模型/序列化/编译/渲染层；解析器侧不含**（"重甲3"文本→DSL 属解析层词条行联动，规划归批 4）。本批不单独建"参值→填写"转换器：值即 DSL 值字段的赋值能力本身；"自动填"无消费方（词条壳未迁移）故不建，避免过早落定接口形状。
- **子问 2＝确认排除**。本批"通道就位"的可判定口径＝三层：①DSL 层：值字段可赋值、序列化往返一致；②编译/渲染层：值占位符渲染为整数字面量并进入 csx（未提供＝保持既有形态）；③运行时层：带参值授予经既有机制生效（参值可读、钳制语义不变）。
- **子问 3＝"放行、由组件钳制兜底"**。通道层不设值域校验（不要求非负、不设上限）；词条域（如重甲/情报 [0,3]）由词条组件既有机制钳制（构造与参值改写均钳制——现状既有）。验收断言＝**经新通道授予"重甲5"→读回 3**（与既有直接路径行为一致）；"拒绝"不是本通道层语义。

**备选方案与拒绝原因**：

- 备选 A（本批即做"运行时填槽"）→ 拒绝：无消费方（词条壳未迁移）、与批 1/2 设计耦合、过早落定接口形状（返工风险）、本批无法独立验收。
- 备选 B（解析器侧一并接入"重甲3"文本）→ 拒绝：越出批 0 边界（解析层联动规划属批 4）；与"词条行如何进入效果"的核心设计耦合。
- 备选 C（通道层做值域校验/拒绝"重甲5"）→ 拒绝：①语义域（0..3 等）是词条侧知识、通道层不认识具体词条；②既有实现已定"组件侧钳制"，通道层再校验＝双重校验、口径分裂；③与"放行、组件兜底"的既有行为一致性冲突。
- 备选 D（本批提供专用"参值填槽 API"）→ 拒绝：见主问题口径——本批仅保证通道（值可携带、可渲染、可承接）；"填槽"动作由后续批次调用方（词条壳/解析器）按需组合。

**架构审视补充**：

- **边界完整性**：①"未提供 vs 显式 0"形态区分（见基线，防混淆）；②运行时口承接既有语义（幂等/终态拒绝/参值改写前提＝词条存在）——暴露层不得改写；③负数渲染＝合法字面量（通道不拒绝），最终语义由组件钳制。
- **失败模式**：授予携带参值时标识未注册→沿用既有 fail-fast；参值改写目标不存在→既有明确异常；暴露层不吞错、不降级、不静默。
- **非功能**：构建 0 警告＋全量测试绿（硬约束）；通道无性能敏感面。
- **多视角**：终端用户无可见行为变化；业务＝解锁"有参词条→模板效果"（批 1/2 前置）；技术＝通道单一（避免双校验/双路径）；运营＝低成本。
- **元审视**：子方三子问题均为真实边界歧义、识别准确；主问题理解与规划意图一致。

- 备选 C（允许"未提供"路径渲染也变化、随批调整既有断言）→ 拒绝：违反"缺省不携带＝保持既有行为"（委托 1.d）与解析层稳定渲染输出的既有口径。

**架构审视补充**：

- **边界完整性**：三操作（撤销/参值改写/内容型授予）的"运行时口 × 语言面"分层已明确（口做、op 不做）；csx 沙箱约束处理归口"RevealRules 包装先例"（申报）。

- **元审视**：子方对委托文本不一致（测试节 vs 正文 vs FilesToModify）的识别准确；本解答消解该不一致（并修正 FilesToModify 描述口径）。

### Q&A-3（2026-10-06）：内容型授予（GrantWithContent）的验收深度与暴露形态

**子的问题原文（摘要）**：

主问题：验收②要求"EffectRuntime 三新口（Revoke／SetKeywordValue／GrantWithContent）行为级可用"，但 csx 实编译清单只列"带参值授予/撤销/参值改写"三项、未含内容型授予。现状：内容型授予既有能力＝KeywordManager.GrantWithContentAsync(keyword, Effect? content)——内容参数是游戏层效果对象（如亡计场景的 DeathrattleEffect 抽象基类），csx 脚本侧构造此类对象没有现成通道；委托预留"如遇 csx 沙箱技术约束，按 RevealRules 包装先例处理并申报"。子方理解倾向：内容型授予＝暴露面直接映射既有能力（接受既有内容对象），验收＝"口存在＋C# 行为级可用（真实对局断言）"，csx 脚本可达性不属本批硬要求。

子问 1：csx 实编译是否必须覆盖内容型授予？还是确认为：csx 实编译覆盖范围＝带参值授予/撤销/参值改写三项；内容型授予仅要求"运行时口存在＋C# 行为级（真实对局路径）可用"？

子问 2：内容对象形态：暴露面是否直接沿用既有游戏层内容类型（映射 KeywordManager 既有签名）？还是本批要求设计"csx 可达的内容形态"（如经包装面以标识/载荷提供）？若属后者，遇技术硬阻时按"包装面申报 vs 口暴露＋申报"哪种处理？

子问 3："行为级可用"的可判定口径：内容型授予是否要求断言"内容随授权装载"的完整链路（授予后词条存在＋内容进入承载并可被消费；移除后内容卸载；重复授予幂等）？以什么观察面验证？请给出最低验收断言集。

**解答**：

1. **主问题/子问 1＝确认子方理解**：csx 实编译覆盖范围＝**带参值授予/撤销/参值改写三项**（撤销/改写经逃生舱承载）；内容型授予＝**"运行时口存在＋C# 行为级（真实对局路径）可用"**——csx 脚本可达性（含内容对象构造）**不属本批硬要求**。理由：①委托测试节原意即三项实编译；②"内嵌效果运行时落地"（嵌套文本→内容对象）属后续批次设计（现为留痕口径），本批不提前落定；③csx 侧构造内容对象无现成通道＝**已知缺口**，申报（不阻塞本批验收）。
2. **子问 2＝直接沿用既有内容类型**（映射既有签名：`keyword ＋ 内容对象`；行为语义完全沿用——幂等/回滚/终态拒绝/内容随词条生灭）；**不要求设计"csx 可达的内容形态"**。遇技术硬阻（暴露本身引发的 csx 侧障碍）＝**"口暴露＋申报"**——不做包装面设计（无消费方；内容数据化属"内嵌效果运行时落地"批次）。
3. **子问 3＝要求完整链路（最低断言集）**：
   - A1（硬性）：授予带内容 → 词条存在＋**内容可被消费**（真实链路——如复用既有亡计链构造：授予带内容 → 死亡结算执行内容）；
   - A2（硬性）：移除 → 词条不存在＋内容卸载（不可再消费）；
   - A3（硬性）：重复授予 → 幂等（无操作、返回 false、内容不重复装载）；
   - A4（建议纳入）：空内容（null）＝合法静默；授予失败（如标识未注册）＝fail-fast、零残留回滚。
   - 观察面：**真实对局路径观察**（内容执行产生的对局结果）优先；如需直查装载状态，用既有可查面（词条存在性/行为执行）——**不新造测试专用观察 API**。

**备选方案与拒绝原因**：
