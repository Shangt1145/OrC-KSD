# S2 隐蔽机制 —— 需求阐明记录

> 委托：第 3 批 S2（CodeImplementation；grill 层级＝类/功能流程级）。
> 职责范围＝隐蔽机制：状态承载（covert→"隐蔽"标记）／豁免（指令效果索敌判定器接线＋无头选靶/光环收集剔除＋钳击配对剔除＋单卡例外）／揭示（先移除标记→揭示逻辑；攻击执行段入口、伤害结算前）／信号（`unit.revealed`）／读取面；不含 EffectParsing（S3）与攻击候选/单点伤害/修饰链的改动。
> 关联：《老兵与隐蔽（模板效果补全）》实现文档 S2 节、需求文档 R2/S6-S10；A2 勘验结论。

## 一、功能职责与流程约束（本委托需求基线）

- **状态承载**：隐蔽＝单位数据中声明的状态（官方标识 `covert` 映射为"隐蔽"标记；词条标记方案，与"被压制/烟幕"同族；不打对战词条标；无实体切换、无占位）。
- **豁免（"无法被卡牌效果影响"）**：
  - 指令效果索敌统一经判定器 `targeting.candidate.eligibility`（J3 示范②；现状生产零调用→新接线）；默认规则＝隐蔽单位不可选。
  - 效果无头选靶（`EffectRuntime.SelectAsync`→`effect.target.resolve`，8 op 共用）剔除隐蔽；光环受益收集（`AuraSystem.CollectAuras` 单点收口）剔除隐蔽。
  - 攻击候选/单点伤害/修饰链不改（隐蔽可被攻击——会被揭示）。
  - 钳击配对候选剔除（自裁）。
  - 单卡例外（"可以指向隐蔽单位"2 处）：请求级覆盖＋判定器 moding 改写口。
- **揭示**：RevealAsync 型服务（先移除隐蔽标记→调揭示逻辑）；触发点＝攻击执行段入口（复验后、**伤害结算前**——用户裁定 E2-Q3a）；主动揭示动作可调（"揭示 1 个隐蔽单位"）；`unit.revealed` 信号（先落定后发射、恰一次；GameUpdates/GameHooks/GameHooksJson 同步）。
- **读取面**："隐蔽单位"筛选经判定器/lambda 承载；"处于隐蔽回合数"不建机制（效果层自管 handler——不属本单）。
- **卡侧具名"揭示触发器"**（供 S3 模板效果按名对接；参考 S1"老兵触发器"先例）。
- **非功能**：P1/P2；构建 0 警告（勿动 EffectParsing 在途警告）；全量测试绿（含兼容断言同步：词条 16→17、信号 30→31 等）；不删除文件；编辑范围限本单。

### Q&A-1（2026-10-06）：豁免范围与方向性（1a-1d）＋接线对象与调用点范围（2a-2c）

**子的问题原文（摘要）**：

【主问题 1·豁免范围与方向性】
- 1a 方向性＝不分敌我（含友方效果、友方光环）还是仅敌方？目标合法性判定器既有签名（candidate→bool，无来源视角参数）若要区分敌我需要额外上下文。
- 1b 剔除层次＝豁免是否统一只在"选靶/影响范围收集"层（选靶后已确定的作用不再二次检查）？"攻击候选/单点伤害/修饰链不改"的准确含义（子理解为"攻击相关路径不做隐蔽检查"，非"单点伤害类效果可绕开豁免"）。
- 1c 光环方向＝CollectAuras 剔除的是"隐蔽单位作为受益者"侧；作为来源（提供者）不受限？
- 1d 群体/随机＝SelectAsync 候选集合为全模式共用基底——all 结果集与 random 取样池都应先剔除（random 在剔除后池取样）？

【主问题 2·接线对象与调用点范围】
- 2a "指令"含义＝卡牌效果的目标选择（含指令卡与单位卡等一切卡牌效果索敌），还是泛指指挥动作（与 d 冲突）？
- 2b 接线调用点范围＝"卡牌效果的目标选择流程"、不覆盖攻击/移动等指挥路径候选；接入形态（AsFilter 包装/新收口）设计＋全部调用点清单由实施阶段设计并申报？
- 2c C1 断言口径＝①候选端剔除（前端不可点）＋②强行提交被拒（不构成终局）？对齐 JudicatorTargetSelectionTests 既有两向断言习惯。

**解答**：

【1a】**不分敌我——统一豁免**。任何卡牌效果（含友方效果、友方光环）都不能选择/作用于**场上**的隐蔽单位。
- 依据：①用户裁定原文未限敌我（"无法被卡牌效果影响"；示例"相邻陆军这种无法影响隐蔽单位"）；②卡池无"对场上隐蔽单位施加增益"的既有需求文本（受作用类用法均可由"揭示后"/费用层/查询层承接）；③判定器签名无需来源视角参数（既避免上下文扩展，又与 Targeter"归属中立"精神一致）。
- 边界澄清：**查询/计数**（"每有1个友方隐蔽单位…"、"友方隐蔽单位被揭示时…"监听）不受限；**手牌/卡组中的隐蔽单位牌**与**规则层（费用等）修正**不属于"对场上单位实体的影响"，不受豁免限制；**作为效果来源**不受限（其自身效果照常对外作用）。
- 备选"仅敌方豁免"→ 拒绝：与用户表述及示例不符；需来源视角参数、复杂化判定器签名；卡池无支撑需求。

【1b】**确认——豁免统一只在"选靶/影响范围收集"层发生**（三剔除点：①判定器候选过滤〔指令效果索敌〕②`SelectAsync` 无头选靶候选基底 ③`CollectAuras` 受益收集）；经选靶/收集后已确定的作用（修饰链应用、伤害应用、移动执行等）不再二次检查。
- "攻击候选/单点伤害/修饰链不改"的准确含义＝**攻击相关路径不做隐蔽检查**（隐蔽可被攻击、会被揭示）；"单点伤害类效果"（卡牌效果）仍受选靶层豁免（不允许作用于隐蔽）——不构成绕开通道。

【1c】**确认——光环剔除仅"受益者"侧**：隐蔽单位不作为光环受益者（不被收集）；作为**光环来源（提供者）**不受限，其光环照常作用于其他单位。

【1d】**确认——全模式候选基底统一剔除**：`SelectAsync`→`effect.target.resolve` 的候选集合为所有模式共用基底；all 的结果集合与 random 的取样池均先剔除隐蔽（random 在剔除后的池上取样）。既有 self 分支/覆盖顺序保持。

【2a】**确认——"指令"指"卡牌效果的目标选择"**：接线覆盖含指令卡与一切卡牌效果（单位卡效果等）的**效果性索敌**；不泛指指挥动作（攻击/移动路径的候选不改——与 d 一致）。

【2b】**确认**：接线指向"卡牌效果的目标选择流程"，不覆盖攻击/移动等指挥路径候选；"调用点按 AsFilter 包装或新收口"的形态设计＋**全部调用点清单**由实施阶段设计并申报（设计自主权在实现者）；如某调用点无法接入须申报（不静默遗漏）。

【2c】**确认**：C1 断言＝①隐蔽单位不出现在允许集（候选端剔除、前端不可点）＋②即使强行提交也因不在允许集被拒（不构成终局）。对齐 `JudicatorTargetSelectionTests` 既有两向断言习惯。

**架构审视补充**：
- 边界完整性：豁免三剔除点＋例外路径（请求级/改写口）＋攻击路径保持——覆盖"选择/施加"全链；查询/规则层/来源侧明确不受限。
- 失败模式：判定器未装配/异常沿用既有失败模式；揭示流程先移除标记（幂等）。
- 非功能：不新增异步；P1（有变更才传播）；构建 0 警告与兼容断言同步（词条 17、信号 31）。
- 元审视：子的问题判断准确（1a/2a 的歧义真实且关键；签名约束观察正确）。
