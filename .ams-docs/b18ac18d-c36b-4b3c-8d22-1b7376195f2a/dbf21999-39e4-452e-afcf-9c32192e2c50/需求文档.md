## 一、功能职责与流程约束（本委托需求基线）

- **词条组件化承载**（A1 既有体系）：9 项词条＝组件＋行为；参值词条（重甲N/情报N）经参值通道（声明＋读改写口）。
- **抑制**：清空处置——①清理除自身外所有词条；②清空所有修饰器（清空后若防御力上限＞当前防御力，则把防御力设为「原防御力」〔复位口径：复位至清空修饰器后的上限、损伤清零——逐项落定见 Q&A-4〕）；③清除所有额外效果；需在词条管理组件＋单位组件新增「清空词条/清空修饰器」方法。

- **对战词条**：分类标记（供随机筛选/计数类消费）——清单与口径见 Q&A-2。
- 行为细节按 KARDS 官方文本（outputs/kards-card-text）对齐；遇歧义申报（不自行发明语义）。
- 非功能：P1（禁止无条件数据更新）/P2（同步语义）；不破坏既有测试；构建 0 警告。

### Q&A-3（2026-10-04）：钳击（Pincer）的语义边界与最小闭环

1.1 本批钳击落地范围是否＝「部署时选择另一个友方单位（选同伴）→ 双方同时获得『钳击效果』→ 一方离开战场后另一方失去」完整闭环？「钳击效果」（各卡不同的 X：修饰类/词条类/状态类/特殊类/触发类）在本批如何承载：至少落地一种示例并留通用承载面，还是仅同伴关系、X 留卡池批次？
1.2 「离开战场」判定口径：死亡（毁灭）算；撤退（前线→支援线）是否算？返回手牌/被移除是否算？「同伴失去钳击效果」＝行为面撤销即可，还是词条（含登记）也清除？
1.3 「钳击单位数」计数与「获得钳击加成时」事件面是否本批落地？

**解答**：

**1.1 落地范围＝完整闭环＋至少一种示例＋通用承载面。**

- 备选「仅同伴关系机制、X 整体留卡池」→ 拒绝：验收要求行为场景（无示例则无行为面可验）。备选「全部 X 形态本批实现」→ 拒绝：X 属卡池内容、数量不定，非机制层。

**1.2 「离开战场」判定与撤销口径：**
- **判定＝该单位不再处于「已放置/在场」状态**——覆盖：死亡/毁灭（算）、返回手牌（算）、被移除/销毁（算）；**撤退（前线→支援线）不算**（仍在场上，属场内移动）。本批验证**至少覆盖死亡路径**；其余离场路径在其实现接入时按同一判据（统一「不再在场」真值）。
- **撤销＝行为面撤销（按来源整组撤销）即可**：「钳击效果」（效果/修饰/授予物）随关系失效撤销；**词条登记不动**（「钳击」为固有词条；被清的是加成/效果而非词条本身）。离场方自身状态不另行处理（其离场清理走既有离场/死亡链）。

**1.3 计数与事件面：**
- 「钳击单位数」计数＝**由既有查询面组合实现**（友方单位遍历＋词条读口；不新增专门计数机制），示例场景中覆盖一次（与「对战词条数」同类口径）。

- 备选「事件面本批落地」→ 拒绝：单项成本虽小，但会造成同类观察面碎片化（后续统一时返工）。

**架构审视补充（本点）**：
- 边界：钳击形成时机＝**部署链**（按官方文本「部署时」）；「加入战场」（非部署路径）是否形成钳击按卡文本后续处理。

### Q&A-4（2026-10-04）：抑制（Suppress）的精确口径

**子的问题原文（摘要）**：
2.1 「清理除自身外所有词条」中的「自身」指什么？是否保留「抑制/被抑制」标记（供条件查询与「无法被抑制」判定）？「无法被抑制」判定落点？
2.2 「防御力复位」精确语义与示例（基础 5、+2 修饰（上限 7）、已受伤 4（当前 3））：（a）上限值；（b）当前值；（c）「原防御力」指代；（d）是否修复损伤？
2.3 「清除所有额外效果」的边界（卡牌效果（含光环）/词条内嵌效果/运行态标记）；「重置攻击力、防御值与行动花费」中攻/行动费＝自然回落？

**解答**：

**2.1 「自身」与标记保留：**
- 「自身」＝**当前被施加的「抑制」标记本身（即「被抑制」状态）**；清空处置**跳过该标记**（否则抑制无法存续/无法被查询）。
- **保留标记**（非一次性无痕动作）：「被抑制」保留于目标，供：①条件查询（「消灭 1 个被抑制或被压制的单位」part-05:L85 等）；②防护判定承载。标记承载＝词条体系的施加物（「被抑制」经运行时授予/移除路径管理——其清除走词条移除路径）。
- 「无法被抑制」＝**施加前的资格判定**：具「无法被抑制」（自带或授予，part-01:L19/part-09:L20/part-11:L68/part-19:L36）者，**不得被施加抑制**；施加流程须先判后施加。判定落点形态（专门入口 vs 施加方自查）由实现者裁量并记录。
- 补充（边界披露）：施加后的「被抑制」解除/期限语义本地资料无明文——本批按「标记保留＋经移除路径可清除」实现；如后续资料澄清再补。

**2.2 防御力复位——逐项落定（示例：基础 5、+2 修饰（上限 7）、受伤 4（当前 3））：**
- 清理修饰器：撤销 +2 → 上限 7→**5**、当前 3→**1**（自然回落）。
- 条件判定：「清空后上限＞当前」＝「5＞1」→ 成立。
- （a）防御力上限＝**5**（基础值，修饰清除后）；
- （b）当前防御力＝**5**（复位至上限）；
- （c）「原防御力」＝**清空修饰器后的防御力上限（即基础/基准防御值）**；
- （d）**＝是，含修复语义**（损伤差额清零）；若无损伤（上限＝当前）则条件不触发、无操作。
- 口径来源：委托方既有「复位口径」的落定（以本记录为准）。
- 架构审视补充：抑制由此兼有「复位至基准」语义（＝把防御打回基准满值）——此为委托口径的已知选择（记录之）。

**2.3 「额外效果」边界与「重置」口径：**
- 覆盖对象：①**卡牌效果（含光环声明、被动/主动效果）**＝清除（撤销）；②**词条内嵌效果**＝随词条清除覆盖（词条卸载链既有）；③**运行态成果**（由上述效果/词条产生的计数器、成果等）＝由其**卸载链负责清理**；无主的独立标记**不属本项**（不做全局扫描）。
- 「重置攻击力、防御值与行动花费」：**攻击力与行动花费＝清修饰器后的自然回落**（无损伤维度、无需专门复位动作）；**防御力＝自然回落＋复位条款**（2.2——防御特殊之因：具有「损伤」维度）。
- 备选「攻/费也做专门复位动作」→ 拒绝：无损伤语义、多余且与修饰体系重复。

**架构审视补充（本点）**：
- 边界：「被抑制的复制」类文本（part-18:L41）＝复制（静态，G6 口径）＋施加抑制的组合，非复制携带状态——与本批口径一致。
- 失败模式：抑制对被施加者无资格（无法被抑制）时不施加、无副作用（拒绝而非部分执行）。

- 行为场景**覆盖拒绝路径（正反两态）**：有防护→施加被拒绝且**无副作用**（拒绝而非部分执行——与 Q&A-4 口径一致）；无防护→正常施加。

**2.3 共用判定族＝是（同一「施加前资格判定」族）：**
- 「无法被压制/无法被抑制」与压制/抑制的施加流程＝**同一族的施加前资格判定**（判定模式一致：施加前查对位防护标记）；**按对位配对读取**（压制↔无法被压制；抑制↔无法被抑制）；实现可共用判定模式/工具（实现者裁量并记录），需求层＝一族两对位。
- 备选「各自独立判定点」→ 拒绝：重复实现、语义漂移风险；同族统一更利「无法被 X」家族后续扩展。

**架构审视补充（本点）**：
- 边界：「无法被」家族全貌（部署/指令指向/陆军攻击/弃掉/修复等）分属各自机制域——**本批仅落定压制/抑制对位防护**；「无法撤退」（随撤退机制）等亦不在本批。
- 失败模式：拒绝路径须无副作用（不产生部分施加、不消耗；施加方按「拒绝」处理并记录）。

### Q&A-11（2026-10-04）：抑制清空处置的「清词条」边界（与施加物/防护家族交互）

**子的问题原文（摘要）**：
1.1 单位已带「被压制」标记时被施加抑制——清空处置是否清除「被压制」标记？（清除后该单位不再受限、不再被「被压制单位」条件命中；不清除则两者并存。）
1.2 单位带「无法被压制」等防护标记时被施加抑制——防护标记是否被清除？（「无法被抑制」因资格判定拒绝、不构成场景；此处问其它防护。）清除后「防护失效」是否符合预期？
1.3 落定「清词条」的清除范围口径：＝「除『被抑制』自身外的全部词条（含其它施加物与防护标记）」的字面全量，还是「含保护名单」？

**解答**：

**1.1 「被压制」标记＝在清除范围内（清除）。**
- 口径＝字面全量（见 1.3）：「被压制」作为施加物（词条体系承载）属「除『被抑制』自身外的一切」——被清除；后果＝该单位**不再受限**（移动/攻击限制解除）、**不再被「被压制单位」条件命中**；两者不并存（抑制后仅存「被抑制」）。
- 依据：wiki/基线「移除目标所有词条、关键字与加成效果」——「所有」无例外；用户口径「除自己外的所有词条」的「除自己」为**功能性保护**（保「被抑制」自身存续），非施加物家族保护。
- 注记：如后续资料/需求方明确「被压制保留」再调整（当前口径＝全量清除）。

**1.2 防护标记＝在清除范围内（清除、防护失效）。**
- 同口径：「无法被压制」等防护标记属「除『被抑制』自身外的一切」——被清除；**清除后防护失效**＝预期（「被抑制＝剥光」的强重置语义：单位只剩「被抑制」）；后续可被压制/抑制（再施加时资格判定将读不到防护）。
- 「无法被抑制」不构成场景（施加前资格判定拒绝——Q&A-10）✓。

**1.3 范围口径＝「除『被抑制』自身外的全部词条（含其它施加物与防护标记）」的字面全量（无保护名单）。**
- 该口径即「抑制＝剥光至仅剩『被抑制』」；实现与验收断言以字面全量为准（交叉场景：「被压制×抑制」「防护×抑制」均按清除断言）。
- 备选「含保护名单（保留被压制/防护）」→ 拒绝：无资料依据（wiki「所有」＋用户口径无保护项）；且「剥光」语义最简、行为最可预期。
- 备选「按『负面保留、正面清除』类分类处置」→ 拒绝：无依据、引入分类复杂度（且「被压制」为负面——若按该分类反而保留，与字面冲突）。
- 边界注记：如未来出现「不可被移除」类文本（防护的更高阶），另行评估（不属本批）。

**架构审视补充（本点）**：
- 交叉场景验收：正反两态——「被压制×抑制→清除」「防护×抑制→清除」各一例断言（与 Q&A-10 拒绝路径并列，构成抑制施加的完整断言面）。
- 与 Q&A-4 一致性：清空后数值面（修饰/攻防/行动费）仍按 Q&A-4 复位口径；词条面按本 Q&A 全量清除。

### Q&A-12（2026-10-04）：钳击的配对拓扑与选择语义

**子的问题原文（摘要）**：
2.1 配对拓扑——一对一（「钳击同伴」单数）还是可多配对？「一方离场另一方失去」在非一对一情形如何界定？
2.2 「选择」的必需性——「你可以选择」暗示可选：放弃/无合法候选时结果？交互形态是否沿用既有单选？
2.3 候选范围与占用约束——「另一个友方单位」的判定（不含自身/HQ？含其它钳击单位？）；一对一下已被配对单位是否可作候选？

**解答**：

**2.1 配对拓扑＝一对一（单一配对）。**
- 依据：wiki「选择**另一个**友方单位形成钳击。**两个**单位都在战场上时」——单数配对；卡文全览（17 处）无多同伴证据（「钳击同伴」单数、无「多个同伴」表述）。
- 「一方离场另一方失去」＝该（唯一）配对失效（一对一情形无歧义）；**关系终结后不自动恢复**（离场方回场不重建配对；重建仅经新的部署形成——如后续资料另有规定再议）。

**2.2 「选择」＝可选（放弃/无候选＝不形成，部署照常完成）。**
- 「你可以选择」：①放弃选择→不形成钳击（该单位仍具「钳击」词条——「钳击单位数」按词条计数、与是否形成配对无关）；②无合法候选（如场上无其它友方单位）→**不发起选择**（无可选项）、不形成、部署正常完成；③交互形态＝**既有单选交互**（与 Q&A-3 一致）。

**2.3 候选范围与占用约束：**
- 候选＝**己方战场上单位**；不含**自身**（「另一个」）、不含 **HQ**（总部实体、非单位）、不含**已被配对的单位**（一对一占用约束——先到先得；避免抢占式重配对）。
- 未被配对的其他钳击单位**可**为候选（「另一个友方单位」无限定——形成后各自一对一）。
- 备选「抢占式重配对（旧配对随新配对失效）」→ 拒绝：违背一对一简洁语义、引发旧同伴失效的连锁语义；保守裁定「已配对者不可选」。

**架构审视补充（本点）**：
- 边界：形成时机＝部署链（Q&A-3）；「加入/回场」路径不形成（Q&A-3 注记）。
- 非功能：无新增信号；关系失效即时（Q&A-3）。
