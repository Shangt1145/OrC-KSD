## 三、定型申报（集中节）

### 3.1 命名规范（J1 定型；J2/J3 引用基准）

- **判定器名**：英文点分式、「域.用途」两级起（必要时多级）、全小写、ordinal 逐字敏感（机制层 `StringComparer.Ordinal`＋逐字比较）。判定器名系代码级引用标识（机制性标识体系——与信号名同族），非卡面词汇域。
- **承载**：受控常量集合＝`Orc.Game.Judicators.JudicatorNames`（KeywordIds 式；注册源与消费引用的唯一称谓来源）。机制骨架阶段暂无条目，具体名字随各单提报加入；名称一经 J3 引用视为冻结契约（更名需申报迁移说明）。
- **实验性成分**：不在字面标注（字面保持干净）；以常量注释＋本记录申报承载。J1 骨架期无命名条目（无实验性字面）。
- **C# 词根映射**（供 J2/J3 沿用）：判定器＝`Judicator`；强类型适配基类＝`Judicator<TDelegate>`；对局级注册表＝`JudicatorRegistry`；条目等价句柄＝`JudicatorRegistration`；moding 句柄＝`JudicatorModingRegistration`；条目内部件（internal）＝`JudicatorEntry`；拆包辅助＝`Unpack<T>`；强类型适配＝`Adapt`。

### 3.2 加载时点

- **对局加载时加载**＝判定器注册表随对局装配链在 `Match.Initialize` 内创建（『初始化内创建＋注入』范式）；**装配期注册段**＝创建参数 `Action<JudicatorRegistry>? judicatorAssembly`，在「目标选择管理器注入后、再触发服务创建前」**一次性执行**（注册动作返回条目等价句柄、供注册方持有）。
- **就绪语义**＝装配期已注册条目在卡加载阶段即可被解析调用：就绪由装配链位置保证（注册段远早于洗切与加载段）；测试以受控观测点验证「注册动作执行时零更新（无 card.load）」＋「其后加载段确实发生」＋「装配后经可达面可解析调用」（就绪=可达性证据＋结构保证＋观测点）。
- **运行期注册尝试的处置语义**：机制不提供运行期条目注册通道（无注册期状态位——「装配期后不再接受注册」由装配结构自然承载：注册表创建＋注册完成于 Initialize 装配链内、构成对局装配的封闭部件；对局面可达面在准备态被门禁拒绝〔仅"进行"与"结束"态可读〕）。
- **并发口径**：条目注册单线程假设（装配期）；同步调用不承诺并发安全；快照＝同步语境一致性语义。

### 3.3 错误语义（两族分界）

- **引用面（按名）＝fail-fast**：`Resolve`/`Invoke` 未注册 → `KeyNotFoundException`（明确失败、不设 Try/宽容旁路）；名字 null/空白 → `ArgumentNullException`/`ArgumentException`。
- **重复注册拒绝＝fail-fast 族**（配置期错误）→ `InvalidOperationException`。
- **参数契约不符（拆包失败）＝fail-fast 族**：`Unpack<T>` 抛 `ArgumentException`（推荐用法、形态一致）；子类若直接转换，标准异常（如 `InvalidCastException`）同样传播（不吞）。
- **强类型面适配错误＝fail-fast 族**：判定器不支持该强类型 delegate → `RegisterModing<TDelegate>` 抛 `InvalidOperationException`；调用时拆包失败＝子类适配（`Unpack`）抛 `ArgumentException`。
- **句柄面＝幂等宽容**：跨注册表 `RegisterModing` → `null`（无操作、不生效）；跨注册表/重复 `UnregisterModing` → `false`；均不抛错。null 参数＝`ArgumentNullException`（参数错误——非句柄宽容域）。
- **异常对称性**：moding 不改变调用的异常可见性——不吞、不包装（默认逻辑与替换逻辑异常均直接传播）。

### 3.4 句柄形态与 moding 面组织

- **条目等价句柄** `JudicatorRegistration`：注册动作返回；按名解析所得为**同一实例**（同一可寻址锚——两通道等效）；含 `Name` 与 `Invoke`（持有句柄的调用）；不含可变状态。
- **moding 注册句柄** `JudicatorModingRegistration`：注销凭据（句柄即权限——无注册者校验/所有权面）；内部＝目标条目引用＋注册序；不含可变状态。
- **双形态组织**：统一签名底层 `RegisterModing(JudicatorRegistration, Func<object[]?, object[]?>)`＋强类型封装便捷面 `RegisterModing<TDelegate>(JudicatorRegistration, TDelegate)`（经 `Judicator<TDelegate>.Adapt` 机制适配、注入者无需手工拆包/组包）；两形态**共用同一条目同一栈同一解析点**（交叉栈序「最后者胜」成立）；经强类型面注入的 moding 同样返回句柄（双形态同凭据语义）。
- **操作面布局**：moding 注册/注销在**注册表**上（X4 同构——句柄作锚）；调用面＝按名（`JudicatorRegistry.Invoke`）＋持有句柄（`JudicatorRegistration.Invoke`），均经条目内统一解析点。
- **未加项申报**：注册表查询面（存在性/枚举）默认不加（最小面＋"默认不加亦合规"口径——防"先查再调"伪宽容）；条目注销通道不加（CardEffectRegistry 档——对局生命周期内条目不可撤销；测试以独立实例清理「对局级实例天然隔离」）。
- **机制静默**：moding 面严格静默——无读面、注册/注销/解析不留痕（无事件、无日志）；实现仅以明细注释说明，不加任何可观测面。
