# Requirements — 判定器机制

为支撑 KARDS"特例"型机制，在框架层建立「判定器」机制：由游戏规则预定义的独立无状态服务，对局加载时加载，handler 按字符串名/ID 引用进行判定/取数/bool 判断，并支持注入 delegate moding（语义与 handler moding 一致）且 moding 后全局生效。

## Scope

- Includes:
  - 判定器机制骨架（框架/内核定义）：判定器形态（统一主方法 `object[]? func(object[]?)`＋子类 delegate 强类型面）、注册面、按名引用、delegate moding（纯替换、栈语义、全局生效）、对局加载时加载；
  - 两个示范判定器：①卡组顶特点判定（含恒真/恒假改写）；②判定器包装的 Targeter（含选择规则替换）；
  - 验收：机制测试＋两示范场景＋边界（未注册引用/注销回退等）。
- Excludes:
  - 现成判定逻辑的大规模收编（24 项候选留后续按需追加）；
  - 无改写需要的判定（直接在 handler 内部判定，不包装为判定器）；
  - 引擎其他缺口/机制（后续批次另议；老兵机制仍搁置）。

## Constraints

- **分层**：判定器**机制**由框架（内核）定义；判定器**内容**由游戏层按需定义（仅服务"可被改写"的逻辑）；
- **无状态**：判定器不持有对局状态，输入经参数/上下文；
- **语义一致性**：moding 语义与 handler moding（X4）一致（纯替换/最后者胜/注销回退/句柄寻址，仅"全局生效"为新增能力面）——细节实现 grill 定稿；
- 显式装配与注入、可测试、无隐藏全局（延续）；P1/P2 原则延续；
- 不破坏既有测试；构建 0 警告。

## Requirement Items

### R1: 判定器机制骨架（形态/注册/引用）

- Status: Confirmed
- Scenario/Trigger: 对局创建时判定器随对局加载（由游戏规则预定义）；handler 需要执行可能被改写的判定/取数逻辑时。
- Behavior: 框架定义判定器基类（统一主方法 `object[]? func(object[]?)`；子类声明自己的 delegate 签名并重载方法）；判定器对局加载时加载（注册面）；handler 经字符串名/ID 引用调用；判定器为独立无状态服务。
- Acceptance:
  - [ ] 判定器基类与子类形态就位（统一主方法＋强类型 delegate 面）
  - [ ] 注册面就位（对局加载时加载；注册语义明确）
  - [ ] handler 按名引用并调用成功；未注册引用行为明确（不崩、可诊断）
  - [ ] 无状态（判定器不持有对局状态）
- Terminology: [判定器](../../../CONTEXT.md)、[handler](../../../CONTEXT.md)

### R2: moding（注入 delegate、全局生效）

- Status: Confirmed
- Scenario/Trigger: 特例卡牌效果需要改写某判定（如"让这些判定恒为真或假"；"替换 targeter 改变选择规则"）。
- Behavior: 允许注入 delegate 替换判定器主逻辑（与 handler moding 一致：纯替换、栈语义、最后者胜、注销回退）；moding 后全局生效（对局内所有引用方调用均按栈顶解析）。
- Acceptance:
  - [ ] 注入 delegate 后判定器行为被替换；注销后回退
  - [ ] 栈语义：多次替换最后者胜、逐层回退
  - [ ] 全局生效：同一判定器的多个引用点统一按栈顶解析
- Terminology: [moding](../../../CONTEXT.md)

### R3: 示范① 卡组顶特点判定（恒真/恒假改写）

- Status: Confirmed
- Scenario/Trigger: 卡牌效果根据"卡组顶是否具有某种特点"产生额外效果；另一些卡将该判定改写为恒真/恒假。
- Behavior: 提供"卡组顶特点判定"判定器（默认实现按真实卡组顶求值）；特例效果经 moding 将其改写为恒真/恒假（全局生效）；注销后回退。
- Acceptance:
  - [ ] 默认判定：按真实卡组顶求值（含"无该特点"实况）
  - [ ] 恒真改写生效；恒假改写生效（两态）
  - [ ] 改写注销后回退默认判定
- Terminology: [判定器](../../../CONTEXT.md)、[卡组](../../../CONTEXT.md)

### R4: 示范② 判定器包装的 Targeter（选择规则替换）

- Status: Confirmed
- Scenario/Trigger: 效果需改写 Targeter 的选择规则时——以"判定器包装过的 targeter"承载；其他效果通过 moding 替换该判定器来改变选择规则。
- Behavior: Targeter 逻辑经判定器包装（引用方经判定器调用选择规则）；moding 替换判定器 → 选择规则改变并全局生效；注销回退。
- Acceptance:
  - [ ] 包装形态就位（选择规则经判定器调用链）
  - [ ] moding 替换后选择规则变化（示例：可选集合改变）且对引用方生效
  - [ ] 注销回退
- Terminology: [判定器](../../../CONTEXT.md)、[Targeter](../../../CONTEXT.md)
