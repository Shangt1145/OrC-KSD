## 二、设计申报（实现者设计项·已在代码注释留档）

1. **亡计内容效果形态**：`DeathrattleEffect : PassiveEffect`——动作面（`OnExecuteAsync`，作者覆写）＋框架面（`internal ExecuteAsync`，执行面调用）；被动装载语境使内嵌效果通道的生命周期完整（授予装载/移除卸载/授予失败回滚无残留）；执行面驱动动作、不经订阅面（动作型约定＝无交互、可同步完成）。
2. **内容授予通道**：`GrantWithContentAsync`（通用面）＋`AttachContent`（组件内容装载点，默认忽略）；注入时点＝组件创建后、装载遍历前（失败＝未置位、无状态变更）；空内容＝合法（空亡计＝无操作）；参值位不随本形态携带（对亡计无语义）。
3. **亡计执行面单源（硬性口径落实）**：`DeathrattleRules.ExecuteAsync`——两路径（死亡结算/再触发）共用；解析依据＝**行为态**（`TryGetActiveComponent`——死亡注销后不可见、天然跳过）；逐条异常隔离（记录、继续；取消类穿透）。
4. **死亡链插入点**：`ProcessDeathAsync` 完整次序（①槽位释放 → ②置毁 → **③亡计结算** → ④词条死亡注销 → ⑤修饰器清理 → ⑥钳击失效通知 → ⑦效果卸载 → ⑧位置字段置空 → ⑨card.died）；③ 位于「死亡前可观察状态」完整时（位置字段可读、词条行为态仍在、修饰仍生效、效果仍装载、IsDestroyed 已置位）；异常隔离不中断死亡流程。
5. **重入防护实现形态**：`RetriggerSystem` 内 per-链执行中集合（`_deployExecuting` / `_deathrattleExecuting`，引用相等）；「同卡同链执行中重入＝跳过并记录」（source「再触发」、keywords `reentry-skip`）；死亡结算经 `ExecuteDeathrattleAsync`（防护统一入口——与再触发共用）；死亡结算的「恰一次」＝流程内步骤位次＋行为态解析（注销后跳过）＋既有「已死亡/已毁＝跳过」幂等协作。
6. **再触发＝总线包装底层触发器**：请求以一条内部更新发布（`"retrigger.request"`）→ 接收触发器（`Trigger<RetriggerRequestView>`，Passive、hooks＝[请求更新]——与归零检查触发器同构）→ 解析参数（目标卡＋链类型）→ 驱动对应执行面；发布—接收—执行同一同步链（返回即已完成）。
7. **发布入口形态**：`RetriggerSystem.RequestAsync`（服务面）＋`RetriggerRules.RequestDeployAsync / RequestDeathrattleAsync`（静态便利口——效果作者可达，经「卡 → 玩家 → 服务」解析）；单卡请求；批量＝调用方遍历；非幂等（重复请求＝各执行一次）。
8. **部署生成面接入位置**：加载模板固定链 ⑤（元数据装配之后、词条装载之前——「数据装配组收尾」）；仅单位卡；无登记不生成（缺省）；相遇＝生成环节跳过并申报（对齐容器「每类型恰一份」语义——Info 记录 `generate-skip`）；生成失败＝记录不阻断加载；手动登记继续合法并存。
9. **参数收窄与非法输入分层**：目标卡非单位卡＝`RequestAsync(UnitCard, ...)` 编译期排除（运行期不可达——申报对齐）；目标卡 null／未知链类型＝明确异常（发布面 `Enum.IsDefined` 拒绝）；接收侧对构造性非法（载荷缺失/未知链值）＝防御拒绝记录（双层）；状态失效（已离场/已死亡/非在场）＝忽略（遍历安全）。
10. **门禁**：发布面（`_lifecycle.IsEnded` → 返回 false、零发射）＋接收侧兜底（不执行）——「执行/接收环节为兜底保证点」。
11. **返回语义**：`RequestAsync` 返回「请求已完成处理（执行/按语义忽略）」＝true；终局门禁拒绝＝false。
12. **越出预期清单申报**：`Match.cs` / `Player.cs` / `CardLibrary.cs` / `CardBase.cs` / `UnitCard.cs` / `KeywordSystem.cs` 等相邻既有文件的加性修改（装配接线、加载链步骤、单源替换）——均属「机制落地所需的相邻既有文件的必要修改」（Q&A-6 第 9 点授权、汇报列明）。
