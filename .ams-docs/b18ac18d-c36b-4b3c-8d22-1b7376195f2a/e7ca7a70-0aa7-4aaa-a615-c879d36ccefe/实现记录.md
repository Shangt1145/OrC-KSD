## 2. 关键裁量定稿项（需求轮 6 口径：报列明、不回写需求文档）

### 2.1 触发源清单（全域重跑传播——复用更新清单＋按需补充）
- **纳入**：`unit.deployed`、`unit.joined`、`unit.position.changed`、`card.died`（布局与在场类）；`card.hand.add`、`card.drawn`、`card.played`（手牌与动作类）；`card.stat.changed`（数值联动类——「条件依赖他卡数值」类表达的随动通路，倾向纳入项）。
- **不纳入**：`turn.*` 系列（相位）、`card.load`（加载链）——如未来条件表达依赖回合相位，属「按需补充」加性演进范围。
- 既有字面值不改不删；判定见 `GameEnvironment.IsRerunTrigger`。

### 2.2 合成稳定序与相对序（固定、可复现、文档化）
- **合成稳定序＝收集面登记序**（推荐序源）；各声明独立参与合成（不合并、不去重）。
- **相对序（固定）**：有效值 ＝ 基准 → Σ挂载修饰器（挂载序）→ Σ光环收集贡献（登记序）。
- 同输入 → 同序 → 同输出（「全量重跑＝确定变换」）；验收只断言最终有效值（不锁定内部序）。
- 合成路径：主链（RunChainAndDetect）与现算读取（ComputeEffectiveValue）同构；有效上限读取面不含光环收集（本单无上限光环场景，属加性扩展点）。

### 2.3 命名（实现者选定）
`GameEnvironment`（环境面）/ `AuraRegistry`（场级收集面）/ `AuraDeclaration`（光环声明）/ `ConditionalModifier`（条件评估节）/ `CollectAuras` / `RerunAllCardsAsync` / `ResolveFor`（卡→环境解析）。

### 2.4 通用门禁口径（收集过滤步骤内建，必经兜底）
- 单位卡（已单位化）：未死亡 ∧ 位置非空；HQ 实体：已入场（占位槽非空——不入死亡链）；其余（未单位化——卡组/手牌中）：不满足。
- 卡组期注册的声明被门禁拦截（不生效）；宿主进场后经全域重跑生效；「失效即消失」两条合法路径均支持：门禁不命中（主路径）＋声明注销（托管收口）。

### 2.5 「全卡」范围与判据
- 全卡＝引擎卡登记的全部**已加载**卡实例（卡组中/手牌中/战场；含 HQ 实体）。判据：`Hq` 实体恒参与；`CardBase` 以「归属已装配（Owner 非空）」＝已加载。
- 重跑顺序＝引擎卡登记序（创建序）；遍历快照（调用时点一致副本）。
- 无变化不通知＝每卡缓存比较既有保证（零发射）；逐卡异常隔离（记录、不阻断其他卡；取消类穿透）。
- 重入合并：全卡重跑执行窗内到达的新请求＝合并标记（当前轮结束后重扫，取代嵌套执行）——收敛由「改变才传播＋固定点」保证；性能收窄后置（正确性优先）。

### 2.6 托管收口顺序（效果卸载/装载失败）
①光环声明按来源注销（结构）→ ②修饰器按来源撤销（既有）→ ③受益侧衔接一轮全卡重跑（有命中才跑、同步等待——P2 语义）。

## 3. 验证方式与结果

- 构建：`dotnet build OrcEngine.sln` → **0 警告 0 错误**。
- 全量测试：`dotnet test OrcEngine.sln` → **失败 0**；Orc.Tests 166 / Orc.Lua.Tests 157 / Orc.Game.Tests 378。
- 四场景测试（`AuraSystemTests`，10 个）：
  1. `Scenario1_AdjacentAura_Follows_Source_Presence_Movement_And_Death`——①相邻光环随动（完整装载链时序证据〔注册先于 card.load 广播〕／卡组期不生效／出现／移动两态／离开／再现／死亡消失；托管注销；零增删；「无变化不通知」增强断言）。
  2. `Scenario1b_AdjacentAura_Stacks_From_Multiple_Sources`——①b 双源叠加（推荐增强）。
  3. `Scenario1c_AdjacentAura_Follows_Explicit_Effect_Removal`——显式效果移除路径（非死亡）托管注销＋衔接随动。
  4. `Scenario2_SelfCondition_FrontLine_Attack_Bonus_Follows_Position`——②自条件（在前线 +1／离开前线失效产出原值／按来源撤销）。
  5. `Scenario3_SourceCondition_Grants_Whole_Support_Line`——③源条件全体（≥2 受益／离开前线消失／死亡消失）。
  6. `Scenario4_AdjacentCount_Scales_And_Falls_Back`——④计数型（HQ 不计数／递进两级／死亡与离开回落）。
  7. `Environment_Queries_Are_ReadOnly_And_Safe`——查询面纯只读/未在场安全/隔槽不相邻/跨线不算/关系与计数分离（HQ）。
  8. `Modifier_And_Aura_Compose_On_Same_Field`——修饰器 × 光环同字段组合（固定相对序）＋现算读取同构。
  9. `Aura_Collects_Across_Fields_And_Unregisters_By_Source`——字段无关（行动费域）＋机制级注册面幂等/按来源注销。
  10. `StatChanged_Drives_Full_Rerun_For_Cross_Card_Conditions`——`card.stat.changed` 纳入重跑的行为证据（他卡数值条件随动）。
