## 一、功能职责与流程约束（本委托需求基线）

- **完整链载体（Q&A-1 裁定）**：以**真实效果类在效果运行期**为载体——『效果施放 → 取样 → 授予 → 行为生效』**同一闭环**；不得以「测试内直接组合」替代验收（可作辅助补充）。
- **确定性**：固定种子复现贯穿全链（取样序列 → 授予结果 → 行为断言）；异种子至少取样序列变化。
- **桩→完整升级**：原桩（真实效果类 → 运行期取用随机服务 → 『授予调用』记录器）保留载体底座、升级末端为真实词条授予与行为验证；升级对照与去向（保留/替换/标注）记录申报。
- **池构成**：池＝**可随机授予的行为词条集**——排除「无法被压制／无法被抑制」类元规则词条与未接通项；池构造与筛选口径在测试中显式说明。
- **非功能（延续）**：不破坏既有测试；构建 0 警告；最小加性适配授权申报制；无第二真源。

### Q&A-1（2026-10-04）：验收载体形态与行为断言层级

**子的问题原文（摘要）**：

- 背景：B1④ 原桩的形态是「真实效果类（经效果注册表注册、经装载链在卡加载时点生效）→ 效果运行期取用对局随机服务 → 取样 → 『授予调用』记录器」。本补验要求把④升级为完整链：『从词条池经确定性随机服务取样 → 授予单位（词条管理组件登记） → 词条行为实际生效』。歧义：补验的「完整链」没有明说是否仍以「效果运行期」为载体。
- 主问题 1：补验的『完整链』验收形态——是否仍要求以「真实效果类在效果运行期取用随机服务并完成授予」的形态执行（效果施放 → 取样 → 对单位授予 → 行为生效 同一闭环），还是允许以「测试内直接组合」（构建池 → 调随机服务取样 → 调真实授予面 → 行为断言）达成即可？两者验收强度差异明显（前者证明『效果可表达随机词条』，后者只证明『服务＋词条体系可组合』）。
- 子问题 1.1：行为生效断言的最低标准：是否要求至少经该词条「既有行为消费路径」的真实驱动验证（如重甲减伤经真实战斗结算、免疫经伤害结算归零、压制经行动可用性），而非仅经读取面（HasKeyword/GetKeywordValue）或其他点状断言？
- 子问题 1.2：行为验证与取样结果的闭环关系：是否要求「取样结果＝被授予词条＝被验证行为词条」严格一一对应（链闭合）？若取样多个，是要求逐个验证行为，还是可从中选取 ≥2 个验证、其余仅读取断言？
- 子问题 1.3：确定性覆盖范围：同种子复现／异种子变化，是仅要求「取样序列一致／变化」，还是要求延伸到「授予结果与行为断言结果」层面也复现？

**解答**：

**主问题 1：必须仍以「真实效果类在效果运行期」为载体——效果施放 → 取样 → 授予 → 行为生效 同一闭环。**
- 理由：① 与原桩为同载体升级（升级点仅在末端：记录器 → 真实授予＋行为），保持「桩 → 完整」对照关系；② 本补验目标是**「效果可表达随机词条」**（表达力验证），非「服务＋词条体系可组合」；③ B1 交付能力本就含「效果经对局上下文取用随机服务」，闭环同时验证该能力。
- 备选与否决：测试内直接组合——否决（验收强度不足，证明不了效果表达链）；「两者皆可」——否决（验收模糊）。允许将直接组合的机制级测试作为**辅助补充**，但**不得替代**效果运行期闭环验收。

**1.1：是——行为生效断言须经该词条「既有行为消费路径」的真实驱动（≥2 个词条）；读取面断言不能替代行为断言。**
- 「授予后读取」（HasKeyword/GetKeywordValue）＝验证「登记/传递」环节（可覆盖全部已授予词条）；「行为断言」＝验证「生效」环节（≥2 个）。
- 词条选取：从 **A2 已交付且行为面完整**的词条中选择（如重甲减伤经真实伤害结算、免疫经伤害结算归零、压制经行动可用性——按 A2 行为面选择并说明）；**避开** A2 申报的骨架级／待接通道项（如预报、免疫指令伤害通道等）。

**1.2：链闭合必须成立——「取样结果＝被授予词条＝被验证行为词条」；读取面全覆盖、行为断言 ≥2。**
- 每一取样结果须真实授予（经读取面验证全部——一一对应、无丢失/替换）；
- 行为断言从**被真实授予者**中选取 ≥2 个驱动（不得用未授予者或另行构造者）；
- 其余已授予词条允许仅读取断言；取样不足 2 个的场景（单元素池等）以场景内实际词条全部验证为准并说明。

**1.3：延伸到全链——同种子：取样序列一致 → 授予结果一致 → 行为断言结果一致；异种子：至少取样序列变化。**
- 同种子两次运行全链复现（含行为断言结果一致）；
- 异种子断言须**确定性构造**（选定种子样本／对比样本使差异稳定），避免概率性 flaky（如小池／偶然相同序列）。

**架构审视补充（本轮）**：
- 池构成边界：池＝可随机授予的行为词条集——排除「无法被压制／无法被抑制」类元规则词条（禁授语义）与未接通项；池构造与筛选口径在测试中显式说明。
- 失败/异常路径：沿用既有语义（授予拒绝、终态等不新增行为）；测试不断言未定义行为。
- 测试稳定性：确定性断言不得依赖概率巧合（见 1.3）。

### Q&A-2（2026-10-04）：池口径来源与「取 N／组合」语义

**子的问题原文（摘要）**：

- 背景：Q&A-1 已裁定「池＝可随机授予的行为词条集——排除『无法被压制／无法被抑制』类元规则词条与未接通项；池构造与筛选口径在测试中显式说明」。但池的**来源与构建责任**尚未落地，且委托「从词条池随机取 N（确定性随机服务 PickOne/PickN）」「多词条组合」等表述仍有歧义。补充现状：A2 交付已含「随机对战词条」表达（池＝打标全集＝闪击/奋战/烟幕/伏击/重甲，经注册/标记面提供），且明确定义「对战词条」为 5 项打标词条；本补验还要求覆盖「多词条组合」。
- 主问题 1（池的来源边界）：补验「词条池」的清单来源与构建责任——是否要求池可溯源到既有注册/标记面（即复用既有「对战词条」池读取语义或其等价可溯清单，测试不得另立清单副本），还是允许在测试中按「可随机授予且行为面完整」口径自行构建池内容（如从九词条中挑重甲/免疫/压制等）？「不引入第二真源」在池上的准确边界是什么？另：本补验对应的表达是否即 A2 的「获得 1 个随机对战词条」（池限于打标词条），还是允池含非打标行为词条（如压制/动员/免疫等）？
- 主问题 2（「取 N」与「多词条组合」语义）：2.1「随机取 N」的核定（N 固定值或范围？「循环 PickOne」与「PickN（不放回多取）」两种取样形态是否都须在完整链覆盖，还是允许择一为主、另一为边界并说明）；2.2「多词条组合」的确切含义（一次授予多个词条的「组合共存」？多次取样授予序列？是否含「词条行为之间的组合交互」〔同一伤害链上多词条叠加〕——行为交互是否属本补验范围，还是 A2 已覆盖、本补验只做链式集成）；2.3 链构成的两个待定语义（①「≥2 个行为词条」达成方式——是否允许通过池构造确保固定种子下取样结果可验证；②效果运行期「对单位授予」的目标单位如何确定）。

**解答**：

**主问题 1：池来源＝既有权威面（对战词条注册/标记面）；主链表达＝『获得 N 个随机对战词条』（池限打标词条）。**
- **链上池（效果运行期闭环）**：复用既有「对战词条」池读取语义（打标全集＝闪击/奋战/烟幕/伏击/重甲，经注册/标记面提供）——**测试不得另立清单副本**（真源边界＝词条权威清单在注册/标记面，测试只读取引用、不复制重写）。
- **边界构造**：空池／单元素／池不足等边界场景，允许经「从权威面选取子集／空集」的参数化构造达成（**子集选取≠清单副本**；取样原语层接收池参数，边界即传空集/单元素集）。
- **非打标行为词条**：主链不强制；如需补充（如压制/免疫场景）允许作为**辅助补充**、经既有权威面/参数化构造引用，不设第二清单副本、不改变主链验收。
- 理由：① A2 已交付「随机对战词条」表达＝本补验的链上表达对齐点（池＝打标面，天然满足「可随机授予＋行为面完整」且不含元规则词条/未接通项）；② 「不引入第二真源」的准确边界＝不得复制清单；读取与子集选取不违反。
- 备选与否决：测试自建池内容清单——否决（等同第二真源副本；且与 A2 既有表达脱钩）。

**主问题 2：**

**2.1「取 N」：N 取固定值（场景声明的小值）；「PickN（不放回）」与「循环 PickOne」两种取样形态均须覆盖（均在效果运行期闭环内；主/边界定位由实现者定并说明）。**
- N 取固定值（如 N=2/3；便于全链断言）；无范围语义。
- 两形态均为 B1 已交付取样语义（PickOne/PickN），作为「完整验证」应双向闭环；不得降级为纯服务层断言。

**2.2「多词条组合」＝一次授予多个词条的「组合共存」为主（授予 N≥2 → 多词条共存于同一单位 → 读取全部＋≥2 行为断言）；多次取样/授予序列为可选补充。**
- **词条行为之间的组合交互（同一伤害链多词条叠加）不属本补验必需范围**——A2 既有行为测试为个体行为与已知交互的主覆盖；本补验做**链式集成**（经真实行为消费路径驱动），自然发生的叠加可顺带断言，不为交互特别设计场景。
- 理由：本补验目标＝链（效果 → 随机 → 授予 → 行为生效），避免范围蔓延。

**2.3 两个待定语义：**
- ①「≥2 个行为词条」：**允许且推荐**通过池构造（池＝打标面，5 项均行为面完整）确保固定种子下取样结果可验证；前提＝不另立副本、不改取样语义。
- ②「对单位授予」目标对象：**推荐宿主自身**（最简闭环：效果施放 → 取样 → 对宿主授予 → 行为生效）；如因语义需要选择其它对象（选中单位等），由实现者选定并说明（保持链闭环）。

**架构审视补充（本轮）**：
- 池不足语义：N＞池数时沿用 B1 原语既有语义（不新定义），链层场景说明。
- 失败路径沿用既有语义（Q&A-1 已提）；不新增未定义断言。

### Q&A-3（2026-10-04）：主链池形式与行为断言落点、两形态分工、池边界层级

**子的问题原文（摘要）**：

- 背景与张力：Q&A-2 已裁定「链上池＝打标全集（闪击/奋战/烟幕/伏击/重甲）」「允许且推荐通过池构造确保固定种子下取样结果可验证」「≥2 行为断言从被授予者中选取」。三处待明确张力如下：
- 主问题 1（主链池形式与行为断言落点）：1.1 主链场景中「池内容＋种子」的自由度边界——为「确保取样结果可验证」，允许的手段是：①从打标面选取子集作为主链池（如只为可验证的行为词条）；②必须全量 5 项入池、仅允许挑选种子；③其它（请明确）？该自由度须与「不另立副本（读取引用、不复制重写）」如何兼容（子集选取是否需说明选取理由）？1.2「≥2 个行为断言」的落点：是否必须全部落于主链池词条（打标 5 项中取样所得者）？辅助场景的非打标词条（如免疫/压制）能否计入「≥2」，还是仅作补充、不计入主链验收？1.3 标记型词条（如烟幕）的「行为」以其消费路径（如被指定/筛选禁止的真实消费）驱动，是否构成合法的行为断言形态（与重甲经伤害结算同族）？
- 主问题 2（两形态分工与池边界层级）：2.1 PickN 与循环 PickOne 两形态场景的断言分工——是否两个场景都须各自达成「多词条组合（一次授予 N≥2 共存、读取全部、≥2 行为断言）」，还是主链整体至少一次（如 PickN 主场景）＋另一形态按其循环语义（允许重复选中）适度覆盖？若循环 PickOne 场景也须「≥2 互异词条共存＋≥2 行为断言」，其「允许重复」与「≥2 互异」的张力如何处置（例如由种子选取确保含 ≥2 互异，或该场景豁免互异要求）？2.2 池边界场景（空池/单元素/池不足）的层级——是否均须在「效果运行期」闭环内验证，还是允许以取样原语层用例承担（B1 交付已有原语级边界测试）？其中空池在链路中的期望行为请明确：原语「空候选集＝明确拒绝」语义的传播（断言拒绝发生、效果不吞），还是效果侧防御（功能不可用、不抛错、不失败）？「池不足（N＞池数）」同理请明确链路期望。

**解答**：

**1.1 主链池形式：允许从打标面选取子集（推荐，须说明理由）；亦允许全量入池（须保障可验证性）；「不另立副本」边界＝不复制全量清单、选取动作作用于权威面产物。**
- 子集与「不另立副本」的兼容：子集元素须取自/校验于打标面（引用权威面读取产物，而非另行写死一份「词条名单」副本）；**子集选取须说明理由**（如「为满足固定种子下取样结果可验证／覆盖行为断言目标」）。
- 全量入池案：允许，但须说明「全量下取样结果可验证」的保障（种子选取／通用断言设计）。
- 备选与否决：①子集选取（采纳，推荐）；②全量＋挑种子（允许、须说明保障）；③自定义其它形式（未采纳——无必要，且易滑向清单副本）。

**1.2 「≥2 行为断言」落点：须落于主链池词条（打标项中取样所得者）；辅助场景的非打标词条仅作补充、不计入主链验收。**
- 理由：链闭合一致性——主链抽的是打标词条，行为验证须与其一致；非打标词条（如免疫/压制）若用于辅助场景，其断言可另行记录（增值），不改变主链口径。

**1.3 标记型词条的「行为」：以其「既有行为消费路径」（被消费的真实地点）驱动——合法且正当（与重甲经伤害结算同族）。**
- 标记型词条语义（沿用 A 链定性：仅被消费）——其「行为」＝被真实消费的判定点（如烟幕的「不能被指定／筛选排除」经目标合法性／筛选的真实消费驱动；断言其被正确禁止/排斥）。
- 限定：须为**已接通的真实消费路径**（延续「避开未接通项」口径）。

**2.1 两形态分工：**
- 「≥2 行为断言」以**主链整体**为口径（合计 ≥2、落于主链池词条、可由两场景分担；不要求每场景各自集齐 ≥2）。
