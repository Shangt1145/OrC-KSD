## 五、Q3【类/流程层】：爆牌/弃置的终局信号契约与解耦范围

### 问题要旨（子 agent 预想契约 + 核对请求）

- 预想：DrawCard 满手＝drawn → 销毁（card.destroyed）→ burned；PlaceToHand 满手＝销毁 → burned；DiscardCardAsync 弃置＝移除 → 销毁 → discarded（完全不动）。
- 请求核对：burned 是否沿用 discarded 惯例（恰一次／销毁先于信号／载荷 {Card, Player}〔被爆卡在前〕／不携带原因与路径、两路差异仅由 emitDrawn 与 drawn 的有无体现）。
- 请求阐明：(a) 契约正确完整性；(b) 解耦范围与共享关系更新表述；(c) "独立信号/触发器"承载的准确含义与信号名方向。

### 裁定

**(a) 三条路径终局信号契约＝正确完整（确认）**，并核定细节：

- DrawCard 满手：card.drawn（算被抽到）→ 销毁 → **burned 恰一次**；hand.add 零次。
- PlaceToHand 满手：销毁 → **burned 恰一次**（不发 drawn／hand.add）。
- DiscardCardAsync 弃置：移除 → 销毁 → card.discarded 恰一次（**完全不动**）。
- burned 惯例（与 discarded 对齐）：**恰一次**；**销毁先于信号**（观察者所见即终态）；载荷 **{Card, Player}**（被爆卡在前、玩家在后）；**不携带原因/路径**（不区分两路差异；两路差异仅由 emitDrawn 参数与 drawn 的有无体现）。销毁步骤照发 card.destroyed（销毁语义不变）。

**(b) 解耦范围**："爆牌不走弃牌路线"＝**爆牌两条路径都不再复用 card.discarded**；弃置路径行为与信号**完全不变**。共享关系更新表述（替代 K0 时代表述）：

- **弃置＝销毁＋discarded；爆牌＝销毁＋burned；两者仅共享『销毁』步骤**（引擎既有销毁、card.destroyed 保留）；**信号发射各自独立**（不复用、不互发）。
- 爆牌**不经弃置动作**（DiscardCardAsync）——语义与信号双解耦。

**(c) "独立信号/触发器"承载的准确含义**：＝**总线信号面**——GameUpdates 新常量＋发射助手＋任意监听方可经既有触发器 hooks 机制挂载监听；**不新增其它机制件**（不建专用 Trigger 实例/专用机制）。信号名方向＝**card.burned**（与既有命名构词一致）；定型以实施阶段申报为准——除有强理由（如与既有契约冲突）否则按 card.burned 落地、变更须申报理由。

### 备选与拒绝

- 备选1（burned 携带"路径"字段区分两路）：拒绝——两路差异已由 drawn 的有无体现；载荷对齐 discarded 惯例（不携原因/路径）保持一致性。
- 备选2（保留"爆牌复用 discarded + 另加区分标记"）：拒绝——即被修正对象（正是"不触发弃牌路线"所禁止）。

## 六、Q4【类/流程层】："行为零变化"的准确语义与测试随改口径

### 问题要旨

- 需求 §一⑤写"行为零变化＋全量回归全绿"，但本单本身即用户有意的信号契约变更。
- 已知受影响测试：HandLimitBurnUnificationTests（并排断言断 discarded）、G7DiscardScenarioTests（⑥ HandLimit 段断 discarded 恰一次/drawn 先于 discarded/destroyed 先于 discarded）、CardServiceTests（Scenario1_Burn 断 discarded 恰一次）、清单面（GameHooksTests 17→18／MatchHistoryReadTests 契约核对）。
- 请求阐明：(a) "行为零变化"语义；(b) 测试随改原则；(c) 随改清单收口方式。

### 裁定

**(a) 语义**："行为零变化"＝**除爆牌信号输出这一有意变更**（弃用 discarded、改用 burned、对应断言随改）**外，其余全部行为零变化**（弃置/抽牌/销毁/手牌计数/终态/放置状态等）；且有意变更面本身＝**恰一处、两路径一致**的信号替换（drawn 语义、destroyed、hand.add 零次等其余信号序列不变）。

**(b) 随改原则**：凡以 card.discarded 观测爆牌路径的用例**一律改为观测 card.burned**，且**保留"不发 discarded"的反向断言**（正/反向双断言）；弃置/回收等无关用例**不动**；**覆盖不减少**；随改**旧→新对照记录**（逐条申报）；HandLimitBurnUnificationTests 的**两路并排对照保持并排**（差异仍仅 drawn 一项）。

**(c) 收口方式**：已列文件为已知起点；**以"实施时全库搜索复核"收口**——凡以 discarded 观测爆牌路径之处一律更新（含预计类别：事件流/历史读取/清单描述表等如有命中）；收口标准＝**搜索复核零遗留＋覆盖不减少＋旧→新对照完整**。

### 备选与拒绝

- 备选1（仅改"断言 discarded→burned"、不加反向断言）：拒绝——失去"爆牌≠弃置"的防回归锁定。
- 备选2（允许受影响无关用例"顺便清理"）：拒绝——最小随改原则；(b) 已定"无关不动"。
