# W1-B1 需求阐明 — G8 效果级随机服务（第 2 批）

> 本文档＝W1-B1 委托的 grill 对齐记录：功能职责／约束／验收标准／已解决的歧义，逐轮增长。层级＝类/功能流程级（记录类功能职责、业务流程步骤、数据流需求；不含方法体实现与技术方案）。
> 依据：委托《第 2 批 W1-B1》｜《实现文档（第 2 批）》S6｜《实现-grill计划（第 2 批）》场 2 决议（Q1-Q3）。

## 一、功能职责（类级）

1. **随机服务（对局级）**：对局持有统一随机设施——提供数值与取样原语；**单流、顺序确定**地消费；**确定性**＝固定种子显式化＋确定性 PRNG（消除平台/版本不确定性；为在线同步预留）。
2. **洗切接入同一服务**：既有洗切复用该服务/单流（集合洗切 API 改造为服务/受控源形态）；"兼容"＝语义级（见约束）。
3. **效果取用面**：效果可在运行期取得随机服务并完成取样（本委托的接入闭环，验收核心）。
4. **"随机分配"组合归调用方**：服务只提供取样原语；"分配"＝调用方（效果侧）循环取样组合（场 2 决议）。
5. **原语面与契约（轮 3 裁定）**：最低能力集＝**数值原语**（Next 类）＋**单取样**（PickOne）＋**多取样**（PickN＝**不放回**、返回 n 个互异元素；返回顺序由实现者定义并文档化，同种子下结果确定复现）；"如"为示例——命名/签名形态由实现者定（以委托所列形态为原型），**能力不得缺项**；取样原语须**对任意元素类型可用**（泛型形态；服务不依赖元素语义）。

## 二、约束

- **分层与受控**：接入面经装配期注入/上下文传递建立——显式、可测试；不得引入隐藏全局单例，不得给卡/效果引入"自由引用对局"的形态（沿用既有分层约束）。
- **候选职责**：服务对给定序列取样；筛选与候选合法性由调用方负责（服务不做过滤）。
- **消费纪律与无旁路**：对局内随机消费统一经该服务；绕过服务使用其他随机源将破坏确定性保障（及在线同步前提）。"无旁路"＝**可核查证据**：生产代码对局/效果侧 `System.Random` 消费点清零或逐点列明（创建期一次性种子生成——未显式传入时——不构成对局内消费，须列明）；测试中对局内随机行为的驱动须经确定性源/服务（其他非对局语义用途不强制清理）。
- **洗切兼容口径**："保持既有洗切行为"＝**语义级**——就地打乱（Fisher–Yates 性质、多重集不变）＋同随机源可复现；洗牌具体序列因 PRNG 更换而变化**属预期**；**不要求**与既有 `System.Random` 路径逐位相同。集合洗切 API 允许改造为服务/受控源形态；既有测试机械随改＋必要断言值更新；"测试兼容"＝**随改后全绿**（非"测试文件不得改动"）；不接受保留 `System.Random` 旧签名不动（与无旁路冲突）。
- **既有基线**：P1/P2 原则；全量测试（Orc.Tests／Orc.Lua.Tests／Orc.Game.Tests）不回退；构建 0 警告。

## 三、验收标准（细化）

**取用口径（轮 1 裁定）**：验收①②③使用**真实效果类**（经效果注册表注册、经装载链在卡加载时点生效的 Effect 子类；运行时经接入面取用服务）；④允许桩（见下）。

| # | 场景 | 细化口径 | 断言 |
|---|---|---|---|
| ① | 随机消灭 | 真实效果执行取样→接入**统一死亡流程**；不经任何交互面 | 固定种子下选中预期单位；死亡恰一次（可观察）；状态可观测（已销毁/离场） |
| ② | 随机分配 | 真实效果循环取样 6 次"选目标→+1"；**允许重复选中、可叠加**；必须**真实落值**（经既有防御力受控变更面） | 总增量＝6；各目标增量与固定种子下预期序列一致 |
| ③ | 随机转移 | 真实效果随机选目标→伤害经**既有伤害结算路径**应用于其（可观测）；**边界披露**：重定向完整语义随第 3 批 | 选中正确；伤害真实结算 |
| ④ | 随机词条 | **桩**：真实经"随机服务取样"环节；"授予调用"＝测试内自定义记录器（词条授予面属 A 链交付、未实施）；完整验证待 A 链后补测 | 记录器收到选中词条标识（且取样路径真实） |
| ⑤ | 确定性 | 固定种子下相同操作序列→相同随机结果 | 复现断言（单进程内） |

**补充口径与证据面（轮 2 裁定）**：

- **单流证据**：至少一项可观察断言证明"洗切与效果取样共用同一流"——推荐形态（等效亦可）：（a）同种子下额外执行一次洗切后，后续效果取样结果随预期序列变化；或（b）同种子下整体"洗切＋取样"组合消费序列复现。"单流＋顺序确定"须在交付汇报中声明（必需）＋代码注释（推荐）；"顺序确定"＝按确定性流程顺序消费（无并发/异步乱序，与 P2 一致）。
- **种子面**：现有 `Seed`（创建时可传入＋公开只读可查）**即满足**"固定种子显式化（对局状态可载明/查询）"；**不要求**新增"随机流消费状态/位置"查询面；"为在线同步预留"在本批的落点＝**确定性 PRNG＋单流＋顺序确定＋种子可载明/查询**，不要求更多同步机制。
- **原语级测试面（轮 3 裁定）**：三项原语（数值／PickOne／PickN）均要求原语级测试覆盖（行为＋边界；可独立或并入场景测试）；数值原语虽无场景直接消费，其专项测试属交付面。
- **防退化与复现细化（轮 3 裁定）**：验收⑤除复现断言外，须有**防退化验证**（推荐：固定种子下结果与"恒取首项"等退化行为可区分的确定性用例；可选辅助：多种子多样性检查）；⑤的"相同操作序列"＝效果取样序列复现（含④桩的取样环节）；"洗切＋取样"混合序列的复现性由 2.2 共流断言承担（不强制在⑤重复）。
- **验收测试面汇总（轮 4 确认）**：最低完整集＝①-⑤场景（各按细化口径）＋原语级测试（行为＋边界）＋防退化验证（≥1）＋共流断言（≥1）＋**多对局隔离断言（≥1，见轮 4）**＋门禁行为测试（准备态对外拒绝／进行态可用／终局拒绝）＋脱局降级行为测试＋无旁路核查（汇报正文清单）。本清单为最低完整集。
- **交付汇报要求（汇总）**：①申报所用接入路径（形态与层级）；②声明④补验边界；③声明③重定向边界；④无旁路核查结果（消费点清零/逐点列明，以清单落汇报正文）；⑤单流与顺序确定声明；⑥访问门禁实现说明。

## 四、边界与失败模式（审查补充）

- **边界行为定义责任（轮 3 扩展）**：以下边界的具体行为**由实现者定义（文档化）并测试覆盖**（需求侧不规定具体行为，仅要求"有定义、可测试"）：取样——空候选集；PickN——n<0／n=0／n＞候选数；数值原语——Next(max) 的 max≤0。
- **接入面不可用语境**：脱离对局的装配语境下的行为由实现者明确（宜沿用"功能不可用、不抛错、不失败"既有先例）。
- **确定性范围**：验收断言＝单进程内同种子复现；跨进程/平台一致性为设计目标（PRNG 确定性实现）。
- **访问门禁（轮 2 裁定，沿用既有先例、区分两层）**：**对局内部链路**（初始化链、准备态）的洗切消费**合法**（既有行为，不破坏）；**对外取用面**＝进行态可用、结束态（终局）拒绝、准备态对外请求不可用（明确拒绝/抛错，风格与既有管理器门禁对齐）。效果取用面发生于效果执行期（进行态），天然满足对外门禁。

### 轮 2（2026-10-04）：洗切兼容口径、无旁路证据、单流与门禁

**子问要点（摘录）**：

- 主问：洗切接入的"保持既有洗切行为与测试兼容"与"消费纪律（不得旁路）"的边界如何划分？现状张力：`Shuffle(System.Random)` 公开方法与既有测试直连 `new Random(seed)` vs 消除 System.Random 不确定性、确认无旁路。
- Q1："保持既有洗切行为"＝语义级性质，还是要求对既有调用逐位相同结果？
- Q2：集合洗切 API 允许改造为新服务/新随机源形态并随改既有测试（有先例）吗？还是必须保留旧签名？"测试兼容"＝随改后全绿，还是测试文件不得改动？
- Q3："无旁路"除汇报声明外，是否要求可核查证据（System.Random 消费点清算、测试不得用 System.Random 驱动对局内随机）？
- 2.1：现有 `Seed` 是否即满足"固定种子显式化"？是否要求新增消费状态/位置查询面？"在线同步预留"的落点范围？
- 2.2：是否要专门断言证明"洗切与效果取样共用同一流"？"单流＋顺序确定"的声明程度？
- 2.3：服务与取用面的访问门禁沿用哪种先例？初始化链（准备态）洗切合法性与对外取用面是否区分？

**解答**（已并入 §一/§二/§三/§四）：

- Q1：**语义级兼容**——（i）就地打乱、多重集不变；（ii）同随机源（同一确定性种子流）可复现；（iii）洗牌具体序列因 PRNG 更换而变化属**预期**；（iv）**不要求**与 `new Random(seed)` 路径逐位相同的洗牌结果。
- Q2：**允许并预期**集合洗切 API 改造为服务/受控源形态（具体签名由实现者定；对局路径经统一服务/确定性源驱动）；既有测试**机械随改＋必要断言值更新**（先例：既有"52 处随改"型）；"测试兼容"＝**随改后全绿**；**不接受**保留 `Shuffle(System.Random)` 旧签名不动（与无旁路冲突）。
- Q3：**要求可核查证据**——（i）交付汇报声明（必需）；（ii）核查结果：生产代码对局/效果侧 `System.Random` 消费点清零或逐点列明（创建期一次性种子生成须列明、不算对局内消费）；（iii）测试侧：对局内随机行为的驱动须经确定性源/服务（其他非对局用途不强制清理）。
- 2.1：现有 `Seed`（可传入＋只读可查）**即满足**；**不要求**新增消费状态/位置面；"在线同步预留"落点＝**确定性 PRNG＋单流＋顺序确定＋种子可载明/查询**（仅设计约束），不要求更多同步机制。
- 2.2：**要求至少一项可观察断言**体现共流（形态二选一或等效："额外洗切→后续取样变化" ／ "整体消费序列复现"）；"单流＋顺序确定"须在交付汇报中声明＋注释（推荐）。
- 2.3：**沿用既有先例、区分两层**——内部初始化链（准备态）洗切**合法**；对外取用面＝进行态可用、终局拒绝、准备态对外明确拒绝（风格与既有管理器门禁对齐）。

**备选与拒绝原因**：

- Q1：逐位相同 → **拒**：技术矛盾（换 PRNG 必变序列）且与"消除 System.Random"目标冲突。
- Q2：保留旧签名不动 → **拒**：与"无旁路/统一服务"直接冲突；"测试文件不得改动" → **拒**：与既有随改先例不符、过度僵化。
- Q3：仅汇报声明、无核查证据 → **拒**：无旁路为硬约束，须可复核证据面；"测试中完全禁用 System.Random" → **拒**：过严（非对局语义用途无碍）。
- 2.1：新增消费状态/位置面 → **拒**：超出"预留"范围、无当前需求；更强同步机制 → **拒**：本批仅预留。
- 2.2：仅声明、无断言 → **拒**：单流为核心约束，无证据面则验收不完整；消费日志/序列记录 → **拒**：超出本批范围。
- 2.3：无门禁随时可访问 → **拒**：与既有门禁体系不一致；内部链路也按对外门禁（准备态拒）→ **拒**：破坏初始化链既有行为。

### 轮 3（2026-10-04）：原语契约、边界责任与复现细化

**子问要点（摘录）**：

- 主问：随机服务原语的方法级契约——原语集合的最低要求、各类边界行为的定义责任、PickN 的采样语义。
- Q1："如 Next(max)、PickOne(candidates)、PickN(candidates, n)"中"如"是否示例性——三件套是否都必须提供，还是"至少 Next＋PickOne、PickN 按需"？允许增删/改名？数值原语（无场景直接消费）是否要求专项测试与交付？
- Q2：边界定义责任是否统一扩展到 Next(max) 的 max≤0、PickN 的 n<0／n=0／n＞候选数（全部由实现者定义＋测试覆盖，需求侧不做行为规定）？
- Q3：PickN 是否为不放回语义（n 个互异元素）？返回顺序与候选序的关系（集合同即可／保序／随机序）？
- 3.1：取样原语通用性——须对任意元素类型可用（单位/卡实例、词条标识、槽位引用…），还是允许限定某类？
- 3.2：验收⑤是否要求防退化断言（避免"固定返回首项"类退化实现亦通过）？"相同操作序列"是否要求含"洗切＋效果取样"混合序列（还是混合性由 2.2 共流断言单独承担）？

**解答**（已并入 §一/§三/§四）：

- Q1："如"＝**示例**；最低能力集＝**数值＋PickOne＋PickN**（命名/签名形态自由，能力不得缺项）；**三项均要求原语级测试覆盖**（数值原语虽无场景直接消费，专项测试属交付面）。
- Q2：**统一口径成立**——全部边界由实现者定义（文档化）并测试覆盖；需求侧只要求"有定义、可测试"。
- Q3：**不放回语义**（返回 n 个互异元素）；返回顺序**不作需求级约束**（保序/打乱皆可；实现者定义并文档化）；**同种子下结果确定复现**。与"循环 PickOne（可重复）"互不混淆——后者承担"可叠加分配"语义（如场景②）。
- 3.1：**要求通用**（任意元素类型、泛型形态；"通用取样面"属本单职责；服务不依赖元素语义）。
- 3.2：**要求防退化验证**（推荐确定性区分用例；可选多种子多样性辅助）；⑤"相同操作序列"＝效果取样序列复现（含④桩取样环节），混合序列复现性由 2.2 承担、不强制重复。

**备选与拒绝原因**：

- Q1：三件套必须全供（固定命名/签名）→ **拒**：命名与形态属实现自由（"如"为示例）；"至少 Next＋PickOne、PickN 按需"→ **拒**：PickN 有真实用途（"取 N 个互异候选"——如开发/发现的候选生成）且原语面完整性属本单交付；数值原语免测试 → **拒**：原语级测试面应完整。
- Q2：需求侧规定具体边界行为（如统一抛错/统一空集）→ **拒**：越权定义实现细节、与既定"空集"口径不一致。
- Q3：允许重复（=n 次独立 PickOne）→ **拒**：与"循环 PickOne"语义重复、与"取 n 个互异候选"的真实用途不符；强制保序或强制随机序 → **拒**：顺序语义非需求关注点、留给实现（但须复现）。
- 3.1：限定仅对象引用 → **拒**：与场景④（词条标识）及"纯取样、不依赖元素语义"的服务定位不符。
- 3.2：不设防退化 → **拒**：存在"退化实现亦通过复现断言"的验收漏洞；把概率性多样性断言设为必过 → **拒**：概率性断言不适合硬性验收（列为可选辅助）。

### 轮 4（2026-10-04）：验收测试面完整性确认

**子问要点（摘录）**：

- 主问：验收测试覆盖面的完整性——本单测试交付的最低覆盖清单是否即现有各条（①-⑤＋原语级＋防退化＋共流＋无旁路核查＋门禁＋脱局降级），还是仍有未列出的必须覆盖点？
- Q1：上列清单是否即"测试交付的最低完整集"？未列出项（如种子可载明/查询断言、服务构造/空状态行为、接入面申报对应的可测试证据）是否必须？
- Q2：多对局隔离（两对局各自持服务、互不影响）是否要求专门断言，还是"对局级"语义的自然推论（不强制）？
- 4.1：是否要求新增"经随机服务洗切"的专项断言（同种子两次对局逐位复现；共流若已由 2.2 承担则无需重复）？
- 4.2：无旁路核查除文字声明外，是否要求留置可复核技术证据（核查命令与输出记录），还是汇报中的列明即满足？

**解答**（已并入 §三）：

- Q1：**清单成立、补一项**——"最低完整集"＝①-⑤场景＋原语级测试（行为＋边界）＋防退化＋共流＋**多对局隔离（新增，见 Q2）**＋门禁行为测试＋脱局降级测试＋无旁路核查（汇报项）。三点逐项厘清：① 种子可载明/查询——既有面（传入＋只读），由"传入种子"的测试构造隐式覆盖，**不强制新增专门断言**；② 服务构造/空状态——无需专门验收点（由门禁/脱局条款覆盖）；③ "接入面申报对应的可测试证据"——已由①②③真实效果场景覆盖（接入面可用性即其证据），不另立。
- Q2：**要求专门断言（轻量）**——"多对局隔离"纳入测试面（≥1）：建议形态"两个独立对局（同种子）各自洗切/取样结果一致，且一方消费不改变另一方的后续序列"（等效亦可）。理由：随机服务为新建设施，"对局级"本义（无全局状态）需要证据，与约束"不得引入隐藏全局单例"互为印证。
- 4.1：**不强制新增独立专项断言**——"经服务路径洗切"的证据由 2.2 共流断言承担（其推荐形态均已含"经服务洗切"环节）；"同种子两次对局逐位复现"由 Q2 多对局断言的推荐形态自然涵盖；额外增强不列入最低集（可选）。
- 4.2：**汇报正文清单即满足**——以"消费点清零/逐点列明"清单落交付汇报正文（含位置与用途说明）；**不强制**留置命令/输出记录等附加形式产物。

**备选与拒绝原因**：

- Q1：将种子查询/服务构造等全部列为强制断言 → **拒**：冗余膨胀（既有面/隐式覆盖），非最低集所需；不补多对局隔离 → **拒**：见 Q2（新建设施缺"无全局状态"证据）。
- Q2：不设专门断言（语义推论即可）→ **拒**：与"不得引入隐藏全局单例"约束缺乏互证，存"静态共享随机源"类实现错误的漏检风险；多对局断言做成重型矩阵（多种子×多形态）→ **拒**：超出必要性（轻量 ≥1 即可）。
- 4.1：强制新增独立专项断言 → **拒**：与 2.2 断言重复、增测试负担；完全不要求任何"经服务洗切"证据 → **拒**：2.2 已要求（不可降低）。
- 4.2：仅口头"已清零"无清单 → **拒**：不满足"可核查"；强制留置命令与输出文件 → **拒**：形式过重，清单已足以复核。
