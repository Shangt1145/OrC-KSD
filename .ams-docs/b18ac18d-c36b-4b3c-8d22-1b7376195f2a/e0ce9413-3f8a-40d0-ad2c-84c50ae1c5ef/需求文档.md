# 需求阐明 — 词条组件化体系（第 2 批·A1）

> 委托：Orc 引擎表达力缺口补全（第 2 批）· W2-A1 词条组件化（对应实现文档 S1）。粒度：**类级**。
> 本文档记录本委托的需求阐明与 grill 对齐过程（功能职责 / 约束 / 验收标准 / 已解决歧义）；技术实现与计划由实现者自行制定。

## 一、功能职责（类/组件级）

### 1. 词条组件（基类形态）
- 词条＝**独立组件**：自含数据（含参值）＋运行逻辑（可选）＋基类提供的**授予/移除生命周期回调**＋**可内嵌效果**（复用 Effect 体系）。
- **语义双轨（仅语义划分，不建两套框架）**：能力型＝有主动行为面（运行逻辑与/或内嵌效果）；标记型＝无行为面（仅数据、被读取消费）。两类**共用同一组件基类与同一挂载/卸载机制**。
- 组件挂载/卸载＝词条授予/移除的承载；生命周期回调由基类统一维护（词条作者只实现行为）。

### 2. 词条管理组件（卡上）
- 词条组件的**注册处与索引**：查询有无、读取参值；承载词条集合管理（授予/移除入口面）。
- 现有三数据面（标识登记 / 逻辑装载 / 运行计数器）由本组件体系**合并替代**、不保留为独立可查询组件（第 2 轮裁定：保留查询语义与静态消费口、禁止双面并存——详见五·第 2 轮）；既有查询行为保持可用（读取方经动态查询判定有无词条）。
- 对外寻址（第 5 轮）：卡上可寻址词条面（偏好专用实例属性；**含无词条卡不抛**）；统一根写法（迁移对照清单以此为准）；静态口为其转发面——详见五·第 5 轮 2.3。

### 3. 内嵌效果（复用 Effect 体系）
- 词条组件可内嵌效果（Effect 实例）。
- **驱动关系（统一由体系负责）**：词条挂载 ⇒ 内嵌效果**自动装载**；词条卸载 ⇒ 内嵌效果**自动卸载**——词条作者无需手工管理内嵌效果生命周期。
- 内嵌效果与卡牌自身效果（外部效果）并行存在、互不冲突。
- 来源形态与装载深度（第 4 轮）：至少支持**实例持有**（作者构造/注入；声明式为可选扩展）；装载走**完整装载链语义**（挂主触发器＋OnMount＋托管登记＋失败回滚）、卸载**无残留**——"复用即完整链"（详见五·第 4 轮）。

### 4. 参值
- 声明形态：标识＋可选参值（如"重甲2"）——**单一声明类型**（"仅标识"＝参值位空简写；同标识重复＝拒绝〔不论参值〕——详见五·第 4 轮 2.2）；数据面以（标识, 参值?）承载。
- 读取口：有无查询＋参值读取（统一读改写口）；运行时改写经同一口；参值由组件自持。

### 5. 4 词条迁移
- 闪击 / 奋战 / 烟幕 / 伏击**全部迁移**至组件形态（含纯被动烟幕——统一管理）；**行为不变**（以既有测试回归证明）。
- 语义归类（描述层）：闪击/伏击/奋战＝**能力型**；烟幕＝**标记型**。四者实现形态均走同一组件基类（烟幕＝轻量组件：数据＋空回调/无主动逻辑）。
- 奋战须**保留运行逻辑承载**（攻击记账 / 收尾判定 / 回合清零——影响流程与可用性，非纯标记），不得退化为"标记型＋外部读取"。

## 二、业务流程需求

### 装载流程（对局加载期）
- 词条组件随卡牌加载链装配（时机与现状一致：先于 card.load）；无词条卡＝零副作用早退。

### 授予 / 移除流程
- **生命周期三操作**：授予＝挂载（存在 true／行为生效）；**移除＝完整卸载**（存在 false／参值不可读／行为注销）；**死亡注销＝仅行为撤销**（存在 true／信息照常可读／行为注销）——两档并存、语义不同（详见五·第 3 轮语义表）。重复授予/重复移除**幂等**（重复授予含不同参值＝无操作，参值变更一律走改写口）；卸载不存在词条不报错。
- 卸载时该词条行为的完整撤销（运行逻辑注销＋内嵌效果卸载）由体系统一负责。
- **完成语义与上下文供给**（第 4 轮）：授予/移除提供**可等待完成语义**（完成时装载/卸载已毕、状态一致；不允许返回后内部异步悬置）；装载上下文延续**提供器注入**先例、**缺上下文＝防御跳过（不抛错）**——动态授予同此（详见五·第 4 轮）。
- **序列与终态**（第 5 轮）：授予＝存在性置位→内嵌效果装载→OnGrant（装载链内失败→逆序整体回滚、无半态）；移除＝OnRevoke→内嵌效果卸载→存在性清除（链内失败＝操作失败、不留半态）；死亡注销＝同 OnRevoke 序列（不执行存在性清除）；**已死亡卡的操作面（授予/移除/改写）＝拒绝（终态）**、查询面保持可用——详见五·第 5 轮。

### 与效果体系的衔接边界
- 内嵌效果沿用 Effect 体系的装载/卸载与**失败策略**（装载期 fail-fast / 运行期隔离——不引入新语义）；回调异常沿用现有装载链路策略。
- 授予到"未放置卡"的**内嵌效果**装载时机，遵循场 1 Q6 装载策略（三型：延迟挂载 / 内部门控 / 直接注册）——**效果装载驱动（card.placed 等）属 S3**；**词条授予的挂载机制（含动态授予）属本委托**（详见五·第 3 轮 1.3）。

## 三、约束
- **行为不变**：4 词条迁移后既有词条行为测试全绿。
- 不破坏既有测试；遵循 P1（禁止无条件数据更新）/ P2（同步、无异步）；构建 0 警告。
- 参值通道与读改写口统一（场 1 Q2）。
- 词条注册面（第 5 轮）：**进程级**（生产内建静态注册；测试唯一命名隔离）；**"注册先于使用"为使用者义务**（定义校验与装配单源）——详见五·第 5 轮。
- 空词条卡零负担（对齐既有轻量组件原则），不劣化加载链复杂度。
- 编辑域：`src/Orc.Game/Cards/` 与测试；越域需申报。

## 四、验收标准
1. 词条组件基类 ＋ 词条管理组件就位；
2. 带参值词条（示例"重甲2"）声明 → 装配 → 读取（`GetKeywordValue`）通过；**含参值改写口最小验证（改写 → 读取新值）**；
3. 授予/移除闭环（测试内示例词条，**经注册面注册**）：**动态授予（含无词条卡"无→有"挂载）** → 行为生效 → 移除 → 失效 →（再授予）；含授予/移除**回调验证**；另含**移除 vs 死亡注销的对照断言**（信息保留差异）；其中"行为生效/失效"的载体要求：**内嵌效果的装载/卸载随动**（示例词条以内嵌效果为主要行为载体演示）＋运行逻辑挂载/撤销（体系能力）——两层均须覆盖；
4. 4 词条迁移后既有词条行为测试全绿（行为不变；口径＝**允许受控随改**：内部结构断言迁移至新组件面、逐条记录〔旧→新〕、覆盖不减少——保真清单见五·第 2 轮 1.3）。
- 全量测试回归（Orc.Tests / Orc.Lua.Tests / Orc.Game.Tests）通过、构建 0 警告。

## 五、Grill 对齐记录（逐轮）

### 第 1 轮（类级结构）

**子问·主问题 1：**"双轨仅语义划分"的准确含义与 4 词条归类。
- 子问 1.1：双轨是否即"能力型/标记型"？"仅语义划分"是否指：两类共用同一套组件基类与同一挂载机制、差异仅在语义层？
- 子问 1.2：4 词条归类——闪击/伏击属能力型；烟幕属标记型；**奋战归属**？迁移后奋战是否保留运行逻辑承载，或可退化为标记型＋外部读取？
- 子问 1.3："能力型＝产出效果主动改写"中的"效果"是否**特指内嵌效果**？即能力型主动改写是否必须经内嵌效果表达；还是可为组件运行逻辑自有通道（如伏击现直接注册 handler）？

**父裁答 1.1：** 是——双轨＝"能力型/标记型"；"仅语义划分"＝两类共用同一套组件基类与同一挂载机制（不建两套框架），差异仅在语义与行为面（与场 1 Q1 记录一致）。

**父裁答 1.2：** 闪击/伏击/奋战＝能力型；烟幕＝标记型。**奋战须保留运行逻辑承载**（不得退化为"标记型＋外部读取"）。归类为语义描述层；实现形态上四者均走同一组件基类；烟幕＝轻量组件（数据＋空回调/无主动逻辑），消费方仍经管理组件查询。

**父裁答 1.3：** "效果"**不特指"必须经内嵌 Effect 实例"**。能力型词条的主动行为有两种合法承载：①**内嵌效果**（复用 Effect 体系——新词条与适配行为的推荐路径）；②**组件运行逻辑**（组件自有逻辑/注册通道——如伏击的改写注册，迁移后保留）。二者均属"词条组件自含运行逻辑"范畴。4 词条迁移**不强制**改用内嵌效果（行为不变原则）；内嵌效果作为体系能力就位，以测试内示例词条演示。

**子问·主问题 2：**"可内嵌效果（复用 Effect 体系装载/卸载）"在本次 A1 中的使用边界。
- 子问 2.1：4 词条迁移中是否存在**必须使用内嵌效果**的情形？（还是"词条行为沿用运行逻辑表达，内嵌效果＝体系能力就位＋测试示例演示"？）
- 子问 2.2：验收③"行为生效→失效"以什么载体演示——示例词条的运行逻辑（挂载时注册、卸载时撤销）？其内嵌效果（装载/卸载）？还是两者都要覆盖？
- 子问 2.3：内嵌效果装载/卸载与词条挂载/卸载的驱动关系是否为——"词条挂载 ⇒ 内嵌效果自动装载；词条卸载 ⇒ 内嵌效果自动卸载"，由体系统一驱动（作者无需手工管效果生命周期）？

**父裁答 2.1：** **不要求任何既有词条改用内嵌效果**。口径＝"行为沿用运行逻辑＋内嵌效果体系就位＋测试内示例词条演示"。（用户 Q4 答复"内部效果复用 Effect 体系"针对的是"词条内部效果"路径——新词条/需效果化行为时的实现路径，而非既有词条的行为改造。）

**父裁答 2.2：** 覆盖两层：①授予/移除**回调触发**验证（必备）；②**内嵌效果装载/卸载随动**（示例词条以内嵌效果为主要行为载体演示"挂载→行为生效→卸载→失效"）。运行逻辑（非效果）的挂载/撤销为组件能力（4 词条迁移已含），不强制单独场景。

**父裁答 2.3：** 是——**词条挂载 ⇒ 内嵌效果自动装载；词条卸载 ⇒ 内嵌效果自动卸载**，由体系的挂载/卸载动作统一驱动（无需词条作者手工管效果生命周期）。此即基类"维护授予/移除回调＋内部效果"的直接实现口径。

**备选方案与拒绝原因（本轮汇总）：**
- 备选 A（1.3-B）："能力型行为必须统一经内嵌效果表达（含迁移词条改造）"——**拒绝**：与"行为不变"验收冲突、迁移风险高；且"免疫＝handler 注入"等既有裁定表明运行逻辑/改写注册通道为合法形态。
- 备选 B（2.1-B）："至少 1 个既有词条改用内嵌效果示范"——**拒绝**：4 词条行为（触发/改写/记账）均非"效果生命周期"自然形态，改造收益低；以测试示例词条演示即可。
- 备选 C（1.2-B）："奋战退化为标记型＋外部读取"——**拒绝**：奋战含记账状态与收尾判定/清零逻辑（回合驱动状态维护），退化会丢失行为语义。

### 第 2 轮（三口结构处置 + 读口形态）

**子问·主问题 1：**三口结构与词条管理组件的最终关系；及"既有测试全绿"的口径矛盾。
- 子问 1.1："承接重构"的确切含义——三口（KeywordData / KeywordLogicData / KeywordRuntimeData）是被**合并替代**（不再作为独立可查询组件），还是**部分保留**？请给出"保留什么、吸收什么"的边界。
- 子问 1.2：验收④"4 词条迁移后既有词条行为测试全绿"的口径矛盾——既有测试断言了三口内部结构（如 `GetData<KeywordData>()`；KeywordSystemTests.cs:197-218 等）。要求**原样不改全绿**，还是允许**受控随改**（断言迁移到新组件面、行为语义不变）？
- 子问 1.3：若允许受控随改，"行为不变"的保真清单以什么为准（是否以：加载完成即可查询、无词条卡零副作用、死亡后登记保留可查询、闪击部署收尾落点〔扣费后〕、奋战记账/收尾/清零、烟幕筛选、伏击改写注册与注销——为唯一基准）？

**父裁答 1.1：** **合并替代**——三口由"词条管理组件＋词条组件"合并替代，**不保留为独立可查询组件**。边界：
- **吸收**：标识登记 → 管理组件的注册与索引（词条存在性＝组件/索引条目）；逻辑装载 → 词条组件自含运行逻辑（个体卸载替代 UnmountAll）；运行计数器 → 词条组件自含数据（如奋战攻击计数；不保留通用字符串键计数器形态）。
- **保留**：查询语义（有无/参值——经新读口）；静态消费口 `KeywordRules.HasKeyword`（便利转发面，见 2.1）；行为语义（保真清单见 1.3）。
- 禁止"双面并存"（旧三口径路与新面并存会造成两套查询路径）；**替换即替换**。

**父裁答 1.2：** **允许受控随改**（依据：第 1 批先例——内部结构断言随改须逐条记录；"行为不变"指用户可观察语义不变，非内部结构测试不动）。约束：
- 三口内部结构断言 → **迁移**到新组件面断言（逐条记录〔旧→新〕，验收汇报附清单）；
- **覆盖不得减少**（每条既有断言须迁移或有等价替代，不得以删除代替迁移）；
- 行为语义（保真清单）必须全绿。

**父裁答 1.3：** **是**——以所列为保真基准；父补充两条并合并列：
1. 加载完成即可查询（词条装载先于 card.load 的时机语义）；
2. 无词条卡零副作用（不挂词条组件、不装载逻辑）；
3. 死亡后**行为注销、信息保留可查询**（登记保留语义）；
4. 闪击部署收尾落点（扣费后）；
5. 奋战记账/收尾判定/回合清零；
6. 烟幕筛选；
7. 伏击改写注册与注销；
8. **定义期 fail-fast 校验语义**（未实现标识/重复项拒绝）〔父补〕。
- 随改记录义务：所有测试修改逐条〔旧→新〕记录于验收汇报。

**子问·主问题 2：**读口/写口（HasKeyword＋GetKeywordValue）的对外形态与缺省语义。
- 子问 2.1：保留静态 `KeywordRules.HasKeyword(card, keyword)` 并加性扩展 GetKeywordValue，还是收敛为卡上/管理组件实例读口（静态口删除或转发）？"统一读改写口"的"统一"指什么？
- 子问 2.2：`GetKeywordValue` 缺省语义——无词条卡 / 卡无该词条 / 词条无参值（如闪击）三种情形的返回值与"可选参值"含义。
- 子问 2.3："运行时改写"范围——仅"授予/移除"（有无变化），还是包括"参值数值的运行时变更"（重甲2→重甲3）？若含：A1 是否要求提供参值改写口并验收，还是仅通道形态、数值改写属后续？

**父裁答 2.1：** **静态便利口保留 ＋ 实例主口**：
- 主口＝词条管理组件实例面（卡→管理组件→查询有无/参值）；
- `KeywordRules.HasKeyword(card, keyword)` **保留**（内部转发至新面；消费方〔如烟幕筛选〕与调用形态不变——贯彻行为不变）；`GetKeywordValue` 加性扩展（静态面同步提供）。
- "统一"的语义（两维）：①**单一入口**——读与写、存在与参值，经同一体系口（不得绕过口直读内部结构）；②**多来源统一**——固有声明/运行时授予、能力型/标记型，均经同一查询面读取（不分路）。

**父裁答 2.2：** 契约（语义锁定；形态建议 `int?`，若采 Try 对等形态须满足同等区分语义并汇报）：
- **无词条卡 → null**；**卡无该词条 → null**（二者语义等价：该卡没有此可读词条；与 HasKeyword=false 一致——查询面保持无异常风格）；
- **词条无参值（如闪击）→ null**（"可选参值"＝声明期可不提供；读取以可空表达）；
- 区分方式：`HasKeyword=true 且 Get=null` ⇔ 有词条无参值。
- "可选参值"含义：声明面＝参值可选；数据面＝（标识, 参值?）。

**父裁答 2.3：** "统一读改写口"的**改写覆盖**：存在性（授予/移除）＋**参值变更**（对已挂载词条的参值改写，如重甲2→重甲3）。
- A1 边界：**口就位＋最小验证**——授予/移除闭环＝必验（验收③）；**参值改写须提供口并含最小验证（1 例：改写→读取新值，并入验收②）**；完整业务级数值效果（如"重甲+1"的行为与消费）留 A2。

**备选方案与拒绝原因（本轮汇总）：**
- 备选 A（1.1-B）："部分保留（KeywordData 保留为兼容查询面）"——**拒绝**：双面并存（两套查询路径）、与"组件化统一管理"目标冲突；兼容经静态口转发达成即可。
- 备选 B（1.2-A）："三口及查询面原样保留、测试不改"——**拒绝**：与"合并替代"裁决矛盾；第 1 批先例已确立"内部结构断言受控随改＋逐条记录"口径。
- 备选 C（2.2-B）："缺省返回 0/默认值"——**拒绝**：0 是合法参值，无法与"无参值"区分。
- 备选 D（2.2-C）："前提违例抛异常"——**拒绝**：查询面（HasKeyword=false 为常态）引入异常面、破坏调用平滑性；以可空＋HasKeyword 组合区分即可。
- 备选 E（2.3-B）："参值改写完全推后（A1 不提供）"——**拒绝**：统一读改写口为 A1 交付件、"能力型由产出效果主动改写"含参值改写；口不留空。

**父·对抗性审视补充（本轮）：**

### 第 3 轮（生命周期三操作语义 + 示例词条注册通道）

**子问·主问题 1：**生命周期三操作（授予 / 移除 / 死亡注销）的语义区分与边界。
- 子问 1.1：请给出三操作语义表（操作 × ①存在性查询 ②参值查询 ③行为是否注销）；"移除"与"死亡注销"是两个不同操作（体系并存两档）还是同一操作？
- 子问 1.2：重复授予同标识**不同参值**（重甲2 再授重甲3）的语义——幂等无操作／覆盖参值／拒绝？与"参值变更经统一改写口"如何呼应？
- 子问 1.3：A1 的授予/移除闭环演示对象——（a）已声明装配卡做"移除→再授予"闭环，还是（b）**无词条卡被运行时授予**（要求管理组件可延迟挂载）？"运行时授予驱动属 S3"与"A1 体系就位"的边界线？

**父裁答 1.1：** 三操作语义表（**"移除"与"死亡注销"＝两个不同操作，体系并存两档**）：

| 操作 | ① 存在性 HasKeyword | ② 参值 GetKeywordValue | ③ 行为 |
|---|---|---|---|
| 授予（挂载） | true | 可读（若有） | 生效 |
| 移除（完整卸载） | false | 不可读（null） | 注销 |
| 死亡注销（仅行为撤销） | **true（保留）** | **照常可读** | 注销 |

- 依据：①"脱钩根治"（授予/移除＝挂载/卸载，数据与行为一体）；②保真清单 3（死亡：行为注销、信息保留）——两者语义不同、不可合并为同一操作。
- 附注：死亡注销为终态（死亡不可逆）；"移除"可复装（再授予）。

**父裁答 1.2：** **幂等无操作**——重复授予同标识（含不同参值）＝无操作、参值保持；**参值变更一律走改写口**（与第 2 轮 2.3"单一入口"呼应；授予口不承担改值、避免 upsert 隐式语义）。需要"授予并更新参值"的效果由效果侧显式组合（改写口 或"移除＋再授予"）。

**父裁答 1.3：** **A1 支持动态授予**（含"向无词条卡挂载"——管理组件可按需创建/挂载；挂载机制完备）。边界澄清：
- "无词条卡零副作用"＝**加载期语义**（定义无词条→加载时不产生词条面）；运行时授予才按需创建。
- "运行时授予驱动属 S3"特指**效果装载驱动**（card.placed 等）；**词条授予的挂载机制属本委托**。
- 验收③闭环＝授予（含无→有）→ 行为生效 → 移除 → 失效 →（再授予）。

**子问·主问题 2：**测试内示例词条（"重甲2"）的注册/声明合法通道。

### 第 5 轮（操作序列/回调/失败语义 + 注册面作用域/寻址形态）

**子问·主问题 1：**授予/卸载（含死亡注销）的操作序列与回调语义。
- 子问 1.1：挂载序列——授予时执行次序与失败边界：（a）"存在性置位 → OnGrant → 内嵌效果装载"或"内嵌效果装载 → OnGrant"或其他？（b）装载期 fail-fast（上抛）时词条**整体回滚**（存在性回 false、零残留）？运行期隔离型失败是否仍算授予成功（词条在位、该效果缺失有留痕）？
- 子问 1.2：卸载序列——移除时次序："OnRevoke → 内嵌效果卸载 → 存在性清除"？死亡注销是否**同样触发 OnRevoke**（差别仅在"信息是否保留"）？
- 子问 1.3：死亡后的操作边界——死亡注销为终态：对已死亡卡再行授予/移除/参值改写的语义（拒绝／幂等／允许）？

**父裁答 1.1：** 挂载序列＝**①存在性置位（数据面可见）→ ②内嵌效果装载 → ③OnGrant（授予回调、最后）**（依据：登记先于启动〔效果体系 AddEffect→Mount 先例〕、机制面先于作者钩子〔挂主触发器→OnMount 先例〕）。失败边界：
- **装载链内失败**（构造/挂载/回调抛）＝fail-fast → **整体回滚（逆序撤销：②→①；存在性回 false、零残留）**——不允许半装载态；
- **装载链完成后的运行期失败**＝隔离（记录、跳过）→ **授予仍成功**（词条在位、失败留痕）。
- 即："授予成功"以装载链完成为界。

**父裁答 1.2：** 移除序列＝**①OnRevoke → ②内嵌效果卸载 → ③存在性清除**（挂载的逆序：行为面先撤、数据面后清）；链内失败＝操作失败（上抛）、**不留半态**（对称策略，细节对齐效果体系先例）。**死亡注销＝同样触发 OnRevoke 序列**（OnRevoke→效果卸载），**不执行"存在性清除"步**——差别仅在数据面保留。对已无行为态的重复注销＝无操作（幂等）。

**父裁答 1.3：** **公开操作面（授予/移除/参值改写）对已死亡卡＝拒绝（明确异常）**——死亡为终态；**查询面（HasKeyword/GetKeywordValue）保持可用**（信息保留，见第 3 轮语义表）。对照关系为终态语义的组成部分（可测试）。

**子问·主问题 2：**注册面的作用域/时序契约与管理组件的对外寻址形态。
- 子问 2.1：注册面作用域与隔离——进程级全局（跨对局共享）还是对局/装配级（每局独立）？测试内注册的隔离预期（测试间隔离、重复注册处理、清理）？
- 子问 2.2：注册面与声明解析的时序契约——"注册先于定义解析/加载"是否对外约束（使用者义务）？定义期合法性与加载期装配是否均以注册面为唯一来源？
- 子问 2.3：词条管理组件对外寻址形态——"从卡拿到词条面"的根写法偏好（GetData 式／专用实例属性／实现者定）？决定迁移清单根写法。

**父裁答 2.1：** **进程级全局**——依据：①定义构造时校验需静态可查（保真 8"定义期 fail-fast"时机——对局级会使脱离对局的定义无法校验）；②与现状（静态合法集）迁移最平滑；③词条集属"游戏规则一部分"（全局域）。隔离预期：测试以**唯一命名**隔离；提供注销/作用域面更佳（可选、汇报）；重复注册处理（拒绝/幂等）实现者定并汇报；线程安全（装配期注册为主；如支持运行时注册须声明）。

**父裁答 2.2：** **是**——"注册先于使用（定义声明构造 / 加载装配）"为**使用者义务**（对外契约）；**定义期合法性与加载期组件构造均以注册面内容为唯一来源**（单源）。

**父裁答 2.3：** 偏好**卡上专用实例属性**（总是可寻址——含无词条卡、不抛）；**硬性语义**：①从卡可寻址词条面（含无词条卡不抛异常）；②统一根写法（迁移对照清单以此为准）；静态口为其转发面。若实现者有理由选用他形态（如 GetData 式＋缺省面），须满足同等语义并汇报。

**备选方案与拒绝原因（本轮汇总）：**
- 备选 A（1.1-B）："OnGrant 先于内嵌效果装载"——**拒绝**：违背"机制面先于作者钩子"先例；作者钩子内若引用其效果将不可用；失败回滚面扩大。
