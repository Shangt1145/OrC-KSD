# W1-1 G12 卡牌元数据维度 — 需求阐明记录

> 委托：实施波次 1 · W1-1（G12：TagData 组件 / 定义期声明 / 构筑外 ID 水位线）。
> 设计依据：《实现文档.md》S1。本记录＝需求阐明（功能职责 / 约束 / 验收口径 / 已解决歧义）；非实现计划、非技术设计。级别：类/功能流程级。

## 〇、委托需求基线（摘要）

- **TagData 组件**：必填强类型槽位（国籍、稀有度〔基础/限定/特殊/精英〕）＋开放 tag 字典（子类别：海军/T-34/谢尔曼等；支持运行时增删）；槽位强类型约束。
- **定义期声明 → 加载装配**：CardDefinition 扩展（fail-fast）；加载时装配到卡牌实例。
- **构筑外＝对局级 ID 水位线**：卡牌加载时分配对局级自增整数 ID；初始化加载完成后快照水位线；判定＝ID＞水位线；提供访问口。
- **验收四场景**：①组合筛选 ②开放子类别 ③构筑外判定 ④开放 tag 运行时增删。
- **约束**：P1/P2；既有测试全绿（随改说明）；老兵不做；编辑域限定；分层原则。

## 一、需求点 A：必填槽位 × 既有构造调用的调和（第 1 轮）

### 子问题（原文）

- 1）既有构造调用的处置：「不破坏」是指旧调用一字不改即可编译并保持通过（新增参数带默认值/另辟重载）？还是允许全部旧调用统一补传新参数（受控变更、随改并说明）？两种口径对"必填"的成立方式完全不同。
- 2）若旧调用可不改而"必填"仍要成立：省略声明时的默认语义是什么（例如默认国籍、默认稀有度＝基础）？若旧调用必须改：是否所有 30+ 处测试调用都属"受影响随改"授权范围？
- 3）fail-fast 的失败面清单与国籍枚举值域：定义期应拒绝哪些输入（未声明国籍/稀有度、未定义枚举值、空/重复 tag 等）？国籍枚举取哪些成员值域（KARDS 七国全量？还是含日本的最小子集；场景①「日本精英空军」要求日本在内）？

### 裁定

- **A1｜「不破坏」口径（勘误）**：「不破坏既有构造调用」＝**不破坏既有测试的行为语义与通过状态**（允许受控随改＋说明）；**不是「旧调用零改动」**。**「必填」严格成立**：新定义卡必须**显式提供**国籍与稀有度；缺失＝定义期 fail-fast 拒绝。
- **A2｜随改范围**：src 业务代码无既有调用（已核实）→ 随改仅涉 `tests/Orc.Game.Tests` 的 30+ 处构造调用；**全部属于「受影响随改」授权范围**；补充值须与测试场景语义自洽（无特定语义者取合理值）；调整清单在汇报中说明。
- **A3｜fail-fast 失败面（定义期拒绝）**：①未提供国籍/稀有度（缺失必填）；②未定义枚举值（沿用既有 Enum 校验风格）；③空/空白开放 tag；④重复 tag（「明确错误」风格，与词条/单位类型先例一致）。运行时增删的重复语义（幂等/拒绝）按词条先例（幂等）由实现者定、汇报说明。
- **A4｜国籍枚举值域**：KARDS 已知国家**全量**——至少含五大主国：**德国、苏联、美国、英国、日本**；按来源材料（《KARDS核心规则基线》/卡牌文本分片）补充盟友国（法国、意大利等）；不得少于五主国；场景①要求「日本」在内（「含日本的最小子集」不满足——按全量原则）。

### 备选方案与拒绝原因

| 备选 | 结论 | 原因 |
|---|---|---|
| a. 全部新参数带默认值（旧调用零改动） | **拒绝** | 国籍无可接受默认值；「省略即默认」架空「必填」语义（与需求裁定相悖） |
| b. 另辟重载、旧签名保留 | **拒绝** | 双入口使「必填」失效（任意调用可走旧口） |
| c. 必填严格＋测试受控随改 | **采纳** | 唯一同时满足「必填」语义与工程可控的路径 |

## 二、需求点 B：对局级 ID 水位线的判定与访问口（第 1 轮）

### 子问题（原文）

- 1）快照的确切时机（＝LoadDecksAsync 全量加载返回后、起手装载之前？）与读面（水位线数值本身可读吗、经哪一级对象读）？
- 2）「访问口」的目标形态：判定落在卡牌侧（卡牌自身回答"我是否构筑外"）还是对局侧（对局查询"某卡是否构筑外"）？两者都要吗？
- 3）未被分配 ID 的卡（未加载/独立构造/初始化前创建的卡）的判定语义（false？未知态？明确拒绝？）；以及场景③「构筑外生成牌模拟」的期待路径——是否要求产品侧提供"生成构筑外牌"入口，还是测试用既有公开 API（实例化＋加载）模拟即可；模拟牌是否要、且仅要满足"ID＞水位线"这一判定（不要求走 card.load 广播或标签装配）？

### 裁定

- **B1｜快照时机与读面**：语义＝**初始化卡牌加载（双方卡组全量加载）完成后、任何后续动作（起手装载等）之前**；水位线值＝**此时已分配卡牌 ID 的最大值**（初始化域末位）。实现参照现有流程「加载链完成后、起手之前」等价落地。**数值读面不作公开要求**（测试可见性自定）；需求只约束「判定」能力。
- **B2｜判定访问口**：要求**至少存在一个可用判定口**（从「卡＋对局上下文」可发起判定；承载形态／单口或双口由实现者定，不锁定）。验收锚点：测试代码可从测试面完成判定。
- **B3｜未分配 ID 的卡**：判定请求＝**明确失败（拒绝）**；不得静默返回 false（先例：集合「未装配实例取件＝明确错误」，fail-fast 风格）。
- **B4｜场景③路径**：本批**不要求产品侧「生成牌」入口**（生成/衍生物属 G6 范畴）；测试经**既有「实例化＋加载」路径**模拟构筑外牌（经加载获得＞水位线的新 ID）即可；**不要求**走 card.load 广播或标签装配；判定成立条件＝「ID＞水位线」。
- **B5｜边界补充（对抗性审视）**：
  - ① 重复加载同一实例的 ID 行为（幂等/拒绝）按加载链语义由实现者定；须保证「同一实例同一 ID」、判定不失真；
  - ② 分配顺序＝加载推进顺序（既有确定性：玩家索引升序×洗牌后序）；水位线＝最大值；
  - ③ 判定为纯读、无副作用、不触发更新（P1 精神）。

## 三、需求点 C：TagData 的运行时可操作面与语义边界（第 2 轮）

### 子问题（原文）

- 1）开放 tag 的结构语义与边界：三个示例值（海军＝兵种类别、T-34/谢尔曼＝型号系列）在需求上是否同为平等的一组开放标签值（单一「子类别」维度、按值增删查），还是标签本身需分属多个命名维度（如「兵种」「型号」各成一组）？查询需求（场景②）＝按单个 tag 值筛出含该值的卡、且多值可组合（AND）吗？开放 tag 的值域是否完全开放（任意非空白字符串均可声明/增删、受控清单不存在）；以及它与既有机制词条清单（Keywords）的边界——「开放 tag 不承载机制行为、机制词条不走 TagData」是否为明确需求？
- 2）槽位的运行时语义：「必填」是否＝恒有值且**实例侧只读**（国籍/稀有度在卡牌实例上不允许运行时修改，只随定义声明固定）？还是需要支持运行时修改（如「改变国家」类效果）——若需要，是否有条件约束？
- 3）运行时可操作与更新语义：增删/修改的作用对象是否＝目标卡牌实例本身（仅该实例可见，不影响定义与同定义的其它实例——「定义静态、实例可变」）？开放 tag 的运行时增删（及槽位修改，若允许）是否要求产生任何「更新/通知」（触发既有更新线、通知效果系统）？还是静默数据变更——仅对同实例的后续读取、以及筛选查询结果可见即可（P1 精神：无无条件广播）？「生效」的验收观测面＝同实例即时读回＋筛选结果随动，对吗？

### 裁定

- **C1｜开放 tag 的结构语义**：三个示例（海军/T-34/谢尔曼）**同为平等的一组开放 tag 值**（单一「子类别」性质集合）；**不要求**命名维度分组（「兵种」「型号」不另立维度）；未来如确需分组，另行评估。
- **C2｜查询语义**：①按单个 tag 值筛出含该值的卡；②组合筛选＝**多条件 AND**——跨维度（国籍×稀有度×子类别，场景①）与**同一开放集合内多值 AND**（同含 A 且 B）均属支持范围。
- **C3｜值域与校验**：**完全开放**——任意非空白字符串可声明/增删，**无受控清单、无预登记**（对照：词条为「固定字面值受控」，二者刻意区分）；空白/纯空白＝拒绝（定义期既有裁定 A3；运行时增删同口径）；重复语义按词条先例（幂等）由实现者定、汇报说明。
- **C4｜与词条边界（明确）**：**开放 tag 不承载机制行为；机制词条不走 TagData**——tag＝纯分类标记、词条＝独立机制体系，二者不互相吞并。
- **C5｜槽位运行时语义**：**「必填」＝恒有值且实例侧只读**——国籍/稀有度随定义声明固定，**本批不支持运行时修改**；当前无「改变国家」类效果需求（老兵〔可变筛选维度〕系有意搁置、不构成反例）。未来如出现此类效果，另行评估（须处理「定义静态 vs 实例可变」一致性）。
- **C6｜作用域**：**定义静态、实例可变**——增删/修改作用于**目标卡牌实例的 TagData**；不影响卡牌定义、不影响同定义的其它实例（与词条 KeywordData 实例侧登记先例一致）。
- **C7｜更新语义**：运行时增删＝**静默数据变更**，**不要求产生任何更新/通知**（P1 精神：无无条件广播）；本批不要求监听面；未来如某效果需要感知 tag 变更，另行提出。
- **C8｜「生效」验收观测面**：＝**同实例即时读回 ＋ 筛选查询结果随动**（增删后即查即得、无需额外刷新）；**不含**更新线断言。
- **C9｜非功能性边界（审视补充）**：本批对 tag 声明/增删/查询无性能、并发、持久化等附加要求；顺序/同步语义沿用 P2 与既有对局模型。

### 备选方案与拒绝原因

| 备选 | 结论 | 原因 |
|---|---|---|
| a. 开放 tag 按命名维度分组（兵种/型号各一组） | **拒绝** | 无需求驱动（示例值为同级子类别）；增加模型复杂度、无验收面向 |
| b. 开放 tag 受控清单/预登记 | **拒绝** | 与「开放」语义相悖（词条受控先例系刻意对照）；新值接入成本与维护负担 |
| c. 必填槽位支持运行时修改 | **拒绝** | 无代表效果驱动；引出定义/实例一致性与通知治理问题，本批无必要 |
| d. 运行时增删发更新/通知 | **拒绝** | 无消费方（P1 精神）；C8 观测面已足以验收 |
| e. 平等单集合＋实例级增删＋静默变更（本裁定） | **采纳** | 与用户设计（开放字典/平等子类别）及词条实例侧登记先例一致，边界最小 |

## 四、需求点 D：国籍枚举值域落定（第 3 轮）

### 子问题（原文）

- A4 裁定「KARDS 已知国家全量，按来源材料补充盟友国」。我已完成来源核实：官方卡牌数据（docs/kards官方卡牌.json，1646 张）的 faction 字段共 **11 个值**——Germany 276 / Soviet 277 / USA 284 / Britain 266 / Japan 264 / France 64 / Italy 62 / Poland 60 / Finland 44 / Anzac 33 / Neutral 16。请裁定：
- 1）国籍枚举的最终成员清单：取 11 值全量？还是剔除非国家性质项——Neutral（中立，16 张）与 Anzac（澳新军团，非单一国家）如何处置？请给出最终枚举成员清单（这是定义期必填槽位的值域，直接影响 fail-fast 校验与「日本精英空军」等验收构造）。
- 2）稀有度映射与命名惯例确认：数据源 rarity 恰为四值 Standard / Limited / Special / Elite，与委托「基础/限定/特殊/精英」一一对应（基础=Standard、限定=Limited、特殊=Special、精英=Elite）；枚举成员命名沿用既有英文惯例（如 UnitType/CardCategory 的英文成员名）——确认无误？

### 裁定

- **D1｜国籍枚举成员清单（终稿）**：**11 值全量**，拼写与来源数据 faction 字段一致——**Germany / Soviet / USA / Britain / Japan / France / Italy / Poland / Finland / Anzac / Neutral**。处置说明：**Anzac（澳新联军）与 Neutral（中立）同为 KARDS 合法阵营归属**，一并入枚举（保证来源数据 1646 张全部可通过定义期校验；剔除会迫使未来返工）。五主国（Germany/Soviet/USA/Britain/Japan）在内——满足 A4「不得少于五主国」；「日本」在内——场景①可构造。枚举类型命名与成员顺序实现自由（成员清单锁定）。
- **D2｜稀有度映射与命名（确认）**：**无误**——一一对应：**基础=Standard、限定=Limited、特殊=Special、精英=Elite**；枚举成员命名沿用既有英文惯例（Standard/Limited/Special/Elite，与 UnitType/CardCategory 同风格）；中文语义对照建议入 XML 注释（实现自由）。

### 备选方案与拒绝原因

| 备选 | 结论 | 原因 |
|---|---|---|
| a. 剔除 Neutral 与 Anzac（仅 9 国） | **拒绝** | 二者是来源数据的合法 faction 归属；剔除使 49 张来源卡无法通过定义期校验、未来返工；与 A4「全量」原则相悖 |
| b. 仅五主国最小集 | **拒绝** | 违反 A4 全量裁定；盟友国（法/意/波/芬等）无归属 |
| c. 11 值全量（本裁定） | **采纳** | 与来源数据逐一对应；fail-fast 完备；零返工 |

## 五、需求点 E：装配链验收（第 3 轮）

### 子问题（原文）

- 我的理解：「定义期声明 → 加载时装配到卡牌实例（仿词条装配流）」——词条先例为『加载时挂载、登记先于 card.load 广播、未加载不可查』。请明确：
- 1）适用范围：TagData 装配覆盖**全部三类卡**（单位/指令/反制——国籍/稀有度/开放 tag 对指令与反制同样必填、加载后一律可读）吗？
- 2）可观测时点：装配须先于 card.load 广播（订阅者在该广播的处理窗口内即可读到已就绪的槽位与开放 tag，与词条「查询不到未就绪状态」一致）？还是仅要求「加载完成后任意时刻可读」、不约束广播窗口？
- 3）未加载实例（已构造、未走加载）读取 TagData 的语义：＝组件缺失、明确错误（沿用「未装配实例取件＝明确错误」先例）？还是构造期即挂空组件、加载前可读？

### 裁定

- **E1｜适用范围（三类全覆盖）**：**是**——TagData 装配覆盖全部三类卡（单位/指令/反制）；国籍/稀有度对三类卡**一律必填**（定义期 fail-fast 同口径）；开放 tag 三类均可声明；加载后一律可读。依据：官方数据全体卡牌均含 faction/rarity；「所有卡牌」持有、避免类别特例。
- **E2｜可观测时点（先于广播）**：**装配先于 card.load 广播**（与词条「登记先于广播」先例一致）——订阅者在 card.load 广播的**处理窗口内**即可读到已就绪的槽位与开放 tag；查询不到「未就绪」状态。不接受「仅要求加载完成后任意时刻可读」的松口径（广播窗口是既有契约的一致延伸）。
- **E3｜未加载实例读取**：**＝组件缺失、明确错误**（沿用「未装配实例取件＝明确错误」先例与 GetData 缺失抛异常契约）；**不采用**「构造期挂空组件、加载前可读」（避免「未加载/已加载」读取语义模糊、维持 fail-fast 风格）。

### 备选方案与拒绝原因

| 备选 | 结论 | 原因 |
|---|---|---|
| a. 仅单位卡装配 TagData；指令/反制缺省 | **拒绝** | 官方数据全类别均有国籍/稀有度；分类别特例破坏必填一致性与筛选完整性 |
| b. 仅要求「加载完成后任意时刻可读」、不约束广播窗口 | **拒绝** | 与词条先例（登记先于广播）不一致；订阅者在窗口内读不到已就绪数据（潜在时序缺陷） |
| c. 构造期挂空组件、加载前可读 | **拒绝** | 模糊「未加载」语义；与既有「未装配＝明确错误」（fail-fast）先例冲突 |
| d. 三类覆盖＋先于广播＋未加载明确错误（本裁定） | **采纳** | 与词条装配流先例完全一致；口径最严、无歧义 |

## 六、需求点 F：查询/筛选的验收边界与本批落地范围（第 4 轮）

### 子问题（原文）

- 我的理解：委托验收场景①「组合筛选查询（国籍×稀有度×子类别，如『日本精英空军』式）」、场景②「开放子类别查询（海军/T-34）」；《实现文档》S1 的 Target 写有「＋相关读取/筛选位置」，但同处注明「查询接入与验收转实现轮细化」；委托 FilesToModify 清单未含任何既有筛选位置文件。请澄清：
- 1）「筛选查询」的代码路径与集合对象：验收是否以「TagData 提供的基础读取能力（槽位读取、开放 tag 存在性/枚举）＋测试内组合筛选（对测试内构造的卡集合）」证明即可？还是要求产品代码提供面向特定集合（如卡组/手牌/战场/定义集）的筛选入口——若是后者，哪些集合属验收范围？
- 2）「相关读取/筛选位置」的本批边界：本批是否要把 TagData 接入任何既有读取/筛选位置（现有业务筛选消费口），还是本批范围＝组件＋定义声明＋装配＋水位线＋四场景测试，既有筛选位置的接入一律后续波次（本批不碰）？
- 3）回归与随改的合规口径：既有测试受控随改的边界是否为——允许修改既有断言/调用（随改说明）、允许新增测试，但**不得删除既有测试用例**（总数不减）？新增四场景测试的组织与命名（独立测试文件/并入既有文件）是否实现自由？

### 裁定

- **F1｜验收路径（确认）**：**以「基础读取能力＋测试内组合筛选」为准**——基础读取能力＝①槽位读取（国籍/稀有度值可读）；②开放 tag **存在性判断**；③开放 tag **枚举**（只读面，读出全部）。验收＝测试内对构造的卡集合执行「国籍×稀有度×子类别」组合条件筛选、断言结果正确（场景①）；开放子类别条件（海军/T-34）筛选正确（场景②）。**不要求**产品代码提供面向特定集合（卡组/手牌/战场/定义集）的专用筛选入口。
- **F2｜本批边界（收窄确认）**：本批范围＝**组件＋定义声明＋装配＋水位线＋四场景测试**；**不接入任何既有读取/筛选位置**（现有业务筛选消费口一律后续，随其消费方需求推进）——与「最小可用＋代表效果可验证」及分层最小侵入原则一致；FilesToModify 清单未含筛选位置文件即为此边界之体现。
- **F3｜回归与随改口径（确认）**：允许修改既有断言/调用（**随改说明、旧→新对照**）；允许新增测试；**不得删除既有测试用例、总数不减**（沿用项目既有口径：「迁移非删除、总数不减、旧→新对照」）。新增四场景测试的**组织与命名＝实现自由**（独立文件或并入既有文件均可；建议独立文件便于审阅——不强制；汇报说明）。

### 备选方案与拒绝原因

| 备选 | 结论 | 原因 |
|---|---|---|
| a. 要求产品代码提供集合级筛选入口（卡组/手牌/战场/定义集） | **拒绝** | 无消费方（本批无效果使用）；超出「最小可用」；集合入口随消费方后续落地 |
| b. 本批把 TagData 接入既有读取/筛选位置 | **拒绝** | 现有位置无 tag 消费需求；扩大改动面、无验收面向；违背最小侵入 |
| c. 允许删除既有测试用例以适配 | **拒绝** | 违反项目既有回归口径（迁移非删除、总数不减） |
| d. 基础读取＋测试内筛选＋不接既有位置＋不删测试（本裁定） | **采纳** | 与 S1「查询接入转后续」口径、委托「测试内构造」表述及既有回归先例完全一致 |

## 七、验收口径（本记录约束）

- 场景①：组合筛选（国籍×稀有度×子类别，如「日本精英空军」式）；

- 回归：既有测试随改后全绿（调整清单说明）。
