## 二、关键实现决策（供验收对照）

1. **「必填」的形态（A1/A3）**：`faction`/`rarity` 为可空可选参数，**运行期 fail-fast 拒绝缺失**（无可用默认值——「省略即默认」不成立；「旧调用零改动」不成立、须受控随改）。「缺失必填」失败面可测（`new CardDefinition("x",1,1,1,1)` → `ArgumentException`）。
2. **校验顺序**（定义期）：name → category → **faction → rarity** → keywords → unitTypes → tags（必填槽位先行；各失败面独立可达）。
3. **开放 tag 承载形态（C1/C3）**：以**值集合**（登记序、去重）承载「平等的一组开放 tag 值」——「字典」语义＝自由词表、无命名维度分组、无受控清单；`AddTag`/`RemoveTag` 幂等（词条先例）、空白拒绝、`ContainsTag` 查询不抛错。
4. **槽位实例侧只读（C5）**：`TagSlot.Value` 与 `TagData.FactionSlot/RaritySlot` 均 get-only（值随定义固定；本批无运行时修改面）。
5. **装配链（E1/E2/E3）**：三类卡全覆盖；装配先于 card.load 广播（订阅窗口内可读）；未加载＝组件缺失明确错误（不构造期挂空组件）。`LoadTagData` 由定义读数、无开放 tag 卡＝空集合装配（槽位恒在）。
6. **ID 水位线（B1/B2/B5）**：加载时经注入 provider 分配自增 ID；**幂等**（`MatchCardId is null` 才分配——「同一实例同一 ID」）；快照＝`LoadDecksAsync` 后、起手装载前；判定＝`ID ＞ 水位线`；**双访问口**（`Match.IsOutsideDeck` ＋ `PlayerManager.IsOutsideDeck`）。
7. **未分配 ID 判定＝明确失败（B3）**：抛 `InvalidOperationException`（不静默 false）；「水位线未快照」同口径（防御面）。
8. **重复加载语义（B5①）**：ID 幂等保持原值；整体重复装配被拒绝（`AddData` 每类型恰一份契约、与词条先例一致）——判定不失真（测试覆盖）。
9. **静默变更（C7/C8）**：运行时 tag 增删不产生任何更新/通知；观测面＝同实例即时读回＋筛选随动（测试覆盖）。
10. **P1/P2**：本批新增路径无更新发射、全程同步。
