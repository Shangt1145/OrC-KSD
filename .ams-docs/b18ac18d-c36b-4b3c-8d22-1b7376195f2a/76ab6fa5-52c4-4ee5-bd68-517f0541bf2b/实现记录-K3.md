## 三、定型申报（集中节；留白点显式定型、不静默）

### 3.1 形态结论（判定器化＝R1 1.1 期望路径）

- 本单**判定器化**（未走纯共享单元退化路径）：新增 3 个经对局注册面（`JudicatorRegistry`）承载、可经 moding 改写的判定器条目（≥1 可改写面——实际 3 个）。
- leg 层＝**分区条目**（R2 1.1 方案乙）：`move.leg.eligibility`／`attack.leg.eligibility`——**一份逻辑×两条目**（同一实现类 `LegEligibilityJudicator` 双实例配置：move＝检查位置、attack＝不检查）；命名由实现定型并申报（略）。
- C8＝**提升**（R3 1.1 默认提升口径）：`move.frontline-enemy`（沿用方案建议名；连字符沿用方案字面——命名由实现定型并申报）。

### 3.2 leg 判定器（`LegEligibilityJudicator`）

1. **名称**：`move.leg.eligibility`（`JudicatorNames.MoveLegEligibility`）／`attack.leg.eligibility`（`JudicatorNames.AttackLegEligibility`）；冻结契约。
2. **类与契约**：`internal sealed class`（由内置注册段/独立构造位创建，不供外部构造）；强类型面 `LegEligibilityRule`＝（UnitCard unit, Slot? position）→ `LegEligibilityFailure?`；统一面载荷＝`[unit, position]`（position 可空——attack 忽略/传 null）、输出＝`object[]{LegEligibilityFailure?}`（1 元素；null＝通过）。
3. **条件序列（单源；短路顺序＝可用性侧现状优先级，两侧现状均不改变——R4 1.1）**：
   GetData(state/command) → current is null → owner is null → owner≠current → destroyed → can（move＝CanMove／attack＝CanAttack）→ 被压制 → 行动费 → 位置（move；`position is null || !支援线.Contains(position)`）→ 通过(null)。
   - GetData 前置：保持复验侧现状取数顺序（未单位化时 GetData 抛出的行为与收编前一致——复验路径；可用性路径由入口 `RequireUnitized` 先行为一致）。
4. **位置参数化**：`position` 由调用点提供——可用性＝`state.Position`、复验＝`oldSlot`（原槽位引用）；谓词＝「源位置∈支援线」（R2 1.3）。attack 侧无等价位置条件（盘查结论：无——attack leg 不含位置项）。
5. **输出枚举 public**（`LegEligibilityFailure`）：moding 改写者与测试需构造输出值（判定器类保持 internal）；枚举语义对齐 leg 条件清单（见 §3.4 映射表）。
6. **注入**：`currentPlayerProvider`＋`battlefield`（move 必需）——仅只读使用；**无状态**、无缓存（moding 即时生效）。
7. **条件豁免示例（moding）**：改写该条目＝该动作全部调用点同步变化（可用性＋复验）；参考演示「移动/攻击无视被压制」（§六）。

### 3.3 C8 推进前置判定器（`MoveFrontlineEnemyJudicator`）

1. **名称**：`move.frontline-enemy`（`JudicatorNames.MoveFrontlineEnemy`）。
2. **类与契约**：`internal sealed`；`FrontlineEnemyRule`＝（Player owner）→ bool；载荷＝`[owner]`。
3. **语义保持**：原 `CommandManager.HasLivingEnemyOnFrontLine` 逐字迁移（空前线或己方已占＝false；敌方清空后实时恢复；enemyOf 缺省＝false；`!TryGetData || IsDestroyed` 死亡防御同源）。
4. **终态（R3 2.2）**：两处（可用性直调＋复验注入转发）**均改经新条目**——可用性经 `_moveFrontlineEnemy` 通道（条目句柄闭包）、复验经 `_moveFrontlineEnemy` 注入通道（同一单源）；**旧注入转发路径退役**（`HasLivingEnemyOnFrontLine` 面删除——引用核查 §五-5）。

### 3.4 输出契约与原因映射表（leg 条件→CommandBlockReason；逐项）

| LegEligibilityFailure | 触发条件（单源 Evaluate 内） | → CommandBlockReason | 备注 |
|---|---|---|---|
| `NonOwnerTurn` | current is null；或 owner≠current | `NonOwnerTurn` | 含「回合未就绪」 |
| `OwnerInvalid` | owner is null | `OwnerInvalid` | |
| `UnitDead` | destroyed | `UnitDead` | |
| `FlagFalse` | can（按动作）＝false | `FlagFalse` | |
| `Suppressed` | 被压制词条 | `Suppressed` | 顺序先于 cost（现状优先级保持） |
| `PointShortage` | Points ＜ 行动费有效值（G5） | `PointShortage` | |
| `PositionNotInSupportLine` | move：position ∉ 支援线（含 null） | `NoCandidates` | 仅 move |
| （null＝通过） | — | —（继续 C8/候选） | 通过标记 |
| （候选项举空） | —（调用点产生，不经 leg） | `NoCandidates` | NoCandidates 来源②；R2 2.1 口径保持 |
| （C8 失败） | —（C8 条目，调用点处理） | `NoCandidates` | NoCandidates 来源③ |

- 流程级提取：`NonOwnerTurn/OwnerInvalid/UnitDead` 三项＝流程级资格原因（`FlowLevelIneligibleReason` 分类读取——**读取路由、非条件重判**）；其余为动作级。
- 复合条件分派口径：current/owner 三态分派（null→NonOwnerTurn／null→OwnerInvalid／≠→NonOwnerTurn）与收编前 `ComputeIneligibility` 逐条一致。

### 3.5 装配与调用通道（R1 1.2 五要素落实）

1. **注册落点**：`Match.Initialize` K3 段（K2 段末尾）——3 条新注册（leg×2、C8）＋复验两条**重建注册**（J2 两条随迁，构造依赖共享条目句柄；条目名/绑定语义不变；注册顺序无关语义——条目按名索引、moding 按条目独立）。「默认名恒可解析、默认判定器无条件可用」保持。
2. **CommandManager 通道**：构造参数 `moveLegEligibility`／`attackLegEligibility`／`moveFrontlineEnemy`（可选；对局＝Match 注入条目闭包〔每次调用经统一解析点〕；缺省＝独立构造内置默认）。
3. **复验判定器通道**：`MoveRevalidationJudicator(lifecycle, moveLegEligibility, battlefield, moveFrontlineEnemy)`；`AttackRevalidationJudicator(lifecycle, attackLegEligibility, isAttackTargetLegal)`——对局＝条目闭包（Match）、独立＝CommandManager 内置通道（同构形态、不内联）。
4. **时序**：通道初始化先于 CommandTrigger/复验绑定（构造体内顺序保证）；延迟读取（`_commandManager?.` 先例）——装配链位置安全。
5. **清单同步**：`JudicatorNameList` 12→15、`BuiltInJudicatorNames` 10→13（4 验证类＋6 交战类＋3 动作资格类）、`GameHooksJson.JudicatorMetadata` 12→15、`GameHooksTests` 3 处断言联动。

### 3.6 三层叠加语义（move leg＋C8＋recheck；R2 2.1/R3 2.2/R4 2.2 申报）

- **底层条件源**（全部调用点）：`move.leg.eligibility`／`attack.leg.eligibility`／`move.frontline-enemy`——改写＝**所有经该层调用点同步生效**（移动＝可用性＋复验两点；攻击＝可用性＋复验两点；C8＝可用性＋复验两点）。
- **其上层**：`validation.move.recheck`／`validation.attack.recheck`（复验整面替换层）——**J2 冻结语义保持**：recheck 改写＝复验整面替换、不影响可用性；**替换后该复验不再经共享层**（替换逻辑自全权判定——本单未改该机制；既有 J2 测试全绿）。
- **排序**：可用性 →（底层条件源）；复验 →（底层条件源 → 默认复验判定器）→ 可被 recheck 层整面替换。
- 「目标空槽」＝调用点（复验）单源、不参与可改写叠加图（R3 2.2 口径保持）。

### 3.7 复验侧顺序保真与"一致性"位置调整（R4 1.1 申报）

- **attack 复验**：逐条保序（current/owner→destroyed/can→suppressed→cost 的复合写法拆分为等价分支、bool 等价；GetData 前置保持）——**无顺序调整**。
- **move 复验**：唯一调整＝「Position==oldSlot 一致性」（复验固有，R2 1.3）与「位置（源∈支援线）」检查的**相对顺序互换**（一致性移至 leg 之后、目标检查之前——移动面最小）。**等价论证**：两检查均为纯读、无副作用、属 AND 链必要条件；输出仅 Invalid/Valid 二值 —— 任何顺序下对给定输入输出相同（值级＋异常级等价；异常源 GetData 仍在 refs 检查后触发）。字段级定位与搬迁复核见 §四 M/6。
- **申报口径**：此为"顺序调整"而非"行为变化"；若父方要求零调整可退回为"一致性置于 leg 之前"（另一等价方案）。

### 3.8 零装配可用性与性能（R1 补充口径）

- **独立构造/零装配路径**：内置直连（`CommandManager` 内置默认实例——构造即可用；对局路径经注册表条目闭包——两形态同构、不内联）；复验绑定（独立路径）经 `CreateRecheckJudicator` 注入内置 leg/C8 通道——`Standalone_..._Defaults_Consistent` 行为断言覆盖（与注册路径同组合同结果）。
- **性能**：无缓存/快照引入；每次判定动态调用（moding 即时生效）——调用次数恒量级（`GetCommandAvailability`＝2 次 leg 调用＋C8/候选；较收编前 1×流程级＋2×动作级同量级）；机制性一跳（条目统一解析）为既有 moding 机制成本。
