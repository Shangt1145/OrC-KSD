# 需求阐明记录 — X4 handler moding（D1 实施委托）

> 用途：本委托的需求阐明与 grill 对齐记录（功能职责、约束、验收标准、已解决的歧义）；逐轮写入。
> 依据：《实现-grill计划（第 2 批）》横切项 X4、《实现文档（第 2 批）》S7；子 agent 第 1 轮定位申报与提问。
> 层级：类/功能流程级（GranularityLevel=class）。
> 称谓：英文保留 **moding**；中文规范表述＝**逻辑替换**；避免词＝修饰器／覆写／包装器／拦截器（第 5 轮定案）。

## 一、功能职责（类/流程级）

- **moding（逻辑替换）机制**：为触发器事件链上的「handler 注册项」提供逻辑替换能力——moding 项（delegate；与目标 handler 同参同返回〔视图／ctx／取消令牌 → Task〕）注册后，该 handler **执行时动态解析**、取**当前最后一个** moding 项**替代自身逻辑**运行；注销回退上一个（栈语义——栈序＝moding 注册序，与 band/优先级/事件名无关）；全部注销＝回退原逻辑。
- **承载（定位申报已确认）**：moding 挂载于**具体 handler 注册项**——以**注册句柄**为锚（唯一可寻址，不按事件名）；**目标外延＝全部事件 handler 注册项**（含构造期初始集合项与流程内置处理器；"必须可寻址"为硬性要求，构造期项句柄供给方式由实现裁定）；替换仅作用其处理回调本身，事件的名称/band/排序位置不变。
- **注册双形态**（同一套注册面、仅调用时点区分）：装配期（子类/构建时）＋运行时增删。
- **用途**：① 基类定义模板＋子类 moding（子类经注册句柄替换模板逻辑）；② 替代「前后插入 handler 实现屏蔽」（屏蔽方经注册句柄替换目标逻辑，不新增条目）。

## 二、约束

1. **纯替换**：moding delegate 不可调用原逻辑（非包装、非链式叠加）——**机制层面不存在指向原逻辑的调用途径**（原逻辑不作参数暴露、无 next/proceed 入口、不可经机制面获取；判定以机制暴露面为准）。
2. **禁止 handler 内流程编排**：handler（含其 moding 逻辑）＝单一处理单元；编排发生在流程层。判定口径：调用其它流程/触发器、串联多个处理单元、组织多步骤序列＝编排（禁止）；单一数据改写/记录/判定（含读取、计算等单处理单元内行为）＝非编排（允许）。
3. **覆盖外延**：仅事件 handler 链的处理回调；不纳入 Validate 等其它回调。
4. **一致性（快照语义）**：沿用既有注册表口径——执行期间的增删不影响本轮已开始的迭代；被撤销项不再参与后续执行；新增项自下一次解析点生效。
5. **生命周期与句柄边界**：注册项被撤销（Unregister）时，其 moding 项随之失效（避免悬空）；替换作用域仅该注册项（不影响同名其它条目与链上其它 handler）；moding 注销**以句柄为准**、沿用既有幂等口径（重复注销／条目不存在／句柄不属 → 无操作不抛错）；**注销权限＝任意持有句柄者**（句柄即权限）；**向无效句柄注册 moding**（条目已撤销／不属该目标）＝幂等无操作、不抛错、不生效（对齐既有宽容口径；返回形态实现裁定）。
6. **异常与非功能**：moding 逻辑执行异常遵循既有「事件内业务异常被隔离记录并继续」语义（不特殊化）；解析轻量、不显著增加 handler 执行路径开销；同步语义（无异步）。
7. **无专门读面**：不提供对外查询面（存在性／数量／顺序／句柄有效性查询皆无）；一切观测经行为断言与汇报；读面留待后续按需加性扩展。

## 三、验收标准（承接 S7）

- ① 装配期注册→替换生效（载体：基类模板＋子类代表场景）；② 运行时注册/注销→最后者胜、回退语义；③ 纯替换行为（行为断言：moding 生效时原逻辑不执行·对照观测）；④ 流程编排禁令落地（判定：能力面＋书面约定〔硬项〕＋测试惯例）。
- 组织：机制级测试＋用途代表场景（①模板/子类；②屏蔽替换）；moding 注册/注销/解析选择不留痕（机制静默）。
- 运行语义断言：运行时注册/注销后**对下一次执行**立即生效；执行轮内稳定（快照）；全量测试回归、构建 0 警告。

> ■ 定位申报（对应 Requirements 第 1 条"先定位 handler 承载"）
> 我已完成引擎内"handler"承载的定位调研，申报结论如下，请确认或纠正：
> 1) 引擎中"handler"＝触发器（`Trigger<TView>`，src/Orc/Core/Trigger.cs）内的事件处理回调。它有两条等价登记通道：装配形态（`TriggerEvent<TView>.Handler`，src/Orc/Core/TriggerEvent.cs）与运行注册形态（`Register(name, handler, …)` 注册进事件链的 handler 参数）；执行时按排序键调用该回调。
> 2) "流程处理器"与之一体同构：AttackFlow / DamageFlow / OrderFlow 等流程本身就是触发器，其"伤害结算"等处理器即流程事件链中的 handler（含经 band 扩展位注入的 handler）——不存在另一套独立的流程处理器承载。
> 3) 据此拟定 moding 的挂载基底＝触发器事件链中的 handler 注册项。

> ■ 主问题 1：moding 要"直接替换某 handler 的运行逻辑"——它如何寻址/锚定目标？
> - 子问 1a：锚定对象是"某个具体的 handler 注册项"（需要唯一可寻址标识，如注册句柄）还是"按事件名"寻址？（注意：现机制中事件名允许重复、注释明确"不承担唯一键职责"——若按名寻址，同名多条的替换语义请一并明确。）另请确认：替换仅作用于处理回调本身，该条目的事件名/band/排序位置保持不变。
> - 子问 1b：请就两个既定用途各描述一次预期寻址路径：「基类定义模板＋子类 moding」中，子类如何指到基类定义的模板 handler？「替代『前后插入 handler 实现屏蔽』」中，屏蔽方如何指到被屏蔽的 handler？
> - 子问 1c：moding 的覆盖外延——仅覆盖"事件 handler"这一承载，还是也覆盖触发器其它可扩展回调（如 Validate）？
>
> ■ 主问题 2：决议①"handler 运行时检查 moding 项、取最后一个生效"的确切语义
> - 子问 2a：解析时机是否＝每次执行 handler 时动态解析"当前最后一个 moding 项"（而注册时静态换绑、注销时换回）？"运行时注册/注销后对下一次执行立即生效"是否即为验收断言语义？
> - 子问 2b：与既有注册表语义的一致性——执行进行中（已开始的一轮）对 moding 的增删，是否沿用既有"执行期间的注册变化不影响本轮迭代、被撤销项不再参与后续执行"的快照语义？

**解答**：

- **定位申报：确认**。抽查依据：`TriggerEvent<TView>`（装配描述/注册项；注释明示事件名"允许重复，不承担唯一键职责"）；`Trigger<TView>.Register` 返回注册句柄 `TriggerRegistration`（S4 加性扩展）；`Unregister` 幂等撤销并注明快照语义；执行链按排序键（band×1000＋优先级＋注册序兜底）调用。结论：moding 挂载基底＝触发器事件链中的「handler 注册项」，以**注册句柄**为锚。
- **1a**：按**具体注册项（注册句柄）**锚定——现机制已有 `TriggerRegistration`（由 `Register` 返回、用于撤销），天然满足唯一可寻址要求；**不按事件名**寻址（事件名非唯一键；"同名多条"的歧义由此消解——每条注册项独立、互不影响）。替换仅作用处理回调本身、条目的事件名/band/排序位置保持不变——**确认**（仍按原排序键参与执行，仅运行逻辑被替换）。
- **1b**：两用途寻址路径——
  - 「基类模板＋子类 moding」：基类装配时注册模板 handler 并**持有其注册句柄**（基类字段/受保护成员）；子类或装配方**经该句柄注册 moding 项**（API 形态由实现定），替换模板逻辑。
  - 「屏蔽」：屏蔽方获得目标 handler 的注册句柄（装配方传递或同作用域），**经句柄注册 moding 项**（替换为无操作/替代逻辑）——不插入前后 handler。
- **1c**：**仅覆盖「事件 handler」**（含流程触发器事件链中的 handler）；Validate 等其它回调**不纳入**——Validate 契约（只读、无副作用、固定调用、作者唯一判定源）保持不动。边界已记入「约束」。
- **2a**：是——**每次执行 handler 时动态解析**"当前最后一个 moding 项"（而非注册时静态换绑、注销时换回）；**"运行时注册/注销后对下一次执行立即生效"即为验收断言语义**（实现可采用缓存等手段，但不得改变该语义）。
- **2b**：是——**沿用既有快照语义**（既有口径："执行期间的撤销不影响本轮已开始的迭代；被撤销条目不再参与后续执行"）。对 moding 具体化：执行中介入的增删不打断进行中 handler 的已解析选择；被撤销的 moding 项不再被选用；新增项自下一次解析点生效。

**对抗性补充（边界与非功能）**：① 注册项被撤销（Unregister）时其 moding 项随之失效（避免悬空）；② 替换作用域仅该注册项（不影响同名其它条目与链上其它 handler）；③ 不执行场景（空转/验证拒绝/中断链）不涉及 moding 解析；④ moding 逻辑异常按既有事件异常语义（隔离记录并继续）；⑤ 解析轻量、不显著增加执行路径开销。

| 决策点 | 备选方案 | 结论 | 拒绝原因 |
|---|---|---|---|
| 寻址锚 | 按事件名寻址 | 拒绝 | 事件名允许重复、不承担唯一键职责；同名多条替换语义歧义 |
| 覆盖外延 | 覆盖 Validate 等全部回调 | 拒绝 | Validate 契约（只读无副作用/固定调用/作者唯一判定源）与替换语义冲突；本机制聚焦 handler |
| 解析时机 | 注册时静态换绑（注销换回） | 拒绝 | 与既定"运行时检查、取最后一个"语义不符；栈语义需动态解析 |

### 第 2 轮（类/功能流程级）— 主问题 3/4（承接"注册句柄锚定 + 执行时动态解析"）

**子 agent 提问原文**：

> 【第 2 轮 · 主层（类/功能流程级）— 承接第 1 轮已确认的"注册句柄锚定 + 执行时动态解析"】
>
> ■ 主问题 3：注册双形态的语义界定（决议②"装配期（子类/构建时）＋运行时增删"；验收①②）
> 理解：moding 注册面挂在触发器实例上，装配期与运行时两种时点均可注册/注销；1b 已答"子类/装配方经句柄注册 moding 项"。待明确：
> - 子问 3a："装配期"与"运行时"的区分是否仅为**调用时点**（构建/装配期间 vs 构建完成后），注册面同一套、无独立的"构造参数一次性声明"通道？（即：不需要像初始事件集合那样提供构造参数形态；装配期形态＝装配代码/子类构造中调用注册。）
> - 子问 3b：注册的返回与注销面——moding 注册是否返回"moding 注册句柄"用于注销？注销是否以句柄为准、并沿用既有注册/撤销口径（`Unregister` 先例：重复注销/条目不存在/句柄不属于本触发器 → 幂等无操作、不抛错）？

>
> ■ 主问题 4：栈语义细节（决议③"最后一者生效；注销回退上一个 moding 项"；验收②）
> - 子问 4a："最后一者"的排序基准＝**注册序**（后注册者的项在栈顶生效）、与 band/优先级/事件名无关——确认？
> - 子问 4b：非栈顶项是否**完全不执行**（纯替换、无链式/无叠加）——"最后者胜"的字面确认？
> - 子问 4c：注销后的解析结果——注销任意项（含中间项）后，取"被注销后仍存在的项中**最后注册**者"；全部注销＝回退原逻辑；注销后重新注册＝按新注册序入栈顶。以上是否即验收②的断言语义？

**解答**：

- **3a：确认**——"装配期/运行时"的区分**仅为调用时点**（触发器构建/装配阶段〔含子类构造、装配代码〕vs 装配完成后运行阶段），注册面**同一套**、无独立"构造参数一次性声明"通道（锚＝注册句柄为运行时产物、构造参数无法承载；子类"直接 moding"即装配期调用注册）。
- **3b：确认**——moding 注册**返回"moding 注册句柄"**（形态由实现裁定；语义＝可用于注销的凭据）；注销**以句柄为准**；沿用既有注册/撤销口径（`Unregister` 先例）：重复注销／条目已移除／句柄不属本目标 → **幂等无操作、不抛错**。
- **3c：确认**——**任意持有句柄者均可注销**（含装配期注册的项；句柄即权限、无"注册者"身份校验——对齐既有 `Unregister` 模型）。验收②断言可直接以"持句柄的测试代码注销"组织。
- **4a：确认**——moding 栈序＝**moding 注册序**（后注册者在栈顶生效）；与目标条目的 band/优先级/事件名**无关**（事件排序键〔决定"哪个 handler 何时跑"〕与 moding 栈〔决定"该 handler 用哪个逻辑"〕分属两层）。
- **4b：确认**——**"最后者胜"字面语义**：仅栈顶（最后注册且未注销）的 moding 项执行；更早的 moding 项**完全不执行**；原逻辑不执行；无链式、无叠加。
- **4c：确认**——以上即**验收②断言语义**：① 注销任意项（含中间项）后，解析＝剩余项中**最后注册者**；② 全部注销＝**回退原逻辑**；③ 注销后重新注册＝**按新注册序入栈顶**。

**备选与拒绝（记录）**：

| 决策点 | 备选方案 | 结论 | 拒绝原因 |
|---|---|---|---|
| 注册面形态 | 另设"构造参数一次性声明"通道（对齐初始事件集合形态） | 拒绝 | 锚＝注册句柄（运行时产物），构造参数无法承载；双通道引入语义分歧；装配期调用注册已满足子类 moding 用途 |
| 注销面 | 仅注册者可注销／装配期项不可被运行时注销 | 拒绝 | 既有 `Unregister` 为句柄制（无注册者身份校验）；一致性优先；"屏蔽"用途需灵活撤销 |
| 栈序基准 | 按 band/优先级排序 | 拒绝 | band/优先级属事件条目层排序；moding 为条目内部逻辑栈、与链序正交 |
