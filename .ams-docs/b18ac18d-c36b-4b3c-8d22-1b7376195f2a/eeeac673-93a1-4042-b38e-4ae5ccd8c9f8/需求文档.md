# 判定器机制实施 J4（验收核对＋全量回归＋记录）— 需求阐明记录

> 委托：判定器机制实施 J4（第 4 单·验收核对＋全量回归＋记录；实现文档 S6）。
> 总目标：对照《判定器机制/实现文档.md》S6 的「6 组验收场景」与「5 项边界清单」，对 J1/J2/J3 已交付测试逐项建立映射、确认覆盖、缺口补测；全量回归（四套件）；产出验收核对记录（落子 Agent 文档区），作为判定器机制的权威复核材料。

## 一、功能职责

1. **逐项核对**：6 组场景 × 子项、5 项边界 × 子项——逐项映射到测试用例（文件／用例名／断言要点）。
2. **缺口处置**：按「断言级直接证据」基准判定与处置（补测／补强／论证豁免）。
3. **回归**：构建（-t:Rebuild）0 警告；四套件全量回归（以工作区实际为准，含并行增量）。
4. **产出**：验收核对记录（子项级映射＋缺口处置＋回归结果）；同时承载「不符合项／补充观察」申报通道。

## 二、已解决的歧义

### 轮 1（2026-10-04）：核对深度／缺口基准／补测裁定权／映射粒度与口径

**子的问题（原文摘要）**：
【主问 1】核对深度与「缺口」判定基准：(a)「每项有测试映射」是内容级核对（逐文件读源码、核对断言内容，信度以源码为准）还是记录级核对（从 J1/J2/J3 映射表转抄）？(b)「行为正确但零直接测试」「仅有间接覆盖」「有用例但断言不直接」三情形，哪些必须补测、哪些可说明后豁免？(c) 补测裁定权：自行裁定并执行，还是结论先经确认？
【主问 2】映射表粒度与口径：(a) 映射表是场景级（6+5 行）还是子项级展开？(b) ⑤示范②委托措辞（持有转发／改写替换／回退）与《实现文档》S6 原文（默认规则／改写替换／回退）不一致——以哪套分解为准？(c) ⑥「迁移后行为保持」的最终证据＝全量回归全绿＋J2 语义点映射表，还是额外专测？

**答复**：

**1(a) 核对深度＝内容级核对（以源码断言为准）**。映射表中每个子项的最终条目必须经**测试源码断言**核对确认；《实现记录-J1/J2/J3》的映射表仅可用于建立候选索引，不得作为入库证据直接转抄。操作口径：每个子项至少核对一条代表用例的断言段（记录文件／用例名／断言要点）；对存疑、断言模糊或与语义疑似不匹配的条目追加核对。

**1(b) 缺口基准＝「该验收语义须有直接、可判定的断言级证据」**。三情形处置：
- 「行为正确但零直接测试」→ **必须补测**；
- 「有用例但断言不直接针对该边界」→ **必须补强断言**（视为缺口，不得仅记录说明）；
- 「仅有间接覆盖」→ 分两档：间接用例中**含实质命中该语义的断言**者，可在记录中完成豁免论证（列用例名／其断言为何实质覆盖／为何无需独立用例）后豁免（并计入映射）；**仅路径路过、无断言命中**者，视为零直接证据 → 补测。

**1(c) 补测裁定权＝自行裁定并执行**（委托已授权「缺口补测，如需；以核对结论为准」）。约束：
- ① 补测仅针对真实缺口、最小范围（不做扩展性测试开发、不扩大测试面积）；
- ② 全部裁定（补测／补强／豁免）在核对记录中**逐条写明理由**，供上级复核；
- ③ **实质缺陷不属于「缺口」**：若发现行为本身与需求／验收标准不符（产品缺陷而非证据缺口），**不得自行修复**（本单无 src 编辑授权）——在记录中列「不符合项」（现象＋证据＋最小复现），显著标记、等待处置；
- ④ 如在核对中发现清单之外的**高风险空洞**，可在记录中列「补充观察」（不强制补测、不属本单验收范围），供上级裁定。

**2(a) 映射粒度＝子项级展开**（确认你的倾向）。6 组场景拆至子项（①对局加载／按名引用／未注册 fail-fast；②替换／栈语义／注销回退／全局生效；③统一主方法＋强类型适配／双形态注入；④默认／恒真／恒假／回退；⑤见 2(b)；⑥经判定器承载／可改写／迁移后行为保持）；5 项边界逐项建行。每条＝子项 → 用例（文件／用例名／断言要点）。

**2(b) ⑤口径归一＝两套措辞互补、按并集核对**。委托措辞描述**形态**（持有转发）、S6 原文描述**行为**（默认规则／改写替换／回退），互不冲突；且「持有转发」原本即列于《实现文档》S5 的验收（「包装（持有转发）就位；选择流程经判定器调用」）。⑤的核对子项＝**持有转发（形态与转发路径）＋默认规则运行＋改写替换（允许或禁止某类目标可选）＋注销回退**；以 S6 为骨架、并入 S5 的「持有转发」子项；若某子项被同一用例实质覆盖，可共用映射（写明断言要点），无需强行拆测。

**2(c) ⑥证据＝全量回归（四套件）全绿＋J2 已提报语义点映射，不要求额外专测**。「迁移后行为保持」＝替换承载后既有行为不变；既有测试（含 J2 重写的 TriggerValidationTests 等）＋全量回归即其权威证据。补充要求：记录中⑥行须指明（i）全量回归结果；（ii）J2 语义点要点（如「每次触发前、只读」「未绑定＝恒合法」等）及对应既有用例抽查 1-2 条（经源码断言核对）。

**备选方案与拒绝原因**：

- （2b 备选）以委托措辞为准修改 S6 → 拒绝：S6 为定稿验收文本（场 3 裁定），两者互补、改稿无必要。

### 轮 2（2026-10-04）：「异常隔离（与 X4 对齐）」判定对象／边界四项核对维度

**子的问题（原文摘要）**：
【主问 1】边界「异常隔离（语义与 X4 对齐）」的核对判定对象：X4 原文＝「moding 异常＝事件内隔离（记录并继续、结局 Normal）」（事件执行层面）；J1 定型＝「异常对称：不吞、不包装（默认与替换逻辑异常均直接传播）」（机制层）；J2 触发路径＝「契约兜底承接、取消类穿透」（调用侧）。(a)「与 X4 对齐」以何为判定对象——(i) 两层合并证据（机制层不吞不包装＋调用侧不炸穿、按契约兜底），(ii) 必须在判定器链上找到「记录并继续／结局 Normal」式行为的直接映射？(b) 若某层确无隔离语义可映射，按何处置——豁免论证／补充观察／不列该层？(c) 需否把「判定器异常不炸穿事件链、触发路径按契约兜底」明确作为该边界映射要点（J2 的 InvokeAsync_Judicator_Throws_Is_Treated_As_Contract_Fallback、…_Cancellation_Pierces 计入该边界证据）？
【主问 2】其余四项边界的核对维度：(a) 未注册引用按「全部引用通道并集」核对（机制级 Resolve/Invoke＋装配级注册段解析＋绑定级 FromRegistration/内置解析）——各通道都要映射行？(b) 空顶卡范围＝「空卡组 false 降级（不抛）」单语义，还是含相关三态（未加载态明确错误、读面越界）？倾向以主语义＋三态附带映射要点。(c) 快照一致性以 X4 三要素为基准逐要素核对，还是以 J1 用例断言范围为准？无断言命中按 1(b) 处置？(d) 注销后回退＝机制级（J1 栈回退）＋示范级（J3 两示范）＋集成级（J2 验证改写）全部通道并集？

**答复**：

**1(a) 「与 X4 对齐」判定对象＝两层合并证据（i）**。「对齐」的准确含义＝**moding 替换逻辑异常在判定器链上不静默、不类型变形、不炸穿**；其隔离效果由所在调用侧的既有契约保障——handler 路径＝事件框架既有 X4 隔离（判定器在 handler 内被调用时，异常经 handler 走既有隔离路径）；验证路径＝契约兜底承接、取消穿透（J2 定型）。**不要求判定器复刻「记录并继续／结局 Normal」文本性行为**：该行为属执行框架职责；判定器为逻辑单元，其职责是「不吞不包装」（异常保真），隔离由调用侧承担（职责分离；J1 定型正为保真所系）。若调用侧存在可观察的「记录并继续」行为（如经事件框架路径），可在映射中注记，不作为必要条件。

**1(b) 层缺失处置**：① 该层适用语义存在而零证据 → 补测（口径同轮 1）；② 该层确无隔离语义适用面（无需求）→ **豁免论证**（写明「无适用面」依据：该层调用语义为何不涉及隔离）；③ 疑似「应有而无」→ 不符合项／补充观察（按轮 1 的 1(c)③④）。

**1(c) 计入（两层合并）**：调用侧＝J2 的 `InvokeAsync_Judicator_Throws_Is_Treated_As_Contract_Fallback`（不炸穿、按契约承接）＋`…_Cancellation_Pierces`（取消穿透、不吞取消）；机制层＝J1 异常对称（不吞不包装）对应用例——**两层合并构成该边界完整映射**；缺一层按本轮 1(b) 处置。

**2(a) 未注册引用＝全部引用通道并集核对（是）**。逐通道映射行；对**类型上不可能出现「未注册」情形**的通道（如仅接受注册产物句柄的通道），作豁免论证（写明类型论据）。映射行统一标注**层／通道**（机制级 Resolve/Invoke、装配级注册段解析、绑定级 FromRegistration/内置解析等），保证覆盖完整性可复核。

**2(b) 空顶卡＝确认你的倾向（主语义＋三态附带映射要点），并明确一点**：主语义＝「空卡组 false 降级（不抛）」（场 2 Q1a 裁定）；「未加载态明确错误」「读面越界」作为同边界的附带映射要点（三态均须证据；其中「未加载态」为与「空」的**语义区分性证据**）；**「附带」不降低证据要求**——附带要点亦须有断言级证据或豁免论证（口径同轮 1）。

**2(c) 快照一致性＝以 X4 三要素为基准逐要素核对（是）**：语义骨架＝（i）进行中已解析不打断／（ii）被注销项不再选用／（iii）新增项自下一次解析点生效；J1 用例为证据层。若某要素无断言命中：零直接测试 → 补测；断言不直接 → 补强；间接含实质命中 → 豁免论证（口径同轮 1）。

**2(d) 注销后回退＝三级并集核对（是）**：机制级（J1 栈回退——含「逐层回退」断言）＋示范级（J3 两示范回退）＋集成级（J2 验证改写回退）；各层映射行；层适用而无证据者补测、不适用者豁免论证。

**备选方案与拒绝原因**：
- （1a 备选 ii）要求「记录并继续／结局 Normal」的直接映射 → 拒绝：职责错位（执行框架 vs 逻辑单元）；与 J1「不吞不包装」定型矛盾（该定型正为保真）；且判定器多数调用路径的隔离本就由既有事件框架承担，强求复刻将引入双重隔离语义。
- （1b 备选）「不列该层」→ 拒绝：验收记录须证明覆盖完整性——不列层将无法区分「不适用」与「遗漏」，违反可复核性要求。
- （2b 备选）三态完全并列为主语义 → 拒绝：与场 2 Q1a 裁定范围不符（Q1a 只裁「空卡组 false 降级」）；其余态为同边界行为面、非裁定主体，应以附带要点定位。
- （2c 备选）以 J1 用例断言范围为基准（断言到哪核到哪）→ 拒绝：基准倒置（以证据定语义会漏掉未覆盖要素）；X4 三要素为边界语义本体，应逐要素核对、缺者补。

**通用要求（两问合并）**：并集核对下，映射行统一标注「层／通道」；每条边界的层清单必须完整（适用→映射行；不适用→豁免论证），不得留白。

### 轮 3（2026-10-04）：补测/补强落点与编辑域／映射证据候选池

**子的问题（原文摘要）**：
【主问 1】补测/补强的落点形态与编辑范围：(a)「断言不直接→补强断言」的落点取舍：优先修改既有用例的断言，还是新增用例承载（原用例保留）？两路径取舍口径？(b) 编辑域「tests（缺口补测，最小范围）」是否包括修改 J1/J2/J3 本链交付的判定器测试文件（tests/Orc.Tests/Judicator*、tests/Orc.Game.Tests/Judicator* 等）——子理解允许修改，请确认或修正。(c) 补测/补强改动是否需逐条「受控适配清单」式申报（改动点／理由／最小性论证）？
【主问 2】映射证据的候选池范围：(a) 候选池＝仅 J1/J2/J3 判定器相关用例，还是允许纳入全库任意既有测试作为某子项的映射证据（经源码断言核对）？(b) 若某子项证据存在于「非判定器专属的既有测试」（如既有 PlayChain/Command 系列），是否可入映射？⑥ 已明确「既有测试＋回归」口径，其他子项是否同口径？

**答复**：

**1(a) 补强落点＝按缺口形态分档（统一收「仅追加／新增，不重写」）**：
- 执行流已覆盖该语义路径、仅断言未针对 → **在既有用例内追加断言**（首选；不得弱化／删除既有断言）；
- 执行流未覆盖、需专门构造 → **新增专用用例**承载；
- 既有断言**错误或与需求语义不符** → 例外：可修正（替换）该断言并单独申报——「语义正确而断言写错」走修正；「实现不符需求」走不符合项（轮 1 的 1(c)③）；
- 禁止：为省事重构／重写既有用例、变更既有用例的目标语义（非必要大改）。

**1(b) 编辑域确认：是，允许修改 J1/J2/J3 交付的判定器测试文件**（tests/Orc.Tests/Judicator*、tests/Orc.Game.Tests/Judicator* 等）——属本链专有、与 S-C／并行在途零交集，在「tests（缺口补测，最小范围）」授权内。附加约束：
- 修改从「追加／新增」起步（见 1(a)）；替换既有断言限「错误断言」例外并逐条申报；
- **非判定器、非本链的既有测试（如早期／并行链的 PlayChain、Command 系列等）：默认不改**——其断言不足时不在其上修补，改用「判定器侧新增用例」或「对靶外部证据＋豁免论证」（见 2）；确属错误断言 → 逐条申报后方可修正；
- 不做与本单无关的风格／结构改动。

**1(c) 申报要求＝是，逐条台账**。补测／补强全部改动并入核对记录的「缺口处置」部分（即轮 1 已定「逐条写明理由」；建议每条列：缺口描述→处置档〔追加／新增／修正／豁免〕→落点〔文件＋用例名〕→理由＋最小性论证）；「修正既有断言」须单独标志（改动既有交付面、影响最大）。台账供上级抽验「最小范围」约束。

**2(a) 候选池＝「判定器链优先＋对靶外部证据可入」（非仅专项、非任意全库）**：
