## 三、定型申报（集中节；留白点显式定型、不静默）

### 3.1 C5 combat.counter.eligibility（判定器吸收形态）

1. **名称**：`combat.counter.eligibility`（`JudicatorNames.CombatCounterEligibility`；冻结契约）。
2. **类与契约**：`CombatCounterEligibilityJudicator`（internal sealed——由内置注册段/独立构造位创建，不供外部构造）；强类型面 `CounterEligibilityRule`＝（UnitCard attacker, UnitCard target）→bool；统一面载荷＝`[attacker, target]`、输出＝`object[]{bool}`（1 元素）。
3. **语义保持**：原 `CounterAttackRules.CanCounterAttack` 逐字迁移——四条款顺序/短路/豁免优先完全一致；null 语义保持（null 攻击者/目标 → ArgumentNullException——原静态入口语义）。
4. **类型判定**：全部经 `CombatTypeGroups`（IsBomber/IsFighter 复用＋IsArtillery 加性）；原私有 `HasUnitType` 移除（消除散落——Q&A-5.1）。
5. **形态**：**判定器吸收**（Q&A-7 确认）——语义唯一真源＝判定器；`CounterAttackRules.cs` 终态＝纯注释弃用壳（§3.3）。
6. **调用点**：默认互伤区（`CommandManager.HandleDefaultAttackDamageAsync` 经 `_combatCounterEligibility`）＋伏击资格（`AmbushKeywordComponent` 经装载上下文 `CounterEligibility` 通道）——两处共用同一条目（对局路径），无第二真源。
7. **改写**：moding `combat.counter.eligibility`——两调用点每次调用经统一解析点（动态取栈顶）同步生效；无状态、零注入。

### 3.2 C6 combat.ambush.condition（判定器）

1. **名称**：`combat.ambush.condition`（`JudicatorNames.CombatAmbushCondition`；冻结契约）。
2. **类与契约**：`CombatAmbushConditionJudicator`（internal sealed）；强类型面 `AmbushConditionRule`＝（UnitCard self, UnitCard attacker）→bool；载荷＝`[self, attacker]`。
3. **语义保持**：原组件内联比较逐字迁移——被攻击单位攻击有效值 ＞ 攻击者防御有效值（严格大于、相等不命中）；双方有效值经既有修饰链「有效值」读取口（`GetEffectiveValue`——G5 口径，不直读基准值）。
4. **边界（Q&A-6.2 定型）**：仅承载条件比较本身——不含任何前置防护（存活/目标侧归属/攻击者单位化/已改写跳过保留组件侧）。
5. **调用点**：`AmbushKeywordComponent` 经装载上下文 `AmbushCondition` 通道；改写＝moding（多次调用动态生效）；无状态、零注入。

### 3.3 CounterAttackRules.cs 终态（弃用壳——Q&A-7 确认）

- **形态**：纯注释壳（无功能成员、无命名空间声明、无类型定义）——「留空并说明」。
- **注释内容**（至少含）：迁移去向（判定器承载）／迁移来源（K2 收编·原 CanCounterAttack 逐字迁移）／退役状态（零引用、无第二真源）；另含保留原因（不删除文件硬约束；不引入 [Obsolete] 避免编译警告）。
- **私有 HasUnitType**：**已移除**（收敛至 CombatTypeGroups 共表——落实 Q&A-5.1「消除散落」）。
- **引用处置**：零引用（全局引用核查见 §七）——不保留任何占位成员（无「可用第二路径」问题）。

### 3.4 装配与调用通道（定型）

1. **注册落点**：`Match.Initialize` 内置注册段（K1 段末尾）追加 2 条固定注册（K2 加性注释）；「默认名恒可解析、默认判定器无条件可用」。
2. **CommandManager 通道**：构造参数 `combatCounterEligibility`／`combatAmbushCondition`（`Func<UnitCard, UnitCard, bool>?`）——对局路径＝Match 注入的条目调用闭包（捕获条目句柄；每次调用经统一解析点）；缺省＝null＝独立构造路径（内置默认，构造即可用；实例主方法调用——不内联）。
3. **KeywordLoadContext 通道**（K2 加性）：`CounterEligibility`／`AmbushCondition`（可空——缺省＝null）；对局路径＝CommandManager 创建时传入其两通道（`_combatCounterEligibility`/`_combatAmbushCondition`——对局/独立构造下恒非空）；装配知识集中（不为避开该文件设计迂回——Q&A-2.1）。
4. **时序**：通道初始化先于 KeywordLoadContext 创建（构造体内顺序保证）；无缓存引入——伏击组件持有通道引用、每次判定动态调用（moding 即时生效）。
5. **独立构造路径**：`CreateBuiltInCombatCounterEligibility`／`CreateBuiltInCombatAmbushCondition` 创建内置默认实例（经实例主方法调用——与对局路径「经条目句柄」形态同构）。

### 3.5 伏击组件接入口径（Q&A-6.1 确认落实）

- **只换判定源、骨架零变化**：资格判定→C5 通道、条件判定→C6 通道；既有防护（存活/目标侧归属/攻击者单位化/「已改写跳过」）与判定顺序（先资格、后条件、无资格短路）保持零变化。
- **降级（Q&A-2.2/8 主口径）**：无装载上下文或判定器通道缺失＝**静默不可用**（不注册、不抛错、不回退直调）；实现于 `Mount`（两处 return）；判定侧另设双保险（通道局部引用为空＝跳过，不回退直调）。
- **Unmount**：通道引用清位（与注册状态一致；重复卸载幂等）。

- 新增独立测试文件 `tests/Orc.Game.Tests/JudicatorCombatCounterAmbushTests.cs`（8 用例）；既有套件零修改全绿＝基线证据。
- 受控适配例外：`GameHooksTests`（清单计数联动）＋`CardServiceTests`（形态联动·两处断言迁移）。
- 多类型单位边界：复用 `CardServiceTests.Scenario7` 联动断言陈述（迁移后仍验证「类型增补前/后反击资格值」——经条目读值、强度不弱化），不重复造。

### 3.7 核心演示语义记录（供跨单一致）

- **C5 改写（无条件反击）**：`combat.counter.eligibility` → 恒真。
  - 调用点一（默认互伤区）：炮兵攻击（原豁免②）——改写后受反击致死（2-2=0）；目标照常受伤（5-2=3）。
  - 调用点二（伏击资格）：炮兵攻击伏击目标——原无资格（改写被豁免约束拦截）→ 改写后资格放行 → 条件命中（5＞2）→ 改写成立（炮兵死亡、伏击者不受伤）。
  - 注销回退：默认互伤区豁免恢复（炮兵不受反击）。
- **C6 改写（恒假）**：`combat.ambush.condition` → 恒假。
  - 默认：条件命中（5＞2）→ 改写成立（攻击者死亡、伏击者不受伤）。
  - 改写后：不命中 → 正常互伤（伏击者 6-1=5、攻击者受反击致死）。
  - 注销回退：条目级恢复命中＋流程级恢复改写成立。
