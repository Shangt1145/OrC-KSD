## 〇、核验差异（与缺口报告 v2 表述逐条对照）

- D1「合法词条仍仅 4 枚：闪击/奋战/烟幕/伏击；不支持带数值词条」（原引用 KeywordSystem.cs:20-38）——**一致**：`KeywordIds` 现行号仍为 20-38（`All` 共 4 项：23/26/29/32/35）；定义期未知标识 fail-fast（CardDefinition.cs:108-112）；带数值词条全链路无参值通道（§1.5）。
- D2「词条不可运行时授予新能力（仅登记/查询）」（原引用 DataComponents.cs）——**成立，建议拆两级限定**：
  - 登记面（数据）可运行时增删：`KeywordData.Add/Remove/Contains` 均为 public（DataComponents.cs:103/117/124），且 `Add` **不校验**已实现标识（任意非空白字符串）；

- D3「效果已可运行时 AddEffect/RemoveEffect 并即时装载」（报告 G1 现状）——**机制成立，需三点限定**：① src 内调用点仅装载期（EffectSystem.cs:197）与死亡清理（CommandManager.cs:994），无效果级封装；② 「即时装载」以 `IsPlaced` 为前提（src/Orc/Cards/Card.cs:119），而 `card.placed` 在 src 内**无发射点**（仅测试发射：tests/Orc.Tests/CardsTestFixtures.cs:169-171）；③ 托管清理（修饰器/光环按来源撤销）仅装载链登记（EffectSystem.cs:215），复装不重建（§2.4）。
- D4「无阵营维度/无主国概念」——**一致**：全 src「轴心|同盟|Axis|Allies」0 命中；「阵营」字样仅注释泛指国籍归属（TagData.cs:4/38/41）；「主国」全 src 仅 1 处注释（TagData.cs:6）。
- D5（补充核验）「无'亡计'能力形态/无'触发某卡的部署/亡计'再触发原语」——**一致**（全 src「亡计」「再触发|触发所有|TriggerAll」0 命中）；补充具体瓶颈：死亡清理**先于** `card.died` 发射（CommandManager.cs:985-998），本卡自身效果无法观察自身死亡（§2.6）。
- D6（补充核验）上批披露「效果托管登记的复装路径」——现状复核见 §2.4：内核支持复装（Effect.cs:15；CardContainerTests.cs:115-116）；缺口＝①托管清理不复装、②即时装载驱动（card.placed）缺失。

## 一、词条系统：定义期 → 加载登记 → 查询全链路（G2）

### 1.1 定义期（静态声明、fail-fast）
- 定义字段：`CardDefinition` 构造参数 `IEnumerable<string>? keywords`（CardDefinition.cs:41；签名区 34-46）；赋值 `Keywords = ResolveKeywords(keywords)`（84）。
- 校验 `ResolveKeywords`（CardDefinition.cs:93-127）：null 元素/空白 → 拒绝；未实现标识 → 拒绝（108-112，错误信息含 `KeywordIds.All` 全清单）；重复项 → 拒绝；登记序保留。
- 合法标识集 `KeywordIds`（KeywordSystem.cs:20-38）：闪击（23）/奋战（26）/烟幕（29）/伏击（32）；`All`（35）；`IsDefined`（38）。
- 约束：定义＝单一真源、不可运行时增删（CardDefinition.cs:9/13 注释）。

### 1.2 加载登记与装载（每卡恰一次、先于 card.load）
- 模板链：`CardBase.LoadAsync`（CardBase.cs:106）＝【重建 → ID 分配（123）→ 元数据装配（136）→ **词条装载（154）** → 效果装载（197）→ 广播 card.load】。
- `LoadKeywords`（CardBase.cs:154-195）三件事：①逐条 `keywordData.Add(keyword)`（165）＋`AddData(keywordData)`（168）；②`AddData(new KeywordRuntimeData())`（169）；③上下文 `KeywordLoadContextProvider?.Invoke()`（171）→`KeywordLogicFactory.Create`（175）→`logic.Mount(this, context)`（181）→`AddData(logics)`（187）。无词条卡＝零副作用早退（156-160）。
- 上下文注入链：`CardLibrary` 收提供器（CardLibrary.cs:39/46）→实例化时注入每卡（106）→`Match` 装配传入（Match.cs:282-289）；`KeywordLoadContext`＝Engine＋「造成攻击伤害」触发器（KeywordSystem.cs:46-59；触发器创建于 CommandManager.cs:124-130）。

### 1.3 词条数据面三口
- `KeywordData`（DataComponents.cs:94-127）：`Keywords` 只读（99）/`Add`（103，幂等）/`Remove`（117）/`Contains`（124）。**登记与查询两面、无行为**。
- `KeywordLogicData`（KeywordSystem.cs:204-222）：`Logics`（209）/`Add`（212，**internal**）/`UnmountAll`（215，后进先出、幂等）。唯一卸载入口＝死亡清理（CommandManager.cs:985）；**无个体卸载、无装载后追加**。
- `KeywordRuntimeData`（KeywordSystem.cs:229-242）：自由 `Dictionary<string,int>` 计数器——`GetCounter`（234）/`SetCounter`（237）/`IncrementCounter`（240）；现用键 `fury.attacks`（251）。
- 边界注释：「词条数值（如「重甲 2」）由效果模块维护、不落本组件」（DataComponents.cs:90）。

### 1.4 四枚词条的读取/消费点清单
- 闪击：`BlitzKeywordLogic.OnDeployChainFinalizedAsync`（KeywordSystem.cs:96-110）←部署链收尾循环逐个逻辑调用（UnitCard.cs:92-97，调用点 96）；仅部署路径（加入链不置位）。
- 奋战：记账 `RecordAttack`（KeywordSystem.cs:260）←攻击执行段（CommandManager.cs:911）；收尾 `ResolveCanAttackAfterAttack`（277）←（838）；回合恢复 `ResetTurnCounters`（289）←（653）。
- 烟幕：攻击目标合法性筛除（CommandManager.cs:434）。
- 伏击：`AmbushKeywordLogic`（KeywordSystem.cs:121-200）——装载注册「伏击改写」（140）→死亡注销（144）→改写判定 `HandleAttackDamageAsync`（157-200，读修饰有效值）。
- 统一查询口 `KeywordRules.HasKeyword`（254）——动态、无组件=false。

### 1.5 不支持「带数值词条」的具体现状
- 装配面：定义仅收字符串（CardDefinition.cs:41/206）；校验仅存在性（108-112）；工厂 `KeywordLogicFactory.Create(string)` 无参值入参（KeywordSystem.cs:299-307，switch 仅 Blitz/Ambush）。
- 数据面：`KeywordData` 只存标识（94-127）；无「声明-数值」配对结构；`KeywordRuntimeData` 计数器与词条声明无绑定（229-242）。
- 全链路（定义→装载→查询）均无参值通道；「重甲/情报（带数值）」等概念全仓 0 命中。

### 1.6 「状态集合」现状
- 现有全部非词条运行态载体：`UnitStateData.IsDestroyed`（DataComponents.cs:31）、`CommandData.CanMove/CanAttack`（82/85）、计数器、`CounterActivationData.IsActive`（136）。
- 「压制/抑制/动员/钳击/预报/隐蔽/明牌」等状态/词条概念全 src 0 命中；无通用「状态」容器（键值/集合型状态面）。

## 二、能力的运行时授予与移除（G1）

### 2.1 效果系统链路总览（装配＝代码注册）
- 注册表 `CardEffectRegistry`（EffectSystem.cs:32）：`Register`（41）/`Declare`（60）/`GetDeclarations`（89）/`Resolve`（93）——**src 内无调用点**（装配侧在测试/外部）。
- 装载上下文 `CardEffectLoadContext`（104-122）：`Declarations`（117）/`ResolveFactory`（120）；经 `Match` 传入（Match.cs:282-289，`new CardEffectLoadContext(_effectRegistry, cardId)` 288）。
- 装载链 `CardEffectLoader.LoadAsync`（138-226）：①声明解析 fail-fast（156）→②构造（执行异常＝隔离跳过；工厂 null＝上抛）→③`card.AddEffect(effect)`（197）→④`card.MountPassiveEffects()`（202）→⑤托管登记 `effect.AddUnmountCleanup(...)`（215）＋失败残留清理（275-321）。
- 托管清理实体 `RunManagedCleanup`（234-273）：光环按来源注销（244）→`Modifiers.RemoveBySourceAsync(effect)`（254）→受益侧重跑（265）。
- 施放面（背景）：`ActiveEffect.CastAsync`（Effect.cs:302-326）；指令流程 band（OrderFlow.cs:11-23/68-111）。

### 2.2 容器面：AddEffect / RemoveEffect（内核）与装载/卸载链
- `Card.AddEffect`（src/Orc/Cards/Card.cs:100-125）：拒绝重复实例/跨卡归属；`IsPlaced && Kind==Passive` → 即时 `CardLoadout.MountEffect`（119）。
- `Card.RemoveEffect`（131-135）→`CardLoadout.CleanupEffect`（CardLifecycle.cs:105-160）——收敛模板：容器移除；已装载→OnUnmount→撤登记→总线卸载→清宿主；未装载→仅容器移除；幂等。
- `Card.MountPassiveEffects`（143-152）：按 Effects 列表序装载（幂等）。
- `CardLoadout.MountEffect`（CardLifecycle.cs:66-99）：挂主触发器→OnMount；失败回滚＋记录。
- `Effect` 模板（Effect.cs）：`ExecuteMount`（121）/`RollbackMount`（137）/`ExecuteUnmount`（149：OnUnmount→RollbackInjections→UnmountMainTrigger→RunUnmountCleanups→清 host）；`AddUnmountCleanup`（102）；`RunUnmountCleanups`（190-213）。
- 幂等/复装语义（骨架注释）：未装载不重复清理、已装载不重复 OnMount；「同一效果实例可多次成对装载/卸载（移除后重新 Add 复装）」（Effect.cs:15）。

### 2.3 运行时调用点现状（src 全量枚举）
- `AddEffect(`：**仅 EffectSystem.cs:197**（装载期）；`RemoveEffect(`：**仅 CommandManager.cs:994**（死亡清理）。
- 即：机制在内核齐备；**游戏层无「给卡授予/移除能力」的效果级 API，也无运行时使用先例（src）**。测试先例：EffectSystemTests.cs:79/102/135、Scenario2Tests.cs:23/84、CardContainerTests.cs:97-116。
- （D14 关联项）`engine.Cards` 含 HQ 登记：Card 构造即 `engine.RegisterCard(this)`（Card.cs:28；LogicEngine.cs:66/69/72），`Hq : Card`（Hq.cs:29）——HQ 亦在引擎卡牌登记面内；处置随 G2/G10 评估。

### 2.4 复装（移除后重新装载）：支持程度与缺口
- 支持（内核语义）：Effect.cs:15；容器测试「先移除再添加＝允许（复装）」CardContainerTests.cs:115-116；作者注入经 OnMount 重放（每次装载重建）。
- **缺口 1（托管面不复装——上批披露点）**：托管清理登记**仅发生**在装载链 ⑤（EffectSystem.cs:215）；卸载时 `RunUnmountCleanups` 执行后**清空**（Effect.cs:190-213）——复装（再 `AddEffect`）不再登记托管清理 ⇒ **二次卸载不再自动撤销该效果施加的修饰器/光环声明**（须另行按来源撤销）。
- **缺口 2（即时装载驱动缺失）**：`Card.AddEffect` 即时装载分支要求 `IsPlaced`（Card.cs:119）；`IsPlaced` 仅由 `card.placed` 处理器置位（CardLifecycle.cs:195-204、MarkPlaced Card.cs:157），而 **src 内无 `card.placed` 发射点**（常量 Updates.cs:10-11、hook CardLifecycle.cs:179；测试夹具发射 CardsTestFixtures.cs:169-171）⇒ 对局流程中复装的被动效果「等待放置驱动」，而该驱动不存在；唯一实际装载驱动＝装载期（197/202）。
- **缺口 3（相关）**：`effect.removed` 更新同样**无发射点**（Updates.cs:19-20；hooks CardLifecycle.cs:188、Effect.cs:242）——「更新驱动的清理路径」休眠；清理唯一实际入口＝`RemoveEffect` 容器 API。
- 上批披露出处：表达力缺口补全记录.md:73（「实现边界（已披露）：效果托管登记的复装路径」）；需求文档.md:71（D14①「复装随 G1」）。

### 2.5 「授予某卡词条/嵌套能力」：无效果级 API（边界拆分）
- 无调用 `KeywordData.Add/Remove` 的效果/流程（src）；无词条逻辑运行时装载入口（§1.3）。
- 反向不一致（隐患）：从 `KeywordData` 移除字符串**不会**卸载已在位的主动词条逻辑（伏击改写仍注册至死亡清理）——`KeywordLogicData` 无个体卸载路径（212/215）。
- 「嵌套能力」（「获得：'亡计：…'」式子能力文本）无承载：效果须按 id 经注册工厂构造（EffectSystem.cs:41/60/156）；无「按文本/组合动态构造效果」链路；无子能力挂载概念。

### 2.6 死亡链与「亡计」；「再触发」原语
- 触发点（三处，均收敛到统一流程）：①战斗结算死亡判定——`HandleDefaultAttackDamageAsync`（CommandManager.cs:916-965；伏击改写分支与常规判定均在内）；②防御归零统一衔接——`HandleDefenseDepletionAsync`（1009-1023，经 `card.stat.changed` 总线触发器，注册于 146-156）；③HQ 侧＝独立归零响应（158-166 + Hq 侧 RespondToZero；HQ **不入**死亡/销毁链，Hq.cs:8-13）。
- 统一流程 `ProcessDeathAsync`（977-1001）顺序：槽位 Clear → `IsDestroyed=true` → 词条逻辑 `UnmountAll`（985）→ 修饰器 `ClearAllForDeathAsync` → 逐效果 `RemoveEffect`（992-996，调用 994）→ `Position=null` → `EmitCardDied`（998）。
- 关键事实：**「亡计」形态不存在**（0 命中）；且清理**先于**信号——本卡自身效果（及其注册）在 `card.died` 前全部卸载，**本卡无法观察自身死亡**；第三方观察者可（守护维护订阅 133-141；环境重跑 GameEnvironment.cs:214/279-280）。死亡信号面：`card.died`（GameUpdates.cs:78；发射助手 247）；引擎 `card.destroyed`（LogicEngine.cs:170/180）在 src 游戏层**无调用点**。
- 「触发某卡的部署/亡计」再触发原语：**不存在**（「再触发|触发所有|TriggerAll」0 命中）。部署链现状：`HandlePlayChainAsync`（UnitCard.cs:70-100，card.played 79）→`DeployTrigger`（公开 59；**唯一调用点 82**）→`HandleDeployChainAsync`（102-155：DeploymentLogicData 条目→单位化→`unit.deployed` 153）；重复部署被守卫拦截（Unitize 180-186；PlayManager 146-167/194-218）。**无面向效果的「重放部署/重放亡计」入口**；也无「非指向部署」等分类概念（0 命中）。
- 半成品挂点：`DeploymentLogicData`（部署逻辑条目）——消费已接线（UnitCard.cs:102-149）、**src 无登记/生成点**（注释自述「本批仅消费」DeploymentLogicData.cs:30；测试装配 PlayChainDeploymentTests.cs:28/72/94/123）。
