## Implementation Steps

### S1: G12 卡牌元数据维度
- Status: Design Settled（设计已定；查询接入与验收转实现轮细化）
- Target: `src/Orc.Game/Cards/`（CardDefinition、新增 TagData 组件）＋相关读取/筛选位置
- Approach: TagData 组件＝必填强类型槽位（国籍、稀有度）＋开放 tag 字典（子类别：海军/T-34/谢尔曼等）；定义期声明（fail-fast）→加载时装配；泛型约束槽位形态（`TagSlot<TTag> where ...`）；开放 tag 支持运行时增删；构筑外＝对局级 ID 水位线（卡牌加载时分配整数 ID；ID＞初始化末位 ID；现行局已具备开局全量加载）。
- Acceptance: 待细化（实现轮：代表效果表达力验证——含组合筛选"日本精英空军"等；不含老兵）。
- Rationale: 独立性最高、无前置依赖，作为首场。

### S2: G14 历史计数与比较
- Status: Design Settled（设计已定；实现轮细化）
- Target: 效果监听 handler 载体（逻辑组件内部数据）＋监听源（含洗切信号最小补）；不建通用计分板
- Approach: "自写监听 handler"模式——效果自写有状态 handler 注册到触发器、自行监听、条件达成触发主动触发器；状态＝私有闭环、存**逻辑组件内部数据**；监听源：现成（使用/回合/死亡/位置）＋本批补洗切信号＋弃牌清单＋HQ 伤害挂 G11。支撑：X1、X2。
- Acceptance: 四场景（①使用计数 ②累计伤害阈值触发 ③首次洗切+洗切信号 ④即时比较），以测试场景落地（机制级）。
- Rationale: 独立性高；模式统一为后续效果型缺口（G3/G4）奠基。

### S3: G9 延迟调度与回合相位效果
- Status: Design Settled（设计已定；实现轮细化）
- Target: 效果订阅面（turn.* 相位）＋逻辑组件内部待办；不建调度器
- Approach: 订阅自管（与 G14 模式同构）：效果订阅 turn.* 相位事件、逻辑组件内部维护待办、到点执行并自清理；锚点约定——"回合开始时"→`turn.start.after`、"回合结束时"→`turn.end`；G3 期限复用本相位面；指挥点结算修正见 X3。
- Acceptance: 四场景（①延迟资源 ②延迟动作 ③结束响应 ④资源语义修正验证），测试内构造。
- Rationale: 独立机制件；G3 期限可能关联（宜先于修饰层就位）。

### S4: G11 HQ 实体化
- Status: Design Settled（设计已定；实现轮细化）
- Target: 新增 HQ 实体（Entity＋组件容器＋词条/效果装载面，不入死亡/销毁链）＋`Player`/目标系统/装配链接改〔G14 联动：HQ 伤害挂点〕
- Approach: 已定型——独立 HQ 实体（取代槽中 Player 引用；Player 持 HQ 引用）；"防御力"＝血量域（HqHealth 迁至 HQ 组件）；数值改变＝"通用数据改变更新"（与单位同机制；`card.stat.changed` 线，载荷待升级）；"通用数据改变"＝可挂载管线（"受伤 -1"/"致命前 +6 防"在其上挂；不建专用 HQ 流程）。
- Acceptance: 四场景（①实体装载+终局迁移回归 ②数值+监听 ③管线改写 ④管线介入），测试内构造。
- Rationale: 是 G3/G4 作用于 HQ 的前提（挂点）；结构件，先于修饰层。

### S5: G3 属性修饰
- Status: Design Settled（设计已定；实现轮细化）
- Target: 卡侧"修饰器组件"（所有卡牌；含 HQ）＋有效值读取链（UnitStateData 及读写路径接改）
- Approach: 方案 A（已裁决）——修饰器＝接口/基类＋抽象挂载（子类自写注销，自托管）；链式调用＋缓存，链＝**全量重跑**（基准→链→有效值，确定变换）；修饰器类型＝**基类＋模板子类＋使用处直接 new（注入回调与具体数值）**；变更检测＝**更新检测接口（生成/比较缓存；卡端持有检测组件名单＋各组件缓存）**；每轮＝链式调用→重新获取缓存→比较→有变更则更新缓存＋最后集中触发更新；按 P1/P2 原则。管线（已确认）：三段合一＝通用数据改变管线；集中触发＝升级版 `card.stat.changed`（载荷化）；读取口＝缓存有效值。门户＝花费组件＋单位组件（效果只经门户变更）；单位防御力上限（加防同步加上限；扣减不减；修复＝恢复上限，衔接 G17）。待细化：验收场景。
- Acceptance: 四场景（①加值/叠加/撤销 ②期限两型 ③设值型 ④上限语义），测试内构造。
- Rationale: 修饰层主体；依赖 S3/S4 就位。

### S6: G4 持续/条件静态能力
- Status: Design Settled（设计已定；实现轮细化）
- Target: 链上"条件节/光环节"＋光环注册面（注册/注销由效果装载链托管）
- Approach: 影响传递＝受益侧收集重算（a）；光环贡献＝重跑时现收集（场级收集面读取过滤，零增删）；条件/光环＝链上贡献节（固定值/条件评估/光环收集）；读取面 a1＝现算查询面；传播＝全域重跑（b1）；条件失效自然产出原值；注册/注销由效果装载链托管。
- Acceptance: 四场景（①相邻光环随动 ②自条件 ③源条件全体 ④计数型），测试内构造。
- Rationale: 与 G3 同域（持续重算面），紧随 G3。

### S7: G5 费用修饰与有效费用查询
- Status: Design Settled（设计已定；实现轮细化）
- Target: 花费组件/单位组件的费用字段（链输出）＋部署费/行动费读取 13 处接改
- Approach: 复用修饰器链（a）——费用字段作为链输出之一；"有效费用"＝链缓存有效值；读取 13 处（校验/扣费/复验）统一接改；按费用筛选＝消费同一读取口；修饰类型＝G3（加法/设值）＋钳制型（min/max；成组注册/注销——组语义）。
- Acceptance: 四场景（①加法 ②设值 ③钳制+组 ④按费用筛选），测试内构造。
- Rationale: 可复用修饰层思想；读取点相对独立，收尾。

## 实现原则（用户裁定）
- **P1：卡牌不允许无条件的数据更新**——更新必须由条件/变化驱动（防无限循环；"改变才传播"、变更收敛）。
- **P2：逻辑引擎的更新不允许异步进行**——更新链路保持同步/顺序语义（防竞态）。

## Cross-Cutting Improvements

### X1: 底层触发器携带"触发者卡牌"
- Status: 方向已定（用户）；待细化
- Target: 卡牌效果可能调用的底层触发器及其视图（现有 4 个内置流程触发器：Command / UnitMove / UnitAttack / AttackDamage；及未来同类）
- Approach: 在触发器上下文/视图增加"触发者卡牌"承载（引发该操作的卡牌）。现状核验：4 个视图仅有操作角色字段（Attacker/Target/Unit…），无触发者字段——本改造为新增承载。用途：监听 handler 归属判断、效果链溯源（为效果系统接线做准备）。
- 待细化：① 语义口径（主动指挥 vs 效果引发时的填充规则）；② 涉及视图/调用点清单与引擎侧对齐（实现轮整理）。
- Rationale: 监听模式（G14）与效果系统接线需要操作溯源。

### X2: 效果系统接线
- Status: 拟记（本批支撑范围；待最终确认）
- Target: 游戏层效果装载/执行链（把引擎 Effect 机制接入卡牌加载与运行）
- Approach: 卡牌加载时装载效果（含监听 handler 注册）；效果调用底层触发器（配合 X1）；条件达成触发主动触发器。
- Rationale: G14（及后续 G3/G4 等效果型缺口）落地的共同前提。

### X3: 回合体系修正——指挥点结算模型（用户裁定）
- Status: 已定（实现轮落实）
- Target: `TurnManager` 结束/开始序列、`ResourceManager` 结算
- 内容：移除"回合结束时清零点数"；点数在回合结束时刻与敌方回合内保留（不清零）；保留"回合开始前槽数+1"与"回合开始时点数＝槽数"两步（设为而非累积）。
- 影响：现有"结束清零"相关测试断言需同步调整（实现轮）；"回合结束时"及敌方回合内的效果可读到残留点数。
