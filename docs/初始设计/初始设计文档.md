# 卡牌游戏触发器引擎架构文档

> 目标语言：C# (.NET 8+)
> 状态：设计稿 v1.0
> 范围：触发器系统（Trigger System）——被动/主动触发器、优先级、上下文、生命周期、日志、异步、中断

---

## 一、设计目标

1. **统一抽象**：被动触发（事件驱动）与主动触发（引用调用）共用同一套包装器、优先级、日志、异步、中断机制。
2. **声明式上下文**：每个触发器显式声明它读什么、写什么、可缺省什么，杜绝"整个引擎当上下文"的失控。
3. **安全引用**：可被删除的实体使用生命周期令牌，下游逻辑在对象失效时自动跳过而非崩溃。
4. **可扩展优先级**：双层（Band × Inner）优先级，允许新效果插入而不重排旧值。
5. **异步与超时**：原生 `async/await`，支持超时与取消，异常隔离。
6. **可观测**：全链路 `ChainId` + `Depth` + `Band` 日志，能一眼看出因果。

**非目标**：不负责游戏规则本身（伤害、费用、胜负判定在引擎之外）；不负责网络同步；不负责 UI。

---

## 二、术语与核心概念

| 术语 | 含义 |
|---|---|
| **Event** | 引擎在结算流水线上暴露的更新点，如 `BeforeDamage` |
| **Trigger** | 包装器，同时承载被动与主动两种触发器的执行 |
| **TriggerBus** | 事件槽位容器，被动触发器在此挂载 |
| **Context** | 一次结算的完整上下文，贯穿整条因果链 |
| **ContextView** | 触发器执行时看到的受限视图，按声明裁剪 |
| **Ref / Lifetime** | 安全引用与生命周期令牌 |
| **Band** | 双层优先级的外层，语义化的相位 |
| **Inner** | 双层优先级的内层，同 Band 内的微调 |
| **ChainId** | 一次因果链的全局标识 |
| **Interrupt** | 取消当前引擎动作 |
| **Stop** | 中止本事件后续触发器 |

## 四、模块设计

### 4.1 Lifetime 与 Ref —— 生命周期令牌

**目的**：让"对象已删除"可检测，下游触发器在跑之前就能跳过。

```csharp
public sealed class Lifetime
{
    private int _alive = 1;
    public bool IsAlive => Volatile.Read(ref _alive) == 1;
    public void Kill() => Interlocked.Exchange(ref _alive, 0);
}

public sealed class Ref<T> where T : class
{
    private readonly T _target;
    private readonly Lifetime _life;
    public string Name { get; }

    internal Ref(T target, Lifetime life, string name)
    { _target = target; _life = life; Name = name; }

    public bool IsAlive => _life.IsAlive;

    public T Value => _life.IsAlive
        ? _target
        : throw new StaleReferenceException($"Ref<{typeof(T).Name}> '{Name}' 已失效");
}

public class Entity
{
    public string Name { get; }
    public Lifetime Life { get; } = new();
    public Ref<Entity> Ref { get; private set; }

    public Entity(string name)
    {
        Name = name;
        Ref = new Ref<Entity>(this, Life, name);
    }

    public void Destroy() => Life.Kill();   // 引擎随后通知 bus.UnmountOwner(this)
}

public sealed class StaleReferenceException : Exception { ... }
```

**要点**

- `Lifetime` 用 `Interlocked` 保证多线程（若未来引入）安全。
- `Ref<T>.Value` 访问时二次校验，兜底第一道防线（Preflight）之外的漏网。
- `Entity` 是基类；卡牌、随从、玩家都继承。

### 4.2 Context —— 执行上下文

**目的**：一次结算的完整数据载体，贯穿父子链。

```csharp
public sealed class Context
{
    public string Event { get; }
    public object? Source { get; }
    public Context? Parent { get; }
    public string ChainId { get; }
    public int Depth { get; }

    internal Dictionary<string, object?> Data { get; }

    public bool Stopped { get; private set; }
    public bool Interrupted { get; private set; }
    public string? Reason { get; private set; }
    public List<(string Trigger, object? Result)> Results { get; } = new();

    public Context(
        string @event,
        object? source = null,
        IDictionary<string, object?>? data = null,
        Context? parent = null)
    {
        Event = @event;
        Source = source;
        Parent = parent;
        ChainId = parent?.ChainId ?? Guid.NewGuid().ToString("N")[..8];
        Depth = (parent?.Depth ?? -1) + 1;
        Data = data is null ? new() : new(data);
    }

    public void Stop(string reason = "") { Stopped = true; Reason = reason; }
    public void Interrupt(string reason = "")
    {
        Stopped = true;
        Interrupted = true;
        Reason = reason;
    }
}
```

**要点**

- `ChainId` 用于串联整条因果链，子 Context 继承父的。
- `Depth` 用于日志缩进。
- `Data` 是唯一的载荷载体；触发器通过 `ContextView` 访问它。

### 4.3 ContextView —— 声明式受限视图

**目的**：让每个触发器只能看到自己声明的字段，只能改声明为可变的字段。

C# 强类型，推荐 **Source Generator 编译期生成**。设计上分两层：

#### 4.3.1 声明特性

```csharp
[AttributeUsage(AttributeTargets.Class)]
public sealed class ContextViewAttribute : Attribute
{
    public Type EventType { get; }
    public ContextViewAttribute(Type eventType) => EventType = eventType;
}

[AttributeUsage(AttributeTargets.Property)]
public sealed class ReadAttribute : Attribute { }

[AttributeUsage(AttributeTargets.Property)]
public sealed class MutateAttribute : Attribute { }

[AttributeUsage(AttributeTargets.Property)]
public sealed class OptionalAttribute : Attribute { }
```

#### 4.3.2 声明式视图（由卡牌作者书写）

```csharp
[ContextView(typeof(BeforeDamageEvent))]
public partial class ShieldView : IContextView
{
    [Read]     public Ref<Entity> Target { get; }
    [Read]     public Ref<Entity> Source { get; }
    [Mutate]   public int Amount { get; set; }
}
```

#### 4.3.3 Source Generator 生成（节选示意）

```csharp
// 由 Source Generator 生成的实现
partial class ShieldView
{
    private Dictionary<string, object?> _data = null!;
    private Context _ctx = null!;

    public void Bind(Dictionary<string, object?> data, Context ctx)
    {
        _data = data; _ctx = ctx;
        EnsureRequired("Target"); EnsureRequired("Source"); EnsureRequired("Amount");
    }

    public Ref<Entity> Target
    {
        get
        {
            var v = (Ref<Entity>)_data["Target"]!;
            if (!v.IsAlive) throw new StaleReferenceException("Target");
            return v;
        }
    }

    public int Amount
    {
        get => (int)_data["Amount"]!;
        set => _data["Amount"] = value;
    }
}
```

#### 4.3.4 运行时绑定器（备用反射方案）

若首版不引入 Source Generator，可用反射在首次构造时缓存 setter/getter：

```csharp
public interface IContextView
{
    void Bind(Dictionary<string, object?> data, Context ctx);
    void Seal();
}

public static class ContextViewBinder
{
    private static readonly ConcurrentDictionary<Type, ViewMeta> _cache = new();

    public static IContextView Create(Type viewType, Dictionary<string, object?> data, Context ctx)
    {
        var meta = _cache.GetOrAdd(viewType, ViewMeta.Build);
        var instance = (IContextView)Activator.CreateInstance(viewType)!;
        // 反射填充：检查 required 字段、构造属性代理
        // 首次构建慢，之后走缓存
        meta.Bind(instance, data, ctx);
        return instance;
    }
}
```

**推荐**：MVP 阶段用反射缓存；数据量大、性能敏感时切换 Source Generator，接口不变。

**语义总结**

| 声明 | 读 | 写 |
|---|---|---|
| `[Read]` | ✅ | ❌ 抛 `PermissionDeniedException` |
| `[Mutate]` | ✅ | ✅ |
| `[Optional]` + `[Read/Mutate]` | ✅（缺失返回 default） | 视主特性 |
| 未声明 | ❌ 抛 `PermissionDeniedException` | ❌ |

### 4.4 Band 与 Inner —— 双层优先级

#### 4.4.1 常量与排序键

```csharp
public static class PriorityBands
{
    public const int Stride = 1000;

    // 每个事件一套独立 band 命名空间
    public static class Damage
    {
        public const int Prevent  = 100;
        public const int Replace  = 200;
        public const int Reduce   = 300;
        public const int Amplify  = 400;
        public const int Finalize = 500;
    }

    public static class PlayCard
    {
        public const int Counter    = 100;
        public const int Retarget   = 200;
        public const int Tax        = 300;
        public const int PreEffect  = 400;
    }
}

public readonly record struct SortKey(int Band, int Inner) : IComparable<SortKey>
{
    public int CompareTo(SortKey other)
    {
        int c = Band.CompareTo(other.Band);
        return c != 0 ? c : Inner.CompareTo(other.Inner);
    }

    // 可选：序列化用
    public long Pack() => (long)Band * PriorityBands.Stride + Inner;
}
```

**要点**

- 用 `record struct` + `IComparable` 做排序键，语义清晰且零分配。
- `Pack()` 仅在需要持久化排序顺序时使用；**Pack 要求 Inner ∈ [0, Stride)**。
- **不要用乘法**——用元组比较或定点打包，两者等价但前者更安全。

#### 4.4.2 同 Band 同 Inner 的兜底

**稳定排序 + 注册序号**：

```csharp
public sealed class Trigger
{
    internal long RegistrationSeq { get; set; }   // 由 Bus 分配

    public SortKey SortKey { get; }
    public long TieBreaker => RegistrationSeq;
}
```

比较时：

```csharp
int c = a.SortKey.CompareTo(b.SortKey);
if (c != 0) return c;
return a.TieBreaker.CompareTo(b.TieBreaker);
```

→ 退化为"卡牌入场顺序"，本身具备语义。

### 4.5 Trigger —— 统一包装器

```csharp
public delegate Task TriggerHandler<in TView>(TView view, CancellationToken ct)
    where TView : IContextView;

public sealed class Trigger
{
    public string Name { get; }
    public SortKey SortKey { get; }
    public object? Owner { get; }
    public bool Once { get; }
    public TimeSpan? Timeout { get; }

    public IReadOnlySet<string> Reads { get; }
    public IReadOnlySet<string> Mutates { get; }
    public IReadOnlySet<string> Optionals { get; }

    public long RegistrationSeq { get; internal set; }
    public bool Fired { get; private set; }

    private readonly Func<IContextView, Context, CancellationToken, Task> _invoker;

    internal Trigger(
        string name, SortKey sortKey,
        object? owner, bool once, TimeSpan? timeout,
        IEnumerable<string> reads, IEnumerable<string> mutates, IEnumerable<string> optionals,
        Func<IContextView, Context, CancellationToken, Task> invoker)
    { ... }

    // ------------ 唯一执行入口 ------------
    internal async Task<object?> RunAsync(Context ctx, CancellationToken ct)
    {
        if (Once && Fired) return null;
        Fired = true;

        // ① Preflight：检查所有声明的字段中 Ref 是否失效
        if (!Preflight(ctx, out var staleField))
        {
            Log.Debug("[{Chain}] 跳过 {Trigger}：{Field} 已失效",
                ctx.ChainId, Name, staleField);
            return null;
        }

        // ② 构造视图
        var view = ContextViewBinder.Create(_viewType, ctx.Data, ctx);
        var indent = new string(' ', ctx.Depth * 2);
        var sw = ValueStopwatch.StartNew();

        Log.Debug("{Indent}→ [{Event}] {Trigger} band={Band}/{Inner} rw={Reads}|{Mutates}",
            indent, ctx.Event, Name, SortKey.Band, SortKey.Inner,
            string.Join(",", Reads), string.Join(",", Mutates));

        try
        {
            // ③ 异步执行 + 超时
            using var timeoutCts = Timeout.HasValue
                ? CancellationTokenSource.CreateLinkedTokenSource(ct)
                : null;
            timeoutCts?.CancelAfter(Timeout!.Value);

            var token = timeoutCts?.Token ?? ct;
            await _invoker(view, ctx, token).ConfigureAwait(false);

            return null;
        }
        catch (OperationCanceledException) when (Timeout.HasValue && timeoutCts!.IsCancellationRequested && !ct.IsCancellationRequested)
        {
            Log.Error("{Indent}✗ [{Event}] {Trigger} 超时 {Timeout}",
                indent, ctx.Event, Name, Timeout);
            return null;
        }
        catch (OperationCanceledException)
        {
            Log.Warning("{Indent}✗ [{Event}] {Trigger} 被外部取消", indent, ctx.Event, Name);
            throw;   // 外部取消要向上传播
        }
        catch (StaleReferenceException ex)
        {
            Log.Debug("{Indent}~ [{Event}] {Trigger} 提前退出：{Msg}",
                indent, ctx.Event, Name, ex.Message);
            return null;
        }
        catch (PermissionDeniedException ex)
        {
            Log.Error("{Indent}✗ [{Event}] {Trigger} 越权访问：{Msg}",
                indent, ctx.Event, Name, ex.Message);
            return null;
        }
        catch (Exception ex)
        {
            // ④ 异常隔离
            Log.Error(ex, "{Indent}✗ [{Event}] {Trigger} 异常", indent, ctx.Event, Name);
            return null;
        }
        finally
        {
            view.Seal();
            Log.Debug("{Indent}← [{Event}] {Trigger} {Ms}ms stop={Stop} intr={Intr}",
                indent, ctx.Event, Name, sw.Elapsed.TotalMilliseconds,
                ctx.Stopped, ctx.Interrupted);
        }
    }

    private bool Preflight(Context ctx, out string? staleField)
    {
        staleField = null;
        foreach (var f in Reads.Concat(Mutates))
        {
            if (!ctx.Data.TryGetValue(f, out var v)) continue;
            if (v is IRef r && !r.IsAlive) { staleField = f; return false; }
        }
        return true;
    }

    // ------------ 主动触发入口 ------------
    public Task<object?> InvokeAsync(Context? ctx = null, CancellationToken ct = default)
    {
        ctx ??= new Context($"active:{Name}", Source: Owner);
        return RunAsync(ctx, ct);
    }
}
```

**类型参数与 `_viewType`**：用强类型泛型构造，把 `_viewType` 存在 Trigger 里，`RunAsync` 时按需构造视图。构造过程由 `TriggerFactory<TView>` 完成，向用户隐藏细节（见 4.6）。

### 4.6 TriggerFactory —— 友好的构造入口

让卡牌作者不用写反射或泛型体操：

```csharp
public static class TriggerFactory
{
    public static Trigger Create<TView>(
        string name,
        SortKey sortKey,
        Func<TView, Context, CancellationToken, Task> handler,
        TriggerOptions? options = null)
        where TView : IContextView
    {
        var opts = options ?? TriggerOptions.Default;
        // 从 TView 上静态分析（反射或 Source Generator）出 reads/mutates/optionals
        var meta = ViewMeta.For<TView>();

        return new Trigger(
            name, sortKey,
            opts.Owner, opts.Once, opts.Timeout,
            meta.Reads, meta.Mutates, meta.Optionals,
            async (rawView, ctx, ct) =>
            {
                var typed = (TView)rawView;
                await handler(typed, ctx, ct);
            })
        { _viewType = typeof(TView) };
    }
}

public sealed record TriggerOptions
{
    public static readonly TriggerOptions Default = new();
    public object? Owner { get; init; }
    public bool Once { get; init; }
    public TimeSpan? Timeout { get; init; }
}
```

**使用侧**：

```csharp
var shieldTrigger = TriggerFactory.Create<ShieldView>(
    name: "护盾",
    sortKey: new SortKey(PriorityBands.Damage.Reduce, inner: 0),
    handler: async (view, ctx, ct) =>
    {
        if (view.Target.Value != _shieldEntity) return;
        int newAmount = Math.Max(0, view.Amount - 2);
        Log.Info("  🛡 护盾减伤 {Old} → {New}", view.Amount, newAmount);
        view.Amount = newAmount;
        await Task.CompletedTask;
    },
    options: new TriggerOptions { Owner = _shieldCard });
```

### 4.7 TriggerBus —— 被动触发器挂载点

```csharp
public sealed class TriggerBus
{
    private readonly Dictionary<string, List<Trigger>> _slots = new();
    private readonly object _lock = new();
    private long _seq;

    public Trigger Mount(string @event, Trigger trigger)
    {
        lock (_lock)
        {
            trigger.RegistrationSeq = _seq++;
            if (!_slots.TryGetValue(@event, out var list))
                _slots[@event] = list = new List<Trigger>();
            list.Add(trigger);
            list.Sort(Compare);
            Log.Info("mount [{Event}] {Trigger} band={Band}/{Inner}",
                @event, trigger.Name, trigger.SortKey.Band, trigger.SortKey.Inner);
            return trigger;
        }
    }

    public void Unmount(string @event, Trigger trigger)
    {
        lock (_lock)
        {
            if (_slots.TryGetValue(@event, out var list)) list.Remove(trigger);
        }
    }

    public void UnmountOwner(object owner)
    {
        lock (_lock)
        {
            foreach (var list in _slots.Values)
                list.RemoveAll(t => ReferenceEquals(t.Owner, owner));
        }
    }

    public async Task EmitAsync(string @event, Context ctx, CancellationToken ct)
    {
        // 快照，防止遍历中被改
        Trigger[] snapshot;
        lock (_lock)
        {
            if (!_slots.TryGetValue(@event, out var list)) return;
            snapshot = list.ToArray();
        }

        foreach (var t in snapshot)
        {
            if (ctx.Stopped)
            {
                Log.Debug("[{Chain}] 在 [{Event}] 处停止", ctx.ChainId, @event);
                break;
            }
            await t.RunAsync(ctx, ct).ConfigureAwait(false);
        }
    }

    private static int Compare(Trigger a, Trigger b)
    {
        int c = a.SortKey.CompareTo(b.SortKey);
        return c != 0 ? c : a.RegistrationSeq.CompareTo(b.RegistrationSeq);
    }
}
```

### 4.8 GameEngine —— 规则动作与更新点

```csharp
public sealed class GameEngine
{
    public TriggerBus Bus { get; } = new();

    public async Task<int> DealDamageAsync(
        Entity source, Entity target, int amount,
        Context? parent = null, CancellationToken ct = default)
    {
        var ctx = new Context(
            "BeforeDamage",
            source: source,
            data: new Dictionary<string, object?>
            {
                ["Source"] = source.Ref,
                ["Target"] = target.Ref,
                ["Amount"] = amount,
                ["Engine"] = this,
            },
            parent: parent);

        await Bus.EmitAsync("BeforeDamage", ctx, ct).ConfigureAwait(false);

        if (ctx.Interrupted)
        {
            Log.Info("[{Chain}] 伤害被中断：{Reason}", ctx.ChainId, ctx.Reason);
            return 0;
        }

        int final = (int)ctx.Data["Amount"]!;
        if (final <= 0)
        {
            Log.Info("[{Chain}] 伤害被减为 0", ctx.ChainId);
            return 0;
        }

        Log.Info("[{Chain}] {Source} → {Target} 造成 {Amount} 伤害",
            ctx.ChainId, source.Name, target.Name, final);

        // ... 实际扣血 ...
        target.TakeDamage(final);

        var after = new Context(
            "AfterDamage",
            source: source,
            data: new Dictionary<string, object?>
            {
                ["Source"] = source.Ref,
                ["Target"] = target.Ref,
                ["Amount"] = final,
            },
            parent: ctx);

        await Bus.EmitAsync("AfterDamage", after, ct).ConfigureAwait(false);
        return final;
    }

    public async Task<bool> PlayCardAsync(Card card, Context? parent = null, CancellationToken ct = default)
    {
        var ctx = new Context(
            "BeforePlayCard",
            source: card,
            data: new Dictionary<string, object?>
            {
                ["Card"] = card,
                ["Engine"] = this,
            },
            parent: parent);

        await Bus.EmitAsync("BeforePlayCard", ctx, ct).ConfigureAwait(false);

        if (ctx.Interrupted)
        {
            Log.Info("[{Chain}] 出牌被反制：{Reason}", ctx.ChainId, ctx.Reason);
            return false;
        }

        Log.Info("[{Chain}] 打出 {Card}", ctx.ChainId, card.Name);
        // ... 实际结算 ...
        await Bus.EmitAsync("AfterPlayCard", ctx, ct).ConfigureAwait(false);
        return true;
    }
}
```

## 五、运行时流程

以"打出火球术 → 造成 5 点伤害 → 护盾减伤 2 → 受伤后回血"为例：

```
ChainId = "ab12ef90"

play_card(fireball, parent=null)
  ctx.chainId = "ab12ef90", depth = 0
  emit BeforePlayCard
    ├─ [Counter] 法术反制 (band=100)  → 检查非反制
    └─ ...
  ✓ 出牌成功

  cast_fireball(ctx)
    fireball.InvokeAsync(parent=ctx)  → 主动触发器进入 RunAsync
    ...
    deal_damage(fireball, shield, 5, parent=ctx)
      ctx.chainId = "ab12ef90", depth = 1
      emit BeforeDamage
        ├─ [Prevent] 免疫检查 (band=100)
        ├─ [Reduce] 护盾 (band=300)
        │   view.Amount = 5 - 2 = 3      ← 写入 ctx.Data
        └─ [Amplify] 增伤 (band=400)
           读取 ctx.Data["Amount"] = 3
```

## 六、异常、取消与中断语义

| 情形 | 处理 | 是否中断链 |
|---|---|---|
| 触发器内部业务异常 | 捕获、记日志、返回 null | ❌ 继续下一个 |
| 视图越权（PermissionDenied） | 捕获、记 Error | ❌ 继续（便于暴露 bug） |
| Ref 失效（StaleReference） | Preflight 拦截或捕获、记 Debug | ❌ 继续 |
| 超时（Timeout） | 捕获 OperationCanceled、记 Error | ❌ 继续 |
| 外部取消（CancellationToken） | 捕获、记 Warning、**重新抛出** | ✅ 整个链终止 |
| `ctx.Stop()` | 引擎在下一个触发器前检查 | ✅ 本事件后续终止 |
| `ctx.Interrupt()` | 引擎动作边界检查 | ✅ 动作整体取消 |
| `ctx.Interrupt()` + 回滚需求 | **引擎侧负责**（前置校验点模式） | — |

**关键约定**

- **触发器**只能"喊停"，不能"撤回已发生的事"。反制类效果必须落在 `Before*` 事件。
- **引擎**在动作边界（emit 之后）检查 `ctx.Interrupted`。
- **取消令牌**必须从引擎一路传到触发器，用于真实资源清理。

## 七、异步模型

### 7.1 统一签名

所有触发器 handler 都是：

```csharp
Func<TView, Context, CancellationToken, Task>
```

同步逻辑用 `Task.CompletedTask` 或 `ValueTask`（若追求零分配）。

### 7.2 超时

在 `Trigger.RunAsync` 内用 `CancellationTokenSource.CreateLinkedTokenSource` + `CancelAfter`。

### 7.3 并发

**首版建议：单线程调度**。所有触发器通过一条 `Task` 链顺序 await。若引入并行，需要：

- 每个触发器独立的 `ContextView`（当前实现已具备）
- `ctx.Data` 写入需加锁或使用 `ImmutableDictionary`
- 明确哪些 band 可并行（一般只有 `Read` 类可并行）

**不建议原型阶段并行**，调试成本远高于收益。

## 九、扩展指南

### 9.1 新增一个事件

1. 定义 `Band` 常量（若有多相位）
2. 定义 `ContextView`（声明读写）

4. 写文档告诉社区"这个事件的 band 表"

3. 被动：`bus.Mount("BeforeDamage", trigger)`

**只允许追加，不允许重排已有枚举值**。若需要插到两个 band 之间，用预留空隙或新 band 数字（如 `Prevent=100` 和 `Replace=200` 之间插 `PreventExt=150`）。

## 十一、C# 实现注意事项

1. **`Ref<T>` 用 `sealed class`**，避免虚调用开销；访问 `Value` 是热路径。
2. **`SortKey` 用 `readonly record struct`**，排序零分配。
3. **`TriggerBus` 的 `_slots` 用 `Dictionary<string, List<Trigger>>`**，`List` 内部有序，配 `Sort(Compare)` 保证顺序。
4. **`Context.Data` 用 `Dictionary<string, object?>`**。若需极致性能，可换 `FrozenDictionary` 做只读阶段，但写入阶段仍需可变。
5. **Source Generator 是长期方案，反射缓存是短期方案**。接口 `IContextView.Bind` 不变，方便切换。
6. **`ValueTask` vs `Task`**：原型用 `Task`；热点路径（如每秒上千次结算）可评估 `ValueTask`。
7. **`ConfigureAwait(false)`**：引擎内部一律加，避免同步上下文死锁。
8. **多线程**：v1 单线程调度，`TriggerBus` 的 `_lock` 仅为防御；未来若并行，需升级为 `ReaderWriterLockSlim` 或每事件独立锁。
9. **日志用 `Microsoft.Extensions.Logging`**，通过结构化字段支持过滤。
10. **不要在 `ContextView` 里存引用**，只做 `_data` 的转发；每次 `Bind` 复用或新建均可。

## 十三、设计决策速查表

| 决策 | 选择 | 理由 |
|---|---|---|
| 被动/主动是否共用包装器 | ✅ 共用 | 优先级/日志/异步/中断统一 |
| 上下文传递 | `Context` + `ContextView` | 收窄范围，防越权 |
| 引用安全 | `Lifetime` + `Ref<T>` | 悬空可检测 |
| 优先级 | `(Band, Inner)` 元组 | 避免浮点、避免重排 |
| 排序键比较 | `IComparable` 元组 | 零成本、安全 |
| 同键冲突 | 注册序号兜底 | 语义即入场顺序 |
| 异步 | `async Task` + `CancellationToken` | 原生支持 |
| 超时 | `CancelAfter` | 防止卡死 |
| 异常 | 隔离，除非外部取消 | 单个触发器不拖垮链 |
| 中断 | `ctx.Stop/Interrupt` + 引擎边界检查 | 显式、可测 |
| 日志 | `ChainId` + `Depth` + 结构化 | 全链路可读 |
| 视图实现 | 反射缓存（MVP）→ Source Generator（长期） | 兼容切换 |

---

**结语**

这套架构的核心思想是把"上下文"和"引用"从**万能对象**降级为**每个触发器自己的切片 + 生命周期令牌**，把"优先级"从**单值调数**升级为**双层语义相位**。所有复杂度都收敛在 `Trigger.RunAsync` 一个方法里，卡牌作者面对的是强类型视图和命名 band。这是可长期维护、可扩展、可观测、可测试的形态。
